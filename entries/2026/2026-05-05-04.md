## Objetivo
Comprender que una clase debe tener un solo motivo para cambiar, evitando la complejidad innecesaria y facilitando el mantenimiento del código al separar responsabilidades lógicas.

## Explicación
El principio de Responsabilidad Única establece que cada clase debe encargar una única tarea. Si una clase realiza múltiples funciones distintas, cualquier cambio en una de ellas podría afectar a las otras, aumentando la fragilidad del sistema. Por ejemplo, mezclar lógica de negocio con persistencia de datos o manejo de errores es una mala práctica. Al dividir estas responsabilidades en clases separadas, mejoramos la modularidad y la reutilización. Este enfoque permite que los desarrolladores modifiquen un aspecto específico sin riesgo de romper funcionalidades ajenas, promoviendo arquitecturas más limpias y escalables.

## Ejemplo (no ejecutado automáticamente)
Clase separada para calcular impuestos versus clase para generar reportes de ventas.

```javascript
class CalculadoraImpuestos {
  calcular(total) { return total * 0.16; }
}
class GeneradorReporte {
  exportar(datos) { console.log('Reporte generado'); }
}
```

## Ejercicio
Refactoriza una clase 'Pedido' que actualmente guarda el pedido, calcula impuestos y envía un correo en un solo método. Divide la lógica en tres clases distintas.

## Criterios de revisión
El código debe tener tres clases separadas sin dependencias circulares, cada una con un único propósito claro y métodos públicos mínimos.

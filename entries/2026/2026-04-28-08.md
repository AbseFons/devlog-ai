## Objetivo
Comprender la importancia de dividir una aplicación en capas lógicas (presentación, lógica y datos) para mejorar el mantenimiento, la escalabilidad y la seguridad del software.

## Explicación
El diseño por capas organiza el sistema en niveles funcionales independientes. La capa de presentación maneja la interacción con el usuario, mientras que la capa de negocio encapsula la lógica crítica y las reglas de operación. Finalmente, la capa de acceso a datos se encarga exclusivamente de la persistencia de información. Esta separación permite que cada nivel evolucione sin afectar a los demás, facilitando pruebas unitarias aisladas y cambios tecnológicos graduales. Al evitar el acoplamiento directo entre interfaces y bases de datos, se reduce la complejidad técnica y se promueve un código más legible y robusto frente a errores.

## Ejemplo (no ejecutado automáticamente)
Implementación básica en Python que define clases separadas para manejar la entrada del usuario, procesar una transacción simple y guardar el resultado en una base de datos simulada.

```python
class CapaPresentacion:
    def __init__(self):
        self.input_usuario = "Usuario A"

class CapaNegocio:
    def procesar(self, usuario):
        return f"Procesando para {usuario}"

class CapaDatos:
    def guardar(self, resultado):
        print(f"Guardado: {resultado}")
```

## Ejercicio
Crea un archivo 'app.py' con tres clases distintas. La primera debe leer una línea de texto desde la consola. La segunda debe validar si el texto tiene más de cinco caracteres y devolver un mensaje condicional. La tercera debe imprimir ese mensaje final simulando una escritura en disco.

## Criterios de revisión
El código debe tener exactamente tres bloques 'class' sin herencia entre ellos. Debe existir una función principal que instancie las clases en orden secuencial. No se permiten bucles ni condicionales complejos dentro de las clases, solo la lógica básica requerida.

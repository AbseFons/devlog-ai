## Objetivo
El desarrollador identificará cómo la selectividad afecta al rendimiento y diseñará índices compuestos con el orden correcto de columnas para filtrar datos primero, reduciendo el tiempo de respuesta en tablas grandes sin comprometer la integridad de los datos.

## Explicación
Los índices no son mágicos; su eficacia depende del orden de las columnas. En un índice compuesto, SQL utiliza las primeras columnas para localizar rápidamente una subconjunto pequeño de filas antes de escanear el resto. Si indexas (nombre, apellido), la base de datos puede buscar por nombre y luego filtrar apellidos, pero no al revés. Para consultas eficientes, coloca siempre la columna con mayor selectividad (menor cardinalidad) primero. Además, evita funciones en las columnas indexadas dentro del WHERE, ya que esto fuerza un escaneo completo de la tabla. Una consulta bien diseñada aprovecha el B-Tree para saltar directamente a los datos necesarios, evitando lecturas innecesarias y saturando menos la memoria caché.

## Ejemplo (no ejecutado automáticamente)
```sql
-- Tabla: usuarios (millones de registros)
-- Columnas: id, nombre, apellido, email, fecha_registro

-- MALA PRÁCTICA: Índice en orden incorrecto para filtrar por apellido primero
CREATE INDEX idx_usuarios_malo ON usuarios(apellido, nombre);
SELECT * FROM usuarios WHERE apellido = 'Garcia' AND nombre = 'Juan';

-- BUENA PRÁCTICA: Índice optimizado para el patrón de consulta frecuente
DROP INDEX idx_usuarios_malo;
CREATE INDEX idx_usuarios_optimo ON usuarios(nombre, apellido);

-- Consulta que aprovecha el índice correctamente
SELECT id, email FROM usuarios 
WHERE nombre = 'Juan' AND apellido = 'Garcia';
```

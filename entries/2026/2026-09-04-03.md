## Objetivo
Aprender a usar git bisect para identificar eficientemente el commit exacto que introdujo un error de regresión en una rama, ahorrando horas de revisión manual.

## Explicación
El comando git bisect es una herramienta poderosa que permite realizar una búsqueda binaria sobre la historia de los commits. En lugar de revisar cada cambio manualmente desde el último commit correcto hasta el actual con el bug, el sistema guía al usuario probando puntos intermedios. El flujo consiste en marcar el estado actual como 'buggy' y un commit anterior conocido como 'good'. Luego, ejecutando git bisect start, se inicia el proceso. Git seleccionará automáticamente un punto medio para probar. Si ese punto tiene el bug, se marca como 'buggy'; si no, como 'good'. Este ciclo se repite hasta aislar el commit culpable, mostrando el resultado final con git bisect bad o git bisect reset.

## Ejemplo (no ejecutado automáticamente)
Script de bash que automatiza la marcación de estados durante un bisect manual para encontrar un bug en una aplicación web.

```bash
# Verificar si el commit actual tiene el bug
if [ -f /tmp/bug_marker ]; then
  echo "Bug presente"
  git bisect bad
else
  echo "Funciona correctamente"
  git bisect good
fi
```

Ejecuta 'git bisect start' marcando el estado actual como 'buggy' y el commit anterior como 'good'. 4. Sigue las instrucciones de git para probar los commits intermedios hasta que aparezca el resultado final.

## Criterios de revisión
El usuario debe ejecutar correctamente el comando git bisect, marcar adecuadamente los estados 'good' y 'bad', y finalizar el proceso identificando el commit específico que introdujo la falla sin cometer errores de sintaxis.

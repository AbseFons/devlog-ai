## Objetivo
Al finalizar esta lección, el desarrollador será capaz de identificar cómo encapsular la complejidad de múltiples módulos internos mediante una interfaz unificada, reduciendo acoplamiento y simplificando la lógica de negocio en sistemas modulares.

## Explicación
La separación de responsabilidades evita que una clase o módulo acumule demasiada lógica, lo que dificulta el mantenimiento. El patrón Facade ilustra esto al crear una interfaz simplificada que delega tareas a subsistemas complejos. Imagina un sistema de reservas donde la lógica de base de datos, notificaciones y facturación están en módulos distintos. En lugar de importar todos estos detalles en cada servicio, usamos un Facade que expone solo los métodos necesarios. Esto protege al cliente de cambios internos y permite evolucionar el subsistema sin romper dependencias externas. La clave es definir límites claros: el Facade sabe qué hacer, pero no cómo hacerlo internamente.

## Ejemplo (no ejecutado automáticamente)
```python
class SistemaReservasFacade:
    def __init__(self):
        self.db = BaseDeDatos()
        self.notificaciones = ServicioNotificaciones()
        self.facturacion = Facturador()

    def procesar_reserva(self, cliente_id, producto_id):
        # 1. Verificar stock en DB
        disponible = self.db.verificar_stock(producto_id)
        if not disponible:
            raise Exception('Producto agotado')
        
        # 2. Crear reserva y facturar
        reserva = self.db.crear_reserva(cliente_id, producto_id)
        factura = self.facturacion.generar(reserva.id)
        
        # 3. Enviar confirmación
        self.notificaciones.enviar_correo(f'Cliente {cliente_id}', f'Reserva {reserva.id}')
        return reserva
```

## Criterios de revisión

2. Debe incluir manejo de excepciones para cada paso fallido.
3. No debe exponer las instancias de los módulos internos directamente.

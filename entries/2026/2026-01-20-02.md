## Objetivo
Aprender a utilizar el comando git bisect para identificar eficientemente en qué commit exacto se introdujo una regresión o error, ahorrando tiempo frente al uso manual de bissection.

## Explicación
El comando git bisect permite realizar una búsqueda binaria automática sobre la historia del repositorio. Es ideal cuando un bug aparece repentinamente y no sabes cuándo fue introducido. Primero, marcas el commit actual como 'bueno' (sin error) y el commit donde apareció el error como 'malo'. Luego, ejecutas git bisect start. Git seleccionará automáticamente un commit intermedio para que lo pruebes. Si ese commit tiene el error, lo marcas como malo; si no, como bueno. Este proceso se repite hasta que Git encuentra el primer commit defectuoso. Es crucial tener una forma rápida de verificar si el bug existe en cada estado probado.

## Ejemplo (no ejecutado automáticamente)
Ejecución del flujo de bisect marcando commits buenos y malos para aislar la causa raíz de un fallo en la aplicación.

```bash
git bisect start
HEAD~100:good
HEAD:mango
```

## Ejercicio
Simula que un bug apareció hace 50 commits. Marca el commit actual como malo y el anterior a la última versión estable como bueno. Ejecuta git bisect y marca los commits intermedios según si el bug está presente o no hasta que Git identifique el culpable.

## Criterios de revisión
El usuario debe completar correctamente al menos tres iteraciones de bisect, marcando cada commit intermedio con 'git bisect bad' o 'git bisect good' según corresponda, y finalizar con 'git bisect reset'. Debe explicar por qué eligió cada marca.

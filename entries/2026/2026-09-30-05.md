## Objetivo
Aprender a identificar y resolver conflictos de merge manteniendo la integridad del código, utilizando herramientas visuales y edición directa para integrar cambios específicos sin perder lógica.

## Explicación
Cuando Git detecta un conflicto, detiene el proceso y marca las líneas problemáticas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. En esta microlección, exploraremos cómo abrir el archivo afectado en tu editor de código preferido. El objetivo es revisar ambas versiones: la tuya (actual) y la del otro desarrollador o rama. Debes decidir qué lógica conservar, si fusionar ambas o reescribir la sección completa. Una vez resuelto, elimina los marcadores de conflicto manualmente. Finalmente, ejecuta 'git add' para marcar el archivo como resuelto y 'git commit' para finalizar el merge. Esta práctica manual es crucial cuando las herramientas automáticas no pueden determinar la solución correcta.

## Ejemplo (no ejecutado automáticamente)
Fragmento de código JavaScript mostrando una función con conflicto donde se modifica un parámetro en ambas ramas, requiriendo decisión manual sobre qué valor usar.

```javascript
function calcularTotal(impuesto) {
  // Conflicto: Rama A usa 0.21, Rama B usa 0.16
  const tasa = impuesto || 0.21; 
  return precio * (1 + tasa);
}
```

## Ejercicio
Crea dos ramas en tu repositorio local. En la rama 'feature-a', modifica una variable de configuración a 'modo: debug'. En la rama 'feature-b', modifícala a 'modo: production'. Intenta hacer un merge y resuelve el conflicto editando el archivo para establecer el valor correcto según el contexto del proyecto.

## Criterios de revisión
El archivo debe estar libre de marcadores de conflicto (<<<<, ====, >>>>). El código final debe compilar sin errores. Debes haber utilizado 'git add' y 'git commit' correctamente tras la resolución.

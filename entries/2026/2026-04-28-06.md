## Objetivo
Comprender qué es un hook en Git y cómo configurar uno básico para validar código antes de cada commit, mejorando la calidad del repositorio desde el inicio.

## Explicación
Los hooks son scripts que Git ejecuta automáticamente en eventos específicos como commits o merges. El hook pre-commit se activa justo antes de guardar cambios. Es ideal para formatear código o ejecutar pruebas rápidas. En esta lección, crearemos un script simple en Bash que verifica si hay archivos sin formato y bloquea el commit si es así. Esto evita introducir deuda técnica en cada push.

## Ejemplo (no ejecutado automáticamente)
Script bash que comprueba la existencia de archivos .unformatted y detiene el commit si los encuentra.

```bash
#!/bin/bash
if [ -f "file.unformatted" ]; then
  echo "Error: Archivo no formateado detectado."
  exit 1
fi
```

## Ejercicio
Crea un archivo llamado .git/hooks/pre-commit en tu repositorio local con el contenido del ejemplo anterior y haz un commit que intente incluir file.unformatted.

## Criterios de revisión
El commit debe fallar si existe file.unformatted. El script debe estar ejecutable (chmod +x). No deben haber errores de sintaxis en el hook.

## Objetivo
Aprender a utilizar el comando git bisect para identificar eficientemente la revisión específica que introdujo un error de comportamiento en el historial de commits, ahorrando tiempo de depuración manual.

## Explicación
El comando git bisect es una herramienta poderosa que permite realizar una búsqueda binaria sobre el historial de commits. En lugar de revisar cada cambio manualmente, el usuario marca un commit conocido como 'bueno' y otro como 'malo'. Git luego divide automáticamente el rango de cambios, permitiendo al desarrollador probar solo los puntos medios hasta aislar la causa raíz. Este método es esencial cuando un bug aparece repentinamente tras una serie de commits sin errores previos.

## Ejemplo (no ejecutado automáticamente)
Se inicia una sesión de bisect marcando el commit actual como malo y uno anterior estable como bueno, luego se ejecuta la prueba de regresión en cada paso intermedio hasta que git bisect detecta el cambio problemático.

```bash
git bisect start
git bisect bad
GIT_AUTHOR_DATE="2024-01-01" GIT_COMMITTER_DATE="2024-01-01" git commit --date=now -m "Commit bueno"
git bisect good
```

## Ejercicio
Identifica el commit que rompió la funcionalidad de autenticación en un repositorio local simulando una regresión.

## Criterios de revisión
El usuario debe ejecutar correctamente los comandos de inicio, marcar los commits adecuados y finalizar con 'git bisect reset' tras encontrar el culpable.

## Objetivo
Aprender a utilizar Pull Requests para integrar código en ramas principales, resolviendo conflictos de manera colaborativa y manteniendo la estabilidad del proyecto mediante revisiones sistemáticas antes de la fusión.

## Explicación
En esta lección exploramos el flujo de trabajo moderno basado en Pull Requests. En lugar de fusionar directamente a 'main', los desarrolladores crean ramas de características, realizan commits locales y abren un PR. Este mecanismo permite que otros revisen el código antes de integrarlo. Cuando dos ramas modifican la misma línea, Git genera un conflicto. La estrategia correcta es inspeccionar manualmente ambos cambios en el editor, decidir cuál preservar o combinarlos lógicamente, y luego ejecutar 'git add' seguido de 'git commit'. Finalmente, se realiza el merge manual desde la interfaz del sistema de control de versiones para asegurar que todas las pruebas pasen antes de liberar la nueva funcionalidad al entorno de producción.

## Ejemplo (no ejecutado automáticamente)
Comandos para crear una rama, simular un cambio en dos archivos y preparar la resolución de conflictos manualmente.

```bash
git checkout -b feature-nueva-login
vim src/login.py
echo 'nuevo_cambio' >> src/login.py
git add .
git commit -m "Añadir validación de token"
```

## Ejercicio
Crea una rama llamada 'fix-bug-calculadora', modifica la función suma en un archivo Python para que devuelva el doble del resultado, haz un commit y simula cómo se resolvería un conflicto si otra persona modificó ese mismo archivo.

## Criterios de revisión
El estudiante debe crear la rama correctamente, modificar el archivo sin romper la sintaxis, explicar los pasos de resolución de conflictos y demostrar comprensión de por qué no se deben fusionar directamente a 'main'.

## Objetivo
Aprender a estructurar mensajes de commit claros que describan la adición de nuevas características, facilitando el seguimiento del historial y la generación automática de changelogs en proyectos modernos.

## Explicación
Los commits convencionales requieren un tipo específico para cada cambio. Para añadir funcionalidad, usamos 'feat'. El mensaje debe ser imperativo ('Añade login') y breve. Esto permite herramientas como Angular o React generar releases automáticas. Un buen commit explica el qué, no el cómo detallado (eso va en el cuerpo). Mantener este estándar mejora la legibilidad del historial para todos los colaboradores.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de script bash que simula un comando git con mensaje convencional para añadir una nueva función de autenticación.

```bash
# Simulación de commit convencional
git add src/auth/login.js
git commit -m 'feat: añade sistema de autenticación básico'
# El cuerpo explicaría detalles técnicos si fuera necesario
```

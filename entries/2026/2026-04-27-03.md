## Objetivo
Aprender a estructurar mensajes de commit legibles mediante convenciones estándar, facilitando la generación automática de changelogs y mejorando la trazabilidad del historial en repositorios colaborativos.

## Explicación
Los commits convencionales siguen el formato 'tipo(scope): descripción'. El tipo indica la naturaleza del cambio (feat, fix, docs). El scope especifica la parte afectada. La descripción debe ser imperativa y breve. Esta estructura permite a las herramientas CI/CD detectar automáticamente nuevas funcionalidades o correcciones de errores. Un buen mensaje resume el cambio sin incluir detalles de implementación internos ni referencias a tickets en el cuerpo principal, reservando estos últimos para el cuerpo del commit si es necesario.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de script bash que genera un archivo de registro con un commit convencional válido.

```bash
#!/bin/bash

# Generar mensaje de commit convencional
tipo="feat"
scope="auth"
desc="agregar validacion de token jwt"

commit_msg="$tipo($scope): $desc"
echo "Commit generado: $commit_msg" > .git/last_commit.log
```

## Criterios de revisión
El script debe ejecutar sin errores, generar exactamente tres archivos con nombres descriptivos y contener mensajes que sigan estrictamente el formato tipo(scope): descripción. Cada mensaje debe tener al menos una palabra en la descripción.

## Objetivo
Aprender a crear etiquetas semánticas (SemVer) en Git para gestionar releases estables, entender la diferencia entre tags ligeros y anotados, y automatizar el proceso de versionado mediante hooks o scripts básicos.

## Explicación
Las etiquetas (tags) en Git son marcadores que identifican puntos específicos del historial como versiones estables. Existen dos tipos principales: los tags ligeros (lightweight), que son referencias simples a un commit, y los tags anotados (annotated), que incluyen autor, fecha y mensaje de commit, comportándose como commits reales. Para proyectos profesionales, se recomienda usar etiquetas anotadas con el formato SemVer (Major.Minor.Patch). Este enfoque permite mantener un historial claro de las versiones sin alterar el flujo de trabajo diario. Utiliza 'git tag -a v1.0.0 -m "Release inicial"' para crear una etiqueta anotada y 'git push --tags' para enviarlas al remoto.

## Ejemplo (no ejecutado automáticamente)
Creación de una etiqueta anotada con mensaje personalizado y empuje a un repositorio remoto.

```bash
git tag -a v2.1.0 -m "Corrección de bug crítico en autenticacion"
git push origin v2.1.0
```

## Ejercicio
Crea una etiqueta ligera llamada 'beta' en el commit actual y luego crea una etiqueta anotada 'v3.0.0' con un mensaje que incluya la fecha de hoy.

## Criterios de revisión
El usuario debe ejecutar correctamente los comandos para crear ambos tipos de etiquetas, verificar su existencia con 'git tag -l' y empujar al menos la etiqueta anotada al remoto sin errores.

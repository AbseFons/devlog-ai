## Objetivo
Comprender la inyección de dependencias como patrón de diseño para desacoplar componentes, facilitando pruebas unitarias y mantenimiento del código en aplicaciones modernas.

## Explicación
La inyección de dependencias es un patrón que permite pasar las dependencias necesarias a una clase desde el exterior, evitando la creación manual de objetos. Esto promueve el principio de inversión de dependencias (DIP), donde los módulos de alto nivel no dependen de implementaciones concretas de bajo nivel. Al externalizar la creación de objetos, se logra un código más modular y flexible. Este enfoque simplifica las pruebas unitarias al permitir sustituir implementaciones reales por mocks o stubs fácilmente. Además, mejora la legibilidad del código al declarar explícitamente qué recursos requiere una clase.

## Ejemplo (no ejecutado automáticamente)
Clase Servicio que recibe un reproductor de audio inyectado en su constructor para reproducir música sin crear el objeto internamente.

```javascript
class Reproductor {
  reproducir() { console.log('Reproduciendo...'); }
}
class ServicioMusica {
  constructor(reproductor) { this.reproductor = reproductor; }
}
```

## Ejercicio
Crea una clase 'Notificador' que acepte un objeto 'CorreoElectronico' en su constructor. Implementa un método 'enviarAlerta' que utilice la instancia inyectada para notificar sobre errores del sistema.

## Criterios de revisión
El código debe mostrar claramente la inyección de la dependencia en el constructor y no instanciar directamente la clase 'CorreoElectronico' dentro de 'Notificador'. Debe ser funcional y seguir buenas prácticas de encapsulamiento.

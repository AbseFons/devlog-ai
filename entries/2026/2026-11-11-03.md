## Objetivo
Distinguir funcionalmente entre mocks y stubs mediante un caso de uso realista, evitando confusiones comunes sobre verificación de interacciones versus inyección de datos controlados para pruebas unitarias.

## Explicación
En esta lección analizamos la distinción crítica. Un stub es una implementación simplificada que devuelve valores predefinidos para simular dependencias externas sin lógica compleja, permitiendo aislar la unidad bajo prueba. Por otro lado, un mock no solo responde, sino que verifica explícitamente cómo fue invocado: qué argumentos recibió y cuántas veces. Usar mocks cuando solo necesitas datos es excesivo; usar stubs cuando necesitas validar interacciones puede ocultar fallos de integración. La elección depende estrictamente del propósito: aislamiento rápido (stub) o validación de contratos (mock).

## Ejemplo (no ejecutado automáticamente)
Se define un objeto mock para una base de datos que verifica si se llamó a la función 'insertar' con el parámetro correcto, mientras que un stub simple solo devolvería un ID ficticio sin importar los argumentos.

```javascript
const dbMock = {
  insertar: jest.fn().mockResolvedValue(101)
};
dbMock.insertar('usuario'); // Verifica la llamada
```

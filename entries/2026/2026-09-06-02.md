## Objetivo
Comprender cómo las consultas dinámicas vulnerables permiten a los atacantes manipular la lógica de la base de datos mediante cadenas mal construidas, y aprender a evitarlo usando parámetros.

## Explicación
La inyección SQL ocurre cuando se insertan entradas no filtradas directamente en una consulta. Un ejemplo clásico es concatenar el valor del usuario con la sentencia SELECT. Si un atacante envía 'admin'-- como nombre de usuario, el guion doble comenta el resto de la consulta, logrando acceso sin contraseña. La solución robusta es utilizar parámetros o Prepared Statements. Esto separa la estructura de la consulta de los datos, asegurando que cualquier entrada especial sea tratada literalmente y no como código SQL ejecutable.

## Ejemplo (no ejecutado automáticamente)
Consulta vulnerable vs segura usando parámetros en Python con sqlite3

```python
import sqlite3
conn = sqlite3.connect('db.sqlite')
cursor = conn.cursor()
usuario = 'admin'--'
password = '1234'
# Vulnerable: cursor.execute(f"SELECT * FROM users WHERE user='{usuario}' AND pass='{password}'")
# Seguro: cursor.execute("SELECT * FROM users WHERE user=? AND pass=?", (usuario, password))
```

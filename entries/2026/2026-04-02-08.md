## Objetivo
Comprender qué es un Git hook y cómo configurar uno básico para validar el código antes de cada commit, mejorando la calidad del repositorio desde el inicio.

## Explicación
Los hooks son scripts que Git ejecuta automáticamente en eventos específicos como commits o merges. Este microcurso introduce el 'pre-commit', ideal para formatear código o ejecutar pruebas unitarias rápidas. Al crear un archivo .git/hooks/pre-commit con lógica de validación, se evita subir código sucio al repositorio compartido. Esto fomenta buenas prácticas sin interrumpir el flujo de trabajo diario.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que verifica si hay archivos no formateados antes de permitir el commit.

```bash
#!/bin/bash
if ! git diff --cached --name-only | xargs -I {} sh -c 'echo "Archivo: {}"' ; then
  echo "Error: Se detectaron cambios sin formatear."
  exit 1
fi
```

## Ejercicio
Crea un archivo .git/hooks/pre-commit en tu repositorio local que muestre una alerta si existen archivos con extensión .py no formateados.

## Criterios de revisión
El script debe ejecutarse al intentar hacer commit, mostrar mensaje de error claro y detener el proceso si se detectan archivos incumplidores.

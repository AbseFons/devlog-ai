## Objetivo
Aprender a crear etiquetas semánticas en Git para marcar versiones estables del proyecto, diferenciándolas de los commits regulares y entendiendo su utilidad en la distribución de software.

## Explicación
Las etiquetas (tags) en Git son marcadores inmutables que señalan puntos específicos en el historial de commits, típicamente usados para indicar lanzamientos de versión. A diferencia de los branches, las tags no se mueven y representan un estado fijo del código. Para crear una etiqueta ligera, usa 'git tag v1.0.0'. Si deseas incluir una descripción, añade '--annotate' o '-a', seguido de un mensaje con el símbolo '-m'. Las etiquetas siguen la convención semántica (Major.Minor.Patch) para facilitar la identificación rápida de cambios importantes. Es crucial distinguir entre tags ligeros y anotados: los primeros son rápidos pero no tienen autor ni fecha, mientras que los segundos permiten atribuir responsabilidades a un desarrollador específico en el momento del lanzamiento.

## Ejemplo (no ejecutado automáticamente)
Creación de una etiqueta anotada con mensaje para marcar la versión 1.0.0 del proyecto.

```bash
git tag -a v1.0.0 -m "Primer lanzamiento estable"
git push origin v1.0.0
```

## Objetivo
Comprender y aplicar el principio de mínimo privilegio configurando roles con permisos estrictos para reducir la superficie de ataque en entornos cloud, evitando accesos innecesarios a recursos sensibles.

## Explicación
El principio de mínimo privilegio establece que cada entidad de seguridad debe tener solo los permisos necesarios para realizar su función específica. En ingeniería de software moderna, esto implica evitar el uso de cuentas con acceso administrativo global o roles 'superusuario' por defecto. Al diseñar microservicios o funciones serverless, se deben asignar políticas de IAM granulares que limiten las acciones permitidas (por ejemplo, solo lectura de logs en lugar de escritura y borrado). Esta práctica mitiga el riesgo de propagación lateral ante una brecha. Un caso común es configurar un rol para una función Lambda que pueda invocar otra función específica pero no acceder a buckets de almacenamiento críticos ni modificar configuraciones de red. La implementación requiere revisar constantemente las políticas existentes y eliminar permisos heredados o redundantes.

## Ejemplo (no ejecutado automáticamente)
Definición de una política IAM en AWS que otorga a un servicio Lambda acceso de solo lectura a un bucket S3 específico, sin permitir operaciones de escritura ni listados globales.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::mi-bucket-de-logs",
        "arn:aws:s3:::mi-bucket-de-logs/*"
      ]
    }
  ]
}
```

## Ejercicio
Crea una política JSON similar para un rol de base de datos que permita únicamente consultas SELECT a tablas específicas, prohibiendo cualquier operación DDL o acceso a otras bases de datos.

## Criterios de revisión
La política debe especificar acciones limitadas (solo lectura), recursos restringidos a identidades o rutas concretas y no incluir permisos de administración o escritura.

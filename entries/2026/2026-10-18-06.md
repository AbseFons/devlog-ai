## Objetivo
Diferenciar claramente entre autenticación (quién eres) y autorización (qué puedes hacer), aplicando estos conceptos a flujos de seguridad en APIs REST modernas mediante tokens JWT.

## Explicación
En el desarrollo de APIs, la autenticación verifica la identidad del usuario, mientras que la autorización determina sus permisos. Un error común es confundir ambos procesos. Por ejemplo, un token JWT puede contener información sobre quién es el usuario (autenticación) y qué recursos puede acceder (autorización). Es crucial implementar middleware que valide primero el token de autenticación y luego extraiga las claims para aplicar políticas de autorización específicas antes de procesar la solicitud.

## Ejemplo (no ejecutado automáticamente)
Middleware en Node.js que valida un token JWT y verifica si el usuario tiene permiso para acceder a una ruta protegida.

```javascript
const jwt = require('jsonwebtoken');

function verificarPermiso(req, res, next) {
  const token = req.headers['authorization'];
  if (!token) return res.status(401).send('Falta el token');
  try {
    const decoded = jwt.verify(token, 'SECRET_KEY');
    if (decoded.roles.includes('admin')) next();
    else return res.status(403).send('Acceso denegado');
  } catch (e) { return res.status(401).send('Token inválido'); }
}
```

## Ejercicio
Crea una API en Python con Flask que requiera un token Bearer para acceder a '/datos'. Implementa una función de autorización que permita solo al rol 'analista' leer los datos y al rol 'admin' poder borrarlos.

## Criterios de revisión
El código debe incluir la validación del token, la extracción de roles y la lógica condicional para diferenciar entre lectura y borrado. Debe manejar errores de token inválido o expirado correctamente.

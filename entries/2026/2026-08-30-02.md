## Objetivo
El desarrollador diferenciará el flujo de ejecución de agregaciones, aplicará HAVING para filtrar grupos resultantes (no filas) y evitará errores comunes al mezclar condiciones de filtro con cláusulas de agrupación en consultas SQL complejas.

## Explicación
En SQL, GROUP BY agrupa filas idénticas según columnas especificadas, permitiendo funciones agregadas como COUNT o SUM. HAVING filtra estos grupos formados, actuando después del cálculo de agregados, a diferencia de WHERE que opera antes. El orden lógico es: FROM, WHERE, GROUP BY, SELECT (agregados), HAVING, ORDER BY. Es crucial recordar que solo las columnas incluidas en GROUP BY o dentro de funciones agregadas pueden aparecer en SELECT. Usar HAVING sin GROUP BY es válido pero menos común; aquí se enfoca en filtrar conjuntos de datos agrupados para reportes precisos.

## Ejemplo (no ejecutado automáticamente)
```sql
SELECT departamento, COUNT(*) como_empleados, AVG(sueldo) como_sueldo_promedio
FROM empleados
WHERE activo = true
GROUP BY departamento
HAVING COUNT(*) > 5 AND AVG(sueldo) > 40000
ORDER BY departamento ASC;
```

## Ejercicio
Crea una consulta SQL que agrupe ventas por mes y producto, calcule el total vendido y filtre solo aquellos grupos donde las ventas superen los 1000 euros y existan al menos 3 transacciones.

## Criterios de revisión
La consulta debe usar GROUP BY con dos columnas, incluir funciones agregadas correctas en SELECT, aplicar HAVING para filtrar los grupos basándose en el conteo y la suma, y no utilizar WHERE para condiciones de agregado.

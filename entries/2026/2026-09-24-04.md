## Objetivo
Aprender a clasificar errores por severidad y tipo utilizando códigos HTTP estándar para mejorar la legibilidad, automatizar el manejo de fallos en clientes y garantizar una experiencia de usuario coherente en aplicaciones modernas.

## Explicación
El diseño robusto de APIs comienza definiendo correctamente los códigos de estado HTTP. No basta con devolver un error genérico; cada respuesta debe reflejar la naturaleza del fallo. Utiliza 400 para errores de sintaxis o validación del cliente, como campos faltantes en una petición POST. Emplea 401 cuando falta autenticación y 403 si el usuario está autenticado pero carece de permisos. Para fallos del servidor interno, usa 500. Esta distinción permite que los clientes decidan si mostrar un mensaje amigable, solicitar reintentos o notificar al administrador. Una buena práctica es incluir un campo 'error' en el cuerpo JSON con una descripción clara y un código específico, evitando mensajes crípticos que confundan al desarrollador.

## Ejercicio
Crea una función en tu lenguaje preferido que simule una petición a una API. La función debe lanzar un error personalizado con el código HTTP correspondiente (400, 401 o 500) dependiendo de si los datos son inválidos, falta credenciales o ocurre un fallo interno.

## Criterios de revisión
El ejercicio debe incluir al menos dos casos de prueba: uno que valide correctamente la respuesta 401 y otro que maneje un error 500. La solución debe mostrar cómo capturar el código de estado en el bloque catch para diferenciar las acciones a tomar.

## Objetivo
Aprender a dividir las funciones de validación, transformación y persistencia dentro del código que interactúa con una base de datos para mejorar el mantenimiento y la seguridad.

## Explicación
En este módulo exploramos cómo aplicar la separación de responsabilidades específicamente en la capa de acceso a datos. En lugar de mezclar lógica de negocio con consultas SQL, creamos un repositório que se encarga exclusivamente de persistir información. La validación de reglas ocurre antes de llegar al repositorio, y la transformación de entidades se realiza mediante mapeadores dedicados. Este enfoque reduce el acoplamiento entre capas, facilita las pruebas unitarias del modelo de datos y permite cambiar de base de datos con menor impacto en la lógica de negocio.

## Ejemplo (no ejecutado automáticamente)
Un servicio que valida un usuario antes de insertarlo en la base de datos usando un repositório separado.

```javascript
class UserRepository {
  async save(user) {
    if (!user.email.includes('@')) throw new Error('Email invalido');
    await this.db.insert('users', user);
  }
}

const repo = new UserRepository();
await repo.save({ email: 'test@example.com' });
```

## Ejercicio
Crea una clase llamada ProductRepository que guarde productos en una base de datos ficticia. Asegúrate de que la validación de precios negativos ocurra antes de llamar al método de persistencia del repositorio.

## Criterios de revisión
El código debe tener un objeto separado para operaciones de escritura, validar el precio antes de guardar y lanzar una excepción si el valor es menor o igual a cero.

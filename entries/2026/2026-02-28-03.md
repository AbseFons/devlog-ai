## Objetivo
Aprender a identificar y fusionar manualmente cambios contradictorios en archivos locales, utilizando herramientas visuales para mantener la integridad del historial y evitar pérdida de datos durante la integración de ramas.

## Explicación
Cuando Git detecta un conflicto al realizar un merge o una pull request, marca las líneas afectadas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. El desarrollador debe editar el archivo para conservar ambas versiones lógicas. Se recomienda usar herramientas como VS Code o Meld para visualizar los bloques en disputa. Una vez resuelto, se guarda el archivo y se ejecuta 'git add' seguido de 'git commit' o 'git merge --continue' para finalizar la operación. Este proceso asegura que no se sobrescriba información crítica sin revisión humana.

## Ejemplo (no ejecutado automáticamente)
Archivo de configuración con conflicto entre dos desarrollores modificando el mismo parámetro

```bash
<<<<<<< HEAD
port = 8080
=======
port = 3000
>>>>>>> feature-api-v2
```

## Ejercicio
Crea un repositorio local con dos ramas. Modifica la misma línea en ambas ramas con valores distintos. Intenta unir las ramas y resuelve el conflicto manualmente editando el archivo resultante.

## Criterios de revisión
El archivo debe contener solo una versión válida del código, sin marcadores de conflicto. El historial de Git debe reflejar un commit de resolución claro.

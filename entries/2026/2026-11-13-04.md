## Objetivo
Distinguir claramente entre autenticación (quién eres) y autorización (qué puedes hacer), implementando un flujo seguro donde el token de acceso valida la identidad y los roles definen los permisos específicos para proteger recursos sensibles.

## Explicación
En las APIs modernas, la autenticación verifica la identidad del usuario mediante credenciales o tokens como JWT, mientras que la autorización determina qué operaciones puede ejecutar dicha identidad. Un error común es confundir ambos conceptos, lo que lleva a vulnerabilidades graves. Por ejemplo, un token válido no garantiza acceso total; los metadatos dentro del token (claims) deben incluir roles específicos. El servidor debe validar tanto la firma del token como las políticas de acceso basadas en esos roles antes de procesar cualquier solicitud crítica, asegurando el principio de mínimo privilegio desde el primer momento.

## Ejemplo (no ejecutado automáticamente)
Validación de token JWT y extracción de roles para aplicar reglas de autorización en una API REST.

```javascript
const token = 'eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...';
const payload = JSON.parse(atob(token.split('.')[1]));
if (payload.role === 'admin') { return res.json({ access: true }); }
else { return res.status(403).json({ error: 'No autorizado' }); }
```

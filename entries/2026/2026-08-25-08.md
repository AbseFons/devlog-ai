## Objetivo
Identificar el uso correcto de los códigos 201, 202 y 204 para manejar creación de recursos, aceptaciones asincrónicas y respuestas sin contenido en APIs RESTful modernas.

## Explicación
Los códigos 2xx indican éxito, pero cada uno tiene un propósito distinto. El 201 Created confirma que el recurso se creó tras una petición POST, devolviendo la ubicación del nuevo recurso. El 202 Accepted es crucial para operaciones costosas o asincrónicas; indica que la solicitud fue aceptada para procesamiento posterior, sin garantizar el resultado inmediato. Finalmente, el 204 No Content responde a peticiones exitosas como DELETE o PUT donde no hay cuerpo de respuesta útil. Usar estos códigos correctamente mejora la semántica de la API y permite a los clientes manejar flujos de trabajo complejos con mayor precisión.

## Ejemplo (no ejecutado automáticamente)
```python
import requests

# Caso: Creación de un usuario (POST)
response = requests.post('https://api.ejemplo.com/usuarios', json={'nombre': 'Ana'})
if response.status_code == 201:
    print(f'Recurso creado en: {response.headers.get("Location")}')

# Caso: Envío de reporte masivo (POST)
response = requests.post('https://api.ejemplo.com/reports', json={'tipo': 'anual'})
if response.status_code == 202:
    print('Solicitud aceptada para procesamiento asincrónico.')

# Caso: Eliminación de un registro (DELETE)
response = requests.delete('https://api.ejemplo.com/usuarios/123')
if response.status_code == 204:
    print('Registro eliminado exitosamente sin contenido.')
```

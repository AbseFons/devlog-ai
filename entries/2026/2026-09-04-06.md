## Objetivo
Distinguir cuándo usar merge para preservar historia compartida y cuándo usar rebase para mantener un lineal limpio en ramas de desarrollo personal.

## Explicación
Merge crea un nuevo commit de fusión que mantiene la topología histórica original, ideal para ramas públicas o colaborativas donde la evidencia del proceso es vital. Rebase reescribe la historia local moviendo commits, creando una línea temporal lineal; útil antes de push en ramas privadas. Merge es seguro y transparente; rebase requiere cuidado con conflictos y no debe usarse en repositorios compartidos sin consenso.

## Ejemplo (no ejecutado automáticamente)
Comandos para realizar un merge y luego un rebase entre dos ramas locales

```bash
git checkout feature
feature: add new functionality
git checkout main
git merge feature
git checkout feature
git rebase main
```

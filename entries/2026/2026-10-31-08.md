## Objetivo
Diferenciar entre las operaciones de actualización completa (PUT) y parcial (PATCH) en APIs RESTful, comprendiendo cuándo usar cada una para mantener la integridad de los datos.

## Explicación
En el tercer grupo de métodos HTTP, PUT y PATCH manejan actualizaciones de recursos. PUT reemplaza toda la representación del recurso; si envías un objeto incompleto, faltará información en el servidor. Es idóneo para sincronización total o creación idempotente. Por otro lado, PATCH aplica cambios parciales, enviando solo los campos modificados. Esto reduce el tráfico de red y evita sobrescribir datos no deseados. Ambos métodos son esenciales para arquitecturas modernas que requieren flexibilidad y eficiencia en la gestión de estado distribuido.

## Ejemplo (no ejecutado automáticamente)
Actualización parcial de un perfil de usuario enviando solo el campo 'email'.

```javascript
fetch('https://api.ejemplo.com/usuarios/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
})
```

## Ejercicio
Crea una petición POST a una API de tareas que use el método PATCH para cambiar el estado de una tarea específica de 'pendiente' a 'completada' sin modificar su descripción.

## Criterios de revisión
La respuesta debe devolver un código 200 OK con los datos actualizados; si se usa PUT en lugar de PATCH, la prueba fallará al no incluir campos opcionales.

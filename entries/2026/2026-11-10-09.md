## Objetivo
Aprender a estructurar aplicaciones separando la lógica de acceso a datos de la lógica de negocio, mejorando mantenibilidad y seguridad mediante el patrón de capas.

## Explicación
La separación de responsabilidades en el diseño de software implica dividir una aplicación en módulos con funciones únicas. En este caso, analizamos la arquitectura por capas: la capa de presentación maneja la interfaz, mientras que la capa de datos se encarga exclusivamente de las consultas y transacciones. Esto evita que la lógica de negocio dependa directamente de implementaciones específicas de bases de datos. Al encapsular el acceso a datos en un repositorio o DAO, podemos cambiar la fuente de datos sin afectar al resto del sistema. Este enfoque promueve pruebas unitarias más sencillas, ya que cada capa puede validarse aisladamente. Además, facilita la implementación de transacciones distribuidas y mejora la seguridad al restringir el acceso directo a las tablas desde el controlador.

## Ejemplo (no ejecutado automáticamente)
Implementación de una clase Repository en JavaScript que encapsula la lógica de consulta a una base de datos simulada, separándola del controlador.

```javascript
class UserRepository {
  async findAll() {
    const db = await import('./database');
    return db.users;
  }
}
```

## Criterios de revisión
El código debe mostrar claramente la abstracción del acceso a datos. Debe existir una interfaz o tipo definido para el repositorio. No debe haber referencias directas a tablas SQL dentro de la lógica de negocio.

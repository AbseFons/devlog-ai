## Objetivo
Comprender la estructura jerárquica de las pruebas de software, priorizando casos unitarios sobre integración y E2E para optimizar velocidad, costo y cobertura en el ciclo de desarrollo.

## Explicación
La pirámide de pruebas es un modelo arquitectónico que organiza los tipos de pruebas según su complejidad y alcance. La base amplia está compuesta por las pruebas unitarias, ejecutadas frecuentemente para validar lógica individual con alta velocidad y bajo costo. Sobre ellas se sitúan las pruebas de integración, que verifican la interacción entre módulos o servicios, detectando fallos de comunicación antes de llegar a la capa superior. Finalmente, en la cúspide estrecha, residen las pruebas de aceptación o end-to-end, críticas pero lentas y costosas. Este enfoque asegura que la mayoría de los errores se capturen temprano, reduciendo el riesgo de fallas en producción y facilitando refactoring seguro.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de código unitario en JavaScript usando Jest para probar una función matemática simple, representando la base de la pirámide.

```javascript
const sumar = (a, b) => a + b;

describe('Funcion Sumar', () => {
  test('Debe sumar dos numeros correctamente', () => {
    expect(sumar(2, 3)).toBe(5);
  });
});
```

## Ejercicio
Crea una función en Python que calcule el área de un círculo dado su radio. Luego, escribe tres casos de prueba unitarios: uno para un radio entero positivo, otro para un radio decimal y un tercero para validar que lance una excepción si el radio es negativo.

## Criterios de revisión
El código debe importar la librería unittest o pytest. Debe incluir al menos tres métodos de prueba distintos. Cada prueba debe verificar el resultado numérico con una tolerancia de error menor a 0.01 para los casos decimales y lanzar AssertionError para el caso negativo.

## Objetivo
Diferenciar claramente el comportamiento de merge y rebase al integrar ramas, entendiendo cómo cada uno afecta la historia del repositorio y cuándo aplicar cada estrategia para mantener un historial limpio o preservar contextos.

## Explicación
Merge crea un nuevo commit que fusiona dos líneas de desarrollo, preservando exactamente la topología original. Es seguro y transparente, ideal para ramas compartidas activamente. Rebase reescribe la historia local moviendo los commits de una rama sobre el final de otra, creando una línea lineal. Esto simplifica la lectura pero modifica el historial, por lo que debe usarse solo en trabajo local antes de pushear a ramas públicas.

## Ejemplo (no ejecutado automáticamente)
Comandos para realizar un rebase local de la rama feature sobre main antes de fusionar

```bash
git checkout feature
git rebase main
```

## Ejercicio
Clona un repositorio con dos ramas: 'main' y 'feature'. Haz tres commits en 'feature'. Luego, haz un commit en 'main'. Finalmente, ejecuta el rebase de 'feature' sobre 'main' y verifica que los commits ahora aparezcan secuencialmente.

## Criterios de revisión
El historial debe mostrar una línea lineal sin ramas divergentes visibles después del rebase. Los mensajes de commit deben mantener su contenido original pero con fechas actualizadas al momento del rebase.

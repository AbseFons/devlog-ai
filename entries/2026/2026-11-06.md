## Objetivo
Aprender a cancelar peticiones asíncronas en JavaScript para evitar bloqueos de la interfaz cuando una red es lenta o el usuario abandona la página, mejorando la experiencia de usuario.

## Explicación
Las peticiones fetch pueden colgar indefinidamente si el servidor tarda demasiado. Para solucionar esto, se utiliza AbortController junto con un signal. Este objeto permite detener una petición activa enviando una señal de cancelación. Al crear un nuevo controller y pasar su signal a fetch, cualquier interrupción del controlador (como llamar a abort()) lanzará un error específico en la promesa. Esto evita que el hilo principal se bloquee y permite limpiar recursos o mostrar mensajes de 'tiempo agotado' de forma elegante.

## Ejemplo (no ejecutado automáticamente)
Se crea una petición fetch a una URL pública de prueba con un límite de tiempo de 3 segundos. Si la respuesta no llega, el controlador aborta la solicitud automáticamente.

```javascript
const controller = new AbortController();
fetch('https://httpbin.org/delay/5', { signal: controller.signal })
```

## Ejercicio
Crea una función que realice un fetch a 'https://jsonplaceholder.typicode.com/posts/1' con un timeout de 2 segundos. Si la petición no se completa en ese tiempo, debe lanzar un error personalizado 'Tiempo agotado'.

## Criterios de revisión
El código debe importar o instanciar correctamente AbortController, pasar el signal a fetch y manejar el evento de error para distinguir entre fallos de red y cancelaciones por timeout.

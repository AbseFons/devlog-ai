## Objetivo
Aprender a aplicar roles y permisos mediante middleware en una API REST para proteger recursos críticos sin exponer lógica interna ni usar credenciales estáticas.

## Explicación
El Control de Acceso Basado en Roles (RBAC) permite restringir operaciones según la identidad del usuario. En esta microlección, implementaremos un middleware en Node.js que intercepta peticiones HTTP, verifica el rol extraído del encabezado 'X-Role' y compara contra una matriz de permisos definida. Si el rol no tiene autorización para la ruta solicitada, se responde con 403 Forbidden inmediatamente. Este enfoque centraliza la lógica de seguridad, evita fugas de información al no exponer detalles del servidor en errores y permite escalar políticas complejas sin modificar cada controlador individualmente.

## Ejemplo (no ejecutado automáticamente)
Middleware que valida roles para rutas protegidas usando una matriz de permisos simple.

```javascript
const permissions = { admin: ['GET', 'POST', 'DELETE'], user: ['GET'] };
app.use((req, res, next) => {
  const role = req.headers['x-role'];
  if (!permissions[role] || !permissions[role].includes(req.method)) {
    return res.status(403).json({ error: 'Acceso denegado' });
  }
  next();
});
```

## Ejercicio
Crea un servidor Express con dos rutas: /datos (GET) y /configurar (POST). Define roles 'analista' y 'admin'. Asegura que solo 'admin' pueda POST a /configurar y ambos puedan GET a /datos. Registra en consola el nombre del usuario autorizado cuando una petición sea exitosa.

## Criterios de revisión
El código debe incluir la definición de la matriz de permisos, el middleware de validación antes de los controladores, respuestas JSON con estado 403 para denegados y 200 para éxitos, y no debe contener credenciales ni lógica destructiva.

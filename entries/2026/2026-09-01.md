## Objetivo
El desarrollador aplicará SRP para separar la lógica de validación de datos de su persistencia, evitando acoplamientos innecesarios y facilitando pruebas unitarias aisladas en arquitecturas modulares.

## Explicación
El Principio de Responsabilidad Única establece que cada clase debe tener un solo motivo para cambiar. En la práctica, esto significa evitar mezclar responsabilidades como validar entrada y guardar datos en una misma función o clase. Al separar estas tareas, el código se vuelve más legible y mantenible. Si cambiamos cómo validamos los usuarios, no debemos tocar la lógica de base de datos. Este enfoque reduce el riesgo de errores al modificar el sistema y permite escalar componentes individualmente sin afectar toda la aplicación.

## Ejemplo (no ejecutado automáticamente)
```python
class Usuario:
    def __init__(self, nombre):
        self.nombre = nombre

class ValidadorUsuario:
    @staticmethod
    def es_valido(usuario):
        return len(usuario.nombre) > 0 and usuario.nombre.isalnum()

class RepositorioUsuario:
    def guardar(self, usuario):
        if not ValidadorUsuario.es_valido(usuario):
            raise ValueError("Nombre inválido")
        # Simulación de guardado en DB
        print(f"Guardando usuario: {usuario.nombre}")

usuario = Usuario("Ana")
repositorio = RepositorioUsuario()
repositorio.guardar(usuario)
```

## Ejercicio
Refactoriza una clase existente que maneje pedidos para extraer la validación de inventario en un módulo separado, asegurando que el método de persistencia solo reciba datos ya verificados.

## Criterios de revisión
El código debe tener dos clases distintas (Validador y Repositorio), no debe haber lógica de negocio mezclada con acceso a datos, y las pruebas unitarias deben poder fallar en la validación sin tocar la capa de persistencia.

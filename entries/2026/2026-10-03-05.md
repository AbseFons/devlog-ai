## Objetivo
Comprender el significado de los códigos de estado HTTP que comienzan con 2, específicamente 200, 201 y 204. Aprender cuándo usar cada uno en una API RESTful para indicar éxito, creación de recursos o respuestas sin contenido.

## Explicación
Los códigos 2xx indican que la solicitud fue recibida, entendida y procesada exitosamente. El código 200 OK es el estándar para respuestas exitosas donde el cuerpo contiene datos (como un JSON). El 201 Created se usa específicamente cuando una petición POST o PUT resulta en la creación de un nuevo recurso persistente; el encabezado Location debe indicar su URI. Por otro lado, el 204 No Content confirma que la acción se completó correctamente pero no devuelve ningún cuerpo de respuesta útil, común en operaciones de borrado (DELETE) o actualizaciones silenciosas. Elegir el código correcto es vital para que los clientes interpreten adecuadamente el estado del servidor y manejen la lógica de negocio sin errores.

## Ejemplo (no ejecutado automáticamente)
Respuesta exitosa a una petición POST que crea un nuevo usuario en una API ficticia, incluyendo el cuerpo JSON con los datos del recurso creado y el encabezado Location.

```javascript
fetch('https://api.ejemplo.com/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana', rol: 'admin' })
}).then(res => res.json());
```

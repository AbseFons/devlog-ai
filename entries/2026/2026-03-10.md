## Objetivo
Aprender a encapsular la lógica de negocio y el estado transaccional dentro de agregados para garantizar la integridad de los datos durante la publicación de eventos.

## Explicación
En el Diseño Orientado a Dominio, los eventos no son meros registros pasivos; son la consecuencia inmutable de una transacción exitosa. Para evitar inconsistencias, debemos encapsular la lógica que genera un evento dentro de un Agregado. Este objeto agrupa entidades relacionadas y sus reglas de negocio, asegurando que cualquier cambio de estado sea atómico. Solo cuando el agregado valida su integridad interna y persiste correctamente, se debe emitir el evento. Esto previene que datos corruptos o estados intermedios contaminen el log de eventos, manteniendo la trazabilidad fiel a los cambios reales del sistema.

## Ejemplo (no ejecutado automáticamente)
Un agregado de pedido valida el stock antes de crear un evento de 'PedidoCreado'.

```javascript
class Pedido {
  constructor(id, cliente) {
    this.id = id;
    this.cliente = cliente;
    this.items = [];
  }

  agregarItem(producto, cantidad) {
    if (producto.stock < cantidad) {
      throw new Error('Stock insuficiente');
    }
    this.items.push({ producto, cantidad });
    return this;
  }

  finalizar() {
    const evento = { tipo: 'PedidoCreado', pedidoId: this.id, fecha: new Date().toISOString() };
    // Aquí se persistiría el evento en un almacén de eventos
    return evento;
  }
}
const pedido = new Pedido(101, 'Ana');
pedido.agregarItem('Laptop', 2);
console.log(pedido.finalizar());
```

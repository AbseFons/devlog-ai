## Objetivo
Comprender cómo la base de datos decide ejecutar consultas y optimizar el rendimiento analizando los pasos lógicos y físicos que realizará el motor antes de devolver resultados al usuario.

## Explicación
El comando EXPLAIN revela el plan de ejecución generado por el optimizador del sistema. Este plan detalla las operaciones como escaneos de índices, uniones de tablas o filtrado de datos. Al analizarlo, identificamos cuellos de botella como lecturas secuenciales innecesarias en tablas grandes. Por ejemplo, si la consulta usa un índice compuesto pero el plan muestra un escaneo completo, debemos revisar la definición del índice o los patrones de acceso a datos. Esta herramienta es fundamental para transformar consultas lentas en operaciones eficientes sin modificar la lógica de negocio.

## Ejemplo (no ejecutado automáticamente)
Consulta que selecciona usuarios activos con ordenamiento por fecha y su plan de ejecución correspondiente.

```sql
EXPLAIN ANALYZE SELECT id, nombre, fecha_registro FROM usuarios WHERE estado = 'activo' ORDER BY fecha_registro DESC LIMIT 10;

-- El resultado mostrará si se usa el índice en fecha_registro y la operación de ordenamiento.
```

## Ejercicio
Crea una tabla con 50.000 registros, inserta datos aleatorios y ejecuta una consulta sin índices para observar el plan de escaneo completo.

## Criterios de revisión
El plan debe mostrar explícitamente la operación 'Seq Scan' en lugar de 'Index Scan' cuando no existen índices adecuados definidos.

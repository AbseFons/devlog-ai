## Objetivo
Aprender a crear etiquetas permanentes en Git para marcar versiones estables del proyecto, diferenciándolas de los commits temporales y facilitando la gestión de releases.

## Explicación
Las etiquetas (tags) en Git son marcadores inmutables que señalan un commit específico como una versión estable. A diferencia de las ramas, no se mueven con nuevos commits. Se usan comúnmente para releases semánticos (ej. v1.0.0). El comando 'git tag' crea la etiqueta; por defecto es ligera ('lightweight'), pero para releases oficiales se recomienda usar '--annotate' o '--signed', que añaden un commit de la etiqueta con mensaje y autor. Las etiquetas pueden ser anidadas en ramas, pero lo ideal es crearlas desde el branch principal actualizado. Para listarlas usa 'git tag'. Nunca borres etiquetas de versiones publicadas; en su lugar, crea nuevas versiones incrementales.

## Ejemplo (no ejecutado automáticamente)
Crear una etiqueta semántica v1.0.0 con mensaje y autor en el branch main

```bash
git tag -a v1.0.0 -m "Release inicial de la aplicación web"
git push origin v1.0.0
```

## Objetivo
Comprender la diferencia entre ramas principales, etiquetas ligeras y pesadas en Git para gestionar releases estables sin afectar el flujo de desarrollo activo.

## Explicación
Las etiquetas (tags) en Git son marcadores inmutables que identifican versiones específicas del historial. A diferencia de las ramas, que son punteros móviles, una etiqueta fija apunta a un commit concreto, ideal para releases como v1.0. Existen dos tipos: etiquetas ligeras, que son simplemente nombres de ramas apuntando a un commit, y etiquetas pesadas, que contienen metadatos adicionales. Para crear una etiqueta ligera se usa 'git tag -a' con nombre y mensaje, mientras que 'git tag' crea una ligera por defecto. Es crucial usar '-a' para anotarlas con autor y fecha, facilitando el seguimiento futuro. Las etiquetas se empujan a otros repositorios con '--push'. Este control permite a los equipos mantener un historial claro de versiones sin comprometer la rama principal.

## Ejemplo (no ejecutado automáticamente)
Creación de una etiqueta anotada para la versión 1.0 y verificación en el local.

```bash
git tag -a v1.0 -m "Release inicial con autenticacion"
git show v1.0
```

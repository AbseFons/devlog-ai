## Objetivo
Aprender a estructurar mensajes de commit usando la convención estándar para mejorar la legibilidad del historial, facilitar las release notes automáticas y mantener un registro profesional de los cambios en el código fuente.

## Explicación
La convención de commits estandariza el formato de cada mensaje. El primer tipo es 'feat', que indica una nueva característica visible para el usuario final. La estructura básica es 'tipo(scope): descripción'. Por ejemplo, 'feat(auth): agregar login con Google'. Esto permite a las herramientas CI/CD generar automáticamente los changelogs. Es crucial mantener la primera línea corta (menos de 72 caracteres) y usar el presente simple ('agrega' en vez de 'agregó'). Un buen commit debe explicar el qué y el porqué, no solo el cómo. Evita incluir referencias a issues cerrados en el cuerpo si no son necesarias para el contexto inmediato. Esta disciplina reduce la fricción durante las code reviews y hace que el historial sea una documentación viva del proyecto.

## Ejemplo (no ejecutado automáticamente)
Ejecución de un commit con formato correcto usando git add y git commit

```bash
git add src/auth/login.js
git commit -m "feat(auth): implementar botón de inicio de sesión con OAuth"
```

## Ejercicio
Crea un archivo llamado 'utils/dateHelper.js' que contenga una función para formatear fechas. Luego, haz un commit siguiendo la convención para este nuevo utilitario.

## Criterios de revisión
El mensaje debe comenzar con 'feat(utils):', incluir el nombre del archivo modificado en el cuerpo si es necesario y no exceder los 72 caracteres en la primera línea.

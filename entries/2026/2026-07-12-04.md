## Objetivo
Distinguir conceptualmente entre merge y rebase en Git, entendiendo cómo cada comando afecta la historia del proyecto y cuándo es preferible usar uno u otro para mantener un historial limpio o preservar ramas paralelas.

## Explicación
Merge crea un nuevo commit de fusión que une dos líneas de desarrollo, preservando fielmente la cronología real de los cambios. Rebase reescribe el historial moviendo commits de una rama sobre otra, resultando en una línea lineal y limpia. Usa merge para fusionar ramas críticas o cuando la historia debe ser inmutable. Usa rebase para preparar contribuciones locales antes de enviarlas a un repositorio compartido, siempre con precaución.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un merge y luego un rebase en una rama local

```bash
git checkout feature
feature: some changes
git checkout main
git merge feature
git checkout feature
git rebase main
```

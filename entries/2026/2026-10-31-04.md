## Objetivo
Implementar un hook pre-commit en Bash para bloquear la subida de archivos obsoletos o sin cambios, asegurando que el repositorio solo contenga código relevante y limpio antes de cada commit.

## Explicación
Los hooks de Git son scripts que se ejecutan automáticamente en momentos específicos del flujo de trabajo. En esta lección, configuraremos un hook 'pre-commit' utilizando Bash. Este script revisará los archivos modificados en el área de preparación (staged area). Si detecta archivos con extensión .log o .tmp, abortará el commit y mostrará un mensaje claro indicando qué archivos deben eliminarse primero. Esto previene la contaminación del historial con datos temporales. La configuración se realiza editando el archivo .git/hooks/pre-commit en el repositorio local.

## Ejemplo (no ejecutado automáticamente)
Script Bash que verifica si existen archivos de log o temporal en los cambios y detiene el commit si es así.

```bash
# Obtener lista de archivos modificados
modified_files=$(git diff --cached --name-only)
# Verificar extensiones no deseadas
for file in $modified_files; do
  if [[ "$file" == *.log || "$file" == *.tmp ]]; then
    echo "Error: No se permiten archivos $file en el commit."
    exit 1
  fi
done
```

## Ejercicio
Crea un archivo de texto llamado 'test.log' con contenido falso, hazlo git add y luego intenta hacer un commit para observar la interrupción del hook.

## Criterios de revisión
El script debe detener el commit si hay archivos .log o .tmp. El mensaje de error debe ser claro. No se deben usar comandos que borren datos permanentemente.

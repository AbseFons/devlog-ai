## Objetivo
Aprender a aislar el desarrollo de nuevas funcionalidades en ramas independientes para mantener el código base estable, facilitando la revisión por pares antes de fusionar cambios.

## Explicación
En ingeniería de software moderna, nunca se debe escribir código directamente en la rama principal (main o master). La estrategia estándar implica crear una rama de característica desde un punto de referencia estable. Esto permite trabajar sin bloquear a otros desarrolladores y garantiza que el historial del proyecto sea limpio. Una vez completada la tarea, se realiza una Pull Request para solicitar la integración. Este proceso obliga a revisar los cambios, ejecutar pruebas automáticas y discutir posibles mejoras antes de afectar la rama principal. Es fundamental usar mensajes de commit claros y pequeños para facilitar esta revisión.

## Ejemplo (no ejecutado automáticamente)
Crear una rama llamada feature-nueva-login desde main, realizar un cambio en el archivo de autenticación y preparar la solicitud de fusión.

```bash
git checkout -b feature-nueva-login
git add src/auth/login.js
```

## Ejercicio
Crea una rama llamada 'fix-bug-calculadora', haz un commit con el mensaje 'Reparar división por cero' y luego ejecuta 'git push origin fix-bug-calculadora'.

## Criterios de revisión
El usuario debe crear la rama correctamente, realizar el commit con el mensaje exacto solicitado y empujar la rama al remoto sin errores.

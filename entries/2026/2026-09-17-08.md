## Objetivo
Comprender cómo diseñar casos de prueba que cubran no solo el camino feliz, sino también los límites exactos de los datos de entrada para prevenir fallos en producción por valores extremos o inesperados.

## Explicación
La cobertura de límites es crítica porque muchos errores ocurren justo en los bordes de las especificaciones. Un campo que acepta números del 1 al 100 debe probarse con 0, 1, 99 y 100, no solo con 50. Este enfoque asegura que la lógica interna maneje correctamente condiciones extremas sin colapsar. Ignorar estos casos deja vulnerables a aplicaciones ante entradas malformadas o valores máximos de base de datos.

## Ejemplo (no ejecutado automáticamente)
Script en Python que valida si un número está dentro del rango permitido [1, 100], probando explícitamente los límites inferior y superior junto con valores fuera de rango.

```python
def validar_rango(n):
    return 1 <= n <= 100

assert validar_rango(1) == True
assert validar_rango(100) == True
assert validar_rango(0) == False
```

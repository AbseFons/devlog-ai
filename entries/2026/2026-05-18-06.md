## Objetivo
Aprender a crear etiquetas semánticas para marcar hitos estables en el historial del repositorio, facilitando la distribución de versiones sin alterar el flujo de trabajo principal.

## Explicación
Las etiquetas (tags) en Git son marcadores inmutables que identifican puntos específicos del historial, típicamente usados para releases. A diferencia de las ramas, una etiqueta no se mueve y apunta a un commit concreto. Se recomienda usar el formato SemVer (ej: v1.0.0). El comando 'git tag' crea la referencia local; añadir '-a' permite crearla directamente en remoto con un mensaje. Esto es crucial para que los usuarios descarguen versiones estables sin necesidad de saber qué rama específica contiene el código final, asegurando consistencia entre desarrollo y producción.

## Ejemplo (no ejecutado automáticamente)
Creación de una etiqueta v1.0.0 en la rama principal con mensaje descriptivo y push a remoto.

```bash
git tag -a v1.0.0 -m "Primera versión estable lanzada"
git push origin main --tags
```

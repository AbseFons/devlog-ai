## Objetivo
Comprender la distinción funcional entre mocks y stubs en pruebas unitarias, identificando cuándo usar cada uno para aislar dependencias externas sin comprometer la integridad del código bajo prueba.

## Explicación
En ingeniería de software, los stubs son respuestas predefinidas que simulan el comportamiento de una dependencia externa, permitiendo ejecutar lógica compleja sin invocar servicios reales. Por otro lado, los mocks verifican no solo el resultado, sino también las interacciones: qué métodos se llamaron, con qué argumentos y cuántas veces. Mientras un stub devuelve datos estáticos para evitar llamadas a base de datos, un mock puede validar que una función específica fue invocada correctamente antes de fallar. Usar stubs es ideal cuando solo necesitas datos de entrada controlados; los mocks son esenciales para asegurar contratos de integración estrictos.

## Ejemplo (no ejecutado automáticamente)
Un stub en JavaScript que devuelve un valor fijo evitando una llamada a API externa, permitiendo probar la lógica de negocio sin red.

```javascript
const apiStub = {
  fetch: () => Promise.resolve({ data: 'respuesta_fija' })
};
```

## Ejercicio
Crea una función que reciba un objeto API como dependencia. Implementa dos versiones de la prueba: una usando un stub que siempre devuelve éxito y otra usando un mock que valida si se llamó a la API antes de procesar el error.

## Criterios de revisión
El código debe diferenciar claramente entre devolver datos simulados (stub) y verificar interacciones (mock). Debe incluir al menos dos casos de prueba distintos. No debe realizar llamadas reales a servicios externos.

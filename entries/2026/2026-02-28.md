## Objetivo
Establecer una convención clara para organizar el código fuente en un repositorio, separando lógica de negocio, configuración y dependencias para facilitar el mantenimiento y la escalabilidad del proyecto.

## Explicación
Un diseño de repositorio sólido comienza con una estructura de carpetas predecible. Se recomienda ubicar la lógica de aplicación principal en 'src', mientras que las pruebas unitarias e integración residen en 'tests'. La carpeta 'config' debe alojar archivos de entorno específicos, nunca valores sensibles en el control de versiones. Las dependencias van a 'node_modules' o equivalentes, excluidas del commit mediante '.gitignore'. Esta separación permite que los desarrolladores naveguen intuitivamente y que las herramientas de CI/CD identifiquen rápidamente qué cambiar al actualizar librerías o ejecutar pruebas.

## Ejemplo (no ejecutado automáticamente)
Estructura de directorios típica para una aplicación web moderna con separación clara entre código, pruebas y configuración.

```bash
mkdir -p src/{controllers,services} tests/{unit,integration} config envs
mv .env.example config/
mv package.json node_modules/ .gitignore/
```

## Ejercicio
Crea una estructura de directorios para un nuevo proyecto en tu máquina local siguiendo la convención descrita, asegurándote de incluir carpetas para controladores, servicios y pruebas.

## Criterios de revisión
El repositorio debe contener al menos tres niveles de profundidad (src, tests, config) y los archivos de entorno deben estar excluidos del historial de commits.

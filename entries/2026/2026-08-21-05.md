## Objetivo
Al finalizar esta lección, podrás utilizar Common Table Expressions (CTEs) para encapsular lógica compleja de filtrado y agregación temporal, permitiendo consultas más legibles sobre series de datos históricos sin necesidad de variables externas ni subconsultas anidadas excesivas.

## Explicación
Las Common Table Expressions (CTEs) permiten definir conjuntos de datos temporales que existen solo durante la ejecución de una consulta específica. En el contexto de análisis temporal, son ideales para aislar periodos de interés, como un mes fiscal o un rango de fechas de incidentes, antes de aplicar agregaciones finales. Esto mejora la legibilidad al separar la lógica de filtrado del tiempo de la lógica de negocio principal. A diferencia de las subconsultas anidadas, los CTEs se leen de arriba a abajo, facilitando el mantenimiento en proyectos con grandes volúmenes de datos históricos.

## Ejemplo (no ejecutado automáticamente)
```sql
WITH periodo_crisis AS (
    SELECT fecha, tipo_incidente
    FROM registros_incidentes
    WHERE fecha BETWEEN '2025-01-01' AND '2025-03-31'
    AND severidad >= 8
)
SELECT 
    COUNT(*) como total_incidentes,
    AVG(severidad) como promedio_severidad
FROM periodo_crisis;
```

## Ejercicio
Crea una CTE que filtre las ventas de un catálogo específico en el último trimestre y luego, en la consulta principal, calcule el porcentaje de crecimiento interanual comparando este volumen con el del mismo trimestre del año anterior.

## Criterios de revisión
La solución debe usar exactamente una CTE definida con la cláusula WITH. La consulta final no puede contener subconsultas anidadas dentro de SELECT o WHERE. El resultado debe incluir dos columnas numéricas: 'volumen_actual' y 'porcentaje_crecimiento'. Si el volumen del año anterior es cero, el porcentaje debe ser null.

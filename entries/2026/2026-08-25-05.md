## Objetivo
Al finalizar esta lección, el desarrollador podrá identificar las capas fundamentales de una aplicación y redactar un módulo que encapsule la lógica de negocio sin depender directamente de la capa de acceso a datos, garantizando mantenibilidad y pruebas unitarias aisladas.

## Explicación
El diseño por capas organiza el sistema en niveles con responsabilidades distintas: presentación, lógica de negocio y persistencia. Esta separación evita acoplamiento directo entre interfaces de usuario y bases de datos. La capa de negocio orquesta las reglas de validación y transformación de datos, mientras que la capa de acceso a datos se encarga exclusivamente de la comunicación con el almacén. Implementar esta estructura permite escalar componentes individualmente y facilita la sustitución de tecnologías subyacentes sin afectar la lógica central. En este primer módulo, nos enfocaremos en definir los contratos de interfaz entre capas para establecer una base sólida antes de implementar detalles técnicos específicos.

## Ejemplo (no ejecutado automáticamente)
```python
class UsuarioModelo:
    def __init__(self, id_usuario, nombre):
        self.id = id_usuario
        self.nombre = nombre

class ServicioUsuario:
    def obtener_usuario(self, id_usuario):
        # Simula llamada a base de datos sin exponerla directamente
        return UsuarioModelo(id_usuario, f'Usuario_{id_usuario}')

class ControladorUsuario:
    def __init__(self, servicio_usuarios):
        self.servicio = servicio_usuarios

    def cargar(self, id_usuario):
        # Lógica de negocio: validación y enriquecimiento
        if id_usuario < 0:
            raise ValueError("ID inválido")
        usuario = self.servicio.obtener_usuario(id_usuario)
        return {"id": usuario.id, "nombre": usuario.nombre}
```

## Objetivo
Aprender a utilizar el comando git cherry-pick para aplicar manualmente un commit específico desde otra rama o repositorio, manteniendo la integridad del historial actual sin fusionar ramas enteras.

## Explicación
El comando git cherry-pick permite seleccionar y aplicar uno o más commits individuales de una referencia existente (como una rama remota o un commit SHA) a tu rama actual. Esto es útil cuando necesitas replicar cambios específicos, como arreglos de seguridad o características puntuales, sin traer el historial completo ni las posibles dependencias no deseadas de la rama origen. El proceso crea nuevos commits con el mismo contenido pero en una nueva ubicación del historial. Es fundamental verificar los mensajes de commit y asegurarse de que el contexto sea compatible para evitar conflictos innecesarios.

## Ejemplo (no ejecutado automáticamente)
Aplicar un commit específico desde la rama feature-auth a la rama principal usando su identificador SHA.

```bash
git cherry-pick abc1234567890
# Verificar el resultado con git log --oneline
```

## Ejercicio
En un entorno de pruebas, selecciona y aplica el último commit de la rama 'hotfix-critical' a tu rama actual. Después, verifica que el mensaje del nuevo commit coincida con el original.

## Criterios de revisión
El usuario debe ejecutar correctamente el comando cherry-pick sin errores de sintaxis, identificar el SHA correcto del commit origen y confirmar visualmente la aparición del nuevo commit en el historial local.

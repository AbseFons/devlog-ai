## Objetivo
Distinguir cuándo usar merge para preservar ramas paralelas y cuándo aplicar rebase para crear una línea de desarrollo limpia y secuencial en flujos de trabajo colaborativos.

## Explicación
Merge crea un nuevo commit que fusiona dos historias, manteniendo la estructura ramificada original. Rebase reescribe la historia moviendo los commits de una rama sobre el final de otra, resultando en una línea cronológica única. Usa merge para puntos de integración estables o ramas de hotfix. Usa rebase para preparar tu rama local antes de enviarla a un repositorio remoto compartido, asegurando que el historial sea lineal y fácil de leer.

## Ejemplo (no ejecutado automáticamente)
```python
# Simulacion de flujo de trabajo Git en terminal
$ git checkout feature-nueva-funcionalidad
$ echo 'Lógica A' > main.py
$ git add .
$ git commit -m 'Añadir lógica A'
$ git checkout main
$ git pull origin main
$ git checkout feature-nueva-funcionalidad
$ # Opción 1: Merge (crea nodo de fusión)
# $ git merge main
$ # Opción 2: Rebase (reordena commits linealmente)
$ git rebase main
$ echo 'Lógica B' >> main.py
$ git add .
$ git commit -m 'Añadir lógica B'
$ git push origin feature-nueva-funcionalidad --force-with-lease
```

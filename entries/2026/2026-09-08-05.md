## Objetivo
Aprender a estructurar mensajes de commit legibles usando tipos estándar como 'feat' para nuevas funcionalidades y 'fix' para correcciones, facilitando el seguimiento del historial del proyecto mediante herramientas automáticas.

## Explicación
La convención de commits estandariza la comunicación en repositorios Git. Cada mensaje debe comenzar con un tipo que define la naturaleza del cambio: 'feat' indica una nueva característica visible al usuario, mientras que 'fix' reporta una corrección de errores. Esto permite generar automáticamente changelogs y entender rápidamente la evolución del código sin leer cada archivo modificado. El formato suele incluir el cuerpo opcional para detalles técnicos y un pie para referencias o notas de cierre. Adoptar esta práctica mejora la colaboración en equipos grandes y automatiza reportes de estado.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de script bash que ejecuta dos commits consecutivos siguiendo la convención: uno para agregar una función de saludo y otro para corregir un bug en el cálculo del total.

```bash
# Agregar nueva funcionalidad
# git add src/saludar.py
git commit -m "feat: implementar funcion de saludo en consola"

# Corregir error de calculo
# git add src/calculadora.py
git commit -m "fix: corregir bug en suma de valores negativos"
```

## Ejercicio
Crea un repositorio local. Modifica un archivo para agregar una nueva función y haz un commit con el prefijo 'feat'. Luego, introduce un error intencional en otro archivo y corrígelo inmediatamente con un commit que use el prefijo 'fix'.

## Criterios de revisión
El historial debe mostrar exactamente dos commits. El primero debe contener la palabra clave 'feat' seguida de una descripción breve de la nueva función. El segundo debe contener 'fix' seguido de la descripción del error corregido. Ambos mensajes deben estar en inglés o español, pero sin usar mayúsculas iniciales innecesarias en el tipo.

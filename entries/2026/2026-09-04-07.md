## Objetivo
Aprender a identificar y resolver manualmente conflictos de archivos durante una operación de merge, asegurando la integridad del código antes de confirmar la integración.

## Explicación
Cuando Git detecta un conflicto, deja marcadores '<<<<<<<', '=======', y '>>>>>>>' en el archivo. El desarrollador debe editar el archivo para conservar solo el código válido, eliminando los marcadores. Una vez resuelto, se ejecuta 'git add <archivo>' para marcarlo como resuelto. Finalmente, 'git commit' finaliza la operación. Este proceso manual es crucial cuando las diferencias lógicas entre ramas no son simples adiciones de líneas.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de resolución de conflicto en un archivo de configuración de servidor web donde dos desarrolladores modificaron el mismo puerto.

```bash
# Edita el archivo para eliminar los marcadores de conflicto
<<<<<<< HEAD
server_port = 8080
=======
server_port = 9000
>>>>>>> feature-secure
# Guarda solo la configuración correcta y elimina los marcadores
```

## Ejercicio
Crea dos ramas en un repositorio local. Modifica el mismo archivo de texto en ambas ramas con contenido diferente. Intenta hacer merge y resuelve el conflicto manualmente editando el archivo.

## Criterios de revisión
El archivo debe estar libre de marcadores de conflicto, contener la lógica correcta del negocio y no haberse perdido ninguna modificación válida antes de confirmar el commit.

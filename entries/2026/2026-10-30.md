## Objetivo
Aprender a estructurar mensajes de commit legibles mediante el formato convencional, facilitando la generación automática de cambios y mejorando la trazabilidad del historial en repositorios Git.

## Explicación
El formato de commits convencionales propone una estructura estándar para los mensajes: tipo (feat, fix, docs), alcance opcional y descripción detallada. Esto permite a las herramientas CI/CD detectar automáticamente nuevas funcionalidades o correcciones. La sintaxis básica incluye un resumen en la primera línea seguido por detalles adicionales separados por una línea vacía. Al seguir esta convención, el equipo mantiene un registro coherente que simplifica las releases semánticas y la documentación automática.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de commit para añadir una nueva funcionalidad de autenticación en una aplicación web.

```bash
git commit -m "feat(auth): implementar login con JWT y refresh tokens"

- Se añade middleware de validación de tokens.
- Se actualiza el archivo de rutas de autenticación.
```

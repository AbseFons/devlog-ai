## Objetivo
Comprender la lógica del algoritmo Token Bucket para controlar el tráfico API, evitando saturación de servidores y garantizando equidad entre clientes mediante una implementación práctica en Node.js.

## Explicación
El rate limiting protege los servicios backend de picos de tráfico excesivos. El algoritmo Token Bucket permite ráfagas controladas: un 'bucket' almacena tokens que se generan a una tasa fija (ej. 10 tokens/segundo). Cada petición consume un token; si no hay suficientes, la petición se rechaza con HTTP 429 Too Many Requests. Esto diferencia el rate limiting por IP de otros métodos como sliding window, permitiendo breves picos legítimos mientras mantiene un límite promedio estricto. Es fundamental para APIs públicas que deben ser justas y resilientes ante ataques DDoS simples o errores de cliente.

## Ejemplo (no ejecutado automáticamente)
Script en Node.js que simula un servidor API con lógica de Token Bucket, generando tokens cada segundo y rechazando peticiones sin token disponible.

```javascript
const rateLimiter = {
  tokens: 10,
  maxTokens: 10,
  refillRate: 10
};
function checkLimit() {
  if (rateLimiter.tokens > 0) {
    rateLimiter.tokens--;
    return true;
  }
  return false;
}
```

## Objetivo
Comprender la importancia de las pruebas de integración para verificar que los componentes del sistema interactúan correctamente, detectando fallos en la comunicación entre módulos o servicios externos antes del despliegue.

## Explicación
Las pruebas de integración evalúan el comportamiento del sistema cuando múltiples unidades funcionales trabajan juntas. A diferencia de las pruebas unitarias, aquí nos enfocamos en las interfaces y los datos que fluyen entre ellas. Un caso común es validar un flujo de compra: desde la selección del producto hasta la confirmación del pago con una pasarela externa. Si el servicio de inventario no actualiza correctamente al finalizar la transacción, esta falla solo se detectará en integración. Es crucial simular respuestas de servicios externos (como APIs de pagos) para evitar dependencias reales durante el desarrollo.

## Ejemplo (no ejecutado automáticamente)
Script que simula una transacción de compra verificando la actualización del inventario y el estado del pedido en un entorno aislado.

```javascript
const mockInventory = { id: 101, stock: 5 };
const mockOrderService = { placeOrder: (qty) => qty > mockInventory.stock ? 'fail' : 'success' };
const result = mockOrderService.placeOrder(3);
console.log(result === 'success' ? 'Inventario actualizado correctamente' : 'Error en integración');
```

## Ejercicio
Crea un script que simule una llamada a una API de envío. Define un objeto con el estado del servicio de logística y verifica si el pedido se marca como 'enviado' solo cuando la API responde con éxito.

## Criterios de revisión
El código debe incluir al menos dos objetos simulados (pedido y servicio), una función que verifique la respuesta lógica y un mensaje de consola que indique si la integración falló o tuvo éxito.

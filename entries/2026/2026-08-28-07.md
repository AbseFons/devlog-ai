## Objetivo
Al finalizar, el desarrollador identificará cómo la selectividad de una consulta afecta al uso de índices B-Tree y evitará patrones comunes como buscar valores NULL o usar funciones sobre columnas indexadas que fuerzan un escaneo completo de tabla.

## Explicación
Los índices B-Tree son eficientes para rangos y valores exactos, pero fallan si buscas NULL o aplicas funciones a la columna indexada. La selectividad mide qué fracción de filas cumple una condición; baja selectividad (ej. 'activo' en tablas grandes) suele ignorar el índice. Para consultas eficientes, asegúrate de que las columnas indexadas contengan valores únicos o altamente distintivos. Evita cálculos en WHERE antes de comparar con el índice. Usa índices compuestos ordenando por la columna más selectiva primero. Esto reduce drásticamente los I/O y mejora el rendimiento sin sacrificar integridad.

## Ejemplo (no ejecutado automáticamente)
```sql
-- Mal: Función sobre columna indexada impide uso del índice
SELECT * FROM usuarios WHERE UPPER(nombre) = 'JOSE';

-- Bien: Comparación directa permite usar el índice B-Tree
SELECT id, nombre, email FROM usuarios WHERE nombre = 'Jose';

-- Mal: Buscar NULL en índice B-Tree estándar es ineficiente
SELECT * FROM pedidos WHERE cantidad = NULL;

-- Bien: Usar índices especiales o lógica alternativa para NULL
SELECT id FROM pedidos WHERE cantidad IS NOT NULL AND cantidad > 10;
```

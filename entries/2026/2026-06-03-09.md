## Objetivo
Aprender a dividir las tareas de captura, validación y presentación de datos para mejorar la mantenibilidad del código y evitar que una sola función haga demasiado trabajo.

## Explicación
El principio de separación de responsabilidades dicta que cada módulo debe tener un único propósito claro. En el contexto de formularios web, esto significa desacoplar la lógica de negocio (reglas de validación) de la interfaz de usuario (manejo del DOM). Si mezclamos ambas, cualquier cambio en las reglas rompe la vista y viceversa. Al crear una función dedicada exclusivamente a validar los datos entrantes, garantizamos que el código sea más legible y testeable. Esta práctica permite reutilizar la lógica de validación en diferentes contextos sin duplicar código ni introducir errores sutiles al modificar la presentación.

## Ejemplo (no ejecutado automáticamente)
Función pura que valida un correo electrónico antes de procesarlo, separando la regla de negocio del manejo del evento del usuario.

```javascript
function esCorreoValido(texto) {
  const patron = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return patron.test(texto);
}
```

## Ejercicio
Crea una función 'esEdadValida' que acepte un número entero y devuelva true si es mayor o igual a 18, false en caso contrario. Luego, escribe un bloque de código que use esta función para mostrar un mensaje de alerta solo cuando el usuario ingrese una edad inválida.

## Criterios de revisión
El código debe contener exactamente dos funciones: la de validación y la de ejecución. La función de validación no debe depender del DOM ni de eventos. El mensaje de alerta debe ejecutarse únicamente si la función devuelve false.

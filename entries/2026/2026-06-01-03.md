## Objetivo
Aprender a dividir las tareas entre controladores y vistas para mantener el código limpio, escalable y fácil de probar, evitando que una sola clase maneje toda la lógica de la interfaz.

## Explicación
En el diseño de software moderno, la separación de responsabilidades es clave. Un patrón común es dividir la lógica de negocio de la capa de presentación. Los controladores (Controllers) deben encargarse únicamente de recibir peticiones, validar datos básicos y decidir qué vista mostrar o qué servicio llamar. Las vistas (Views) se limitan a renderizar el HTML o JSON sin contener lógica compleja. Si mezclamos ambas funciones, el código se vuelve difícil de mantener. Por ejemplo, en una aplicación web, el controlador procesa la entrada del usuario y llama a un servicio de datos, mientras que la plantilla solo muestra los resultados recibidos. Esta división permite probar cada componente por separado y facilita la reutilización de componentes.

## Ejemplo (no ejecutado automáticamente)
Un controlador simple en JavaScript que delega el renderizado a una función de vista externa, sin incluir lógica de marcado dentro del controlador.

```javascript
function mostrarUsuario(usuario) {
  const plantilla = require('./vistas/usuario.html');
  return plantilla.render({ nombre: usuario.nombre });
}
```

## Ejercicio
Crea un archivo 'controlador.js' que reciba un objeto de datos y llame a una función 'renderizar()' definida en otro archivo. Luego, crea 'vista.js' con la función 'renderizar()' que devuelva una cadena HTML simple usando los datos pasados.

## Criterios de revisión
El controlador no debe contener ninguna etiqueta HTML ni lógica de bucles para iterar sobre datos. La vista debe ser un módulo independiente importado por el controlador. El código debe compilar sin errores y la salida del controlador debe ser puramente el resultado de la vista.

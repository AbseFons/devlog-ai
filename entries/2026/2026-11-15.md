## Objetivo
Aprender a aislar componentes bajo prueba simulando dependencias externas como bases de datos o APIs, asegurando que las pruebas sean rápidas y deterministas sin necesidad de infraestructura real.

## Explicación
En la segunda parte de esta serie sobre unittest, profundizamos en el uso de la biblioteca estándar unittest.mock. Esta herramienta permite crear objetos falsos (mocks) que imitan el comportamiento de dependencias externas. Al usar patching con @patch o mock.patch, podemos reemplazar una clase real por un objeto simulado antes de ejecutar la prueba. Esto es crucial para evitar tiempos de espera en llamadas a APIs o consultas a bases de datos durante el desarrollo. El enfoque garantiza que la lógica del sistema bajo prueba se evalúe en aislamiento, haciendo las pruebas más rápidas y confiables.

## Ejemplo (no ejecutado automáticamente)
Simulamos una llamada a una API externa para evitar dependencias reales en la prueba.

```python
from unittest.mock import patch

@patch('mymodule.fetch_data')
def test_fetch(mock_func):
    mock_func.return_value = {'status': 'ok'}
```

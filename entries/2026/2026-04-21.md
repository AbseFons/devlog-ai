## Objetivo
Comprender la diferencia entre cobertura de código y límites funcionales, estableciendo una base sólida para diseñar casos de prueba que validen no solo el flujo normal, sino también los bordes del sistema.

## Explicación
La cobertura de código mide qué porcentaje del código fuente se ejecuta durante las pruebas, pero un alto porcentaje no garantiza la calidad. Los límites son valores críticos donde el comportamiento del sistema puede cambiar drásticamente, como máximos, mínimos o estados de error. Un buen plan de testing debe ir más allá de los casos felices y enfocarse en estos bordes para detectar fugas de memoria, desbordamientos o fallos de seguridad. Ignorar los límites suele ser la causa principal de errores en producción.

## Ejemplo (no ejecutado automáticamente)
Función que valida un rango de edad permitiendo solo valores entre 18 y 65 años.

```javascript
function validarEdad(edad) {
  if (edad < 18 || edad > 65) return false;
  return true;
}
```

## Criterios de revisión
El sistema debe devolver false para valores menores a 18 o mayores a 65, y true para cualquier valor dentro del rango inclusivo [18, 65]. Los casos de prueba deben cubrir explícitamente los puntos de entrada y salida del rango.

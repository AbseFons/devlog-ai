## Objetivo
Comprender la función básica de los hooks en Git, específicamente el pre-commit, para automatizar tareas de validación antes de cada commit y mantener un historial limpio.

## Explicación
Los hooks son scripts que Git ejecuta automáticamente en eventos específicos del ciclo de vida. El hook 'pre-commit' se dispara justo antes de crear un nuevo commit. Es ideal para ejecutar linters, formateadores o verificaciones de seguridad. Si el script devuelve un código de error no cero, Git abortará el commit. Esto previene que código sucio o inseguro entre al repositorio. En esta lección aprenderás a configurar tu primer hook simple en Bash para validar la extensión de los archivos.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que verifica si todos los archivos nuevos tienen una extensión válida antes de permitir el commit.

```bash
#!/bin/bash
# Lista archivos no rastreados y filtra por extensiones invalidas
if git diff --cached --name-only | grep -vE '\.(js|py|sh)$' > /dev/null; then
  echo 'Error: Archivos sin extension valida detectados.'
  exit 1
fi
```

## Ejercicio
Crea un archivo llamado .git/hooks/pre-commit en tu repositorio local. Copia el código del ejemplo dentro de él, asegúrate de que sea ejecutable con chmod +x y prueba a intentar agregar archivos sin extensión para ver cómo se bloquea el commit.

## Criterios de revisión
El hook debe existir en la carpeta .git/hooks/, ser ejecutable y detener el commit si se detectan archivos sin las extensiones permitidas.

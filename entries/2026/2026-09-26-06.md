## Objetivo
Aprender a aplicar cherry-pick para integrar commits específicos de una rama de desarrollo a producción sin fusionar todo el historial, manteniendo la estabilidad y controlando cambios individuales.

## Explicación
El comando git cherry-pick permite seleccionar uno o varios commits de otra rama y aplicarlos como nuevos commits en la rama actual. Esto es útil cuando un bug fue arreglado en desarrollo pero no se desea fusionar todo el resto del código. Se ejecuta especificando el hash del commit deseado. Es crucial revisar los conflictos que puedan surgir durante la aplicación, ya que el contexto de archivos puede haber cambiado. Una vez resueltos, el commit se crea con un mensaje similar al original, aunque a veces es necesario modificarlo para reflejar mejor el nuevo contexto. Este proceso garantiza que solo las correcciones necesarias lleguen a producción.

## Ejemplo (no ejecutado automáticamente)
Aplicar una corrección de seguridad específica desde la rama feature-auth a la rama main sin fusionar cambios no deseados.

```bash
git cherry-pick abc1234567890
```

## Criterios de revisión
El usuario debe haber creado dos commits distintos en una rama temporal, revertido a la rama base y aplicado exclusivamente el segundo commit mediante cherry-pick sin errores de sintaxis.

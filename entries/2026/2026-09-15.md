## Objetivo
Comprender cómo dividir el código en capas para que la lógica de negocio no dependa de interfaces de usuario, facilitando pruebas unitarias y mantenimiento.

## Explicación
En el diseño de software moderno, la separación de responsabilidades exige aislar la lógica de negocio de la presentación. Un error común es mezclar cálculos complejos dentro de funciones que manipulan el DOM o renderizan HTML. Esto acopla la estructura a la funcionalidad, dificultando cambios futuros. La solución reside en crear un controlador que reciba datos puros y delegue su procesamiento a una clase de servicio independiente. Este servicio debe devolver objetos de dominio simples, sin referencias a librerías de vista. Al hacerlo, garantizamos que el núcleo del sistema sea agnóstico al entorno de ejecución, permitiendo migraciones de frontend o pruebas automatizadas sin tocar la lógica central.

## Ejemplo (no ejecutado automáticamente)
Un servicio de cálculo de impuestos que recibe un ingreso bruto y devuelve el neto, separado completamente de cómo se muestra en una web.

```javascript
class CalculadoraImpuestos {
  calcular(neto) { return neto * 0.9; }
}
const servicio = new CalculadoraImpuestos();
const resultado = servicio.calcular(1000);
```

## Ejercicio
Crea una clase 'ServicioDeUsuario' que valide un correo electrónico y devuelva un objeto con el estado 'valido' o 'invalido'. Luego, escribe una función 'renderizarFormulario' que reciba ese objeto y actualice el texto de un elemento HTML sin importar la lógica de validación.

## Criterios de revisión
El código debe tener dos archivos distintos (uno para lógica, otro para vista). La clase de servicio no debe importar ni usar ninguna librería de manipulación del DOM. Las pruebas unitarias deben poder ejecutar la lógica sin necesidad de un navegador.

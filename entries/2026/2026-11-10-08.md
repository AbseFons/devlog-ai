## Objetivo
Aprender a identificar y fusionar manualmente cambios contradictorios en archivos, utilizando herramientas visuales para mantener la integridad del historial sin perder datos valiosos.

## Explicación
Cuando Git detecta un conflicto, detiene el proceso de merge o rebase mostrando marcadores '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, abre el archivo afectado en tu editor preferido. Lee cuidadosamente ambas versiones: la tuya (actual) y la del otro commit (otro). Decide qué lógica conservar o combina ambas si es posible. Elimina los marcadores de conflicto manualmente. Guarda los cambios y ejecuta 'git add' para marcar el archivo como resuelto. Finalmente, completa el merge con 'git commit'. Este enfoque manual garantiza que entiendas exactamente qué código se fusionó.

## Ejemplo (no ejecutado automáticamente)
Fragmento de archivo mostrando marcadores de conflicto en un archivo de configuración de servidor web.

```bash
# Conflicto en puerto del servidor
<<<<<<< HEAD
server_port = 8080
=======
server_port = 3000
>>>>>>> feature-auth
```

## Ejercicio
Crea un repositorio local con dos ramas: 'main' y 'feature'. Modifica el mismo archivo en ambas ramas cambiando una variable distinta. Intenta unir las ramas y resuelve el conflicto manualmente sin usar herramientas automáticas.

## Criterios de revisión
El archivo debe contener la lógica combinada de ambas ramas, sin marcadores de conflicto visibles, y el comando git status debe mostrar todos los archivos como 'staged' o limpios.

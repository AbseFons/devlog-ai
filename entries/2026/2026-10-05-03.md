## Objetivo
Comprender las diferencias fundamentales entre el framework estándar unittest y pytest, destacando la sintaxis más concisa de pytest para escribir pruebas automatizadas eficientes y legibles en proyectos modernos.

## Explicación
Python ofrece dos enfoques principales para pruebas unitarias: unittest, incluido en el estándar, y pytest, una herramienta externa muy popular. Aunque ambos sirven para lo mismo, pytest simplifica la sintaxis eliminando clases herencia y decoradores complejos. En lugar de definir clases TestCase, usamos funciones simples con @pytest.mark.parametrize. pytest descubre automáticamente las pruebas que terminan en test_ y ejecuta el fixture setup/teardown implícito. Esto reduce drásticamente el boilerplate, permitiendo centrarse en la lógica de validación. La salida de pytest es también más intuitiva, mostrando directamente qué falló sin necesidad de inspeccionar estructuras de árbol complejas.

## Ejemplo (no ejecutado automáticamente)
Función simple que verifica si un número es par usando aserciones directas y parametrización implícita.

```python
def test_par(numero):
    assert numero % 2 == 0, f'{numero} no es par'
```

## Ejercicio

## Criterios de revisión
El archivo debe contener exactamente tres funciones decoradas con @pytest.mark.parametrize o definidas directamente como test_*. Al ejecutar pytest, deben pasar dos pruebas y fallar una. El fallo esperado debe mostrar el mensaje de error claro sin traceback excesivo.

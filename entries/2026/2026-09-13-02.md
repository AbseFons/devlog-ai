## Objetivo
Aprender a implementar el patrón adaptador para permitir que clases con interfaces incompatibles colaboren, facilitando la integración de sistemas legacy o librerías externas sin modificar su código original ni violar principios de diseño.

## Explicación
El patrón adaptador actúa como un puente entre dos interfaces incompatibles. Imagina una clase 'LegacyPrinter' que solo acepta métodos sincrónicos y otra moderna 'ModernPrinterService' basada en promesas. El adaptador encapsula la lógica del sistema legacy, exponiendo una interfaz compatible con el cliente moderno. Esto evita la refactorización costosa de código heredado. Al crear un objeto adaptador, se delegan las llamadas al sistema original, traduciendo los parámetros y resultados. Este enfoque mantiene la cohesión de los módulos existentes mientras habilita nuevas funcionalidades sin acoplamiento directo entre componentes dispares.

## Ejemplo (no ejecutado automáticamente)
Un adaptador en JavaScript que permite usar una clase legacy sincrónica dentro de un flujo asíncrono moderno.

```javascript
class LegacyPrinter {
  print(text) { console.log('Legacy:', text); }
}

const adapter = new LegacyAdapter(new LegacyPrinter());
adapter.printAsync('Hola Mundo'); // Traduce la llamada
```

## Ejercicio
Crea una clase 'OldDatabase' con un método 'querySync(sql)' y escribe un adaptador que exponga 'queryAsync(sql, callback)'. Invoca el método interno usando setTimeout para simular asincronía antes de llamar al método legacy.

## Criterios de revisión
El código debe tener una clase adaptadora separada, no modificar la clase original, usar callbacks o promesas en la interfaz externa y mantener la lógica de traducción clara dentro del adaptador.

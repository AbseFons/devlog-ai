## Objetivo
Aprender a configurar un hook pre-commit personalizado que elimine automáticamente comentarios obsoletos y líneas vacías antes de cada commit, asegurando un historial limpio y reduciendo el ruido en los registros de cambio.

## Explicación
Los hooks pre-commit permiten ejecutar scripts automatizados justo antes de crear un commit. En esta lección, utilizaremos Bash para inspeccionar todos los archivos modificados en el área de staging. El script buscará patrones comunes como comentarios al inicio de archivos o líneas vacías consecutivas y las eliminará mediante sed. Es crucial recordar que este hook solo se ejecuta localmente en la máquina del desarrollador, no en el servidor remoto. La implementación debe ser idempotente para no corromper archivos válidos. Este enfoque mejora significativamente la calidad del código antes de que sea revisado por otros miembros del equipo.

## Ejemplo (no ejecutado automáticamente)
Script Bash que recorre los archivos modificados, elimina líneas vacías y comentarios al inicio, y restaura el estado si falla la limpieza.

```bash
#!/bin/bash
for file in "$@"; do
  if [ -f "$file" ]; then
    sed -i '/^$/d' "$file"
    sed -i '1,/^#.*$/!b; /^#.*$/d' "$file"
  fi
done
```

## Ejercicio
Crea un archivo .git/hooks/pre-commit en tu repositorio local. Copia el código del ejemplo dentro de este archivo. Asegúrate de que tenga permisos de ejecución (chmod +x). Modifica ligeramente el script para que también elimine líneas que contengan solo espacios en blanco.

## Criterios de revisión
El hook debe ejecutarse sin errores al intentar hacer un commit con archivos que contienen comentarios o líneas vacías. El historial del commit debe reflejar solo los cambios de código legítimo, sin incluir la eliminación de ruido preexistente como parte del mensaje del commit.

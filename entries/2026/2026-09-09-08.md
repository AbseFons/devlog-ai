# Preventar commits con archivos no rastreados

## Objetivo
Aprender a configurar un hook pre-commit en bash que bloquee accidentalmente el envío de cambios a Git si existen archivos modificados pero no añadidos al índice, protegiendo la integridad del historial.

## Explicación
Los hooks de Git permiten automatizar validaciones antes de cada commit. En esta lección, implementaremos un script en bash que se ejecuta como 'pre-commit'. El script verificará si existen archivos con cambios no rastreados (modificados pero no añadidos). Si se detectan, el hook detendrá la operación y mostrará un mensaje claro indicando qué archivos deben ser añadidos primero. Esto previene commits incompletos o pérdida de datos locales sin intención. Es una práctica esencial para mantener repositorios limpios y evitar errores comunes en equipos colaborativos.

## Ejemplo (no ejecutado automáticamente)
Script bash que detiene el commit si hay archivos modificados no rastreados

```bash
#!/bin/bash
if ! git diff-index --quiet HEAD --; then
  echo "Error: Archivos modificados no añadidos. No se puede hacer commit."
  exit 1
fi
```

## Ejercicio
Crea un archivo llamado .git/hooks/pre-commit con el código proporcionado. Añade permisos de ejecución con chmod +x .git/hooks/pre-commit. Modifica un archivo existente sin añadirlo al índice y prueba hacer commit para observar la advertencia.

## Criterios de revisión
El hook debe detener el commit cuando existan archivos modificados no añadidos, mostrar un mensaje descriptivo en consola y permitir el commit si todos los archivos están correctamente rastreados.

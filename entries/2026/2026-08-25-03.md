## Objetivo
Al finalizar esta lección, el desarrollador podrá configurar un hook pre-commit personalizado para ejecutar formateo de código y detener commits que violen las normas del equipo sin intervención manual.

## Explicación
Los hooks de Git son scripts que se ejecutan en eventos específicos del control de versiones. El hook pre-commit es ideal para validar cambios antes de que sean visibles para otros. Este mecanismo permite automatizar tareas como formateo, detección de vulnerabilidades o verificación de tipos. Al definir reglas estrictas aquí, se evita la acumulación de deuda técnica y se mantiene un códigobase consistente. La configuración se realiza en archivos .git/hooks o mediante herramientas como Husky para entornos profesionales.

## Ejemplo (no ejecutado automáticamente)
```bash
#!/bin/bash
# Hook pre-commit personalizado
if ! command -v black &> /dev/null; then
    echo "Error: black no está instalado. Instálalo con pip install black"
    exit 1
fi
files=$(git diff --cached --name-only --diff-filter=ACM)
for file in $files; do
    if [[ "$file" == *.py ]]; then
        black --check "$file" || exit 1
    fi
done
exit 0
```

## Ejercicio
Crea un archivo .git/hooks/pre-commit en tu repositorio local. Copia el contenido del ejemplo proporcionado, asegúrate de que sea ejecutable (chmod +x) y prueba ejecutar git commit con archivos Python no formateados para observar la detección.

## Criterios de revisión
El hook debe existir en el directorio .git/hooks, ser ejecutable, contener lógica de validación básica y detener el commit si falla la verificación sin generar errores críticos.

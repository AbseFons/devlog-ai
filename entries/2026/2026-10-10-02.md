## Objetivo
Comprender las técnicas principales para gestionar versiones en APIs, asegurando compatibilidad hacia atrás y planificando la evolución del servicio sin romper clientes existentes.

## Explicación
El versionado es crucial para mantener la estabilidad de una API mientras se introducen cambios. Existen tres enfoques comunes: versionado por URL (ej. /v1/users), que es explícito y fácil de depurar; versionado por encabezados (ej. Accept: application/vnd.api+json;version=2), que mantiene las rutas limpias pero añade complejidad al cliente; y versionado por parámetros de consulta, menos recomendado por posibles conflictos con otros filtros. La estrategia recomendada es comenzar con la versión 1 como estándar y documentar claramente los cambios en cada nueva versión. Siempre se debe proporcionar un periodo de transición donde ambas versiones coexistan antes de retirar la anterior.

## Ejemplo (no ejecutado automáticamente)
Definición de rutas para dos versiones distintas de una API de usuarios, mostrando cómo estructurar las URLs para mantener compatibilidad.

```bash
# Versión 1: Estructura básica
GET /api/v1/users
# Versión 2: Campos adicionales y formato mejorado
GET /api/v2/users
```

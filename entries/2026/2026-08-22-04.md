## Objetivo
Al finalizar esta lección, podrás utilizar el comando git bisect para identificar automáticamente la primera commit que introdujo un error de funcionamiento en tu repositorio, ahorrando horas de revisión manual.

## Explicación
El comando git bisect es una herramienta poderosa que permite realizar una búsqueda binaria sobre la historia de los commits. En lugar de revisar cada cambio manualmente desde el último estado conocido hasta el bug actual, git bisect te guía paso a paso. Primero marcas el commit actual como 'buggy' y un commit anterior sabido que funcionaba como 'good'. Luego, ejecutas el comando y Git seleccionará un commit intermedio para que pruebes. Si la prueba falla, lo marcas como buggy; si funciona, como good. Este proceso se repite hasta aislar exactamente el commit culpable.

## Ejemplo (no ejecutado automáticamente)
```bash
git bisect start
git bisect bad
git bisect good v1.0.0
while git bisect bad; do
  echo "Probando commit: $(git log -1 --oneline)"
  # Ejecutar prueba de integración aquí
  if [ $? -eq 0 ]; then
    git bisect good
  else
    git bisect bad
  fi
done
git bisect reset
```

## Ejercicio
En un repositorio local con al menos 10 commits, introduce una variable de entorno que rompa la aplicación en el commit más reciente. Usa git bisect para encontrar el commit exacto donde se introdujo ese cambio.

## Criterios de revisión
El ejercicio debe completar el flujo start/bad/good/reset sin errores. La salida de Git debe mostrar claramente los commits evaluados y el commit final identificado como la causa raíz.

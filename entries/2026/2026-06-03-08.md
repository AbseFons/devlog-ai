## Objetivo
Aprender a identificar y fusionar cambios divergentes en un archivo utilizando la herramienta de línea de comandos, asegurando que ambas versiones se integren correctamente sin pérdida de datos.

## Explicación
Cuando Git detecta un conflicto durante una fusión o un merge, detiene el proceso marcando las líneas problemáticas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, debes abrir el archivo en tu editor preferido. Lee atentamente ambas versiones: la tuya y la del otro desarrollador. Decide qué código conservar, modificando o eliminando los marcadores de conflicto. Una vez resuelto manualmente, guarda el archivo y ejecuta 'git add' para marcarlo como resuelto. Finalmente, completa la fusión con 'git commit'. Este proceso manual garantiza que comprendas las diferencias lógicas entre los cambios antes de fusionarlos permanentemente.

## Ejemplo (no ejecutado automáticamente)
Se muestra un fragmento de código en bash donde se ejecutan los comandos necesarios para añadir el archivo resuelto y finalizar la fusión manualmente.

```bash
git add nombre_del_archivo.conflicto_resuelto.txt
git commit -m "Resolución manual del conflicto: se integró la lógica de validación del usuario con la nueva interfaz de carga asincrónica."
```

## Ejercicio
Crea un archivo llamado 'datos.json' en tu repositorio local. Modifica una propiedad clave en una rama y haz lo mismo en otra rama diferente. Intenta fusionar ambas ramas y observa el conflicto generado.

## Criterios de revisión
El usuario debe haber abierto el archivo, eliminado los marcadores de conflicto, integrado la lógica correcta del código y ejecutado los comandos 'git add' y 'git commit' para finalizar la operación sin errores.

## Objetivo
Comprender la idempotencia en APIs REST, asegurando que múltiples solicitudes idénticas produzcan el mismo efecto único y evitar errores de estado duplicado en sistemas distribuidos.

## Explicación
La idempotencia garantiza que ejecutar una operación múltiple tenga el mismo resultado que ejecutarla una sola vez. En APIs REST, métodos como GET, PUT y DELETE son idempotentes por diseño, mientras que POST suele no serlo. Esto es crucial para manejar fallos de red o reintentos automáticos sin corromper datos. Por ejemplo, crear un usuario con la misma petición dos veces no debe generar dos registros. Implementar cabeceras como 'Idempotency-Key' permite a los servidores reconocer y descartar peticiones duplicadas legítimas, mejorando la robustez del sistema.

## Ejemplo (no ejecutado automáticamente)
Cliente envía solicitud POST con clave idempotente; servidor valida y responde igual si se repite.

```javascript
const headers = {'Idempotency-Key': 'abc-123'};
fetch('/api/transfer', { method: 'POST', headers, body: JSON.stringify({amount: 50}) })
```

## Ejercicio
Implementa un endpoint POST que acepte una cabecera 'X-Idempotency-Key'. Si la clave ya existe en caché, responde con el estado anterior sin procesar la lógica de negocio nuevamente.

## Criterios de revisión
El código debe almacenar claves idempotentes en memoria o caché, devolver respuestas consistentes ante reintentos y no duplicar registros en la base de datos.

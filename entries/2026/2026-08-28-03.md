## Objetivo
Entender que la idempotencia asegura que múltiples solicitudes idénticas produzcan el mismo efecto único, previniendo duplicidad de datos o costos innecesarios por fallos de red.

## Explicación
La idempotencia es un principio crítico en APIs REST donde repetir una solicitud con los mismos parámetros no altera el estado del servidor más allá del primer resultado. Esto protege contra fallos de red que causen reenvíos automáticos. Sin este mecanismo, una transacción bancaria podría procesarse dos veces o un registro duplicarse indefinidamente. Para implementarlo, se usan encabezados como Idempotency-Key o patrones de almacenamiento temporal en la capa de aplicación antes de ejecutar la lógica de negocio.

## Ejemplo (no ejecutado automáticamente)
```python
import hashlib
from datetime import datetime

class IdempotentHandler:
    def __init__(self):
        self.processed_keys = {}
    
    def handle_request(self, request_body, idempotency_key):
        # Generar hash único de la solicitud
        payload_hash = hashlib.sha256(request_body.encode()).hexdigest()
        full_id = f"{idempotency_key}-{payload_hash}"
        
        if full_id in self.processed_keys:
            return {"status": "duplicate", "data": self.processed_keys[full_id]}
        
        # Simular procesamiento exitoso
        result = {"transaction_id": "TXN-998877", "amount": 150.00, "timestamp": datetime.now().isoformat()}
        self.processed_keys[full_id] = result
        return {"status": "success", "data": result}

# Uso: El cliente envía la misma key si la red falla.
handler = IdempotentHandler()
request_body = '{"amount": 150.00}'
key = 'user-123-order-456'
response = handler.handle_request(request_body, key)
print(response)
```

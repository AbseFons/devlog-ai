## Objetivo
Aprender a prevenir inyecciones SQL y XSS mediante la validación estricta de tipos de datos y longitud antes de procesar cualquier entrada del usuario en aplicaciones web.

## Explicación
La seguridad comienza rechazando lo inesperado. Antes de usar datos externos, como parámetros de formulario, debes verificar su tipo, longitud y formato. Por ejemplo, un campo 'edad' debe ser un número entero positivo; si el usuario envía texto o caracteres especiales, la solicitud debe rechazarse inmediatamente. Esta validación temprana reduce la superficie de ataque, evitando que entradas maliciosas lleguen a la base de datos o al motor de plantillas. Implementa reglas claras: máximo 10 caracteres para nombres, solo dígitos para códigos. Nunca confíes en la limpieza posterior; valida siempre en el punto de entrada.

## Ejemplo (no ejecutado automáticamente)
Función que valida un campo de edad recibiendo una cadena y devolviendo un objeto con estado y valor convertido si es válido.

```javascript
function validarEdad(edadStr) {
  if (typeof edadStr !== 'string' || edadStr.length > 3) return { valido: false, motivo: 'Formato incorrecto' };
  const edad = parseInt(edadStr, 10);
  return edad >= 0 && edad <= 150 ? { valido: true, valor: edad } : { valido: false, motivo: 'Rango inválido' };
}
```

## Ejercicio
Crea una función que valide un campo de correo electrónico verificando que contenga exactamente un '@', termine en '.com' o '.org' y tenga entre 5 y 30 caracteres.

## Criterios de revisión
El código debe devolver 'valido: true' solo si todas las condiciones se cumplen, incluyendo la verificación de longitud total y la presencia del símbolo '@'. Debe rechazar entradas vacías o con múltiples símbolos '@'.

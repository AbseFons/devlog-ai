## Objetivo
Aprender la estructura básica de los commits convencionales para mejorar la legibilidad del historial, facilitar las releases automáticas y mantener un registro claro de cambios en el proyecto.

## Explicación
Los commits convencionales siguen un formato estándar: tipo(scope): descripción. El tipo indica la naturaleza del cambio (feat, fix, docs), el scope define dónde ocurre y la descripción resume el impacto sin mayúsculas iniciales ni puntos finales. Esto permite a las herramientas detectar automáticamente nuevas funcionalidades o correcciones de errores. Al adoptar esta convención desde el inicio, se evita el caos en los mensajes de commit y se prepara el terreno para automatizar versiones semánticas.

## Ejemplo (no ejecutado automáticamente)
Ejecución de un comando git commit con sintaxis convencional que añade una nueva funcionalidad a la aplicación web.

```bash
git commit -m "feat(auth): implementar login con OAuth2"

# Verificación del historial actualizado
git log --oneline -1
```

## Ejercicio
Crea un nuevo archivo llamado 'README.md' en el directorio raíz de tu repositorio local y realiza un commit usando la convención: tipo(scope): descripción.

## Criterios de revisión
El mensaje del commit debe comenzar con 'feat(docs)' o 'chore(docs)', seguido de dos puntos y una descripción breve. El archivo README.md debe existir en el árbol de trabajo antes de ejecutar el comando.

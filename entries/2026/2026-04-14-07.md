## Objetivo
Comprender cómo la falta de validación en entradas de usuario permite a atacantes modificar consultas SQL mal construidas, robando datos sensibles. Aprenderás a identificar el patrón de concatenación insegura y por qué es crítico evitarlo.

## Explicación
La inyección SQL ocurre cuando un atacante inserta código SQL malicioso en campos de entrada no filtrados. En la serie 1, analizamos el error más común: concatenar cadenas directamente a las consultas. Por ejemplo, si una aplicación construye 'SELECT * FROM usuarios WHERE nombre = ' + input, un usuario puede ingresar "admin'--" para truncar la consulta y omitir filtros de seguridad. Esto permite leer cualquier dato de la base de datos. La solución fundamental es utilizar parámetros preparados o ORM que separen el código SQL de los datos, asegurando que las entradas siempre se traten como texto literal y no como parte de la lógica de la consulta.

## Ejemplo (no ejecutado automáticamente)
Consulta vulnerable en Python usando f-strings que permite inyección directa al concatenar la entrada del usuario sin sanitización.

```python
user_input = "admin'--"
query = f"SELECT * FROM users WHERE username = '{user_input}'"
```

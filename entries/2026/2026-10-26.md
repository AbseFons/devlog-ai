## Objetivo
Comprender la organización básica de un nuevo repositorio Git, identificando las carpetas .git, src y tests como pilares fundamentales para mantener el código limpio y separar el historial del proyecto.

## Explicación
Al iniciar un repositorio en cualquier lenguaje, la estructura debe ser clara desde el día cero. La carpeta oculta .git almacena exclusivamente el historial de cambios y metadatos, nunca debe modificarse manualmente. El directorio src contendrá la lógica de negocio o código fuente principal, organizado por módulos o características. Por otro lado, la carpeta tests alojará las suites automatizadas para garantizar la calidad continua. Es crucial evitar mezclar archivos de configuración del entorno (como node_modules o venv) con el código fuente en el control de versiones. Esta separación permite que los desarrolladores clonen solo lo necesario y mantenga el historial limpio, facilitando la integración y el despliegue sin errores comunes derivados de dependencias no gestionadas.

## Ejemplo (no ejecutado automáticamente)
Inicialización de estructura básica con archivos placeholder

```bash
mkdir -p mi-proyecto/src mi-proyecto/tests
cd mi-proyecto
git init
echo 'Estructura inicial' > src/README.md
```

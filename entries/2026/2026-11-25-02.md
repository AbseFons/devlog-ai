## Objetivo
Comprender cómo utilizar consultas parametrizadas para evitar que datos de entrada maliciosos alteren la lógica del servidor y comprometan la base de datos.

## Explicación
En esta lección exploramos la técnica fundamental de parametrización. A diferencia de las cadenas concatenadas, donde el usuario controla directamente el texto SQL, los parámetros envían los valores como datos puros al motor de consulta. El sistema interpreta siempre estos valores como contenido y nunca como instrucciones estructurales. Esto neutraliza intentos de inyección al aislar la sintaxis de la lógica de negocio. Implementar este patrón es obligatorio en cualquier aplicación moderna que interactúe con bases de datos relacionales, garantizando integridad y seguridad sin necesidad de sanitizar manualmente cada entrada.

## Ejemplo (no ejecutado automáticamente)
Consulta segura usando placeholders para evitar inyección SQL en una búsqueda de usuario.

```sql
SELECT * FROM usuarios WHERE email = ? AND activo = 1;
SET @email = 'usuario@ejemplo.com';
PREPARE stmt FROM @stmt;
```

Modifica una consulta SQL vulnerable que concatena variables de usuario para reemplazarla por una versión parametrizada segura.

## Criterios de revisión
El código debe utilizar placeholders (como ? o :nombre) en lugar de concatenación directa y no contener lógica condicional basada en el valor del parámetro.

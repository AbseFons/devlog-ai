## Objetivo
Comprender el significado de los códigos de estado HTTP que comienzan con 2, específicamente 200 OK, 201 Created y 204 No Content. Aprender cuándo utilizar cada uno en respuestas de API RESTful para indicar éxito en operaciones de lectura, creación o actualizaciones sin retorno de datos.

## Explicación
Los códigos HTTP con prefijo 2 indican que la solicitud del cliente fue recibida, entendida y procesada exitosamente. El código 200 OK es el estándar universal para respuestas exitosas, especialmente en operaciones GET donde se devuelve el cuerpo de la respuesta con los datos solicitados. Por otro lado, el código 201 Created confirma que una nueva representación de recurso ha sido creada tras una solicitud POST o PUT exitosa; en este caso, el cuerpo suele incluir metadatos del nuevo recurso y un encabezado Location con su URI. Finalmente, el código 204 No Content indica que la acción se completó correctamente pero no hay nada que devolver en el cuerpo de la respuesta, común en operaciones DELETE o actualizaciones PUT donde solo interesa confirmar la modificación. Es crucial distinguir entre devolver datos (200) y confirmar creación (201) para mantener la semántica correcta de la API.

## Ejemplo (no ejecutado automáticamente)
Solicitud POST a un endpoint de usuarios que crea un nuevo registro y devuelve el objeto creado con estado 201.

```javascript
const response = await fetch('https://api.ejemplo.com/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana', edad: 30 })
});
if (response.status === 201) {
  const nuevoUsuario = await response.json();
  console.log('Usuario creado:', nuevoUsuario.id);
}
```

## Ejercicio
Crea una API ficticia en tu entorno local que acepte solicitudes POST para registrar productos. Configura la respuesta para devolver un código 201 con el objeto del producto recién creado y su ID único, asegurando que el cuerpo de la respuesta no esté vacío.

## Criterios de revisión
La implementación debe retornar exactamente el estado 201 al crear un recurso nuevo. El cuerpo de la respuesta debe contener los datos del recurso creado. No se deben utilizar códigos 200 o 204 para operaciones de creación exitosa que devuelven datos.

## Objetivo
Comprender cómo garantizar la idempotencia en operaciones no seguras como POST mediante el uso de cabeceras específicas, evitando duplicidad de datos al reiniciar procesos fallidos.

## Explicación
La idempotencia asegura que múltiples solicitudes idénticas produzcan el mismo efecto que una sola. Aunque HTTP define POST como no idempotente, podemos forzarlo usando la cabecera 'Idempotency-Key'. Al incluir esta clave única en cada petición, el servidor puede almacenar el resultado de la primera operación exitosa y devolverlo inmediatamente si recibe otra con la misma clave, sin ejecutar la lógica nuevamente. Esto es vital en sistemas distribuidos donde las redes pueden causar retransmisiones involuntarias.

## Ejemplo (no ejecutado automáticamente)
Cliente envía una solicitud POST con un token idempotente único para crear un recurso; si se repite la petición con el mismo token, el servidor responde con el estado previo sin duplicar datos.

```bash
curl -X POST https://api.ejemplo.com/transaccion \
  -H 'Idempotency-Key: abc-123-def' \
  -H 'Content-Type: application/json' \
  -d '{"monto": 50}'
```

## Objetivo
Distinguir conceptualmente entre merge y rebase en Git, entendiendo cómo cada uno afecta la historia del proyecto y cuándo aplicar cada estrategia para mantener un historial limpio o preservar relaciones complejas.

## Explicación
Merge crea un nuevo commit que fusiona dos ramas, preservando exactamente la topología de las líneas de tiempo originales. Es seguro y transparente, ideal para flujos de trabajo colaborativos donde el historial debe reflejar fielmente los eventos. Rebase, en cambio, reescribe la historia: toma los commits de la rama actual y los aplica uno a uno sobre la punta de la rama base. Esto produce una línea de tiempo lineal y limpia, pero modifica los hashes de los commits existentes. Usa rebase para preparar tu código antes de enviarlo a un branch compartido; usa merge para fusionar ramas establecidas o cuando el historial complejo es aceptable.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un merge y luego un rebase en una rama local, mostrando la diferencia visual en el historial.

```bash
git checkout feature
# Simular trabajo en feature
git commit -m "Añadir nueva funcionalidad"
# Merge de main a feature
git merge main
# Rebase de feature sobre main
git rebase main
```

## Ejercicio
Crea una rama 'dev' desde 'main', haz dos commits, vuelve a 'main', haz un commit y luego fusiona 'main' en 'dev'. Observa el historial. Ahora intenta rebasar 'dev' sobre 'main' y compara la estructura visual.

## Criterios de revisión
El estudiante debe identificar que merge añade un nodo de fusión mientras rebase linealiza los commits existentes, y saber elegir el método correcto según si se modifica historia compartida o no.

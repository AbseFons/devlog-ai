## Objetivo
Aprender a crear etiquetas semánticas en Git para marcar versiones de software estables, facilitando el despliegue y la gestión del ciclo de vida del proyecto sin romper la historia de commits.

## Explicación
Las etiquetas (tags) en Git son marcadores inmutables que identifican puntos específicos en el historial, ideales para releases. A diferencia de los branches, las tags no se mueven. Para una versión estable, usamos comandos como 'git tag -a v1.2.0 -m "Release 1.2.0"'. Esto crea una etiqueta anónima con un mensaje descriptivo. Es crucial usar versiones semánticas (MAJOR.MINOR.PATCH) para comunicar cambios claros a los usuarios. Las etiquetas pueden ser ligeras o pesadas; las pesadas incluyen metadatos como el autor y la fecha, útiles para auditorías. Nunca borres una etiqueta de una rama principal activa sin precaución extrema, ya que podría afectar a los usuarios que dependen de esa versión específica.

## Ejemplo (no ejecutado automáticamente)
Creación de una etiqueta anónima para un release v2.1.0 con mensaje descriptivo en el repositorio local.

```bash
git tag -a v2.1.0 -m "Release estable v2.1.0: corrección de seguridad y mejoras de rendimiento"
git push origin v2.1.0
```

## Ejercicio
Crea una etiqueta llamada 'v3.0.0-beta' en tu rama actual con el mensaje 'Primer build beta para pruebas'. Luego, verifica que la etiqueta existe usando 'git show-ref --tags' y asegúrate de que no haya errores.

## Criterios de revisión
El usuario debe haber creado correctamente una etiqueta anónima con un mensaje descriptivo relevante. La etiqueta debe ser visible en el historial de referencias del repositorio remoto tras el push. No deben existir etiquetas duplicadas ni mensajes vacíos.

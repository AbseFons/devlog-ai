## Objetivo
Comprender cómo escalar repositorios centralizados mediante partición lógica de datos, optimizando el rendimiento para cargas masivas sin comprometer la integridad del sistema.

## Explicación
En sistemas distribuidos modernos, un único repositorio centralizado puede volverse un cuello de botella. La partición o sharding permite dividir los datos en fragmentos manejables basados en claves específicas, como IDs de usuario o rangos temporales. Esta técnica distribuye la carga de lectura y escritura entre múltiples nodos, mejorando el throughput y reduciendo la latencia. Es crucial diseñar las reglas de partición para evitar hotspots y garantizar que las consultas frecuentes sean eficientes. Además, se debe planificar una estrategia de migración de datos para reequilibrar los shards cuando crezca la base de datos.

## Ejemplo (no ejecutado automáticamente)
Script SQL que define tablas sharded con particionamiento por rango en una columna de fecha.

```sql
CREATE TABLE user_logs (
    id BIGINT,
    user_id INT,
    event_time TIMESTAMP,
    details JSON
) PARTITION BY RANGE (YEAR(event_time)) (
    PARTITION p2024 VALUES LESS THAN (2025),
    PARTITION p2025 VALUES LESS THAN (2026)
);

INSERT INTO user_logs (id, user_id, event_time, details) VALUES (1, 101, '2024-03-15 10:00:00', '{"action": "login"}');
```

## Objetivo
Aprender a utilizar el comando git bisect para identificar eficientemente en qué commit exacto se introdujo un error de regresión, ahorrando tiempo al no revisar manualmente cada cambio histórico.

## Explicación
El comando git bisect es una herramienta poderosa que permite realizar una búsqueda binaria sobre la historia del repositorio. En lugar de revisar commits uno por uno, el usuario marca dos puntos: el commit actual con el bug y un commit anterior conocido como funcional. Git divide automáticamente el rango en mitades, preguntando al usuario si el punto medio tiene el error. Al responder 'bad' o 'good', git recalcula el siguiente punto medio hasta aislar el commit culpable. Este proceso es esencial para depurar problemas de regresión donde no hay logs detallados y se necesita localizar rápidamente la causa raíz sin perder horas en una revisión manual exhaustiva.

## Ejemplo (no ejecutado automáticamente)
Se ejecuta git bisect start marcando el commit actual con --bad y un commit anterior funcional con --good. Git selecciona un punto medio para evaluar.

```bash
git bisect start
GIT_BISECT_BAD=$(git rev-parse HEAD)
git bisect bad $GIT_BISECT_BAD
```

## Ejercicio
Marca el commit actual como 'bad' y busca un commit anterior funcional. Ejecuta git bisect y responde a las preguntas de git hasta que identifique el commit problemático.

## Criterios de revisión
El usuario debe ejecutar correctamente los comandos de inicio, responder a las iteraciones de bisect y finalizar con git bisect reset para limpiar el estado del repositorio.

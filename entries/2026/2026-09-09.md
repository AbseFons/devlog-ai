## Objetivo
Comprender la diferencia entre imagen (plantilla inmutable) y contenedor (instancia ejecutable), y cómo Docker utiliza capas para crear entornos aislados eficientes.

## Explicación
En Docker, una imagen es un archivo de plantillas que contiene todo lo necesario para ejecutar una aplicación: código, librerías y dependencias. Es inmutable. Un contenedor es una instancia en ejecución de esa imagen, aislada del sistema operativo host pero compartiendo el kernel. Las imágenes se construyen con instrucciones (Dockerfile) que crean capas superpuestas; cada instrucción añade o modifica una capa. Al ejecutar un contenedor, Docker monta estas capas y crea un espacio de nombres aislado para procesos, red y almacenamiento. Esto permite portabilidad: la misma imagen funciona en cualquier máquina con Docker instalado. La inmutabilidad de las imágenes facilita el control de versiones y la reproducibilidad del entorno.

## Ejemplo (no ejecutado automáticamente)
Crea una imagen base minimalista y lanza un contenedor que escuche un puerto específico para simular un servicio web simple.

```bash
# Crea una imagen personalizada basada en Alpine Linux
FROM alpine:latest
# Instala curl y crea un archivo de prueba
cmd> apk add --no-cache curl && echo 'Hola Docker' > /usr/share/nginx/html/index.html
# Lanza el contenedor exponiendo el puerto 8080
docker run -d --name mi-servicio -p 8080:80 nginx
```

## Ejercicio
Crea un archivo llamado Dockerfile que instale Python y cree un script 'app.py' con una función de saludo. Luego, construye la imagen con el nombre 'mi-app-python' y ejecuta un contenedor que muestre el resultado al acceder a localhost:5000.

## Criterios de revisión
El Dockerfile debe tener instrucciones FROM, RUN y CMD/ENTRYPOINT. La imagen construida no puede fallar en la fase de build. El contenedor debe estar en modo detached (-d) y exponer un puerto válido.

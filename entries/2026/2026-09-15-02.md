## Objetivo
Comprender cómo diseñar casos de prueba que cubran no solo el flujo normal, sino también los límites exactos (borde a borde) y condiciones anómalas en la gestión de inventario.

## Explicación
La cobertura de pruebas efectiva va más allá de ejecutar el código; implica validar explícitamente los límites de los datos. En este caso de uso, simulamos una API que actualiza stock. Es crucial probar con valores exactos al límite superior e inferior definidos en la especificación técnica, no solo con valores aleatorios dentro del rango. Por ejemplo, si el sistema acepta entre 0 y 100 unidades, debemos probar exactamente 0, 1, 99 y 100. Ignorar estos puntos puede dejar vulnerabilidades críticas donde el sistema falle o acepte datos inválidos. Esta práctica asegura robustez ante entradas extremas que a menudo causan errores en producción.

## Ejemplo (no ejecutado automáticamente)
Script de prueba para validar límites de stock (0, 1, max-1, max) usando Python y la librería requests.

```python
import requests
url = "https://api.ejemplo.com/inventario"
resp_0 = requests.post(url, json={"producto": "A", "cantidad": 0})
resp_max = requests.post(url, json={"producto": "A", "cantidad": 100})
```

## Ejercicio

## Criterios de revisión
El script debe ejecutar cuatro peticiones distintas con los valores exactos especificados. Debe capturar y mostrar el código de respuesta HTTP para cada solicitud, confirmando que se manejan correctamente los límites inferior y superior.

## Objetivo
Aprender a identificar y resolver conflictos de merge utilizando herramientas visuales y edición directa, asegurando la integridad del historial y la coherencia del código antes de finalizar el proceso de integración.

## Explicación
Cuando Git detecta un conflicto durante un merge o una rebase, detiene la operación para evitar sobrescribir cambios no deseados. El sistema marca las líneas problemáticas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, debes abrir el archivo afectado en tu editor de código preferido. Analiza ambas versiones: la tuya (actual) y la del otro rama (remota). Decide qué lógica es correcta o si puedes combinar ambos enfoques. Una vez editado, guarda los cambios eliminando los marcadores de conflicto. Finalmente, ejecuta 'git add' para marcar el archivo como resuelto y 'git commit' o 'git merge --continue' para finalizar la operación.

## Ejemplo (no ejecutado automáticamente)
Archivo de configuración de servidor donde se fusionan actualizaciones de seguridad con nuevas reglas de acceso.

```bash
# Conflicto resuelto en config.yaml
# Versión local: habilita autenticación MFA
mfa_enabled: true
# Versión remota: ajusta puerto para balanceo de carga
server_port: 443
firewall_rules:
  - action: allow
    source: 10.0.0.0/8
```

## Ejercicio
Crea dos ramas en un repositorio local, modifica el mismo archivo en cada una con cambios opuestos, realiza un merge y resuelve el conflicto manualmente.

## Criterios de revisión
El archivo debe estar libre de marcadores de conflicto, la sintaxis debe ser válida y el historial de commits debe reflejar la resolución correcta sin pérdida de datos.

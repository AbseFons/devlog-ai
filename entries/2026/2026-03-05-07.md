## Objetivo
Comprender y aplicar el principio de mínimo privilegio asignando al usuario de despliegue solo las permisos necesarios para ejecutar scripts sin acceso a datos sensibles o configuración crítica del sistema operativo.

## Explicación
El principio de mínimo privilegio establece que cada entidad, ya sea un proceso o un usuario, debe poseer únicamente los permisos estrictamente necesarios para realizar su función. En ingeniería de software, esto reduce la superficie de ataque y limita el daño en caso de compromiso. Por ejemplo, un servicio de aplicación no necesita acceso de lectura/escritura a /etc/passwd ni capacidad de reiniciar otros servicios. Al diseñar roles, se deben auditar las dependencias del código para otorgar permisos granulares mediante grupos específicos o políticas de seguridad, evitando el uso de cuentas con privilegios de root o administradores por defecto en entornos de producción.

## Ejemplo (no ejecutado automáticamente)
Se define un usuario 'deployer' con acceso solo al directorio de aplicaciones y capacidad de ejecución de scripts, sin permisos de sistema global.

```bash
sudo useradd -m deployer
groupadd appgroup
usermod -aG appgroup deployer
chown -R deployer:appgroup /var/www/app
```

## Ejercicio
Crea un usuario llamado 'analista' en tu entorno local y agrúpalo en 'lectura'. Asigna permisos de solo lectura a un directorio de logs compartido.

## Criterios de revisión
El usuario debe existir con el grupo asignado correctamente. El directorio debe tener permisos 755 o equivalentes que permitan ejecución pero no escritura para el grupo, verificando con 'ls -ld'.

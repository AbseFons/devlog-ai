## Objetivo
Aprender a aislar la lógica de negocio del manejo de datos para mejorar la mantenibilidad y facilitar las pruebas unitarias en aplicaciones modernas.

## Explicación
En el diseño de software, la separación de responsabilidades implica que cada módulo debe tener un único propósito claro. En este caso, dividimos la aplicación en una capa de lógica (servicio) y una de persistencia (repositorio). El servicio orquesta las reglas de negocio sin conocer los detalles de la base de datos. El repositorio se encarga exclusivamente de ejecutar consultas SQL o llamadas a APIs de almacenamiento. Esta arquitectura evita que el código de negocio dependa directamente de drivers de bases de datos, lo que permite cambiar la tecnología de persistencia sin alterar la lógica principal. Además, simplifica las pruebas unitarias al poder simular (mockear) el repositorio con datos falsos.

## Ejemplo (no ejecutado automáticamente)
Un servicio de usuario que calcula un descuento aplica una regla de negocio simple, delegando la consulta a un repositorio genérico.

```javascript
class UsuarioRepositorio {
  async obtenerUsuario(id) { return db.query('SELECT * FROM usuarios WHERE id = ?', [id]); }
}
class ServicioUsuarios {
  constructor(repositorio) { this.repo = repositorio; }
  async aplicarDescuento(id, porcentaje) { const u = await this.repo.obtenerUsuario(id); return { ...u, descuento: u.precio * (1 - porcentaje/100) }; }
}
```

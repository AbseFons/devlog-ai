## Objetivo
Comprender la función de los hooks en Git, específicamente el pre-commit, para automatizar validaciones de código antes de cada commit y mantener un historial limpio.

## Explicación
Los hooks son scripts que Git ejecuta automáticamente en momentos específicos del flujo de trabajo. El hook 'pre-commit' se activa justo antes de realizar un commit. Su utilidad principal es ejecutar pruebas locales, formatear el código o verificar patrones para evitar errores comunes. Por ejemplo, puedes configurar este hook para que falle si hay archivos sin formato o con contraseñas expuestas. Esto asegura que solo código validado entre al repositorio, reduciendo la carga de revisión y mejorando la calidad general del proyecto desde el inicio.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que verifica si existen archivos .txt no deseados antes de permitir el commit.

```bash
#!/bin/bash
if git diff --cached --name-only | grep -q '\.txt$'; then
  echo 'Error: Archivos .txt no permitidos.'
  exit 1
fi
```

## Ejercicio
Crea un archivo llamado .git/hooks/pre-commit en tu repositorio local. Copia el código del ejemplo dentro de este archivo, asegúrate de que sea ejecutable con chmod +x y prueba a intentar agregar un archivo .txt al área de staging para observar el bloqueo.

## Criterios de revisión
El script debe bloquear el commit si detecta archivos con extensión .txt en la zona de staging. El mensaje de error debe ser claro y directo.

## Objetivo
Comprender la estructura básica de un sistema de Control de Acceso Basado en Roles (RBAC) utilizando listas de control de acceso (ACLs) para gestionar permisos granulares en recursos específicos sin exponer credenciales ni ejecutar comandos peligrosos.

## Explicación
En este módulo introductorio, exploraremos cómo definir políticas de seguridad mediante la asignación de roles a usuarios y la vinculación de estos roles con recursos protegidos. A diferencia del control de acceso discrecional, el RBAC centraliza las decisiones de permisos, reduciendo errores humanos y complejidad administrativa. Analizaremos un caso hipotético donde un desarrollador necesita acceder solo al repositorio de configuración de su módulo, mientras que otro solo puede leer logs públicos. La implementación se basa en estructuras de datos simples que mapean identidades a conjuntos de permisos predefinidos, asegurando el principio de mínimo privilegio desde el diseño inicial.

## Ejemplo (no ejecutado automáticamente)
Definición de roles y asignación de permisos para un sistema de gestión de archivos simulado en memoria.

```javascript
const roles = {
  admin: ['read', 'write', 'delete'],
  developer: ['read', 'write']
};

function verificarAcceso(usuario, recurso, accion) {
  const permisosUsuario = roles[usuario];
  return permisosUsuario && permisosUsuario.includes(accion);
}

console.log(verificarAcceso('developer', 'config.yaml', 'read')); // true
console.log(verificarAcceso('developer', 'config.yaml', 'delete')); // false
```

## Ejercicio
Crea un objeto JSON que defina tres roles nuevos: 'analista' (solo lectura), 'auditor' (lectura y exportación) y 'soporte' (escritura limitada). Luego, escribe una función que determine si un usuario específico puede ejecutar la acción 'exportar' sobre el recurso 'reporte.csv'.

## Criterios de revisión
El código debe definir correctamente los tres roles con sus permisos asociados sin errores de sintaxis. La función de verificación debe retornar true solo si el rol del usuario incluye explícitamente el permiso 'exportar'. No se permiten credenciales en el código ni referencias a archivos reales.

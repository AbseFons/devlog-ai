## Objetivo
Comprender cómo la base de datos optimiza consultas complejas mediante el análisis del plan de ejecución generado por la instrucción EXPLAIN, identificando cuellos de botella en lecturas de disco o escaneos innecesarios para mejorar el rendimiento de aplicaciones críticas.

## Explicación
La instrucción EXPLAIN revela el algoritmo que el optimizador de consultas seleccionará antes de ejecutar una sentencia SQL. Al analizar la salida, podemos observar si se utilizan índices eficientes o si se realizan escaneos completos de tablas grandes. Esto es vital para depurar lentitud en reportes. Por ejemplo, si el plan muestra un 'Seq Scan' en una tabla con millones de registros, probablemente falte un índice adecuado. Revisar los costos estimados ayuda a predecir tiempos de respuesta antes de afectar la producción.

## Ejemplo (no ejecutado automáticamente)
Consulta que busca empleados por departamento usando EXPLAIN para verificar el uso del índice.

```sql
EXPLAIN ANALYZE SELECT * FROM empleados WHERE id_departamento = 50;
SELECT * FROM empleados WHERE id_departamento = 50;
```

## Ejercicio
Crea una tabla de productos con un campo 'precio' y ejecuta una consulta que filtre por precio. Usa EXPLAIN para verificar si se crea un índice temporal o permanente.

## Criterios de revisión
El plan debe mostrar el uso de un índice (Index Scan) en lugar de escanear toda la tabla (Seq Scan). Los costos estimados deben ser bajos comparados con una consulta sin optimizar.

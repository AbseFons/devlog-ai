## Objetivo
Comprender cómo las APIs protegen recursos mediante límites de tasa y aprender a interpretar headers clave como X-RateLimit-Limit para gestionar solicitudes eficientemente.

## Explicación
El rate limiting es un mecanismo de control que restringe el número de solicitudes que un cliente puede realizar en un periodo determinado. Esto previene abusos, ataques DDoS y asegura la estabilidad del servicio. Las APIs suelen comunicar estos límites mediante headers HTTP específicos. El header X-RateLimit-Limit indica el máximo de peticiones permitidas por ventana, mientras que X-RateLimit-Remaining muestra cuántas quedan disponibles. Si este último es cero, el cliente debe esperar a que se reinicie la ventana o reducir su frecuencia de llamadas. Implementar esta lógica en tu aplicación permite evitar errores 429 Too Many Requests y optimizar el uso de recursos.

## Ejemplo (no ejecutado automáticamente)
Un script que simula una solicitud a una API con rate limiting y muestra los headers recibidos para verificar el límite actual.

```bash
curl -i https://api.ejemplo.com/v1/datos
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
```

## Objetivo
Implementar la rotación programática de credenciales para minimizar la ventana de exposición en caso de compromiso, asegurando que las claves no permanezcan estáticas indefinidamente.

## Explicación
La gestión segura de secretos requiere evitar el almacenamiento estático. En esta lección, utilizaremos HashiCorp Vault para demostrar cómo rotar credenciales de acceso a una base de datos sin interrumpir los servicios. El proceso implica solicitar un nuevo token o clave cifrada al servidor Vault con una duración de vida limitada (TTL). Una vez generado, el servicio debe actualizar su configuración local inmediatamente y revocar la credencial anterior. Este enfoque reduce drásticamente el riesgo: si un atacante roba una credencial antigua, esta dejará de ser válida tras el periodo de rotación programado. Es fundamental que la aplicación tenga acceso a la API de Vault para realizar estas actualizaciones automáticamente mediante scripts o orquestadores como Kubernetes.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que solicita una nueva credencial al servidor Vault y actualiza un archivo local de configuración simulando la rotación segura.

```bash
export VAULT_ADDR='https://vault.example.com'
export VAULT_TOKEN='hvs:your-service-token'
new_secret=$(curl -s -X POST $VAULT_ADDR/v1/secret/data/db-creds \
  -H 'X-Vault-Token: $VAULT_TOKEN' \
  -d 'lease_ttl=3600' | jq -r '.data.data.password')
echo "$new_secret" > /etc/app/config/secrets.json
```

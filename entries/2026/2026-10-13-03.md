# Merge vs Rebase: Preservando la Historia

## Objetivo
Diferenciar cuándo usar merge para mantener un historial realista y cuándo usar rebase para crear una línea de desarrollo lineal limpia antes de fusionar.

## Explicación
Git ofrece dos estrategias para integrar cambios. Merge crea un nuevo commit de fusión que preserva la topología original, ideal para ramas de características donde el orden importa. Rebase reescribe la historia local moviendo los commits, creando una línea lineal; úsalo solo en tu rama local antes de push para mantener un log limpio. Nunca uses rebase en ramas compartidas o públicas.

## Ejemplo (no ejecutado automáticamente)
Comandos para realizar un merge y luego un rebase interactivo sobre la misma rama local.

```bash
git checkout feature
# Realizar merge con el main
git merge main
# Rebase los cambios locales sobre main
git rebase main
```

## Ejercicio
Crea una rama 'feature', haz dos commits. Haz un commit en 'main'. Vuelve a 'feature' y ejecuta 'git merge main'. Luego, intenta 'git rebase main' y observa cómo cambia el orden de los commits.

## Criterios de revisión
El usuario debe identificar que merge añade un nodo al grafo mientras que rebase reordena nodos existentes. Debe saber que rebase es inseguro en ramas públicas.

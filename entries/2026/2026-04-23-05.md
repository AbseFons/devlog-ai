## Objetivo
Aprender a identificar y resolver conflictos de merge utilizando herramientas de línea de comandos, asegurando la integridad del historial y manteniendo el control sobre los cambios integrados.

## Explicación
Cuando Git detecta un conflicto durante una fusión o actualización, detiene el proceso marcando los archivos afectados. El sistema inserta bloques '<<<<<<<', '=======', y '>>>>>>>' entre las líneas en disputa. Para resolverlo, debes abrir el archivo, decidir qué contenido conservar (el tuyo, el del otro rama, o una mezcla), borrar los marcadores de Git y guardar el archivo modificado. Una vez resuelto visualmente, ejecuta 'git add <archivo>' para marcarlo como listo para la fusión. Finalmente, completa la operación con 'git commit' o 'git merge --continue'. Es crucial revisar cada conflicto individualmente; ignorarlos puede corromper la base de datos local.

## Ejemplo (no ejecutado automáticamente)
Se muestra un fragmento de archivo donde se resuelve un conflicto editando manualmente el contenido entre los marcadores y eliminándolos antes de añadir el archivo al área de indexación.

```bash
# Editar archivo.conflictos para eliminar marcadores
<<<<<<< HEAD
funcion() { return 1; }
=======
funcion() { return 2; }
>>>>>>> feature-branch
# Guardar cambios y añadir al index
# git add archivo.conflictos
```

## Ejercicio
Crea dos ramas en tu repositorio local: 'main' y 'feature'. Modifica un mismo archivo de texto en ambas ramas con contenido diferente. Intenta fusionar la rama 'feature' hacia 'main'. Al detectar el conflicto, resuelve los bloques manualmente en el editor de texto preferido, guarda los cambios y ejecuta los comandos necesarios para finalizar la fusión sin errores.

## Criterios de revisión
El usuario debe haber eliminado correctamente todos los marcadores de Git ('<<<<<<<', '=======', '>>>>>>>') del archivo conflictivo. El contenido final del archivo debe reflejar una integración lógica de ambos cambios o la selección deliberada de uno sobre el otro. Debe existir un registro en el historial de Git que confirme la resolución del conflicto mediante un commit o continuación exitosa de la fusión.

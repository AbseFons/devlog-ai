## Objetivo
Comprender que una clase debe tener un solo motivo para cambiar, evitando la complejidad innecesaria y facilitando el mantenimiento del código al separar responsabilidades lógicas.

## Explicación
El principio de Responsabilidad Única establece que cada clase debe encapsular una única responsabilidad. Si una clase realiza múltiples tareas distintas, cualquier cambio en una de ellas podría romper la otra. Por ejemplo, una clase 'Usuario' que maneja tanto el registro como el envío de correos electrónicos viola este principio. Al separar estas funciones en clases distintas, garantizamos que un fallo en el sistema de correo no afecte a la lógica de autenticación. Esto promueve código modular, testeable y escalable, donde cada componente tiene una función clara y bien definida dentro del sistema.

## Ejemplo (no ejecutado automáticamente)
Clase 'Usuario' refactoreada para separar la lógica de registro del envío de correos electrónicos.

```javascript
class Usuario {
  registrar() { console.log('Usuario registrado'); }
}
class NotificadorEmail {
  enviar() { console.log('Correo enviado'); }
}
```

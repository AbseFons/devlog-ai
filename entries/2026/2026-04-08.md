## Objetivo
Entender cómo dividir una aplicación en capas lógicas para que cada módulo tenga una única responsabilidad, facilitando el mantenimiento y la prueba.

## Explicación
El principio de separación de responsabilidades dicta que ningún módulo debe realizar múltiples funciones críticas. En un diseño típico, la capa de presentación maneja la interfaz, la lógica de negocio procesa reglas complejas y la capa de datos se encarga de persistencia. Al aislar estas funciones, podemos modificar el almacenamiento sin afectar la lógica ni la interfaz. Esto reduce la acoplamiento y permite que los equipos trabajen en paralelo sobre diferentes capas del sistema con mayor seguridad y claridad.

## Ejemplo (no ejecutado automáticamente)
Clase de servicio que calcula impuestos separada de la capa de datos.

```javascript
class ImpuestoService {
  calcular(total, tasa) {
    return total * tasa;
  }
}
```

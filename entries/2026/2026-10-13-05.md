## Objetivo
Aprender a dividir la lógica de negocio de validación de entrada de datos del manejo de excepciones y persistencia, mejorando la mantenibilidad y seguridad del sistema mediante el principio de responsabilidad única aplicado a capas específicas.

## Explicación
En este módulo exploramos cómo aislar la validación de esquemas de datos en un servicio dedicado, separado de la lógica de acceso a base de datos. Al crear una clase 'ValidadorDeUsuario' que solo se encarga de verificar integridad referencial y formato, evitamos contaminar los controladores con reglas complejas. Si la validación falla, el sistema lanza excepciones estandarizadas sin tocar la capa de persistencia. Este enfoque permite probar casos de error en aislamiento, facilita el intercambio de esquemas de validación entre microservicios y asegura que un fallo en la entrada no corrompa transacciones críticas. La arquitectura resultante es más clara: cada componente tiene una única razón para existir, lo que reduce acoplamiento y simplifica la evolución del código a largo plazo.

## Ejemplo (no ejecutado automáticamente)
Implementación de un validador independiente en Node.js que verifica campos obligatorios antes de permitir la persistencia.

```javascript
class ValidadorDeUsuario {
  validar(datos) {
    if (!datos.nombre || datos.nombre.length < 2) throw new Error('Nombre inválido');
    if (!datos.email || !/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(datos.email)) throw new Error('Email inválido');
    return true;
  }
}
const validador = new ValidadorDeUsuario();
try {
  validador.validar({ nombre: 'Ana', email: 'ana@ejemplo.com' });
} catch (e) {
  console.error(e.message);
}
```

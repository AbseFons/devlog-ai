## Objetivo
Aprender a estructurar mensajes de commit claros usando el formato conventional commits para mejorar la legibilidad del historial y facilitar la generación automática de changelogs en proyectos modernos.

## Explicación
Las convenciones de commits estandarizan el mensaje de cada cambio. El formato básico es 'tipo(scope): descripción'. Para añadir una nueva funcionalidad, usamos 'feat'. Esto permite a las herramientas detectar automáticamente cuándo lanzar una nueva versión mayor. Un commit bien escrito debe explicar el qué y el porqué del cambio sin incluir detalles de implementación innecesarios. Esta práctica fomenta la colaboración al hacer que el historial sea comprensible incluso para nuevos desarrollores.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de comando git commit con mensaje estructurado que añade una función de autenticación básica a una aplicación web.

```bash
git commit -m "feat(auth): implementar login con validacion de token"

# El mensaje sigue el formato: tipo(scope): descripcion
```

## Criterios de revisión
El mensaje del commit debe comenzar con 'feat', incluir el nombre del archivo modificado en paréntesis como scope y describir brevemente la utilidad de la nueva función sin usar mayúsculas innecesarias.

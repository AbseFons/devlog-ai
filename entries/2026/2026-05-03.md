## Objetivo
Aprender a crear y gestionar etiquetas permanentes en Git para marcar versiones estables del proyecto, diferenciándolas de los commits temporales.

## Explicación
Las etiquetas en Git son referencias permanentes que apuntan a un commit específico, ideal para marcar lanzamientos de software. A diferencia de las ramas, las etiquetas no se mueven automáticamente con nuevos commits. Para crear una etiqueta anónima (sin autor), usa 'git tag v1.0'. Si deseas asignar un autor y fecha, emplea 'git tag -a v1.0 -m "Mensaje"'. Las etiquetas son cruciales para la gestión de versiones en repositorios remotos; al subir una nueva etiqueta con 'git push origin --tags', se sincronizan en el servidor. Es fundamental distinguir entre etiquetas ligeras y anotadas: las primeras son simples referencias, mientras que las anotadas permiten metadatos como mensajes y firmas GPG.

## Ejemplo (no ejecutado automáticamente)
Crear una etiqueta anónima para la versión inicial de un proyecto web.

```bash
git tag v1.0
git push origin --tags
```

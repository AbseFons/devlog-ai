## Objetivo
Comprender la importancia de dividir una aplicación en capas lógicas (presentación, lógica y datos) para mejorar el mantenimiento, la escalabilidad y la seguridad del código.

## Explicación
El diseño por capas organiza el software en niveles con responsabilidades distintas. La capa de presentación maneja la interfaz de usuario y la entrada de datos. La capa de negocio encapsula la lógica crítica, las reglas de validación y los algoritmos de procesamiento. Finalmente, la capa de acceso a datos se encarga exclusivamente de interactuar con bases de datos o servicios externos. Esta separación permite que cada equipo trabaje en su módulo sin afectar al resto, facilita las pruebas unitarias aisladas y hace que sea más sencillo cambiar tecnologías subyacentes sin reescribir toda la aplicación.

## Ejemplo (no ejecutado automáticamente)
Implementación básica de una API REST en Node.js donde el controlador valida la entrada, el servicio calcula el descuento y el modelo accede a la base de datos simulada.

```javascript
const controller = (req, res) => {
  const precio = parseFloat(req.body.precio);
  if (precio < 0) return res.status(400).json({ error: 'Precio inválido' });
};

const service = { calcularDescuento: (precio) => precio * 0.9 };

const model = { guardar: (data) => console.log('Guardado en DB') };
```

## Ejercicio
Crea un archivo 'controller.js' que reciba una solicitud POST con un nombre y edad, valide que la edad sea mayor a 18 y llame a una función de servicio para generar un mensaje de bienvenida.

## Criterios de revisión
El código debe tener al menos dos funciones separadas (una para validación y otra para lógica), no debe mezclar consultas de base de datos con la lógica de negocio, y debe devolver respuestas JSON consistentes.

## Objetivo
Comprender la estructura jerárquica de las pruebas de software para priorizar casos unitarios, de integración y end-to-end, optimizando el esfuerzo de QA y mejorando la estabilidad del sistema desde el nivel más bajo.

## Explicación
La pirámide de pruebas es un modelo visual que organiza los tipos de pruebas según su costo, velocidad y cobertura. La base amplia está formada por las pruebas unitarias, ejecutadas frecuentemente y con alto volumen, ya que son rápidas y baratas. Sobre ellas se sitúan las pruebas de integración, que validan la interacción entre módulos, en menor número pero con mayor complejidad. En la cúspide, encontramos las pruebas end-to-end o de aceptación, escasas y lentas, destinadas a simular flujos completos del usuario. Este enfoque asegura que la mayoría de los errores se detecten temprano, reduciendo el riesgo de fallos críticos en producción y facilitando un ciclo de desarrollo más eficiente.

Ejemplo de una prueba unitaria simple en JavaScript usando Jest para validar la suma de dos números.

```javascript
const sumar = (a, b) => a + b;

  expect(sumar(2, 3)).toBe(5);
});
```

## Ejercicio
Crea una función en Python que calcule el área de un círculo dado su radio. Luego, escribe tres pruebas unitarias: una para un radio positivo válido, otra para un radio cero y una tercera para un radio negativo, asegurando que la última lance una excepción.

## Criterios de revisión
El código debe incluir la función calculadora y las tres pruebas especificadas. Las pruebas deben usar la librería unittest o pytest. El resultado de la prueba con radio negativo debe fallar intencionalmente. El total de líneas de código no debe exceder 20.

## Objetivo
Al finalizar, el desarrollador diferenciará cuándo usar restricciones CHECK para rangos de datos y UNIQUE para duplicidad, aplicando ambas en tablas de inventario sin errores de sintaxis ni lógica incorrecta.

## Explicación
Las restricciones CHECK y UNIQUE son fundamentales para la integridad referencial. CHECK valida que los valores caigan dentro de un rango o condición específica (ej. edad > 0), actuando como una barrera lógica antes del inserto. UNIQUE, por otro lado, garantiza que ninguna columna tenga dos filas idénticas, ideal para identificadores como correos electrónicos. A menudo se combinan: una tabla de usuarios puede tener un campo 'edad' con CHECK y un campo 'email' con UNIQUE. Es crucial recordar que UNIQUE permite un solo valor NULL en la columna, mientras que CHECK no impide explícitamente nulls a menos que se especifique lo contrario. Su uso conjunto previene datos corruptos desde el origen.

## Ejemplo (no ejecutado automáticamente)
```sql
CREATE TABLE inventario (
    id_producto INT PRIMARY KEY,
    nombre VARCHAR(100),
    precio DECIMAL(10, 2) CHECK (precio >= 0),
    stock INT CHECK (stock >= 0),
    proveedor_id INT UNIQUE
);

INSERT INTO inventario (id_producto, nombre, precio, stock, proveedor_id)
VALUES (1, 'Laptop', 850.00, 15, 101);

-- Esto fallará: precio negativo
-- INSERT INTO inventario VALUES (2, 'Mouse', -10.00, 5, 102);
```

## Ejercicio
Crea una tabla llamada 'empleados' con columnas: id (INT), nombre (VARCHAR), salario (DECIMAL) y departamento_id (INT). Aplica CHECK para que el salario sea mayor a 0 y UNIQUE para que el departamento_id no se repita en la misma fila si fuera clave, o simplemente define UNIQUE en una columna de email ficticia 'correo' (VARCHAR).

## Criterios de revisión
1. La tabla debe existir sin errores de sintaxis.
2. El CHECK debe rechazar salarios negativos.
3. El UNIQUE debe impedir insertar dos filas con el mismo correo electrónico.
4. No usar valores NULL en la columna de email para probar UNIQUE.

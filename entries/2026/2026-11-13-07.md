## Objetivo
Diferenciar el uso de PUT para reemplazar recursos completos contra PATCH para actualizaciones parciales, asegurando la integridad de datos no modificados mediante ejemplos prácticos con JavaScript.

## Explicación
En las APIs REST, los métodos HTTP definen cómo se manipulan los recursos. PUT es idempotente y requiere enviar el estado completo del recurso; si falta un campo, se pierde. PATCH, en cambio, permite actualizar solo campos específicos sin afectar el resto de la entidad. Esto es crucial para optimizar el ancho de banda y mantener datos consistentes. Imagina una API de gestión de usuarios donde actualizas solo el correo electrónico con PATCH, mientras que PUT reemplazaría toda la información del usuario si no se envían todos los campos.

## Ejemplo (no ejecutado automáticamente)
Actualización parcial de un perfil de usuario enviando solo el campo 'email' usando el método PATCH en una petición fetch.

```javascript
const response = await fetch('https://api.ejemplo.com/usuarios/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
});
```

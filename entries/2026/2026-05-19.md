## Objetivo
Comprender la organización lógica de archivos en un repositorio para facilitar el mantenimiento, la escalabilidad y la colaboración efectiva en proyectos de software.

## Explicación
Un repositorio bien diseñado separa claramente el código fuente, las dependencias, los scripts de construcción y la documentación. Esta estructura evita la polución del espacio de trabajo principal y permite un control de versiones más limpio. Se recomienda ubicar el código en una carpeta raíz o subcarpeta específica, mientras que las herramientas de desarrollo y pruebas residen en directorios aislados. Esto asegura que los cambios en la configuración no afecten accidentalmente al código productivo, promoviendo una arquitectura robusta y fácil de auditar.

## Ejemplo (no ejecutado automáticamente)
Estructura de directorios típica para un proyecto de aplicación web con separación clara entre código, pruebas y documentación.

```bash
# Estructura base del repositorio
src/
  main.py
tests/
  test_main.py
docs/
  README.md
```

## Ejercicio
Crea un directorio raíz llamado 'mi-proyecto' y dentro de él, establece tres subdirectorios: 'src', 'tests' y 'docs'. Luego, crea un archivo vacío en cada uno para simular la estructura inicial.

## Criterios de revisión
El repositorio debe tener exactamente tres subdirectorios a nivel raíz con los nombres especificados. Cada subdirectorio debe contener al menos un archivo interno. No deben existir archivos fuera de estos directorios.

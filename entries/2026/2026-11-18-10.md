## Objetivo
Aprender a configurar contenedores de dependencias para manejar versiones múltiples y evitar conflictos en aplicaciones complejas, mejorando la mantenibilidad del código.

## Explicación
En esta lección avanzamos más allá de la inyección básica. Exploraremos cómo utilizar contenedores de dependencias (como Spring Boot o módulos npm) para gestionar versiones específicas de librerías externas. Esto es crucial cuando una aplicación necesita dos versiones distintas de la misma librería en diferentes módulos. Al encapsular estas dependencias, evitamos el 'dependency hell' y aseguramos que cada componente funcione con su entorno óptimo sin afectar al resto del sistema.

## Ejemplo (no ejecutado automáticamente)
Configuración de un contenedor de dependencias para manejar versiones específicas de librerías en una aplicación modular.

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class App {
    public static void main(String[] args) {
        SpringApplication.run(App.class, args);
    }
}
```

## Ejercicio
Crea un proyecto de Spring Boot con dos módulos. En el módulo A usa la librería 'commons-lang3' versión 2.6 y en el módulo B usa la versión 3.12. Configura tu archivo pom.xml o build.gradle para incluir ambos contenedores de dependencias sin conflictos.

## Criterios de revisión
El proyecto debe compilar exitosamente con ambas versiones de la librería cargadas correctamente, demostrando que la inyección de dependencias maneja las diferencias de versión sin errores de clase.

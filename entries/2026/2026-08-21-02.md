## Objetivo
Entender cómo el aislamiento evita que una consulta lea datos modificados por otra transacción no confirmada, garantizando la consistencia de los datos en sistemas concurrentes.

## Explicación
El nivel de aislamiento 'Read Uncommitted' permite lecturas sucias, pero 'Read Committed', estándar en SQL Server y PostgreSQL, evita que una sesión lea datos modificados por otra transacción activa hasta su confirmación. Esto previene lecturas sucias donde se accede a registros borrados o actualizados antes del commit. En entornos de alta concurrencia, este mecanismo es vital para mantener la integridad referencial y evitar inconsistencias lógicas. Sin embargo, puede generar bloqueos si las transacciones son largas. Para mitigar esto, se recomienda usar niveles como 'Repeatable Read' cuando sea necesario mantener la consistencia durante múltiples lecturas de la misma consulta.

## Ejemplo (no ejecutado automáticamente)
```sql
-- Transacción A: Modifica un saldo sin confirmar
BEGIN TRANSACTION;
UPDATE cuentas SET saldo = saldo - 100 WHERE id = 1;
-- Lectura en este punto vería el cambio si fuera Read Uncommitted
SELECT saldo FROM cuentas WHERE id = 1;
COMMIT;

-- Transacción B: Lee con aislamiento Read Committed (por defecto)
BEGIN TRANSACTION;
SELECT saldo FROM cuentas WHERE id = 1;
-- No verá el cambio de la transacción A hasta que esta se confirme
COMMIT;
```

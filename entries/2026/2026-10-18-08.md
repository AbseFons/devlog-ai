## Objetivo
Aprender a configurar usuarios con permisos estrictos para evitar el acceso no autorizado a archivos sensibles, aplicando el principio de mínimo privilegio en entornos de producción Linux.

## Explicación
El principio de mínimo privilegio exige que cada usuario o proceso posea únicamente los permisos necesarios para su función específica. En un servidor web, el usuario 'www-data' debe poder leer y ejecutar scripts pero nunca escribir en carpetas críticas como '/etc'. Si este usuario tiene permisos de escritura globales, una vulnerabilidad en una aplicación podría permitir la ejecución de comandos maliciosos o la modificación de configuraciones del sistema. Para mitigar esto, se deben establecer permisos de solo lectura (444) para archivos estáticos y permisos de ejecución limitados (755) para directorios públicos. Nunca se debe conceder al usuario del servicio web acceso root ni permisos de escritura en la configuración del servidor. Esta práctica reduce la superficie de ataque, asegurando que incluso si el proceso del servidor es comprometido, el atacante no pueda escalar privilegios ni alterar el sistema operativo subyacente.

## Ejemplo (no ejecutado automáticamente)
Configuración de permisos para un directorio público y un archivo de configuración sensible en un entorno Linux usando chmod.

```bash
chmod 755 /var/www/html/uploads
chmod 644 /etc/nginx/nginx.conf
```

## Ejercicio
Crea un usuario llamado 'app_user' y asigna permisos de solo lectura a todos los archivos en '/home/app_user/data'. Asegúrate de que el grupo tenga acceso de escritura solo en una subcarpeta específica para logs.

## Criterios de revisión
El usuario no debe tener permisos de escritura en archivos de configuración del sistema. Los archivos deben ser legibles por todos pero ejecutables solo por el propietario. La carpeta de logs debe permitir escritura únicamente por el grupo 'app_group'.

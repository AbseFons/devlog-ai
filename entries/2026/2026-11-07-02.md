## Objetivo
Comprender cómo invertir las dependencias para que las clases de alto nivel no dependan de implementaciones concretas, sino de interfaces, facilitando pruebas y flexibilidad en el diseño del sistema.

## Explicación
El principio L establece que las dependencias deben invertirse: los módulos superiores dependen de abstracciones (interfaces) en lugar de concretos. Esto permite intercambiar implementaciones sin alterar la lógica principal. Por ejemplo, si un servicio de notificaciones depende de una clase concreta 'EmailSender', cambiar a 'SMS' requiere modificar el código del servicio. Con inversión, el servicio depende de la interfaz 'Notificador'. Así, se inyecta la implementación deseada desde fuera, promoviendo bajo acoplamiento y alta cohesión, esenciales para arquitecturas escalables y mantenibles.

## Ejemplo (no ejecutado automáticamente)
Clase ServicioPago que depende de una interfaz Notificador en lugar de una implementación concreta, permitiendo inyectar diferentes estrategias de notificación.

```java
public interface Notificador {
    void enviar(String mensaje);
}

public class EmailNotificador implements Notificador {
    public void enviar(String m) { System.out.println("Email: " + m); }
}

public class ServicioPago {
    private final Notificador notificador;
    public ServicioPago(Notificador n) { this.notificador = n; }
    public void procesar() { notificador.enviar("Pago exitoso"); }
}
```

## Ejercicio
Crea una interfaz 'Logger' con método log(String). Implementa dos clases: ConsoleLogger y FileLogger. Modifica una clase ServicioReporte para que reciba un Logger como constructor. Prueba inyectando ambas implementaciones.

## Criterios de revisión
El código debe usar interfaces para dependencias, no clases concretas. Debe permitir cambiar la implementación del logger sin tocar la lógica de negocio. No debe haber acoplamiento directo a implementaciones específicas.

## Objetivo
Aprender a aplicar cambios específicos de una rama remota a la actual sin fusionar todo el historial, ideal para propagar correcciones críticas o funcionalidades puntuales manteniendo la estabilidad del código base.

## Explicación
El comando git cherry-pick permite seleccionar commits individuales de otra rama y aplicarlos como nuevos commits en la rama actual. Esto es útil cuando necesitas un parche específico sin traer cambios no deseados asociados a ese commit. El proceso implica identificar el hash del commit objetivo, ejecutar el comando con esa referencia y resolver posibles conflictos de archivos si los cambios afectan las mismas líneas. Es fundamental verificar el historial resultante para asegurar que la lógica se aplicó correctamente. Este método preserva la integridad de la línea de tiempo local mientras introduce funcionalidades o arreglos puntuales de manera controlada, evitando la necesidad de una fusión completa que podría introducir ruido innecesario en el desarrollo.

## Ejemplo (no ejecutado automáticamente)
Aplicar un hotfix específico desde la rama 'release/bug-fix' a la rama principal 'main' utilizando el hash del commit correspondiente.

```bash
git cherry-pick <hash-del-commit>
# Resolver conflictos si existen editando los archivos afectados
```

## Ejercicio
Identifica un commit en una rama de prueba que contenga un arreglo de seguridad. Ejecuta cherry-pick en tu rama local y verifica que el cambio se haya aplicado correctamente sin traer otros commits.

## Criterios de revisión
El usuario debe ejecutar el comando con el hash correcto, resolver conflictos si los hay y confirmar que la versión del código incluye solo el cambio deseado.

## Objetivo
Comprender cómo dividir las tareas entre el controlador, el modelo y la vista para mantener el código limpio, escalable y fácil de probar en aplicaciones web modernas.

## Explicación
La separación de responsabilidades es un principio fundamental del diseño de software que evita que una clase o módulo haga demasiado. En el contexto de la capa de presentación, esto significa que el controlador debe encargarse exclusivamente de recibir solicitudes HTTP, validar parámetros básicos y decidir qué lógica de negocio ejecutar. El modelo se encarga de toda la lógica compleja y el acceso a datos, mientras que la vista solo debe renderizar información sin contener lógica de negocio. Esta división permite que cada parte sea independiente; si cambias cómo se calculan los precios en el modelo, no afecta al controlador ni a la plantilla HTML. Además, facilita las pruebas unitarias, ya que puedes probar la lógica del modelo aisladamente sin necesidad de montar una interfaz web completa.

## Ejemplo (no ejecutado automáticamente)
Un controlador simple que delega el cálculo de impuestos a un servicio y devuelve los datos a una vista.

```javascript
class PedidoController {
  async manejarPedido(req, res) {
    const pedido = await this.servicioCalculo.obtenerDatos(req.params.id);
    const total = await this.servicioCalculo.calcularTotal(pedido);
    return res.render('vista', { pedido, total });
  }
}
```

## Ejercicio
Crea una clase 'UsuarioController' que reciba un ID de usuario, llame a un método 'obtenerPerfil' en la clase 'UsuarioModelo' y renderice una plantilla con los datos. Asegúrate de que el controlador no contenga ninguna consulta directa a la base de datos.

## Criterios de revisión
El código debe mostrar claramente la delegación de tareas, usar inyección de dependencias o pasadores explícitos para separar responsabilidades y evitar lógica de negocio dentro del controlador.

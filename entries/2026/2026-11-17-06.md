## Objetivo
Aprender a utilizar códigos HTTP específicos para errores de validación y lógica, mejorando la legibilidad del cliente sin depender únicamente de mensajes genéricos.

## Explicación
En el diseño de APIs, los códigos de estado 4xx deben reflejar la causa raíz del fallo. Evita usar 500 para errores de validación del usuario; en su lugar, emplea 400 Bad Request con detalles específicos. Por ejemplo, si un campo es obligatorio pero vacío, usa 422 Unprocessable Entity o 400 con el mensaje 'missing_field'. Esto permite que los clientes humanos y máquinas procesen la respuesta correctamente sin asumir fallos del servidor.

## Ejemplo (no ejecutado automáticamente)
Respuesta JSON de error para un campo obligatorio faltante en una solicitud de creación de usuario.

```javascript
const response = {
  status: 400,
  message: 'Falta el campo email',
  errors: { email: [ 'El campo es requerido' ] }
};
```

## Ejercicio
Crea una función que devuelva un objeto de error con código 422 cuando la suma de dos números negativos exceda un límite permitido.

## Criterios de revisión
El código debe incluir el campo 'status' igual a 422, un mensaje descriptivo en español y un array de errores detallando qué condición falló.

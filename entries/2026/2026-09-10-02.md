## Objetivo
Comprender el concepto de idempotencia en APIs REST y cómo diseñar endpoints que produzcan resultados consistentes ante múltiples solicitudes idénticas, evitando efectos secundarios no deseados como duplicidad de registros o cobros erróneos.

## Explicación
La idempotencia asegura que ejecutar una operación múltiple con los mismos parámetros genere el mismo resultado final que ejecutarla una sola vez. En APIs REST, las operaciones GET y PUT suelen ser idempotentes por diseño, mientras que POST y DELETE no lo son inherentemente. Para implementar idempotencia en métodos no seguros como POST, se utiliza un encabezado 'Idempotency-Key'. El servidor almacena esta clave y el resultado de la operación; si recibe una solicitud con la misma clave, devuelve inmediatamente el resultado almacenado sin reejecutar la lógica. Esto es crucial en entornos distribuidos donde las redes pueden causar retransmisiones de paquetes.

## Ejemplo (no ejecutado automáticamente)
Implementación de un endpoint POST idempotente usando encabezados personalizados para prevenir duplicidad de transacciones.

```javascript
const handlePayment = async (req, res) => {
  const key = req.headers['idempotency-key'];
  if (!key) return res.status(400).json({ error: 'Missing idempotency-key' });
  const cached = await db.get(key);
  if (cached) return res.json(cached); // Devuelve respuesta guardada
  const result = await processPayment(req.body);
  await db.set(key, result);
  return res.json(result);
};
```

## Ejercicio
Crea un endpoint POST que procese la creación de una cuenta de usuario. Implementa lógica para verificar si el email ya existe antes de insertar en la base de datos. Añade un encabezado 'Idempotency-Key' opcional: si se proporciona y coincide con una operación previa, responde con el estado 200 OK y los datos del usuario creado sin ejecutar la inserción nuevamente.

## Criterios de revisión
El endpoint debe devolver 409 Conflict si el email ya existe. Debe almacenar el resultado de la operación exitosa asociado a la clave idempotente. La respuesta ante una segunda solicitud con la misma clave debe ser idéntica a la primera, sin generar registros duplicados en la base de datos.

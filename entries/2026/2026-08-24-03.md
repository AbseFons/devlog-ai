## Objetivo
Al finalizar esta lección, el desarrollador identificará cómo la concatenación directa de strings en consultas SQL permite a atacantes alterar la lógica de la base de datos. Comprenderá el mecanismo básico de la inyección y reconocerá la necesidad imperativa de utilizar parámetros o prepared statements para construir aplicaciones seguras desde su núcleo.

## Explicación
La inyección SQL ocurre cuando una aplicación toma datos no confiables del usuario e incorpora directamente esos datos en una consulta SQL sin validarlos ni sanitizarlos. Si un desarrollador concatena strings, como 'SELECT * FROM usuarios WHERE nombre = ' + input_usuario, cualquier entrada especial puede romper la sintaxis de la consulta. Un atacante podría ingresar "admin' OR '1'='1" para el campo de nombre. Esto transforma la consulta legítima en una que devuelve todos los registros, ya que la condición se vuelve siempre verdadera. Este error convierte a la aplicación en un punto de entrada directo para robar datos sensibles, modificar registros o ejecutar comandos maliciosos dentro del motor de base de datos.

## Ejemplo (no ejecutado automáticamente)
```python
# VULNERABLE: Concatenación directa de inputs
usuario = input("Ingresa tu nombre:")
password = input("Ingresa tu contraseña:")

query = f"SELECT * FROM usuarios WHERE nombre = '{usuario}' AND password = '{password}'"
cursor.execute(query)
```

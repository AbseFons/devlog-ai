## Objetivo
Aprender a seleccionar y aplicar un commit individual de una rama remota o local sin fusionar todo su historial, manteniendo la integridad del flujo de trabajo actual.

## Explicación
El comando git cherry-pick permite extraer los cambios contenidos en uno o varios commits específicos y aplicarlos como nuevos commits en tu rama actual. Esto es útil cuando deseas integrar una corrección crítica o una funcionalidad puntual sin traer el resto de cambios no deseados de la rama origen. El proceso implica identificar el hash del commit deseado, ejecutar el comando y resolver posibles conflictos si los archivos modificados son comunes entre las ramas. Es fundamental verificar que el commit seleccionado sea seguro antes de aplicarlo, ya que cherry-pick puede generar divergencias en el historial si no se usa con precaución.

## Ejemplo (no ejecutado automáticamente)
Seleccionar y aplicar un commit específico para corregir un bug sin fusionar la rama completa.

```bash
git cherry-pick abc123456789
# Si hay conflictos, edita los archivos afectados y ejecuta:
git cherry-pick --continue
```

## Ejercicio
En una rama de desarrollo, identifica un commit que arregla un error de seguridad en la librería de autenticación. Usa cherry-pick para aplicar solo ese cambio a tu rama principal.

## Criterios de revisión
El usuario debe ejecutar correctamente el comando con el hash del commit, resolver conflictos si los hay y confirmar que el nuevo commit aparece en el historial local sin incluir otros cambios no deseados.

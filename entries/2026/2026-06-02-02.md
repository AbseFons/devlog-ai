## Objetivo
Comprender el nivel de aislamiento READ COMMITTED y cómo prevenir lecturas sucias mediante transacciones ACID, asegurando la integridad de los datos concurrentes.

## Explicación
En este nivel de aislamiento, una transacción solo lee datos que ya han sido confirmados por otras. Esto evita las lecturas sucias (dirty reads), donde se accede a datos no guardados. Sin embargo, puede permitir lecturas no repetibles y fantasmas. Para implementar esto en SQL, se utiliza la directiva SET TRANSACTION ISOLATION LEVEL READ COMMITTED dentro del bloque de transacción. Este enfoque es el predeterminado en muchas bases de datos como PostgreSQL y SQL Server, ofreciendo un equilibrio entre consistencia y rendimiento al permitir que otras sesiones escriban mientras se lee, pero garantizando que lo leído sea persistente.

## Ejemplo (no ejecutado automáticamente)
Se define una transacción con aislamiento READ COMMITTED para evitar leer datos no confirmados en una base de datos SQL.

```sql
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
BEGIN TRANSACTION;
SELECT * FROM cuentas WHERE id = 100;
```

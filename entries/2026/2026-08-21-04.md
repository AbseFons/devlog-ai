## Objetivo
El desarrollador podrá diseñar un sistema de autenticación básico que utilice roles predefinidos para restringir operaciones sensibles, evitando la exposición de datos críticos mediante la aplicación correcta de permisos en el nivel de código.

## Explicación
El Control de Acceso Basado en Roles (RBAC) organiza los permisos alrededor de funciones laborales en lugar de usuarios individuales. En esta microlección, exploraremos cómo estructurar una clase de servicio que verifique si un usuario posee el rol necesario antes de ejecutar una acción crítica. Este enfoque centraliza la lógica de seguridad y reduce errores humanos al asignar permisos. Implementaremos una matriz de permisos simple donde cada método del servicio consulta el rol del sujeto actual contra una lista blanca autorizada. Es fundamental validar siempre la identidad del usuario en cada solicitud, incluso si proviene de un origen interno, para prevenir ataques de elevación de privilegios o inyección de credenciales maliciosas.

## Ejemplo (no ejecutado automáticamente)
```python
class SecureService:
    def __init__(self):
        self.roles = {'admin': ['read', 'write', 'delete'], 'user': ['read']}

    def check_permission(self, user_role, action):
        return action in self.roles.get(user_role, [])

    def delete_record(self, user_role, record_id):
        if not self.check_permission(user_role, 'delete'):
            raise PermissionError('Acceso denegado: falta permisos de escritura.')
        # Lógica segura de eliminación aquí
        return f'Rec {record_id} eliminado por {user_role}'
```

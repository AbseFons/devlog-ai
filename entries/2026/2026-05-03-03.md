## Objetivo
Comprender la diferencia entre comandos y eventos en DDD, identificando cómo los eventos comunican hechos ocurridos que alteran el estado del sistema sin invocar acciones directas.

## Explicación
En el Diseño Orientado a Eventos de Dominio, distinguimos claramente entre Comandos (acciones solicitadas) y Eventos (hechos ocurridos). Un evento representa un cambio irreversible en el dominio. Por ejemplo, cuando se crea una orden, emitimos el evento 'OrdenCreada'. Este evento no ejecuta lógica de negocio adicional por sí mismo, sino que notifica a otros agregados o servicios interesados para que reaccionen, como actualizar el inventario o enviar un correo. Esta separación permite desacoplar las partes del sistema y mantener una narrativa clara de lo que sucedió en el dominio.

## Ejemplo (no ejecutado automáticamente)
Se define una clase Event que representa la creación de una orden, incluyendo datos como ID y monto, lista para ser publicada por un agregado raíz.

```csharp
public record OrderCreatedEvent(Guid orderId, decimal amount);

public class OrderAggregate {
    public void CreateOrder(decimal amount) {
        // Lógica de creación
        Raise(new OrderCreatedEvent(Guid.NewGuid(), amount));
    }
}
```

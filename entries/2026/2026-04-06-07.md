## Objetivo
Aprender a seleccionar y aplicar commits individuales desde otra rama sin fusionar todo el historial, manteniendo la integridad del flujo de trabajo en reposos compartidos.

## Explicación
El comando git cherry-pick permite extraer un commit específico de una rama remota o local y aplicarlo como nuevo commit en la rama actual. Esto es útil cuando necesitas aplicar una corrección puntual sin traer cambios no deseados. El proceso implica identificar el hash del commit deseado usando git log, luego ejecutar git cherry-pick <hash>. Es crucial verificar que no haya conflictos de archivos antes de confirmar la operación. Si surgen conflictos, Git los marcará y se deberá resolver manualmente antes de finalizar el cherry-pick. Esta técnica preserva la historia limpia de la rama objetivo mientras incorpora funcionalidades o arreglos específicos.

## Ejemplo (no ejecutado automáticamente)
Seleccionar un commit de corrección de seguridad desde una rama de hotfix y aplicarlo a la rama principal sin fusionar todo el historial.

```bash
git log --oneline
hash=$(git rev-parse HEAD~2)
git cherry-pick $hash
```

## Ejercicio
En un repositorio local con dos ramas, 'main' y 'feature', identifica el último commit de 'feature' que arregla un bug crítico. Usa git cherry-pick para aplicar ese cambio específico a 'main'. Resuelve cualquier conflicto de archivos manualmente si surge.

## Criterios de revisión
El usuario debe ejecutar correctamente el comando con el hash adecuado, resolver conflictos si los hay y confirmar la creación del nuevo commit en la rama objetivo.

## Objetivo
Aprender a configurar ramas principales como protegidas en Git Flow, evitando fusiones directas y fomentando la revisión de código mediante pull requests antes de integrar cambios en el trunk principal del proyecto.

## Explicación
En entornos profesionales, la rama principal (main o master) debe estar protegida para evitar fusiones accidentales. La estrategia consiste en crear una rama de desarrollo desde main, realizar los cambios y abrir un pull request. Este mecanismo obliga a revisar el código antes de integrarlo. Configura permisos en tu repositorio para desactivar la escritura directa en main. Esto garantiza estabilidad y calidad del software.

## Ejemplo (no ejecutado automáticamente)
Configuración de protección de rama y creación de pull request

```bash
# Crear rama de desarrollo
feature-usuario-login = git checkout -b feature-usuario-login
# Realizar cambios y subir al remoto
git add . && git commit -m 'Añadir login'
git push origin feature-usuario-login
# Abrir PR en la interfaz del repositorio
```

## Ejercicio

## Criterios de revisión
Debe existir la rama creada, tener al menos un commit y no intentar fusionar directamente a main sin usar pull request.

## Objetivo
Comprender cómo la propiedad de consistencia garantiza que una transacción deje el sistema en un estado válido, revertiendo cambios si ocurren errores lógicos o técnicos durante su ejecución.

## Explicación
La consistencia asegura que cada transacción transforme el estado de la base de datos desde otro estado consistente a otro. Si una operación falla, como una división por cero o falta de espacio en disco, el motor de base de datos debe abortar toda la transacción para evitar corrupción de datos. Esto implica revertir cualquier cambio parcial realizado previamente en la misma unidad de trabajo. El sistema no puede dejar al usuario con datos intermedios que violen las reglas de integridad definidas por esquemas o restricciones. Por ello, el control de errores es fundamental dentro del bloque de transacción para asegurar que solo los cambios completos y válidos persistan.

## Ejemplo (no ejecutado automáticamente)
Script SQL que intenta transferir fondos insuficientes, demostrando cómo la base de datos aborta la transacción completa al detectar violación de integridad referencial o lógica.

```sql
BEGIN TRANSACTION;
UPDATE cuentas SET saldo = saldo - 500 WHERE id = 1;
UPDATE cuentas SET saldo = saldo + 500 WHERE id = 2;
-- Simula error: UPDATE falla por saldo insuficiente
ROLLBACK;
COMMIT;
```

## Ejercicio
Crea una transacción SQL que intente actualizar dos tablas relacionadas. Introduce deliberadamente un error lógico (por ejemplo, intentar dividir por cero en una vista o violar una clave foránea) y observa cómo el sistema ejecuta ROLLBACK automáticamente.

## Criterios de revisión
El código debe iniciar con BEGIN TRANSACTION, contener al menos dos sentencias UPDATE o INSERT, incluir una condición que provoque un error lógico y finalizar con ROLLBACK. No se permite COMMIT si la transacción no fue exitosa.

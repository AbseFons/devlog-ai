## Objetivo
Aprender a identificar vulnerabilidades en librerías externas mediante escaneo automático, interpretar reportes de CVE y aplicar parches o mitigaciones inmediatas para proteger la integridad del software.

## Explicación
Las dependencias de terceros son una fuente común de riesgos de seguridad. Un CVE (Common Vulnerabilities and Exposures) describe una vulnerabilidad específica. Para gestionar estos riesgos, los ingenieros deben integrar herramientas de escaneo en su CI/CD. Este proceso detecta versiones obsoletas o con CVEs conocidos antes del despliegue. Al encontrar un problema, se evalúa la criticidad: si es alta, se actualiza la dependencia; si es baja y no tiene parche inmediato, se implementan reglas de firewall o código seguro para mitigar el impacto. La documentación de estos hallazgos es vital para la auditoría continua.

## Ejemplo (no ejecutado automáticamente)
Script que usa npm audit para escanear un proyecto Node.js y listar vulnerabilidades críticas con su ID CVE asociado.

```bash
npm install -g npm-audit-report
npm audit --audit-level=high | grep -E 'CVE-|HIGH'
```

## Ejercicio
Instala una librería vulnerable en un proyecto de prueba, ejecuta el comando de escaneo y documenta al menos dos CVE encontrados junto con su nivel de riesgo.

## Criterios de revisión
El reporte debe incluir el ID del CVE, la versión afectada, la acción tomada (actualización o mitigación) y una justificación técnica de por qué esa decisión protege la aplicación.

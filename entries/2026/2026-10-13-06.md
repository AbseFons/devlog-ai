## Objetivo
Aprender a diseñar casos de prueba que cubran no solo el camino feliz, sino también los límites exactos de entrada y condiciones de error para garantizar la robustez del software ante datos inesperados.

## Explicación
La cobertura de pruebas efectiva va más allá de ejecutar código; implica validar explícitamente los bordes de los rangos de entrada. Un sistema puede fallar catastróficamente si recibe un valor justo por encima o por debajo del límite permitido, aunque el camino central funcione perfectamente. Es crucial definir las condiciones de frontera: ¿Qué ocurre con un entero negativo en un campo que solo acepta positivos? ¿Cómo se comporta la aplicación ante una cadena vacía cuando espera texto obligatorio? El objetivo es identificar estos puntos críticos antes de que lleguen a producción. Al probar los límites, simulamos el comportamiento real del usuario que intenta explotar fallos o cometer errores comunes. Esta estrategia reduce la deuda técnica y previene incidentes en entornos de alta disponibilidad.

## Ejemplo (no ejecutado automáticamente)
Función que valida un rango numérico entre 1 y 100, probando valores exactos en los límites, uno por encima y uno por debajo para verificar manejo de errores.

```javascript
function validarRango(valor) {
  if (valor < 1 || valor > 100) return false;
  return true;
}
console.log(validarRango(1)); // true
console.log(validarRango(100)); // true
console.log(validarRango(101)); // false
```

## Ejercicio
Crea una función en Python que acepte una lista de nombres y devuelva solo los que tengan entre 3 y 15 caracteres. Prueba con nombres de exactamente 3, 15, 2, 16 caracteres y una cadena vacía.

## Criterios de revisión
El código debe incluir la función definida, al menos cinco llamadas a dicha función con datos de borde específicos (límite inferior, límite superior, fuera de rango por abajo, fuera de rango por arriba, vacío) y los resultados deben coincidir exactamente con las reglas establecidas.

## Objetivo
Comprender la distinción fundamental entre mocks y stubs para escribir pruebas unitarias más limpias, controladas y enfocadas en la lógica del sistema bajo prueba.

## Explicación
En ingeniería de software, los stubs son respuestas predefinidas que simulan el comportamiento de dependencias externas sin verificar cómo se invocaban. Son útiles cuando solo necesitas un resultado específico para probar una rama de código. Por otro lado, los mocks son objetos simulados que no solo responden, sino que también verifican si se les llamó con los argumentos correctos y la frecuencia esperada. Esto permite detectar acoplamientos ocultos o uso incorrecto de APIs. Elegir el adecuado depende del nivel de control que requieras: usa stubs para probar flujos simples y mocks cuando la interacción misma es parte de la lógica a validar.

## Ejemplo (no ejecutado automáticamente)
Un stub en JavaScript que devuelve un valor fijo sin importar los argumentos recibidos, simulando una llamada a una API externa.

```javascript
const apiStub = () => ({ id: 1, nombre: 'Usuario Ejemplo' });
const resultado = apiStub(); // Siempre devuelve el mismo objeto
```

## Ejercicio
Crea una función en Python que utilice un stub para simular una base de datos y luego modifica ese stub para que verifique los argumentos recibidos, comportándose como un mock.

## Criterios de revisión
El código debe incluir dos funciones distintas: una que usa un stub simple y otra que valida los parámetros de entrada antes de devolver un valor.

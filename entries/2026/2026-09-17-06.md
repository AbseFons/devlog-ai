## Objetivo
Aprender a identificar y resolver manualmente conflictos de código durante una operación de merge, asegurando la integridad del historial y manteniendo el control sobre los cambios integrados sin perder datos locales.

## Explicación
Cuando Git detecta un conflicto, detiene el proceso y marca las líneas afectadas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, debes abrir el archivo en tu editor de texto preferido. Lee cuidadosamente ambos bloques: el tuyo (actual) y el del compañero o rama remota. Decide qué lógica es correcta: ¿debes conservar solo tus cambios?, ¿solo los del otro?, ¿o combinarlos? Una vez editado, guarda el archivo eliminando los marcadores de conflicto. Git no integrará automáticamente la solución; tú debes confirmar manualmente que el resultado es funcional. Ejecuta 'git add' para marcar el archivo como resuelto y luego completa el merge con 'git commit'. Esta práctica manual previene errores sutiles que un merge automático podría ocultar.

## Ejercicio
Crea dos ramas en tu repositorio local: 'feature-a' que modifique la función de autenticación y 'feature-b' que cambie la validación de correos. Realiza un merge manual desde ambas ramas hacia 'main'. Identifica los archivos con conflictos, edita uno manualmente combinando las lógicas de validación y seguridad, y completa el merge.

## Criterios de revisión
El archivo modificado debe contener la lógica de autenticación y validación sin marcadores de conflicto. El historial de Git debe reflejar un commit de resolución manual con mensaje claro indicando qué se combinó. No deben existir errores de sintaxis en el archivo resultante.

## Objetivo
Entender que la idempotencia garantiza que múltiples solicitudes idénticas produzcan el mismo efecto único, protegiendo contra redirecciones o reintentos accidentales. Al finalizar, podrás diseñar endpoints seguros que ignoren repeticiones legítimas de peticiones POST sin corrupción de datos ni efectos secundarios no deseados en la lógica de negocio.

## Explicación
La idempotencia asegura que ejecutar una operación múltiples veces sea equivalente a ejecutarla una sola vez. En APIs REST, los métodos GET son idempotentes por defecto, pero POST y PUT requieren diseño explícito para evitar duplicidad de transacciones. Esto es crítico en redes inestables donde los clientes reenvían peticiones fallidas. Para lograrlo, se implementan cabeceras como Idempotency-Key que permiten al servidor rastrear y rechazar solicitudes repetidas con el mismo identificador, manteniendo la consistencia del estado sin sobrecargar la base de datos o generar registros duplicados en sistemas financieros.

## Ejemplo (no ejecutado automáticamente)
```python
from flask import Flask, request, jsonify
import hashlib

app = Flask(__name__)
request_log = {}

@app.route('/transfer', methods=['POST'])
def transfer():
    key = request.headers.get('Idempotency-Key')
    if not key:
        return jsonify({'error': 'Missing Idempotency-Key'}), 400
    
    if key in request_log:
        return jsonify(request_log[key]), 200
    
    # Simular lógica de transferencia
    result = {'status': 'success', 'amount': 100}
    request_log[key] = result
    return jsonify(result), 201
```

## Objetivo
Comprender la estructura interna de un repositorio Git, identificando los roles clave de HEAD, refs y objetos para gestionar el historial de manera eficiente.

## Explicación
Un repositorio Git no es solo una carpeta con archivos; es una base de datos distribuida. Al inicializar un proyecto con 'git init', se crea un directorio oculto llamado .git. Este contiene la referencia HEAD, que apunta a la rama actual (normalmente main o master). Las refs almacenan los punteros a los commits específicos. Los objetos son las unidades atómicas de datos: blobs para contenido de archivos, árboles para la estructura de directorios y commits para los metadatos del historial. Entender esta arquitectura permite realizar operaciones avanzadas como rebase interactivo o recuperación de datos eliminados accidentalmente sin depender de servidores remotos.

## Ejemplo (no ejecutado automáticamente)
Comandos para inspeccionar la estructura interna de un repositorio Git recién creado y verificar los objetos almacenados.

```bash
mkdir mi-proyecto && cd mi-proyecto
git init
ls -la .git/refs/heads/
find .git/objects -type f | head -5
```

## Ejercicio
Crea un repositorio vacío, haz un commit inicial con un archivo README.md y luego ejecuta los comandos del ejemplo para listar las referencias de rama y los primeros objetos almacenados.

## Criterios de revisión
El usuario debe demostrar que comprende la diferencia entre el árbol de trabajo y el directorio .git, identificando correctamente HEAD como una referencia móvil a la última commit.

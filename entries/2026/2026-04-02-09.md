## Objetivo
Diferenciar claramente entre autenticación (quién eres) y autorización (qué puedes hacer). Comprender que la primera valida identidad mediante tokens, mientras la segunda aplica políticas de acceso a recursos específicos dentro de una aplicación.

## Explicación
En el desarrollo de APIs, es crucial distinguir dos conceptos fundamentales. La autenticación responde a '¿Quién eres?' y verifica la identidad del usuario, usualmente mediante credenciales o tokens como JWT. Por otro lado, la autorización responde a '¿Qué puedes hacer?' y determina los permisos específicos sobre recursos protegidos. Un error común es confundir ambos: tener acceso al sistema (autenticado) no implica poder borrar datos críticos (no autorizado). Las APIs modernas implementan esta lógica en capas: primero validan el token de autenticación, luego consultan una lista de roles o scopes para decidir si permiten la operación solicitada. Esta separación garantiza seguridad robusta y principios de mínimo privilegio.

## Ejemplo (no ejecutado automáticamente)
Un script que simula una respuesta de API mostrando cómo un token válido permite leer datos pero deniega la eliminación por falta de permisos.

```javascript
const user = { id: 123, role: 'editor' };
const resource = { id: 456, owner: 999 };
if (user.role === 'admin') {
  console.log('Acceso total permitido');
} else if (resource.owner === user.id) {
  console.log('Puedes editar tus propios recursos');
} else {
  console.log('Error 403: No tienes autorización para este recurso');
}
```

## Ejercicio
Crea una función en JavaScript que reciba un objeto de usuario y un ID de recurso. Devuelve 'PERMITIDO' si el usuario es administrador o si el ID del recurso coincide con el ID del usuario. De lo contrario, devuelve 'DENEGADO'.

## Criterios de revisión
El código debe manejar correctamente la lógica condicional para distinguir entre rol de administrador y propiedad del recurso. La función no debe arrojar errores si los IDs son números válidos.

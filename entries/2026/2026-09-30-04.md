## Objetivo
Diferenciar conceptualmente y operativamente el uso de merge y rebase en Git, entendiendo cuándo preservar la historia lineal versus mantener una estructura ramificada clara para colaboraciones efectivas.

## Explicación
Merge crea un nuevo commit que fusiona dos ramas, preservando exactamente la historia de desarrollo con todos los puntos de bifurcación. Es ideal para flujos de trabajo donde el historial debe reflejar fielmente las decisiones de rama. Rebase, por el contrario, reescribe la línea temporal moviendo commits locales a la punta de la rama remota, creando una historia lineal y limpia. Úsalo solo en ramas locales no compartidas para evitar conflictos de historial en equipos.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un rebase local antes de pushear cambios a una rama remota.

```bash
git checkout feature-branch
git pull --rebase origin main
```

## Ejercicio
Realiza un rebase en tu rama local 'feature-login' sobre la rama remota 'main'. Verifica que los commits se hayan movido visualmente y no haya conflictos de historial.

## Criterios de revisión
1. El comando debe ejecutarse sin errores.
2. La historia de commits debe aparecer lineal después del rebase.
3. No deben existir commits duplicados en la rama remota.

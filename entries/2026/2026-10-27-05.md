## Objetivo
Aprender a aplicar roles y permisos en una API mediante middleware para proteger recursos sensibles sin exponer lógica interna ni credenciales, asegurando que solo usuarios autorizados accedan a datos críticos.

## Explicación
El Control de Acceso basado en Roles (RBAC) permite gestionar quién puede hacer qué dentro de un sistema. En esta microlección, implementaremos un middleware en Node.js que intercepta las solicitudes HTTP, verifica el rol del usuario autenticado y decide si permitir o denegar el acceso a una ruta específica. Este enfoque centraliza la lógica de seguridad, evitando repetir validaciones en cada controlador. Es crucial definir roles granulares (ej. 'analista', 'admin') y asignar permisos explícitos para cada recurso. Nunca se deben confiar en los datos del cliente; siempre validar desde el servidor. Además, es buena práctica registrar intentos fallidos de acceso para auditoría futura sin exponer detalles técnicos sensibles en los mensajes de error.

## Ejemplo (no ejecutado automáticamente)
Middleware que verifica si el usuario tiene el rol 'admin' antes de permitir el acceso a la ruta /api/admin/dashboard.

```javascript
const checkAdmin = (req, res, next) => {
  if (req.user && req.user.role === 'admin') { return next(); }
  res.status(403).json({ error: 'Acceso denegado' });
};
```

## Criterios de revisión
El código debe usar la estructura de middleware estándar (req, res, next). Debe devolver un estado 403 con mensaje genérico al denegar acceso. No debe incluir credenciales ni lógica destructiva. La función checkEditor debe aceptar roles múltiples.

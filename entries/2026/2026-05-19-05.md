## Objetivo
Comprender la diferencia entre cobertura de código y límites funcionales, aprendiendo a diseñar casos de prueba que validen no solo el camino feliz sino también los bordes críticos del sistema.

## Explicación
La cobertura de código mide qué porcentaje del fuente se ejecuta durante las pruebas, pero esto no garantiza que el sistema funcione correctamente en todos los escenarios. Un sistema puede tener 100% de cobertura y aún fallar si no se prueban los límites de entrada o condiciones de error específicas. Por ello, es vital complementar la cobertura con pruebas de frontera (boundary value analysis) y casos de uso realistas que simulen comportamientos extremos.

## Ejemplo (no ejecutado automáticamente)
Función que calcula el descuento aplicable a un producto según su precio y categoría, validando límites de precios negativos y categorías inválidas.

```javascript
function calcularDescuento(precio, categoria) {
  if (precio < 0 || !['A', 'B', 'C'].includes(categoria)) throw new Error('Datos inválidos');
  return precio * 0.9;
}
```

## Ejercicio
Escribe una suite de pruebas para la función anterior que incluya: un caso con precio positivo y categoría válida, un caso con precio negativo, y un caso con categoría no reconocida.

## Criterios de revisión
La suite debe ejecutar al menos tres casos de prueba distintos. Cada caso debe tener una descripción clara del dato de entrada esperado y el resultado correcto o el error lanzado.

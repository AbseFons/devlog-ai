## Objetivo
Aprender a dividir las funciones de lectura y escritura de datos para mejorar la mantenibilidad, facilitar pruebas unitarias y evitar efectos secundarios no deseados dentro del mismo módulo de acceso a datos.

## Explicación
El principio de separación de responsabilidades en el diseño de software dicta que cada módulo debe tener un único propósito. En el contexto de una capa de datos, esto implica dividir explícitamente las operaciones de lectura (SELECT) de las de escritura (INSERT, UPDATE, DELETE). Al encapsular estas lógicas en funciones distintas, se logra que el código sea más legible y testeable. Por ejemplo, una función dedicada a obtener un usuario por ID no debe contener la lógica para crear uno nuevo. Esta abstracción permite reemplazar fácilmente la implementación de la base de datos sin afectar al resto del sistema, cumpliendo con el principio de inversión de dependencias.

## Ejemplo (no ejecutado automáticamente)
Definición de funciones separadas para obtener y guardar un usuario en una estructura de datos simulada.

```javascript
function obtenerUsuario(id) {
  return usuarios[id];
}

function guardarUsuario(datos) {
  const id = datos.id || Date.now().toString();
  usuarios[id] = datos;
  return usuarios[id];
}
```

## Ejercicio
Crea una función 'eliminarUsuario' que acepte un ID y remueva la entrada del objeto global 'usuarios'. Asegúrate de que esta función no realice ninguna validación de negocio, solo la eliminación técnica.

## Criterios de revisión
El código debe tener tres funciones distintas: obtener, guardar y eliminar. Cada una debe manipular el objeto 'usuarios' de forma exclusiva sin mezclar lógica de lectura con escritura. No deben existir comentarios explicativos dentro del bloque de código.

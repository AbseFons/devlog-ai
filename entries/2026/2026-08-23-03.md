## Objetivo
Al finalizar esta lección, el desarrollador podrá distinguir conceptualmente entre mocks y stubs, identificar cuándo utilizar cada uno para aislar dependencias externas y aplicar patrones de inyección de dependencias básicos sin comprometer la integridad del código bajo prueba.

## Explicación
En ingeniería de pruebas unitarias, los stubs son datos falsos predefinidos que simulan el comportamiento de una dependencia externa para evitar llamadas reales a bases de datos o APIs. Los mocks, en cambio, son objetos simulados que verifican si se les llamó y con qué argumentos, permitiendo validar interacciones complejas. Confundir ambos conceptos lleva a pruebas frágiles. Usa stubs cuando solo necesitas un valor de retorno simple para probar la lógica del módulo principal. Emplea mocks cuando el comportamiento de la dependencia es crítico para el flujo de negocio o debes asegurar que se invocó un método específico con los parámetros correctos. Esta distinción garantiza que las pruebas sean rápidas, deterministas y fáciles de mantener.

## Ejemplo (no ejecutado automáticamente)
```python
from unittest.mock import Mock, patch

def procesar_pedido(pago_gateway):
    if pago_gateway.pagar(100):
        return 'Pedido completado'
    return 'Pago fallido'

# Stub: Simula un valor de retorno simple sin verificar llamadas
pago_stub = Mock(return_value=True)
resultado = procesar_pedido(pago_stub)
assert resultado == 'Pedido completado'

# Mock con verificación: Asegura que pagar fue llamado con 100
with patch('mi_modulo.PagoGateway.pagar') as mock_pagar:
    mock_pagar.return_value = False
    assert procesar_pedido(mock_pagar) == 'Pago fallido'
    mock_pagar.assert_called_once_with(100)
```

## Ejercicio
Crea una función que calcule el total de un carrito. Implementa un stub para simular la llamada a una API de impuestos y otro mock para verificar que la función intenta restar el cupón solo si el usuario es premium.

## Criterios de revisión
El código debe usar Mock y Stub correctamente, no hacer llamadas reales a APIs externas, incluir aserciones claras sobre los argumentos pasados y manejar casos de error sin lanzar excepciones inesperadas.

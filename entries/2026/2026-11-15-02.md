## Objetivo
Aprender a reducir el tamaño de las imágenes Docker eliminando dependencias de compilación innecesarias en la imagen final, mejorando tiempos de despliegue y seguridad.

## Explicación
En esta lección exploramos los multi-stage builds, una técnica avanzada para crear imágenes ligeras. Consiste en definir múltiples etapas dentro del mismo archivo Dockerfile: una primera etapa utiliza herramientas pesadas como compiladores o SDKs para construir la aplicación, y una segunda etapa limpia solo las binarias resultantes y el código fuente. Al usar un comando COPY desde la etapa anterior, se asegura que la imagen final contenga únicamente lo estrictamente necesario para ejecutar el servicio. Esto reduce drásticamente el tamaño de la imagen, acelera los despliegues en CI/CD y minimiza la superficie de ataque al excluir herramientas de desarrollo no requeridas en producción.

## Ejemplo (no ejecutado automáticamente)
Creación de una imagen optimizada para un servidor web Node.js que elimina las dependencias de compilación del runtime final.

```bash
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build

FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/node_modules ./node_modules
EXPOSE 3000
CMD ["node", "dist/index.js"]
```

## Ejercicio
Crea un Dockerfile para una aplicación Python que utilice pip para instalar dependencias en una etapa de construcción y luego copie solo el código compilado o los archivos .py optimizados a una imagen base slim, asegurando que la imagen final no contenga herramientas de desarrollo como gcc.

## Criterios de revisión
La imagen resultante debe tener un tamaño inferior al 50% comparada con una imagen estándar que incluye todo. El Dockerfile debe contener claramente dos etapas diferenciadas por el comando AS. La etapa final solo debe ejecutar la aplicación sin incluir archivos temporales de construcción.

## Objetivo
Aprender a aplicar el principio de mínimo privilegio configurando roles específicos en un entorno de nube, limitando el acceso solo a los recursos necesarios para una tarea concreta y evitando la concesión de permisos administrativos generales.

## Explicación
El principio de mínimo privilegio exige que cada identidad o servicio tenga únicamente las autorizaciones estrictamente necesarias. En entornos cloud, esto se logra definiendo políticas de IAM detalladas en lugar de usar roles 'admin'. Por ejemplo, un servicio de procesamiento de imágenes no necesita acceso a la consola ni a bases de datos; solo requiere permisos de lectura/escritura sobre un bucket específico y ejecución de funciones Lambda. Al fragmentar los privilegios, se reduce la superficie de ataque: si una cuenta es comprometida, el daño está contenido. Además, facilita la auditoría y el cumplimiento normativo al poder rastrear quién accedió a qué recurso exacto. La implementación requiere mapear cada flujo de trabajo y asignar políticas granulares, evitando patrones de 'todo o nada'.

## Ejemplo (no ejecutado automáticamente)
Definición de una política IAM en AWS que otorga acceso de lectura/escritura a un único bucket S3 para un servicio Lambda específico.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject", "s3:PutObject"],
    "Resource": "arn:aws:s3:::mi-bucket-procesamiento/*"
  }]
}
```

## Ejercicio
Crea una política IAM similar para un servicio de notificaciones que solo pueda enviar correos a un dominio corporativo específico mediante SMTP.

## Criterios de revisión
La política debe restringir la acción 'SendEmail' exclusivamente al dominio 'empresa.com' y no permitir acceso a otros recursos o acciones de correo.

## Objetivo
Distinguir conceptualmente entre merge y rebase en Git, entendiendo cómo cada comando afecta la historia del repositorio y cuándo utilizar uno u otro para mantener un historial limpio o preservar relaciones de ramificación.

## Explicación
Merge crea un nuevo commit que fusiona dos ramas, preservando el historial original con una estructura en forma de Y. Esto refleja fielmente el flujo de trabajo colaborativo donde los desarrolladores trabajan en paralelo. Rebase, por otro lado, reescribe la historia moviendo los commits de la rama actual para que parezcan haber sido hechos después del merge, resultando en una línea recta. Merge es seguro y preferible para ramas compartidas; rebase debe usarse con precaución en ramas locales para limpiar el historial antes de un push.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para crear dos ramas, hacer cambios y ejecutar merge versus rebase localmente.

```bash
git checkout main
git pull origin main
git checkout feature-a
echo 'feature a' >> README.md
git commit -m 'Add feature A'
git checkout feature-b
echo 'feature b' >> README.md
git commit -m 'Add feature B'
git checkout main
git merge feature-a
git rebase feature-a
```

## Ejercicio
Crea una rama, haz un commit y vuelve a la rama principal. Intenta hacer un merge de tu rama local y luego intenta un rebase sobre el mismo historial local.

## Criterios de revisión
El usuario identifica que merge añade un nodo al grafo mientras rebase linealiza los commits; reconoce que rebase no debe usarse en ramas públicas sin consenso.

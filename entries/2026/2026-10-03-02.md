## Objetivo
Comprender la importancia de dividir una aplicación en capas lógicas (presentación, lógica y datos) para mejorar el mantenimiento, la seguridad y la escalabilidad del software.

## Explicación
El diseño por capas organiza el sistema en niveles con responsabilidades distintas. La capa de presentación maneja la interacción con el usuario, mientras que la capa de negocio encapsula la lógica crítica y las reglas de negocio. Finalmente, la capa de acceso a datos se encarga exclusivamente de la persistencia. Esta separación evita que un cambio en la interfaz afecte a la lógica o a la base de datos, facilitando pruebas unitarias aisladas y permitiendo reemplazar componentes sin romper el sistema global.

```python
def calcular_factura(cantidad, precio_unitario):
    if cantidad < 0:
        raise ValueError("La cantidad no puede ser negativa")
    subtotal = cantidad * precio_unitario
    impuesto = subtotal * 0.16
    return {"subtotal": subtotal, "impuesto": impuesto, "total": subtotal + impuesto}

def obtener_inventario(id_producto):
    # Simulación de acceso a datos
    inventario = {1: {"nombre": "Laptop", "precio": 800}, 2: {"nombre": "Mouse", "precio": 25}}
    return inventario.get(id_producto)
```

## Ejercicio
Crea una función en Python que reciba un diccionario de productos y devuelva solo aquellos cuyo precio unitario sea mayor a 100, aplicando la lógica de negocio en una capa separada de la validación de entrada.

## Criterios de revisión
El código debe tener al menos dos funciones: una para validar los datos de entrada y otra para filtrar productos por precio. No deben mezclarse consultas de datos con lógica de negocio.

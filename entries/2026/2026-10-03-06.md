## Objetivo
Distinguir cuándo utilizar mocks para verificar interacciones específicas y stubs para proporcionar datos de respuesta controlados, mejorando la fiabilidad de las pruebas de integración sin depender de servicios externos.

## Explicación
En esta lección exploramos la distinción crítica entre mocks y stubs. Un stub es una implementación simplificada que devuelve un valor predeterminado inmediato, ideal para simular respuestas rápidas de APIs externas o bases de datos durante el desarrollo inicial. Por otro lado, un mock no solo responde, sino que también valida cómo se invoca su método: verifica los argumentos recibidos y la secuencia de llamadas. Utilizar mocks es esencial cuando necesitas asegurar que tu sistema interactúe correctamente con un servicio específico bajo ciertas condiciones de entrada, mientras que los stubs son perfectos para aislar lógica de negocio de dependencias lentas o complejas.

## Ejemplo (no ejecutado automáticamente)
Se define un mock de una API de pagos que valida que se envíe el monto correcto y luego devuelve un objeto de respuesta simulado con éxito.

```javascript
const pagoMock = {
  procesar: (monto, metodo) => {
    if (monto !== 100) throw new Error('Monto incorrecto');
    return { estado: 'completado' };
  }
};
```

## Ejercicio
Crea una función 'calcularTotal' que acepte un objeto de configuración de impuestos. Modifica el código para inyectar un mock de servicio fiscal que valide si la región es 'MX' antes de aplicar el IVA del 16%.

## Criterios de revisión
El código debe fallar inmediatamente si se invoca con una región distinta a 'MX'. Debe retornar el objeto calculado correctamente solo cuando el mock valida los argumentos. No debe hacer llamadas reales a servicios externos.

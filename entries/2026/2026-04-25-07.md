## Objetivo
Aprender a utilizar el comando git bisect para identificar eficientemente en qué commit exacto se introdujo un error de regresión, ahorrando tiempo al no revisar manualmente cada cambio histórico.

## Explicación
git bisect es una herramienta poderosa que asume que tu historial de commits es lineal y permite encontrar el punto exacto donde apareció un bug. El proceso comienza marcando el commit actual como 'bueno' (sin errores) y uno anterior conocido como 'malo' (con el error). Git luego ejecuta un algoritmo binario, seleccionando automáticamente un commit intermedio para que lo pruebes. Si el estado es malo, marca ese punto; si es bueno, indica que el error está más adelante. Repitiendo este proceso, Git reduce rápidamente el espacio de búsqueda hasta aislar el commit culpable.

## Ejemplo (no ejecutado automáticamente)
Ejemplo práctico usando git bisect para encontrar un bug en una aplicación web donde la autenticación fallaba repentinamente tras actualizar la librería de seguridad.

```bash
git bisect start
GIT_BISECT_LOG=1 git bisect bad HEAD~50
git bisect good HEAD~200
```

## Ejercicio
Identifica el commit que rompió la funcionalidad de subida de archivos en un repositorio de ejemplo, marcando los extremos adecuados y ejecutando las pruebas manuales requeridas por git bisect.

## Criterios de revisión
El usuario debe ejecutar correctamente el inicio del bisect, marcar al menos tres puntos intermedios como buenos o malos según la prueba manual, y finalizar con 'git bisect reset' tras identificar el commit culpable.

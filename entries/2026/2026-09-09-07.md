## Objetivo
Aprender a identificar y probar casos borde en la validación de fechas, asegurando que el sistema rechace valores inválidos como días inexistentes o meses incorrectos sin generar excepciones inesperadas.

## Explicación
Los casos borde en fechas ocurren frecuentemente al validar límites del calendario. Ejemplos típicos incluyen probar el último día de un mes con 31 días frente a uno con 30, o verificar transiciones entre años bisiestos. Un caso crítico es ingresar '29 de febrero' en un año no bisiesto. El objetivo es que la función devuelva un error controlado y no falle silenciosamente. Se deben cubrir entradas vacías, valores negativos y fechas futuras lejanas si el negocio lo requiere. La prueba debe simular una API REST que recibe JSON con fecha de nacimiento para validar integridad referencial.

## Ejemplo (no ejecutado automáticamente)
Función en JavaScript que valida si una fecha es real rechazando días inexistentes y años no bisiestos incorrectos.

```javascript
function validarFecha(dia, mes, anio) {
  const fecha = new Date(anio, mes - 1, dia);
  if (fecha.getFullYear() !== anio || fecha.getMonth() !== mes - 1 || fecha.getDate() !== dia) {
    throw new Error('Fecha inválida');
  }
}
```

## Ejercicio
Crea una función en Python que reciba un objeto JSON con campos 'dia', 'mes' y 'anio'. La función debe lanzar ValueError si la fecha no existe, como el 30 de abril. Luego, escribe tres casos de prueba: uno válido (15/08/2026), uno borde (29/02/2023) y otro inválido (31/04/2026).

## Criterios de revisión
El código debe manejar correctamente años bisiestos, rechazar días inexistentes para cada mes y lanzar excepciones claras. La respuesta a entradas vacías debe ser un error de validación inmediato.

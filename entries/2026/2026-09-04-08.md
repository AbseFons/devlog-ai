## Objetivo
Aprender a encapsular la lógica de validación y transformación de datos dentro de una capa de servicio, evitando que el controlador exponga detalles internos del dominio.

## Explicación
En este nivel de la serie sobre separación de responsabilidades, nos enfocamos en cómo estructurar una aplicación para que cada capa tenga un propósito único. El controlador debe limitarse a recibir peticiones y delegar tareas complejas. La capa de servicio se encarga de orquestar la lógica de negocio, mientras que el repositorio maneja la persistencia. Al separar estas funciones, mejoramos la mantenibilidad y probabilidad del sistema. Un ejemplo claro es validar un usuario sin exponer las reglas de validación directamente en la ruta HTTP.

## Ejemplo (no ejecutado automáticamente)
Un servicio que valida credenciales y devuelve un objeto estandarizado de error o éxito, ocultando la lógica interna al controlador.

```javascript
class AuthService {
  async verificarUsuario(email, password) {
    const usuario = await this.repo.buscarPorEmail(email);
    if (!usuario || !this.cifrador.verificar(password, usuario.password)) {
      throw new Error('Credenciales incorrectas');
    }
    return { id: usuario.id, nombre: usuario.nombre };
  }
}
```

## Ejercicio
Crea un controlador que llame al método 'verificarUsuario' del servicio anterior. Maneja la excepción lanzada y responde con un código HTTP 401 si falla, o 200 con el objeto de usuario si tiene éxito.

## Criterios de revisión
El controlador no debe contener lógica de cifrado ni consultas directas a la base de datos. Debe delegar completamente en el servicio y manejar las excepciones para devolver respuestas HTTP apropiadas.

## Objetivo
Comprender la función del rate limiting para proteger servicios backend de sobrecargas y abusos, aprendiendo a implementar límites básicos de solicitudes por segundo utilizando encabezados HTTP estándar como X-RateLimit-Limit.

## Explicación
El rate limiting es un mecanismo esencial en el diseño de APIs que restringe el número de solicitudes que un cliente puede realizar en un periodo determinado. Esto previene ataques DDoS, protege recursos costosos y asegura la equidad entre usuarios. Se implementa comúnmente mediante encabezados HTTP como X-RateLimit-Limit (límite total), X-RateLimit-Remaining (solicitudes restantes) y X-RateLimit-Reset (tiempo de reinicio). Sin este control, una sola aplicación mal configurada podría agotar la capacidad del servidor para todos los demás usuarios. La implementación efectiva requiere definir umbrales claros y comunicar claramente las políticas de uso a los desarrolladores que consumen la API.

## Ejemplo (no ejecutado automáticamente)
Configuración de un middleware simple en Node.js que calcula solicitudes por segundo y devuelve encabezados de límite antes de procesar la petición.

```javascript
const rateLimit = (limit) => async (req, res, next) => {
  const now = Date.now();
  if (!req.rateLimitHits || now - req.rateLimitHits > 1000) {
    req.rateLimitHits = now;
    req.rateLimitCount = 0;
  }
  if (req.rateLimitCount >= limit) return res.status(429).json({ error: 'Too Many Requests' });
  req.rateLimitCount++;
  res.setHeader('X-RateLimit-Limit', limit);
  next();
};
```

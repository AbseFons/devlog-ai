## Objetivo
Comprender la diferencia fundamental entre las peticiones GET para obtener recursos y POST para crear nuevos datos, aplicando los principios de idempotencia y estado transaccional en arquitecturas cliente-servidor modernas.

## Explicación
En el diseño de APIs RESTful, los verbos HTTP definen la acción sobre un recurso. El método GET se utiliza exclusivamente para recuperar información; es seguro e idempotente, lo que significa que múltiples llamadas idénticas no alteran el estado del servidor ni generan efectos secundarios. Por otro lado, POST inicia una petición de creación de un nuevo recurso en el servidor. A diferencia de GET, POST no es idempotente: cada ejecución genera un nuevo registro único. Es crucial distinguir estos comportamientos para evitar errores de lógica, como intentar modificar datos con GET o asumir que múltiples peticiones POST crean duplicados si la API está mal diseñada. Ambos métodos son pilares para construir interfaces web y móviles robustas.

## Ejemplo (no ejecutado automáticamente)
Solicitud para crear un nuevo usuario en una API de gestión de clientes utilizando el método POST con datos JSON válidos.

```javascript
fetch('https://api.ejemplo.com/clientes', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana', email: 'ana@ejemplo.com' })
}).then(response => response.json());
```

## Ejercicio
Crea una petición GET a la misma API para listar todos los clientes y analiza en la respuesta el encabezado 'Content-Type'. Luego, modifica el código del ejemplo cambiando el método a PUT y explica por qué esa acción probablemente fallaría si no se incluye un ID específico.

## Criterios de revisión
El estudiante debe identificar correctamente que GET es idempotente y seguro, mientras que POST crea recursos únicos. Debe demostrar la capacidad de estructurar una petición POST con cabeceras adecuadas y diferenciar el propósito de cada verbo HTTP en el contexto de manipulación de datos.

## Objetivo
Aprender a utilizar git bisect para localizar eficientemente el commit que introdujo una regresión crítica, evitando horas de depuración manual y restaurando la estabilidad del proyecto con precisión.

## Explicación
Cuando una funcionalidad deja de funcionar tras múltiples commits, revisar cada uno es ineficiente. Git bisect automatiza este proceso mediante un método binario. Primero, marcas el commit actual como 'bad' (fallido) y buscas un commit anterior conocido que funcionaba ('good'). Ejecutas el comando bisect start y defines los puntos de referencia. Luego, ejecutas bisect bad para confirmar el estado actual. El sistema seleccionará automáticamente un commit intermedio; debes probarlo y marcarlo como good o bad. Este ciclo se repite hasta que Git identifica exactamente el commit culpable. Una vez encontrado, usas bisect reset para limpiar el historial de la sesión.

## Ejemplo (no ejecutado automáticamente)
Script bash que simula un entorno de prueba fallido y ejecuta el flujo de bisect para encontrar el commit problemático en un repositorio local.

```bash
# Simular un commit malo
GIT_AUTHOR_DATE="2026-11-09T10:00:00" GIT_COMMITTER_DATE="2026-11-09T10:00:00" git commit --allow-empty -m "Introducir bug de cálculo"
echo "Bug introducido. Ahora inicia bisect:"
git bisect start
git bisect bad
git bisect good HEAD~5
# Git seleccionará un commit intermedio para probar.
# Marca el resultado y repite hasta que git bisect identifique el culpable.
```

## Ejercicio
En tu repositorio local, crea un commit con una regresión intencional. Usa git bisect para encontrar ese commit, marcando los estados good y bad correctamente.

## Criterios de revisión
El usuario debe ejecutar bisect start, definir al menos dos puntos de referencia (good y bad), iterar el proceso de marcado hasta que Git identifique el commit exacto y finalizar con bisect reset.

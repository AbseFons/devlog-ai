## Objetivo
Aprender a identificar y fusionar cambios contradictorios en archivos locales utilizando herramientas visuales, asegurando la integridad del historial sin perder trabajo.

## Explicación
Cuando Git detecta un conflicto, detiene el proceso de merge o rebase marcando las líneas problemáticas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. El desarrollador debe editar manualmente el archivo para conservar los cambios relevantes de ambas ramas. Una vez resuelto, se ejecuta 'git add' para marcar el archivo como listo y 'git commit' finaliza la resolución. Es crucial revisar el contexto del cambio antes de decidir qué código mantener.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para preparar un archivo en conflicto y verificar su estado antes de resolver manualmente los marcadores de Git.

```bash
git status
nano src/main.py
```

## Ejercicio
Simula un conflicto editando dos líneas distintas en el mismo archivo local, luego usa 'git add' para marcarlo como resuelto y verifica que Git deje de reportar conflictos.

## Criterios de revisión
El usuario debe identificar correctamente los marcadores de conflicto, editar el archivo manteniendo la lógica funcional y ejecutar los comandos adecuados para finalizar el proceso sin errores.

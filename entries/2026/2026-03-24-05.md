## Objetivo
Comprender el propósito del comando EXPLAIN para analizar el plan de ejecución de consultas SQL antes de ejecutarlas, identificando cuellos de botella como escaneos de tablas completas o ordenamientos costosos que impactan el rendimiento.

## Explicación
El comando EXPLAIN permite inspeccionar cómo el motor de base de datos planea procesar una consulta sin generar efectos secundarios. Al ejecutarlo, obtienes un árbol de operaciones que muestra las tablas involucradas, los índices utilizados y el orden de acceso a los datos. Esto es crucial para detectar ineficiencias como 'Seq Scans' en tablas grandes cuando existen índices adecuados. Analizar este plan ayuda a reestructurar consultas o crear índices estratégicos antes de desplegar cambios críticos en producción, asegurando que las aplicaciones respondan rápidamente bajo carga.

## Ejemplo (no ejecutado automáticamente)
Consulta un plan de ejecución para una búsqueda con filtro parcial y ordenamiento, observando si se usa el índice correcto o si se realiza un escaneo secuencial costoso.

```sql
EXPLAIN SELECT * FROM usuarios WHERE edad > 30 ORDER BY nombre;
SELECT * FROM usuarios WHERE edad > 30 ORDER BY nombre;
```

## Ejercicio
Escribe una consulta SQL que busque registros en una tabla de ventas filtrando por fecha y producto. Luego, ejecuta EXPLAIN sobre ella para verificar si la base de datos utiliza un índice compuesto o realiza un escaneo completo.

## Criterios de revisión
El plan debe mostrar el uso de índices (Index Scan) en lugar de escaneos secuenciales (Seq Scan) para las condiciones de filtro principales. Debe existir al menos una operación de ordenamiento (Sort) si no hay índice adecuado en la columna ORDER BY.

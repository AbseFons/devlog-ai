## Objetivo
Comprender cómo dividir una aplicación en capas lógicas para que cada módulo tenga un único propósito, facilitando el mantenimiento y la prueba unitaria.

## Explicación
El principio de separación de responsabilidades dicta que ningún módulo debe realizar múltiples funciones distintas. En un sistema web típico, esto se traduce en dividir el flujo entre controladores (que manejan la solicitud HTTP), servicios (que encapsulan la lógica de negocio) y repositorios (que gestionan el acceso a datos). Al aislar estas capas, podemos modificar la base de datos sin afectar la interfaz de usuario. Por ejemplo, si cambiamos la estructura de la tabla de usuarios, solo debemos actualizar el repositorio, dejando intacta la lógica de validación en el servicio. Esta arquitectura promueve un código modular donde las dependencias fluyen hacia abajo: los controladores dependen de servicios, y estos de repositorios, evitando acoplamiento circular.

## Ejemplo (no ejecutado automáticamente)
Un fragmento de código que define una clase ServicioUsuario separada de la capa de acceso a datos, demostrando cómo la lógica de negocio no conoce los detalles del almacenamiento.

```javascript
class UsuarioService {
  async obtenerPorId(id) {
    const usuario = await this.repositorio.obtenerPorId(id);
    return this.validarEstado(usuario);
  }
}
```

## Ejercicio
Crea un archivo llamado 'controlador.js' que reciba una petición HTTP, extraiga el ID del parámetro de ruta y llame a la función obtenerPorId del servicio UsuarioService. Asegúrate de no importar directamente las funciones del repositorio dentro del controlador.

## Criterios de revisión
El código debe mostrar claramente la llamada al servicio sin exponer la implementación del repositorio, manteniendo la cohesión funcional en cada capa.

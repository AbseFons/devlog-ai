## Objetivo
Aprender a crear etiquetas (tags) en Git para marcar versiones estables del proyecto, diferenciándolas de los commits de desarrollo y entendiendo su uso en despliegues.

## Explicación
Las etiquetas en Git son marcadores inmutables que identifican puntos específicos en el historial, ideales para releases. A diferencia de las ramas, una etiqueta no se mueve al hacer nuevos commits. Se usan comúnmente con formato semántico (ej: v1.0.0). Para crear una, usa 'git tag -a <nombre> -m <mensaje>'. Esto crea una etiqueta anotada con autor y fecha. Luego, puedes empujarlas a remoto con 'git push origin <etiqueta>'. Es crucial no modificar etiquetas existentes; si hay un error, se debe crear una nueva versión. Las etiquetas facilitan la trazabilidad de cambios entre versiones sin alterar el flujo de trabajo diario.

## Ejemplo (no ejecutado automáticamente)
Crear una etiqueta anotada para la versión inicial del proyecto y empujarla al repositorio remoto.

```bash
git tag -a v1.0.0 -m "Primera release estable"
git push origin v1.0.0
```

## Ejercicio
Crea una etiqueta llamada 'v2.1-beta' con el mensaje 'Prueba de funcionalidad X' y empuja solo esa etiqueta al remoto.

## Criterios de revisión
El comando debe incluir la opción -a para crear una etiqueta anotada, el nombre correcto de la versión, el mensaje descriptivo y el push exclusivo de la etiqueta creada.

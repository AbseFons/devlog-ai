## Objetivo
Aprender a diseñar pruebas que verifiquen la correcta interacción entre múltiples módulos del sistema, asegurando que los datos fluyan sin corrupción y que las transacciones complejas se manejen con integridad bajo condiciones controladas.

## Explicación
Las pruebas de integración en esta serie se centran en validar flujos completos más allá de la unidad aislada. En este caso, simularemos una operación bancaria donde el servicio de autenticación debe coordinarse con el motor de transacciones y el registro de auditoría. El objetivo es detectar fallos de comunicación o pérdida de datos entre capas. Utilizaremos un enfoque basado en contratos para asegurar que cada componente expone las interfaces esperadas. La prueba inyectará datos válidos e inválidos para observar cómo el sistema maneja errores en cascada sin bloquear la aplicación completa, garantizando así la robustez del flujo transaccional integrado.

## Ejemplo (no ejecutado automáticamente)
Script que simula una transferencia bancaria integrando validación de saldo, débito y crédito simultáneos.

```javascript
const mockDB = { balance: 1000 };
function transfer(amount) { if (amount > mockDB.balance) throw new Error('Fondos insuficientes'); mockDB.balance -= amount; return true; }
try { transfer(500); console.log('Transferencia exitosa'); } catch(e) { console.error(e.message); }
```

## Ejercicio
Crea un script que integre tres servicios ficticios: 'Usuario', 'Inventario' y 'Pago'. Define una función 'completarPedido' que llame secuencialmente a estos servicios. Añade lógica para que si el servicio de 'Pago' falla, se descancele la reserva en 'Inventario' y se notifique al 'Usuario'.

## Criterios de revisión
El código debe ejecutar sin errores de sintaxis. Debe manejar correctamente una excepción lanzada por el servicio de pago liberando los recursos del inventario. La salida en consola debe mostrar claramente el estado final de la transacción (éxito o cancelación) y no dejar datos huérfanos en las variables simuladas.

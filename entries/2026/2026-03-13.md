## Objetivo
Diferenciar conceptualmente y operativamente el uso de merge y rebase en Git, entendiendo cómo cada uno afecta la historia del proyecto y cuándo aplicar cada estrategia para mantener un historial limpio o preservar ramas paralelas.

## Explicación
Merge crea un nuevo commit que fusiona dos líneas de desarrollo, preservando la estructura histórica exacta de las ramas. Rebase reescribe el historial moviendo los commits de una rama sobre otra, creando una línea lineal y limpia. Usa merge cuando necesitas preservar la historia real de conflictos o trabajar en paralelo sin afectar a otros. Usa rebase para mantener un log lineal antes de enviar código a producción o compartirlo públicamente, siempre que no afectes a otros colaboradores.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un merge y un rebase localmente, mostrando la diferencia en el historial de commits.

```bash
git checkout feature
# Merge
git merge main
# Rebase
git checkout main
git pull --rebase origin main
```

## Ejercicio
Crea dos ramas locales: 'main' y 'feature'. Haz un commit en cada una. Luego, prueba ambos comandos de fusión y observa cómo cambia el gráfico de commits con git log --graph.

## Criterios de revisión
El estudiante debe identificar cuándo usar merge (preservar historia) y cuándo rebase (limpiar historial), ejecutar ambos comandos sin errores locales y explicar las diferencias visuales en el historial.

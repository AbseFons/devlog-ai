## Objetivo
Comprender el principio fundamental de la arquitectura por capas, donde cada nivel tiene una responsabilidad única y específica, facilitando el mantenimiento, la escalabilidad y la reutilización del código en aplicaciones modernas.

## Explicación
En esta primera lección de la serie sobre arquitectura por capas, exploraremos cómo estructurar una aplicación dividiéndola en niveles lógicos: presentación, lógica de negocio y acceso a datos. Esta separación asegura que el código sea modular; si cambiamos la interfaz de usuario, no afecta al procesamiento interno ni a las bases de datos. Por ejemplo, una capa de control valida entradas, mientras que la capa de servicio orquesta reglas complejas sin exponer detalles técnicos. Esto reduce acoplamientos innecesarios y permite pruebas unitarias más efectivas en cada nivel independiente.

## Ejemplo (no ejecutado automáticamente)
Implementación básica en Python mostrando una clase Controlador que llama a un Servicio, el cual interactúa con un Repositorio de datos, ilustrando la separación clara de responsabilidades sin exponer dependencias directas entre capas.

```python
class Repo:
    def get_data(self): return [1,2,3]
class Service:
    def process(self, repo): return repo.get_data()
class Controller:
    def handle(self, svc, repo): return svc.process(repo)
```

## Ejercicio
Crea un archivo 'app.py' con tres clases: UserController, UserService y UserRepository. Haz que UserController llame a UserService, y este último a UserRepository. Asegúrate de que no haya importaciones directas entre las capas de negocio y datos.

## Criterios de revisión
El código debe tener tres clases separadas en un mismo archivo o módulo. La clase de controlador no debe importar directamente la clase de repositorio. Debe existir una llamada intermedia a través del servicio. El programa debe ejecutarse sin errores de importación circular.

## Objetivo
Aprender a identificar y eliminar dependencias transitivas en tablas relacionales para evitar redundancia de datos, anomalías de actualización y garantizar la integridad referencial en bases de datos normalizadas.

## Explicación
En esta lección avanzamos más allá de la Segunda Forma Normal. Analizamos cómo una tabla puede cumplir con las dos primeras normas pero aún contener dependencias transitivas, donde un atributo no clave depende indirectamente de otra clave no primaria a través de otro atributo. Por ejemplo, si tenemos 'Cliente', 'Dirección' y 'Ciudad', y 'Ciudad' depende de 'Dirección', esto viola la Tercera Forma Normal. La solución implica descomponer la tabla en tres: una para clientes, otra para direcciones y una tercera para ciudades. Esto asegura que cada atributo dependa directamente solo de la clave primaria, eliminando redundancias y facilitando el mantenimiento del esquema.

## Ejemplo (no ejecutado automáticamente)
Se muestra un caso donde se separa una tabla 'Pedidos' que contenía datos de dirección y ciudad en otra tabla 'Ciudades', creando una relación transitiva que debe ser descompuesta para cumplir la T3FN.

```sql
CREATE TABLE Ciudad (id_ciudad INT PRIMARY KEY, nombre VARCHAR(50));
CREATE TABLE Pedido (id_pedido INT PRIMARY KEY, id_ciudad INT, FOREIGN KEY (id_ciudad) REFERENCES Ciudad(id_ciudad));
```

## Ejercicio
Diseña un esquema SQL para una tienda de libros que tenga tablas separadas para 'Autores', 'Libros' y 'Categorías', asegurando que ninguna tabla contenga dependencias transitivas.

## Criterios de revisión
El esquema debe tener al menos tres tablas relacionadas por claves foráneas, cada atributo no clave debe depender directamente de su clave primaria y no deben existir columnas con datos duplicados evitables mediante normalización.

## Objetivo
Comprender y aplicar el principio de mínimo privilegio al definir roles de usuario en sistemas operativos, limitando el acceso solo a los recursos estrictamente necesarios para cada tarea específica.

## Explicación
El principio de mínimo privilegio establece que cualquier entidad de seguridad (usuario, proceso o servicio) debe tener únicamente los permisos mínimos requeridos para realizar su función. En ingeniería de software y operaciones, esto se traduce en evitar cuentas con acceso root o administrador por defecto. Por ejemplo, un servicio de base de datos no necesita escribir en el directorio del sistema; solo debe leer archivos específicos. Implementar este principio reduce la superficie de ataque: si una cuenta es comprometida, el daño potencial se limita. La implementación implica auditar permisos existentes, eliminar privilegios innecesarios y utilizar cuentas dedicadas para tareas automatizadas. Este enfoque fomenta una arquitectura defensiva robusta donde cada componente opera en un contexto aislado y controlado.

## Ejemplo (no ejecutado automáticamente)
Creación de un usuario con acceso restringido solo a leer logs específicos en Linux, evitando permisos de escritura o ejecución en el sistema.

```bash
useradd -m -s /bin/bash audit_user
chmod 750 /var/log/app/
chown audit_user:audit_group /var/log/app/
```

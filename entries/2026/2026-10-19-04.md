## Objetivo
Implementar la rotación automática de credenciales para minimizar la ventana de exposición en caso de compromiso, asegurando que las claves no permanezcan estáticas indefinidamente dentro del sistema.

## Explicación
La gestión segura de secretos requiere evitar el almacenamiento estático. Utilizando HashiCorp Vault, podemos configurar políticas de renovación automática donde los servicios solicitan tokens o credenciales con una vida útil corta (ej. 5 minutos). El cliente debe solicitar la renovación antes de que expiren. Esto reduce drásticamente el riesgo: si un atacante roba una credencial, solo tiene acceso limitado en tiempo real. La implementación implica configurar el agente del Vault en el servidor, definir políticas de autenticación y asegurar que las aplicaciones consuman los secretos mediante llamadas API seguras con tokens de servicio cortos.

## Ejemplo (no ejecutado automáticamente)
Script de bash para renovar un token de Vault automáticamente cada 4 minutos antes de su expiración.

```bash
export VAULT_ADDR='http://127.0.0.1:8200'
export VAULT_TOKEN=$(vault read -field=token auth/token/lookup-self | jq -r .data.token)
vault token renew -duration=5m
```

Configura un agente de Vault en una máquina virtual local, define una política que otorgue acceso a un motor de secrets y escribe un script que renueve el token cada 4 minutos.

## Criterios de revisión
El token debe renovarse exitosamente sin intervención manual antes de la expiración; el script debe manejar errores de red básicos y no debe almacenar tokens en variables de entorno persistentes.

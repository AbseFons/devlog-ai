## Objetivo
Al finalizar, el desarrollador identificará la semántica de GET para lectura idempotente y POST para creación de recursos, aplicando estos conceptos en una API real sin errores de estado ni violaciones de seguridad.

## Explicación
En las APIs REST, los métodos HTTP definen la acción sobre un recurso. GET se usa exclusivamente para recuperar datos; es seguro e idempotente, lo que significa que múltiples llamadas idénticas producen el mismo resultado y no alteran el servidor. POST inicia una petición de cambio, típicamente para crear nuevos recursos en una colección. A diferencia de PUT o DELETE, POST no garantiza la sustitución total ni la eliminación, sino la adición. Comprender esta distinción es vital para diseñar endpoints escalables y predecibles.

## Ejemplo (no ejecutado automáticamente)
```javascript
// Solicitud GET: Obtener lista de usuarios
fetch('https://api.ejemplo.com/v1/usuarios', {
  method: 'GET',
  headers: { 'Accept': 'application/json' }
}).then(res => res.json()).then(data => console.log(data));

// Solicitud POST: Crear un nuevo usuario
fetch('https://api.ejemplo.com/v1/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana', rol: 'admin' })
}).then(res => res.json()).then(data => console.log('Usuario creado:', data.id));
```

## Ejercicio
Crea un endpoint ficticio '/productos' que acepte una petición POST con campos 'nombre' y 'precio'. Luego, escribe una petición GET para listar todos los productos creados. Asegúrate de que la respuesta del POST incluya el ID generado automáticamente.

## Criterios de revisión
1. La petición POST debe devolver un estado 201 Created con el objeto creado.
2. La petición GET debe devolver un estado 200 OK con una lista JSON.
3. No se deben incluir credenciales en los headers de la solicitud.

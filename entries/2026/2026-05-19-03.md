## Objetivo
Aprender a identificar y resolver conflictos de fusión en Git mediante la inspección directa de archivos, utilizando herramientas como nano o vim para editar las líneas marcadas con marcadores de conflicto.

## Explicación
Cuando Git detecta un conflicto durante una fusión, inserta marcadores '<<<<<<<', '=======', y '>>>>>>>' entre los cambios no resueltos. El objetivo es revisar el archivo afectado, decidir qué lógica de negocio prevalece y editar manualmente el contenido para eliminar estos marcadores. Es crucial entender que Git no puede adivinar la intención del desarrollador; por ello, se debe preservar la funcionalidad original mientras se integran las nuevas características. Una vez editado, se guarda el archivo y se ejecuta 'git add' para marcarlo como resuelto, seguido de 'git commit' para finalizar la fusión.

## Ejemplo (no ejecutado automáticamente)
Archivo de configuración de servidor donde se fusionan cambios en la ruta del log y el puerto de escucha.

```bash
# Ruta original: /var/log/app.log
# Nueva ruta propuesta: /tmp/app.log
# Se decide mantener la ruta original por estabilidad
LOG_PATH="/var/log/app.log"
PORT=8080
```

## Ejercicio
Crea un repositorio local con dos ramas. En 'main', modifica el archivo README.md añadiendo una sección de 'Contacto'. En 'feature-contacto', añade la misma sección pero con datos diferentes. Intenta fusionar las ramas y resuelve el conflicto manualmente editando el archivo.

## Criterios de revisión
El usuario debe haber eliminado correctamente los marcadores de conflicto, integrado la información relevante de ambas ramas sin perder datos críticos y ejecutado con éxito los comandos 'git add' y 'git commit' para finalizar la resolución.

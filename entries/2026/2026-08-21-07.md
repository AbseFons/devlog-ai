## Objetivo
Al finalizar esta lección, el desarrollador será capaz de definir qué son las pruebas de regresión, identificar su propósito principal al detectar efectos secundarios no deseados tras una modificación y aplicar estrategias básicas para ejecutarlas sin comprometer la estabilidad del sistema.

## Explicación
Las pruebas de regresión verifican que los cambios recientes en el código no rompan funcionalidades existentes. Son esenciales cuando se actualiza lógica, se añaden características o se corrigen errores. Sin ellas, un parche podría introducir nuevos fallos invisibles. La clave es seleccionar casos de prueba representativos que cubran flujos críticos. No se deben ejecutar todas las pruebas unitarias cada vez; en su lugar, se usa un subconjunto estratégico. Esto ahorra tiempo y recursos mientras mantiene la confianza en la estabilidad del producto ante iteraciones constantes.

## Ejemplo (no ejecutado automáticamente)
```python
def calcular_total(precio, cantidad):
    return precio * cantidad

def test_calculo_regresion():
    # Caso base: multiplicación simple
    assert calcular_total(10, 2) == 20
    
    # Caso de borde: cero
    assert calcular_total(5, 0) == 0
    
    # Caso de borde: negativo (si es permitido)
    assert calcular_total(-3, 4) == -12
    
    print('Pruebas de regresión aprobadas.')

test_calculo_regresion()
```

## Ejercicio
Crea una función en Python que sume dos números. Luego, escribe tres casos de prueba: uno con números positivos, otro con un número negativo y el último con cero. Asegúrate de que la función falle si se le pasa una cadena como argumento.

## Criterios de revisión
El código debe contener la función suma definida correctamente. Deben existir exactamente tres llamadas a assert o if para validar los casos especificados. No debe haber errores de sintaxis y el script debe ejecutarse sin excepciones en los casos válidos.

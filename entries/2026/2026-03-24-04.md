## Objetivo
Comprender por qué almacenar contraseñas en texto plano es inseguro y cómo las funciones hash unidireccionales protegen los datos de usuarios ante filtraciones, estableciendo la base para el uso de salting.

## Explicación
Almacenar contraseñas en texto plano permite a atacantes acceder directamente a credenciales válidas. Las funciones hash transforman cualquier entrada en una cadena única y fija longitud mediante algoritmos criptográficos como SHA-256 o bcrypt. Este proceso es unidireccional: no existe forma práctica de revertir el hash para obtener la contraseña original. Si se filtra la base de datos, los atacantes solo obtienen hashes inútiles sin la clave original. Además, cada hash debe ser único; por ello, se añade una 'sal' aleatoria a cada contraseña antes de encriptarla, impidiendo ataques de diccionario masivos.

## Ejemplo (no ejecutado automáticamente)
Script que genera un hash SHA-256 para una contraseña de ejemplo y muestra el resultado en consola.

```bash
password="MiContraseñaSegura123"
hash=$(echo -n "$password" | sha256sum | awk '{print $1}')
echo "Hash generado: $hash"
```

## Criterios de revisión
El código debe leer la entrada estándar, generar el hash correctamente usando la librería hashlib y escribir solo el valor hexadecimal del hash en el archivo de salida. No debe imprimir la contraseña ni el hash durante la ejecución.

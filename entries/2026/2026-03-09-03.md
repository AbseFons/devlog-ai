## Objetivo
Aprender a seleccionar y aplicar un commit individual desde otra rama sin fusionar todo su historial, manteniendo la limpieza del código en el flujo de trabajo actual.

## Explicación
El comando git cherry-pick permite extraer uno o varios commits específicos de una rama remota y aplicarlos a la rama actual. Esto es útil cuando necesitas resolver un bug crítico que fue arreglado en otra rama, pero no deseas traer los cambios de código innecesarios asociados a ese commit. El proceso implica identificar el hash del commit deseado mediante git log, luego ejecutar cherry-pick con ese hash. Es fundamental verificar la integridad del árbol después de la operación, ya que pueden surgir conflictos de archivos si las líneas cambiadas son idénticas en ambas ramas. Este método preserva la historia lineal del proyecto actual mientras incorpora funcionalidades puntuales.

## Ejemplo (no ejecutado automáticamente)
Seleccionar un commit específico para aplicar sus cambios al rama principal sin fusionar todo el historial de la rama de desarrollo.

```bash
git cherry-pick abc1234567890
# Verificar que los cambios se aplicaron correctamente
git status
```

## Ejercicio
Identifica un commit en la rama feature-authentication que arregla una vulnerabilidad de seguridad. Aplica ese único commit a la rama main usando cherry-pick y verifica el estado del repositorio.

## Criterios de revisión
El usuario debe ejecutar correctamente el comando con el hash válido, resolver conflictos si los hubiera (aunque no se requiere en este caso básico) y confirmar que solo los cambios del commit seleccionado aparecen en la rama objetivo.

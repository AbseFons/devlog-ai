## Objetivo
Comprender la organización física de un repositorio Git, diferenciando entre el área de trabajo, el directorio .git y los archivos indexados para gestionar cambios de manera eficiente.

## Explicación
Un repositorio Git local se compone principalmente de dos áreas: el árbol de objetos (área de trabajo) donde resides tus archivos modificables, y el directorio oculto .git que almacena el historial completo. Dentro del área de trabajo, los cambios no guardados en el índice son 'no staged'. Al ejecutar git add, los cambios se mueven al estado 'staged', listos para ser comprometidos. El directorio .git contiene subdirectorios como objects (historial comprimido), refs (ramas y tags) y hooks (scripts automáticos). Entender esta estructura es vital para diagnosticar problemas de sincronización o conflictos de fusión, ya que Git opera sobre la diferencia entre el estado del árbol y el contenido del índice.

## Ejemplo (no ejecutado automáticamente)
Inicializa un repositorio vacío y verifica su estructura interna mostrando los directorios clave sin usar comandos destructivos.

```bash
mkdir mi-repo && cd mi-repo
git init
ls -la | grep '\.git'
```

El usuario debe crear correctamente la estructura del repositorio, añadir los archivos sin errores y interpretar correctamente la salida de git status distinguiendo entre archivos indexados y no indexados.

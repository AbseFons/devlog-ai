## Objetivo
Comprender cómo la cobertura de pruebas cubre el código pero no garantiza la ausencia de errores, especialmente en los límites de entrada. Aprender a diseñar casos que validen condiciones extremas para asegurar la robustez del software ante datos inesperados.

## Explicación
La cobertura de código mide qué porcentaje del código fuente se ejecuta durante las pruebas, pero un alto porcentaje no implica que el sistema sea libre de fallos. Los límites son puntos críticos donde los errores suelen manifestarse, como valores máximos, mínimos o transiciones entre estados. Es vital probar no solo el valor central esperado, sino también los bordes exactos y uno más allá. Por ejemplo, si un campo acepta números hasta 100, se deben probar 99, 100, 101 y valores negativos. Ignorar estos límites puede dejar vulnerabilidades de seguridad o lógica no tratadas. La estrategia debe incluir explícitamente la validación de entradas al borde del rango permitido para garantizar que el sistema maneje adecuadamente las condiciones extremas sin colapsar.

## Ejemplo (no ejecutado automáticamente)
Script en Python que valida si un número está dentro de un rango seguro, incluyendo pruebas de límites exactos y uno más allá.

```python
def validar_rango(valor, minimo, maximo):
    if valor < minimo or valor > maximo:
        return False
    return True

print(validar_rango(50, 10, 100))
print(validar_rango(10, 10, 100))
print(validar_rango(101, 10, 100))
```

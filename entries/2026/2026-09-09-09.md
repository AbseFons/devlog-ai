## Objetivo
Comprender que la autenticación verifica la identidad del usuario (quién eres), mientras que la autorización determina qué recursos puede acceder una vez identificado. Esta distinción es vital para diseñar APIs seguras que prevengan accesos no autorizados incluso si las credenciales se filtran.

## Explicación
En el contexto de APIs, la autenticación responde a '¿Quién eres?' mediante tokens como JWT o sesiones, validando la identidad del cliente. La autorización responde a '¿Qué puedes hacer?', utilizando listas de control de acceso (ACL) o roles para restringir operaciones específicas. Un error común es confundir ambos: un token válido no garantiza acceso total; solo permite lo definido en sus claims o permisos asociados. Implementar ambas capas por separado asegura que, incluso si un atacante obtiene credenciales, sin los permisos adecuados no podrá modificar datos sensibles ni ejecutar acciones críticas.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de middleware en Node.js que verifica el token de autenticación y luego consulta una base de datos para validar los permisos de autorización antes de permitir la respuesta.

```javascript
const authMiddleware = async (req, res, next) => {
  const token = req.headers['authorization'];
  if (!token) return res.status(401).json({ error: 'No autenticado' });
  const user = await verifyToken(token);
  if (!user.permissions.includes('read')) return res.status(403).json({ error: 'No autorizado' });
  next();
};
```

## Ejercicio
Crea una API en Python con Flask que requiera autenticación para entrar y autorización específica para eliminar recursos. Usa tokens simples y una lista de roles.

## Criterios de revisión
El código debe separar claramente la lógica de validación del token de la lógica de permisos. Debe devolver códigos HTTP 401 para falta de autenticación y 403 para falta de autorización.

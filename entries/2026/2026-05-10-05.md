## Objetivo
Comprender cómo la falta de validación en consultas SQL permite a atacantes manipular bases de datos, extrayendo información sensible o alterando registros mediante el uso de cadenas mal construidas.

## Explicación
La inyección SQL ocurre cuando se insertan entradas no filtradas directamente en una consulta. Imagina una base de datos con usuarios y un formulario de login que concatena texto al comando SQL sin usar parámetros. Si un atacante envía como contraseña: admin' OR '1'='1', la consulta original cambia su lógica, haciendo que el sistema acepte cualquier credencial. Esto sucede porque el motor de base de datos interpreta las comillas simples y operadores lógicos como parte del código SQL en lugar de texto plano. La solución fundamental es utilizar consultas parametrizadas o prepared statements, donde los valores se envían por separado del código, asegurando que siempre se traten como datos seguros.

## Ejemplo (no ejecutado automáticamente)
Consulta vulnerable en Python usando f-strings que permite inyección directa al concatenar el input del usuario con la sentencia SQL.

```python
import sqlite3
conn = sqlite3.connect('db.sqlite')
cursor = conn.cursor()
user_input = "admin' OR '1'='1"
query = f"SELECT * FROM users WHERE username = '{user_input}'"
```

## Criterios de revisión
El código debe utilizar cursor.execute(query, params) en lugar de concatenación. La variable params debe contener los valores del usuario como tupla o lista. No deben existir comillas simples dentro de la cadena de consulta SQL.

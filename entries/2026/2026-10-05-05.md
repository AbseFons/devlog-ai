## Objetivo
Aprender a identificar y probar casos borde críticos en la validación de formularios web, asegurando que el sistema maneje correctamente valores extremos como límites numéricos, cadenas vacías o caracteres especiales sin colapsar.

## Explicación
Los casos borde son entradas que se sitúan justo en los límites de las reglas de negocio. En un formulario de edad, por ejemplo, no basta con probar 18 y 60; hay que verificar 17 (justo antes del límite), 61 (justo después) y valores negativos o nulos. Estos escenarios revelan vulnerabilidades en la lógica de validación que los casos estándar pasan por alto. Un caso borde típico incluye una cadena con espacios invisibles, un número flotante como '25.9' cuando solo se aceptan enteros, o caracteres Unicode no esperados. Probar estos extremos garantiza robustez y evita errores en producción derivados de entradas inesperadas que el usuario podría introducir por accidente.

## Ejemplo (no ejecutado automáticamente)
Script en JavaScript para probar límites de edad en un formulario

```javascript
const validarEdad = (edad) => {
  const min = 18;
  const max = 65;
  return edad >= min && edad <= max && !isNaN(edad);
};
console.log(validarEdad(17)); // false
console.log(validarEdad(18)); // true
console.log(validarEdad(65)); // true
console.log(validarEdad(66)); // false
```

## Ejercicio
Crea un script que valide un campo de email. Prueba con: 'usuario@dominio.com', 'usuario@@dominio.com', '', 'usuario@dominio', y 'usuario@dominio..com'. Registra en consola si pasa o falla cada caso.

## Criterios de revisión
El código debe devolver true solo para emails válidos según RFC básico. Debe manejar al menos tres casos borde: doble arroba, dominio vacío y dos puntos seguidos en el TLD.

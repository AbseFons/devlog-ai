## Objetivo
Diferenciar claramente entre autenticación (quién eres) y autorización (qué puedes hacer), fundamentales para diseñar APIs seguras que protejan recursos sensibles mediante tokens y roles.

## Explicación
En el desarrollo de APIs, la autenticación verifica la identidad del usuario, mientras que la autorización determina sus permisos. Un error común es confundir ambos conceptos. Para autenticar, se usan credenciales o tokens como JWT. Para autorizar, el servidor revisa los roles asociados a ese token contra una política de acceso. Por ejemplo, un usuario logueado puede tener permiso para leer su perfil pero no para borrar registros de otros usuarios. Implementar esta separación es vital para evitar fugas de datos y garantizar que cada operación cumpla con el principio de menor privilegio.

## Ejemplo (no ejecutado automáticamente)
El servidor valida un token JWT en la cabecera de la solicitud y extrae los roles del usuario para decidir si permite la acción de eliminar un recurso.

```javascript
const userRoles = jwtPayload['roles'];
if (userRoles.includes('admin')) {
  return res.status(200).json({ success: true });
}
```

## Ejercicio
Crea una API endpoint que reciba un token en la cabecera 'Authorization'. Implementa una lógica que permita a usuarios con el rol 'editor' actualizar registros, pero niegue acceso a usuarios sin ese rol.

## Criterios de revisión
El código debe extraer correctamente los roles del token y devolver un estado 200 si el rol coincide o 403 si no. No debe exponer credenciales ni permitir acciones de eliminación en este contexto.

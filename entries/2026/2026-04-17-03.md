## Objetivo
Aprender a usar el comando git reflog para visualizar la historia local de HEAD y recuperar accidentalmente eliminados o reseteados sin necesidad de repositorios remotos.

## Explicación
El reflog registra cada cambio en la referencia local HEAD, incluso si se ejecutan comandos como 'reset' o 'revert'. A diferencia del historial normal, el reflog muestra estados intermedios. Para recuperar un commit perdido, primero ejecuta 'git reflog' para ver la lista de hashes y mensajes asociados. Identifica el hash del estado deseado antes de la acción destructiva. Luego, usa 'git reset --hard <hash>' para restaurar el árbol de objetos a ese punto exacto. Este proceso es seguro localmente porque no afecta al historial compartido en remoto, permitiendo deshacer errores comunes como borrados accidentales o resets mal calculados.

## Ejemplo (no ejecutado automáticamente)
Se muestra cómo listar el reflog y restaurar un commit específico eliminado accidentalmente mediante reset hard.

```bash
git reflog
HEAD@{1} -> HEAD (reset: moving to HEAD@{1})
git reset --hard HEAD@{1}
```

## Ejercicio
Ejecuta 'git reflog' en tu terminal local. Busca el hash del commit inmediatamente anterior a un error reciente. Restaura ese estado usando 'git reset --hard <hash>' y verifica que los archivos se hayan recuperado.

## Criterios de revisión
El usuario debe listar correctamente el reflog, identificar el hash correcto de recuperación y ejecutar el comando de restauración sin errores.

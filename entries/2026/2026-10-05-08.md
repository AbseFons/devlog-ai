## Objetivo
Comprender cómo encapsular la lógica de negocio en una capa intermedia para proteger el acceso directo a las fuentes de datos, mejorando la seguridad y mantenibilidad del sistema.

## Explicación
En esta microlección exploramos la arquitectura por capas enfocándonos en la separación estricta entre persistencia y lógica. El objetivo es evitar que las consultas SQL o llamadas a APIs externas se filtren directamente desde el controlador, lo cual expone vulnerabilidades como inyecciones de código. Implementaremos una capa de servicio (Service Layer) que actúa como intermediario. Esta capa valida los datos entrantes, aplica reglas de negocio complejas y orquesta las operaciones de acceso a la base de datos. Al centralizar aquí la lógica, podemos cambiar el motor de persistencia sin afectar la interfaz de usuario ni la lógica de presentación. Este patrón es fundamental para sistemas escalables donde la integridad de los datos es crítica.

## Ejemplo (no ejecutado automáticamente)
Implementación de una clase Service que encapsula la lógica de creación de usuarios y valida el correo antes de persistir en la base de datos.

```java
public class UserService {
    private UserRepository repository;

    public User createUser(String email, String password) {
        if (!isValidEmail(email)) {
            throw new IllegalArgumentException("Correo inválido");
        }
        return repository.save(new User(email, password));
    }
}
```

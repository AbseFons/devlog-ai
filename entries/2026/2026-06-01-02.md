## Objetivo
Aprender a identificar y resolver manualmente conflictos de merge utilizando herramientas de línea de comandos, asegurando la integridad del historial y la coherencia del código base sin pérdida de datos.

## Explicación
Cuando Git detecta un conflicto durante una fusión o rebase, detiene el proceso marcando los archivos afectados con bloques '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, debes abrir el archivo en un editor, editar manualmente la sección conflictiva eliminando las marcas de Git y fusionando lógicamente ambas versiones. Una vez resuelto, guarda el archivo y ejecuta 'git add' para marcarlo como resuelto. Finalmente, completa la operación con 'git commit'. Este proceso manual garantiza que comprendas los cambios integrados, evitando errores sutiles que podrían pasar desapercibidos en herramientas automáticas.

## Ejemplo (no ejecutado automáticamente)
Se muestra un fragmento de archivo donde se fusionan dos versiones distintas de una función, eliminando las marcas de conflicto y manteniendo la lógica correcta.

```bash
# Versión original: def calcular_total():
# Versión modificada: def calcular_total(precio, cantidad):
# Solución fusionada:
def calcular_total(precio, cantidad):
    return precio * cantidad
```

## Ejercicio
Crea un repositorio local con dos ramas. En 'main', modifica una función para agregar parámetros. En otra rama, haz cambios similares pero diferentes en la misma función. Intenta fusionar las ramas y resuelve el conflicto manualmente.

## Criterios de revisión
El archivo debe estar libre de marcadores de Git ('<<<<<<<', '======='), la lógica del código debe ser funcional y consistente con ambas versiones originales, y el comando 'git status' debe mostrar todos los archivos como modificados pero sin conflictos pendientes.

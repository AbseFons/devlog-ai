## Objetivo
Distinguir conceptualmente entre merge y rebase en Git, entendiendo cómo cada comando afecta la historia del proyecto y cuándo utilizar uno u otro para mantener un historial limpio o preservar ramas paralelas.

## Explicación
Git ofrece dos estrategias principales para integrar cambios: merge y rebase. Merge crea un nuevo commit de fusión que preserva la topología original, mostrando claramente las divergencias y convergencias entre ramas. Es ideal para flujos de trabajo colaborativos donde se desea mantener una historia lineal pero transparente. Por otro lado, rebase aplica los commits de una rama sobre la punta de otra, creando una línea temporal lineal y cronológica. Esto resulta en un historial más limpio y fácil de leer, aunque es controversial porque modifica el historial existente. La elección depende del contexto: merge para transparencia y seguridad; rebase para limpieza visual antes de fusionar con main.

## Ejemplo (no ejecutado automáticamente)
Comando git rebase interactivo para reordenar commits locales antes de fusionar

```bash
git rebase -i HEAD~3
# Selecciona los commits a mover o editar en el editor que se abre
```

## Ejercicio
Realiza un cambio en una rama local, haz commit y luego ejecuta 'git rebase -i' para reordenar ese commit con otros anteriores. Verifica que la línea de tiempo sea lineal.

## Criterios de revisión
El estudiante debe explicar cuándo usar merge frente a rebase, identificar los riesgos de modificar historial compartido y ejecutar correctamente el comando interactivo sin perder cambios.

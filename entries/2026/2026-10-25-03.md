## Objetivo
Comprender cómo desacoplar módulos invirtiendo la dependencia hacia interfaces abstractas, facilitando pruebas unitarias y reemplazabilidad de componentes sin alterar el código existente.

## Explicación
El principio de inversión de dependencias establece que los módulos de alto nivel no deben depender de módulos de bajo nivel; ambos deben depender de abstracciones. Esto permite intercambiar implementaciones dinámicamente. Por ejemplo, si un sistema necesita enviar correos, en lugar de depender directamente de la clase SMTP, depende de una interfaz 'EnviarCorreo'. Así, podemos cambiar el proveedor (SMTP, API externa, consola) sin tocar la lógica de negocio. Este enfoque reduce acoplamiento y aumenta flexibilidad.

## Ejemplo (no ejecutado automáticamente)
Clase 'ServicioNotificaciones' que depende de una interfaz 'INotificador'. Se inyecta dinámicamente un objeto 'SMTPNotifier' en el constructor, demostrando la inversión de dependencias en tiempo de ejecución.

```javascript
class INotificador {
  enviar(mensaje): void;
}
class SMTPNotifier implements INotificador {
  enviar(mensaje): void { console.log('SMTP: ' + mensaje); }
}const servicio = new ServicioNotificaciones(new SMTPNotifier());
```

## Ejercicio

## Criterios de revisión

## Objetivo
Aprender a usar git bisect para identificar rápidamente la commit que introdujo un bug en el historial, reduciendo drásticamente el tiempo de depuración mediante una búsqueda binaria automatizada.

## Explicación
git bisect es una herramienta poderosa que asume que tu historial es lineal y ordenado. Funciona como una búsqueda binaria: le dices al sistema cuál commit era bueno (antes del error) y cuál era malo (cuando apareció el bug). Git luego seleccionará automáticamente un commit intermedio, lo hará checkout temporalmente y te permitirá probarlo. Si sigue fallando, repite el proceso con la mitad inferior; si funciona, con la superior. Este ciclo se repite hasta aislar exactamente la commit culpable. Es ideal para errores sutiles que aparecen tras muchas iteraciones de desarrollo.

## Ejemplo (no ejecutado automáticamente)
Inicializa bisect marcando un commit conocido como bueno y otro malo, permitiendo a Git reducir el espacio de búsqueda automáticamente.

```bash
git bisect start
GIT_AUTHOR_DATE="2024-01-01" GIT_COMMITTER_DATE="2024-01-01" git commit --allow-empty -m "Commit bueno"
git bisect bad HEAD
```

## Ejercicio
En un repositorio con al menos 50 commits, introduce un bug en el último commit. Usa git bisect para encontrar la primera commit que causó el fallo.

## Criterios de revisión
Identificar correctamente la commit culpable sin errores de sintaxis y completar el proceso con git bisect reset.

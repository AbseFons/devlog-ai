## Objetivo
Comprender el concepto fundamental de inyección de dependencias y cómo la inversión de control desacopla las clases, facilitando pruebas unitarias y mantenimiento del código en arquitecturas modernas.

## Explicación
La inyección de dependencias (IoC) es un patrón de diseño que permite a una clase recibir sus dependencias desde el exterior en lugar de crearlas internamente. Esto se logra mediante la inversión de control, donde el flujo de ejecución no está determinado por las clases mismas, sino por un contenedor o framework externo. Al delegar la creación de objetos complejos, reducimos acoplamientos fuertes y hacemos que el código sea más modular. Este enfoque es esencial para escribir software mantenible, escalable y fácil de probar sin necesidad de mockear manualmente cada componente.

## Ejemplo (no ejecutado automáticamente)
Se muestra una clase 'ServicioReporte' que antes creaba su propia dependencia 'RepositorioDatos'. Ahora recibe el repositorio a través del constructor, permitiendo inyectar un repositorio real o simulado según el contexto.

```java
public class ServicioReporte {
    private final RepositorioDatos repositorio;

    public ServicioReporte(RepositorioDatos repositorio) {
        this.repositorio = repositorio;
    }
}
```

## Ejercicio
Refactoriza una clase existente que instancia directamente un objeto 'Logger' dentro de su método principal. Modifica la clase para recibir el Logger a través del constructor y registra dos eventos diferentes usando esa dependencia inyectada.

## Criterios de revisión
El código debe mostrar claramente la declaración del constructor con el parámetro de tipo Logger, la inicialización del campo privado y la ausencia de 'new Logger()' dentro del cuerpo de la clase. Debe existir al menos una llamada a un método del logger en el cuerpo de la clase.

## Objetivo
Aprender a usar git bisect para localizar eficientemente la introducción de un bug en el historial de commits, aplicando una estrategia de prueba binaria automatizada para reducir drásticamente el tiempo de depuración en flujos de trabajo ágiles.

## Explicación
El comando git bisect actúa como un buscador binario inteligente dentro del historial de Git. En lugar de revisar commits manualmente, este comando permite marcar una versión actual rota como 'buggy' y una versión anterior funcional como 'good'. Git seleccionará automáticamente un commit intermedio para que pruebes. Si la prueba falla, el proceso se repite en la mitad inferior; si pasa, en la superior. Esta técnica es vital cuando una integración continua rompe el pipeline sin causa obvia inmediata. Al iterar rápidamente con pruebas automatizadas, converges hacia el commit exacto que introdujo la regresión, facilitando su reversión o corrección específica.

## Ejemplo (no ejecutado automáticamente)
Script de bash que automatiza el flujo de bisect ejecutando una prueba unitaria simple para determinar si un commit es bueno o malo.

```bash
# Ejecutar en la rama actual
GIT_BISECT_RUN='./run_test.sh' git bisect start
git bisect bad
git bisect good v1.2.0
```

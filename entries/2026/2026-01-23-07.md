## Objetivo
Comprender la distinción funcional entre mocks y stubs en pruebas unitarias, identificando cuándo utilizar cada uno para aislar dependencias externas sin comprometer la integridad del sistema bajo prueba.

## Explicación
En ingeniería de software, los stubs son respuestas predefinidas que simulan el comportamiento básico de una dependencia externa, permitiendo continuar la ejecución del flujo principal. Por otro lado, los mocks son objetos simulados más estrictos que verifican si se les llamó con los argumentos correctos y en el momento adecuado. Mientras que un stub simplemente devuelve un valor para evitar bloqueos por I/O real, un mock valida las interacciones entre componentes. Utilizar stubs es ideal cuando solo necesitas datos de entrada controlados, mientras que los mocks son esenciales para asegurar que la lógica de negocio interactúe correctamente con sus dependencias sin depender de servicios reales.

## Ejemplo (no ejecutado automáticamente)
Un stub simple en JavaScript que simula una llamada a API devolviendo un objeto estático predefinido.

```javascript
const apiStub = {
  fetch: () => Promise.resolve({ data: 'respuesta_fija' })
};
```

## Ejercicio
Crea una función que acepte un objeto como parámetro y utilice un stub para simular una llamada a base de datos, asegurando que la función no falle si el servicio real está caído.

## Criterios de revisión
El código debe incluir al menos un stub funcional, evitar llamadas a servicios externos reales durante la ejecución y demostrar cómo se aísla la lógica de negocio de la dependencia simulada.

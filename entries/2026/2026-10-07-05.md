## Objetivo
Aprender a reducir drásticamente el tamaño de las imágenes Docker separando la fase de compilación del código fuente de la fase final de ejecución, utilizando múltiples instrucciones FROM en un mismo archivo.

## Explicación
Las imágenes Docker por defecto suelen ser voluminosas porque incluyen herramientas de construcción como compiladores o intérpretes. La técnica de multi-stage builds permite definir varias etapas: una primera etapa con todo el entorno de desarrollo para compilar el binario, y una segunda etapa que solo copia el resultado final en una imagen minimalista basada en un sistema operativo ligero. Esto elimina dependencias innecesarias del sistema de construcción en la imagen producida.

## Ejemplo (no ejecutado automáticamente)
Un contenedor Node.js optimizado donde se compila el proyecto en una etapa y se ejecuta solo con runtime en la segunda.

```bash
# Etapa de construcción
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Etapa de producción
FROM node:18-alpine
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package*.json ./
CMD ["node", "dist/index.js"]
```

## Ejercicio
Crea un archivo Dockerfile para una aplicación Python que utilice pip para instalar dependencias en la primera etapa y solo copie el sitio web compilado (o el script) a una imagen base slimmer en la segunda etapa.

## Criterios de revisión
El Dockerfile debe contener al menos dos instrucciones FROM. La segunda etapa no debe incluir comandos de instalación de paquetes del sistema operativo ni dependencias de desarrollo innecesarias.

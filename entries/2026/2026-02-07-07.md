## Objetivo
Distinguir claramente el concepto de autenticación (quién eres) del de autorización (qué puedes hacer) en el contexto de desarrollo de APIs RESTful, estableciendo las bases para una arquitectura segura.

## Explicación
En seguridad de APIs, la autenticación verifica la identidad del usuario mediante credenciales como tokens JWT o claves API. Responde a '¿Quién eres?'. La autorización ocurre después y determina los permisos específicos de ese usuario identificado, respondiendo a '¿Qué puedes hacer?'. Un error común es confundir ambos: un token válido no garantiza acceso total; solo permite las rutas definidas en sus scopes. Implementar ambos pasos secuencialmente es vital para evitar fugas de datos.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de middleware en Node.js que valida un token de autenticación y luego verifica si el usuario tiene permiso para acceder a una ruta específica.

```javascript
const verifyToken = (req, res, next) => {
  const token = req.headers['authorization'];
  if (!token) return res.status(401).send('No autorizado');
  // Lógica de validación del token
  next();
};
const checkPermission = async (req, res, next) => {
  const userRole = await getUserRole(req.user);
  if (!userRole.canAccessResource) return res.status(403).send('Acceso denegado');
  next();
};
```

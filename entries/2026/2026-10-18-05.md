## Objetivo
Aprender a configurar un hook pre-commit para validar que los archivos subidos no contengan credenciales expuestas o patrones de seguridad críticos antes de que se integren al repositorio, mejorando la higiene del código.

## Explicación
Los hooks de Git son scripts que se ejecutan en momentos específicos del flujo de trabajo. En esta lección, nos enfocamos en el hook 'pre-commit'. Este script intercepta cada intento de añadir o enviar cambios. Su función principal es actuar como una barrera de seguridad automática. Podemos escribir un script en Bash o Python que escanee los archivos modificados buscando patrones comunes de credenciales, como contraseñas en texto plano o claves API malformadas. Si el script detecta una vulnerabilidad, abortará la operación y mostrará un mensaje claro al desarrollador. Esto evita que errores humanos comprometan la seguridad del proyecto antes de llegar a producción. Es una práctica esencial para equipos que manejan datos sensibles.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que busca credenciales simples en los archivos modificados y detiene el commit si las encuentra.

```bash
#!/bin/bash
# Hook pre-commit para detectar credenciales basicas
if git diff --cached --name-only | xargs grep -E 'password=|secret_key='; then
  echo "Error: Se detectaron posibles credenciales expuestas."
  exit 1
fi
```

## Ejercicio
Crea un archivo llamado .git/hooks/pre-commit en tu repositorio local. Copia el código del ejemplo dentro de él, asegurándote de que sea ejecutable (chmod +x). Intenta añadir un archivo con la línea 'password=supersecreto' y observa cómo se bloquea el commit.

## Criterios de revisión
El hook debe existir en .git/hooks/pre-commit. El script debe ser ejecutable. Debe abortar el commit si encuentra las palabras clave especificadas. El mensaje de error debe ser claro.

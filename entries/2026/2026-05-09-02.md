## Objetivo
Comprender y aplicar el principio de mínimo privilegio asignando solo las permisos estrictamente necesarios a un usuario o servicio para reducir la superficie de ataque en sistemas de producción.

## Explicación
El principio de mínimo privilegio establece que cada entidad debe tener únicamente los accesos requeridos para su función específica. En lugar de otorgar roles administrativos amplios, se deben definir roles granulares. Por ejemplo, un servicio de backend no necesita acceso a la consola de administración ni a datos sensibles fuera de su lógica de negocio. Esto limita el daño potencial en caso de compromiso. La implementación implica auditar los permisos actuales, eliminar excesos y configurar políticas de acceso basadas en funciones concretas. Este enfoque es fundamental para cumplir con normativas de seguridad y proteger la integridad del sistema ante amenazas internas o externas.

## Ejemplo (no ejecutado automáticamente)
Se define un rol de 'lector' que solo puede ejecutar consultas SELECT, excluyendo permisos de escritura o borrado en una base de datos relacional.

```sql
CREATE ROLE app_reader;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO app_reader;
```

## Ejercicio
Identifica tres roles existentes en tu entorno que violan el principio de mínimo privilegio y redacta una política para redefinir sus permisos.

## Criterios de revisión
El rol debe tener menos de cinco permisos, no incluir acceso a datos personales ni capacidad de modificación, y estar documentado con su justificación funcional.

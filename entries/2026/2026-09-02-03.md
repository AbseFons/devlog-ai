## Objetivo
Entender que la cobertura de código no garantiza calidad; aprender a identificar límites de validación, condiciones borde y casos de error críticos que el testing automático suele omitir si no se diseñan explícitamente.

## Explicación
La cobertura de rama al 100% es una métrica engañosa. Un sistema puede estar totalmente cubierto pero fallar ante entradas inesperadas o límites de recursos. El testing efectivo requiere definir casos límite: valores máximos, mínimos, nulos y tipos incorrectos. Además, se deben probar escenarios de concurrencia y fallos parciales del sistema. No basta con cubrir el código; hay que validar el comportamiento esperado bajo estrés y condiciones adversas para evitar vulnerabilidades en producción.

## Ejemplo (no ejecutado automáticamente)
```python
def procesar_pedido(cantidad, precio_unitario):
    if cantidad <= 0 or precio_unitario < 0:
        raise ValueError("Valores inválidos")
    if cantidad > 10000:
        return "Pedido bloqueado por límite de seguridad"
    total = cantidad * precio_unitario
    if total > 500000:
        return "Transacción rechazada: monto excesivo"
    return {"total": total, "estado": "aprobado"}
```

## Ejercicio
Crea una función que acepte un string de fecha y devuelva el día de la semana. Incluye casos para fechas inválidas, formatos incorrectos y fechas futuras lejanas.

## Criterios de revisión
El código debe lanzar excepciones claras para entradas inválidas, manejar correctamente los límites del rango de fechas soportadas por la librería estándar y no colapsar con strings muy largos.

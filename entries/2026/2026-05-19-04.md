## Objetivo
Aprender a dividir las funciones de lectura y escritura de datos para mejorar la mantenibilidad del código, evitando que una misma clase gestione múltiples operaciones distintas.

## Explicación
El principio de separación de responsabilidades dicta que cada módulo o clase debe tener un único motivo para cambiar. En el contexto de acceso a datos, es común ver clases 'Usuario' o 'Repositorio' que mezclan lógica de consulta (SELECT) con lógica de persistencia (INSERT/UPDATE). Esta mezcla complica las pruebas unitarias y dificulta la reutilización del código. Al separar estas responsabilidades, creamos interfaces claras: una para obtener datos y otra para modificarlos. Esto permite implementar estrategias como el patrón Repository o DAO de manera más limpia, donde cada método tiene un contrato bien definido.

## Ejemplo (no ejecutado automáticamente)
Clase base con métodos separados para cargar y guardar entidades.

```python
class DataHandler:
    def fetch_user(self, id):
        return self._db.query('SELECT * FROM users WHERE id = ?', (id))

    def save_user(self, user):
        self._db.execute('INSERT INTO users VALUES (?, ?, ?)', (user.id, user.name, user.email))
```

## Objetivo
Comprender la diferencia entre cobertura de código (qué se ejecutó) y límites de negocio (qué se validó). Aprender a diseñar casos que cubran no solo el camino feliz, sino también los bordes críticos del sistema para prevenir fallos sutiles en producción.

## Explicación
La cobertura de código mide la cantidad de líneas o ramas ejecutadas durante las pruebas, pero no garantiza que el software funcione correctamente. Un alto porcentaje de cobertura puede ocultar errores lógicos si no se prueban los límites del dominio. Los límites son valores extremos (máximo, mínimo, nulo) donde suelen fallar los sistemas. Una estrategia efectiva combina métricas de cobertura con pruebas de frontera. Es vital definir casos que validen el comportamiento en los bordes definidos por la especificación de negocio, no solo por la estructura del código. Esto asegura robustez ante entradas inesperadas y protege la integridad de los datos.

## Ejemplo (no ejecutado automáticamente)
Script que valida límites numéricos en un sistema de inventario, cubriendo casos felices y bordes críticos como cero o negativo.

```python
def validar_inventario(cantidad):
    if cantidad < 0:
        return 'Error: Cantidad negativa'
    elif cantidad == 0:
        return 'Stock agotado'
    else:
        return f'Producto disponible: {cantidad}'

print(validar_inventario(5))
print(validar_inventario(0))
print(validar_inventario(-1))
```

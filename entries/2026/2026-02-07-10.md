## Objetivo
Comprender la diferencia fundamental entre las operaciones de lectura (GET) y creación (POST) en el diseño de APIs RESTful, aplicando los verbos HTTP correctos para construir endpoints seguros y semánticamente precisos que reflejen la naturaleza del recurso.

## Explicación
En una API REST, cada método HTTP define una acción específica sobre un recurso. El verbo GET se utiliza exclusivamente para recuperar datos sin efectos secundarios, ideal para listar usuarios o obtener detalles de un producto. Por otro lado, POST inicia una nueva transferencia de datos y es el estándar para crear recursos en el servidor, como registrar un nuevo usuario. Es crucial distinguirlos: usar GET para crear datos viola principios de seguridad y caché, mientras que usar POST para leer puede generar errores inesperados. Esta distinción permite a los desarrolladores construir sistemas escalables donde cada petición tiene un propósito claro y predecible dentro del flujo de la aplicación.

## Ejemplo (no ejecutado automáticamente)
Definición de dos rutas en un servidor Express: una para listar usuarios con GET y otra para crear uno nuevo con POST.

```javascript
app.get('/api/users', (req, res) => {
  res.json({ users: [1, 2, 3] }));
});

app.post('/api/users', (req, res) => {
  const newUser = { id: Date.now(), ...req.body };
  res.status(201).json(newUser);
});
```

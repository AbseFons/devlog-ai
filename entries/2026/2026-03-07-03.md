## Objetivo
Comprender la diferencia entre imagen (plantilla inmutable) y contenedor (instancia ejecutable), y cómo Docker utiliza capas para optimizar el almacenamiento y la distribución de aplicaciones.

## Explicación
En Docker, una imagen es un archivo de plantillas que contiene todo lo necesario para ejecutar una aplicación: código, librerías y variables de entorno. Es inmutable y se almacena en repositorios como Docker Hub. Un contenedor es una instancia ligera y efímera creada a partir de esa imagen. Cuando ejecutas 'docker run', el motor de Docker crea un contenedor basado en la imagen, añadiendo solo las capas de cambios necesarias para ese proceso específico. Esto permite que múltiples contenedores compartan la misma base de datos de imágenes, ahorrando espacio y acelerando el despliegue. Las imágenes se construyen mediante 'Dockerfiles', scripts que definen los pasos para crearla.

## Ejemplo (no ejecutado automáticamente)
Creación de una imagen personalizada con un contenedor web simple usando Python y ejecución del mismo.

```bash
# Crear archivo Dockerfile
FROM python:3.9-slim
WORKDIR /app
COPY app.py .
CMD ["python", "app.py"]
# Construir imagen
docker build -t mi-app-web .
# Ejecutar contenedor
docker run -d --name web-demo -p 8000:8000 mi-app-web
```

## Ejercicio
Crea un Dockerfile que instale Node.js, copie un archivo 'index.js' y exponga el puerto 3000. Construye la imagen con la etiqueta 'mi-nodo:v1' y ejecuta un contenedor llamado 'servidor-prueba' mapeando el puerto local 3000 al remoto.

## Criterios de revisión
El Dockerfile debe tener exactamente tres instrucciones: FROM, COPY y CMD/EXPOSE. La construcción de la imagen debe ser exitosa sin errores de sintaxis. El contenedor debe estar en estado 'running' y el mapeo de puertos debe configurarse correctamente.

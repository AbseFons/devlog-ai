## Objetivo
Distinguir claramente el propósito de los mocks (validar interacciones) frente a los stubs (proveer datos simulados), aplicando cada uno en su contexto adecuado para escribir pruebas más robustas y mantenibles.

## Explicación
En la ingeniería de software, ambos son objetos simulados pero con fines distintos. Un Stub es una función o objeto que devuelve un valor predeterminado predefinido para permitir que la prueba continúe sin depender de servicios externos lentos o complejos. Su único rol es 'llenar el vacío'. Por otro lado, un Mock no solo devuelve valores, sino que registra las llamadas recibidas y sus argumentos. Esto permite validar si nuestro sistema interactuó correctamente con dependencias externas, como una base de datos simulada o una API ficticia. Usar un Stub cuando necesitas datos específicos es correcto, pero si tu objetivo es asegurar que la lógica interna llama a la dependencia correcta, el Mock es la herramienta indispensable.

## Ejemplo (no ejecutado automáticamente)
Se define un Stub para simular una respuesta de red exitosa y un Mock para verificar que se invocó el método de conexión con los parámetros correctos.

```javascript
const stub = () => ({ status: 200, data: 'ok' });
const mock = { connect: jest.fn() };
mock.connect.mockReturnValue(stub());
```

## Ejercicio
Crea un archivo llamado 'test_servicio.js'. Dentro, define una función 'fetchDatos' que llame a un objeto 'apiMock'. Usa 'jest.spyOn' para convertir el método 'get' de 'apiMock' en un Mock. Luego, escribe una prueba que invoque 'fetchDatos' y verifique dos cosas: primero, que 'get' fue llamado exactamente una vez con la URL '/users'; segundo, que el valor devuelto por el Mock sea un objeto con la propiedad 'id' igual a 1.

## Criterios de revisión
La prueba debe fallar si 'fetchDatos' no llama al método espionado o si los argumentos de la llamada no coinciden exactamente con '/users'. Además, el aserto final debe comprobar estrictamente que el objeto devuelto por el Mock tenga el ID correcto.

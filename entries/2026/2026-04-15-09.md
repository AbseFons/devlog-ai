## Objetivo
Comprender la importancia de dividir una aplicación en capas lógicas (presentación, lógica, datos) para mejorar el mantenimiento, la escalabilidad y la seguridad del software.

## Explicación
El diseño por capas organiza el sistema en niveles con responsabilidades distintas. La capa de presentación maneja la interacción con el usuario, mientras que la capa de negocio encapsula la lógica crítica y las reglas de operación. Finalmente, la capa de acceso a datos se encarga exclusivamente de la persistencia. Esta separación evita que los cambios en una interfaz afecten directamente a la base de datos o viceversa. Además, permite reutilizar la lógica de negocio con diferentes interfaces (web, móvil) y facilita las pruebas unitarias al aislar cada componente.

## Ejemplo (no ejecutado automáticamente)
Implementación básica de una API REST que valida un usuario en la capa de negocio antes de consultar la base de datos, demostrando el aislamiento entre capas.

```javascript
const validarUsuario = (usuario) => {
  if (!usuario.email || !usuario.password) throw new Error('Datos incompletos');
};

const obtenerPerfil = async (req, res) => {
  try {
    validarUsuario(req.body);
    const usuario = await db.query('SELECT * FROM usuarios WHERE id = ?', req.params.id);
    res.json(usuario);
  } catch (error) {
    res.status(400).json({ error: error.message });
  }
};
```

## Ejercicio
Crea una función en la capa de presentación que reciba un objeto JSON y llame a la función de validación de la capa de negocio. Si la validación falla, devuelve un mensaje de error sin tocar la base de datos.

## Criterios de revisión
El código debe mostrar claramente tres funciones o bloques distintos correspondientes a las tres capas. La capa de negocio no debe contener consultas SQL directas ni manipulación de HTML. El manejo de errores debe detenerse en la capa correspondiente antes de propagarse innecesariamente.

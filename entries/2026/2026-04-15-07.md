## Objetivo
Comprender la función básica de los hooks en Git, específicamente el pre-commit, para automatizar validaciones antes de cada commit y mantener un historial limpio.

## Explicación
Los hooks son scripts que Git ejecuta automáticamente en momentos específicos del flujo de trabajo. El hook 'pre-commit' se activa justo antes de realizar un commit. Su utilidad principal es validar el código o formatear archivos sin necesidad de intervención manual constante. Por ejemplo, puedes usarlo para ejecutar linters como ESLint o Prettier. Si la validación falla, Git bloqueará el commit y mostrará el error en la terminal. Esto asegura que solo se guarden cambios que cumplan con los estándares del equipo, reduciendo errores humanos y facilitando la revisión de código.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que verifica si hay archivos no formateados antes de permitir el commit.

```bash
#!/bin/bash
if git diff --cached --name-only | xargs git ls-files -o; then
  echo "Archivos sin formatear detectados. Abortando commit."
  exit 1
fi
```

## Ejercicio
Crea un archivo llamado .git/hooks/pre-commit en tu repositorio local. Copia el código del ejemplo dentro de este archivo, asegúrate de que sea ejecutable con chmod +x y prueba a realizar un commit con archivos modificados para observar si se bloquea.

## Criterios de revisión
El script debe existir en la carpeta .git/hooks/, ser ejecutable y detener el proceso de commit al menos una vez durante la prueba.

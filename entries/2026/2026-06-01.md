## Objetivo
Diferenciar conceptualmente y técnicamente las operaciones merge y rebase en Git, entendiendo cuándo preservar la historia lineal versus mantener una estructura de ramas clara.

## Explicación
Merge crea un nuevo commit que fusiona dos líneas de desarrollo, preservando la historia real de las ramas. Rebase reescribe la historia local moviendo los commits para parecer que se hicieron después del merge principal. Merge es seguro y transparente; rebase puede complicar la resolución de conflictos si no se hace en una rama local. Usa merge para colaboracion remota inmediata, rebase para limpiar tu historial antes de push.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un merge y luego un rebase interactivo en una rama de desarrollo.

```bash
git checkout feature
feature: add new functionality
git checkout main
git merge feature
git checkout feature
git rebase main
```

## Ejercicio
Crea una rama 'bugfix', haz un commit, vuelve a 'main', haz otro commit y luego aplica un rebase para ordenar los commits.

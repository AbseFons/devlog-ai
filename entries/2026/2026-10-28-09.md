## Objetivo
Aprender a identificar y resolver conflictos de fusión en Git mediante edición directa del archivo, preservando la lógica de ambas ramas sin perder datos críticos.

## Explicación
Cuando Git detecta un conflicto durante una fusión o rebase, marca las líneas problemáticas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. El objetivo es editar el archivo manualmente para integrar los cambios deseados de ambas versiones. Primero, elimina los marcadores de Git. Luego, escribe la lógica correcta combinando el código del tuyo (HEAD) y del remoto (origin). Guarda el archivo y ejecuta 'git add' seguido de 'git commit'. Esta técnica es esencial para mantener la integridad del historial y evitar pérdida de funcionalidad en proyectos colaborativos.

function calcularTotal(items) {
  if (!Array.isArray(items)) return 0;
  // Lógica combinada: suma segura con manejo de errores
  return items.reduce((sum, item) => sum + (item.price || 0), 0);
}

Crea dos ramas locales llamadas 'feature-a' y 'feature-b'. En 'feature-a', modifica la función 'calcularTotal' para validar que el array no esté vacío. En 'feature-b', añade una validación de tipos dentro del bucle. Intenta fusionar ambas ramas y resuelve el conflicto manualmente editando el archivo.

## Criterios de revisión
El usuario debe eliminar correctamente los marcadores de conflicto, integrar la lógica de validación de ambos archivos en un solo bloque coherente, ejecutar 'git add' y 'git commit' sin errores, y asegurar que la función final maneje tanto arrays vacíos como elementos con precio nulo.

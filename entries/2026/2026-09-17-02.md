## Objetivo
Aprender a usar git bisect para identificar rápidamente el commit exacto que introdujo un bug en el historial, ahorrando horas de revisión manual mediante una búsqueda binaria automatizada.

## Explicación
El comando git bisect es una herramienta poderosa que funciona como una búsqueda binaria sobre tu historial de commits. En lugar de revisar cada cambio manualmente, le indicas al sistema un commit conocido que contiene el error y otro anterior que funcionaba bien. Git luego seleccionará automáticamente un punto intermedio en la línea temporal para que lo pruebes. Si el bug persiste, elige ese punto; si no, indica que funciona. Este proceso se repite hasta aislar el commit problemático con precisión quirúrgica.

## Ejemplo (no ejecutado automáticamente)
Se inicia una sesión de bisect marcando un commit reciente roto y uno anterior sano para comenzar la búsqueda binaria automática.

```bash
git bisect start
GIT_AUTHOR_DATE="2026-09-17T10:00:00" GIT_COMMITTER_DATE="2026-09-17T10:00:00" git commit --allow-empty -m "Bug introducido"
git bisect bad
GIT_AUTHOR_DATE="2026-09-16T10:00:00" GIT_COMMITTER_DATE="2026-09-16T10:00:00" git commit --allow-empty -m "Ultimo estado correcto"
git bisect good
```

## Ejercicio
Identifica el commit que rompió la funcionalidad ejecutando los comandos de inicio y termino de bisect en un repositorio local con al menos 10 commits.

## Criterios de revisión
El usuario debe ejecutar correctamente git bisect start, marcar dos puntos temporales (good/bad) y usar git bisect bad/good hasta que git bisect reset aparezca.

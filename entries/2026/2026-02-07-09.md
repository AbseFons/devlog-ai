## Objetivo
Comprender y aplicar el principio de mínimo privilegio asignando al usuario de despliegue solo las permisos estrictamente necesarios para ejecutar scripts, evitando acceso a datos sensibles o comandos peligrosos como sudo.

## Explicación
El principio de mínimo privilegio establece que cada entidad (usuario, proceso) debe poseer únicamente los permisos mínimos requeridos para su funcionamiento. En un servidor web, el usuario 'deploy' necesita escribir en /var/www/html pero no leer archivos de configuración del sistema ni ejecutar comandos como rm o reboot. Esto limita el daño ante una vulnerabilidad. Implementar esto reduce la superficie de ataque y cumple con normativas de seguridad. Se logra mediante grupos específicos (ej. www-data) y listas de control de acceso (ACLs), asegurando que incluso si las credenciales se filtran, el atacante no pueda escalar privilegios ni modificar el sistema operativo.

## Ejemplo (no ejecutado automáticamente)
Se define un usuario 'deploy' con permisos de escritura limitados a una carpeta específica y se le niega acceso al grupo root o a comandos sensibles mediante sudoers.

```bash
useradd -m deploy
usermod -aG www-data deploy
echo 'deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx' >> /etc/sudoers.d/deploy
```

## Ejercicio
Crea un usuario llamado 'analista' en tu máquina local. Asigna permisos de lectura solo a la carpeta '/var/log/nginx' y asegúrate de que no pueda ejecutar comandos como 'cat /etc/shadow'.

## Criterios de revisión
El usuario debe existir, tener acceso de lectura restringido al directorio especificado y carecer de capacidad para leer archivos sensibles o ejecutar comandos administrativos.

## Objetivo
Diferenciar claramente entre autenticación (quién eres) y autorización (qué puedes hacer) en el contexto de APIs REST, estableciendo la base para diseñar sistemas seguros.

## Explicación
En seguridad de APIs, autenticación verifica la identidad del usuario mediante credenciales como tokens JWT o claves API. Autorización determina los permisos específicos de esa identidad, definiendo qué recursos puede acceder o modificar. Un error común es confundir ambos conceptos; por ejemplo, un token válido (autenticado) no garantiza acceso a todos los datos (autorizado). La implementación correcta requiere middleware que primero valide la identidad y luego consulte una lista de roles o políticas para permitir o denegar la solicitud específica.

## Ejemplo (no ejecutado automáticamente)
Intercepta una petición API para verificar el token de autenticación y validar si el rol del usuario permite acceder al recurso solicitado.

```javascript
const authMiddleware = async (req, res, next) => {
  const token = req.headers['authorization'];
  if (!token) return res.status(401).json({ error: 'No autorizado' });
  // Lógica de autorización basada en el rol decodificado del token
}
```

## Ejercicio
Crea una función que reciba un objeto con 'usuario' y 'recurso'. Devuelve true si el usuario tiene permiso para ese recurso, simulando una matriz de permisos simple.

## Criterios de revisión
El código debe diferenciar claramente la validación del token (autenticación) de la comprobación de permisos (autorización). Debe manejar casos donde falta el token o los permisos son insuficientes.

## Objetivo
Aprender a diseñar pruebas que verifiquen la comunicación entre componentes internos y servicios externos, asegurando la resiliencia del sistema ante fallos de terceros sin depender de su disponibilidad real.

## Explicación
Las pruebas de integración en serie 2 se enfocan en la interacción con APIs externas. En lugar de llamar al servicio real, utilizamos mocks o stubs para simular respuestas exitosas y errores controlados. Esto permite aislar fallos específicos del cliente sin afectar el proveedor. El objetivo es validar cómo nuestra aplicación maneja tiempos de espera, códigos HTTP erróneos y respuestas incompletas. Implementaremos un caso donde una función de pago falla porque la pasarela externa devuelve un error 503, asegurando que la UI muestre un mensaje adecuado y no entre en bucle infinito.

## Ejemplo (no ejecutado automáticamente)
Simulación de fallo en API de pagos usando un stub para validar manejo de errores HTTP 503

```javascript
const mockPaymentService = {
  process: async (amount) => { throw new Error('Service Unavailable'); }
};
try {
  await mockPaymentService.process(100);
} catch (err) {
  console.log('Pago fallido:', err.message);
}
```

## Ejercicio
Crea un archivo de prueba que defina un objeto 'mockUser' con métodos para simular respuestas lentas y errores. Implementa una función 'registerUser' que llame a este mock y maneje tres escenarios: éxito, error de red simulado y respuesta vacía.

## Criterios de revisión
El código debe incluir al menos dos mocks distintos, manejar excepciones explícitamente con bloques try-catch y no contener llamadas a servicios reales. La salida por consola debe diferenciar claramente entre los tres escenarios de prueba.

## Objetivo
Comprender cómo estructurar un sistema simple para restringir operaciones sensibles basándose en roles predefinidos, asegurando que solo usuarios autorizados puedan ejecutar acciones críticas dentro de una aplicación web.

## Explicación
El control de acceso es fundamental para la seguridad informática. En esta microlección, exploraremos los principios básicos del Control de Acceso Basado en Roles (RBAC). Este modelo asigna permisos a roles específicos (como 'admin' o 'usuario') y luego otorga esos roles a los usuarios. Implementar esto evita que cualquier persona pueda acceder a datos confidenciales o modificar configuraciones sin autorización. A diferencia de modelos más complejos, este enfoque inicial es ideal para aplicaciones pequeñas o prototipos donde la claridad y la simplicidad son prioritarias. Analizaremos cómo verificar las credenciales del usuario antes de permitir una acción sensible, asegurando que la lógica de seguridad esté integrada directamente en el flujo de la aplicación.

## Ejemplo (no ejecutado automáticamente)
Script en Python que simula la verificación de un rol para permitir o denegar el acceso a una función administrativa.

```python
def verificar_acceso(rol_usuario, accion_requerida):
    roles_permisibles = {'admin': ['lectura', 'escritura', 'borrado'], 'usuario': ['lectura']}
    if rol_usuario in roles_permisibles and accion_requerida in roles_permisibles[rol_usuario]:
        return True
    else:
        return False
```

## Ejercicio
Crea un script que defina tres roles: 'analista', 'gerente' y 'director'. Asigna permisos de lectura, escritura y borrado a cada uno según una jerarquía lógica. Luego, escribe una función que reciba el rol del usuario y la acción deseada, devolviendo un mensaje claro si se permite o se deniega la operación.

## Criterios de revisión
El código debe definir correctamente los roles y sus permisos asociados. La función de verificación debe devolver 'Acceso concedido' solo si el rol posee el permiso solicitado, y 'Acceso denegado' en cualquier otro caso. El script no debe contener credenciales reales ni comandos que modifiquen el sistema operativo.

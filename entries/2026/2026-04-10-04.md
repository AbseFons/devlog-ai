## Objetivo
Comprender la importancia de organizar archivos en carpetas lógicas dentro de un repositorio para facilitar el mantenimiento, la navegación y el control de versiones eficiente en proyectos de software.

## Explicación
Un repositorio bien diseñado no es solo una colección de archivos, sino una estructura jerárquica intencional. La organización debe reflejar la arquitectura del proyecto o agrupar por tipo de recurso (fuentes, tests, documentación). Esto reduce la complejidad cognitiva al navegar el historial de cambios. Evita tener un único archivo raíz con cientos de líneas; separa lógica de configuración y dependencias. Una estructura clara permite que múltiples desarrolladores colaboren sin conflictos innecesarios y hace que las búsquedas en el historial sean precisas.

## Ejemplo (no ejecutado automáticamente)
Estructura de directorios para una aplicación web simple con módulos separados, tests y documentación.

```bash
mkdir -p src/controllers src/models tests/unit docs/api
mv index.js src/
mv config.json config/
```

## Ejercicio
Crea un repositorio vacío en tu máquina local. Dentro, establece una estructura con carpetas 'src', 'tests' y 'docs'. Luego, añade un archivo de configuración llamado '.gitignore' que ignore nod_modules.

## Criterios de revisión
El directorio raíz debe contener exactamente tres subdirectorios: src, tests y docs. El archivo .gitignore debe existir en la raíz y contener al menos la línea 'node_modules'. No deben existir archivos fuera de estas carpetas ni en el nivel raíz salvo el .gitignore.

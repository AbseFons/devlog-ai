## Objetivo
Diferenciar el uso de PUT para reemplazar recursos completos y PATCH para actualizaciones parciales, comprendiendo sus implicaciones semánticas en la integridad de los datos dentro de una arquitectura RESTful.

## Explicación
En las APIs REST, PUT y PATCH gestionan actualizaciones distintas. PUT es idempotente: reemplaza todo el recurso con la representación enviada; si faltan campos, se pierden. Es ideal para crear o actualizar un objeto completo. PATCH, en cambio, aplica cambios parciales al servidor, permitiendo modificar solo los atributos necesarios sin afectar el resto de la estructura. Esto reduce el tráfico y evita errores por datos obsoletos en el cliente. Ambos métodos son esenciales para mantener la consistencia y eficiencia en sistemas distribuidos modernos.

## Ejemplo (no ejecutado automáticamente)
Actualización parcial de un usuario usando PATCH con JSON

```javascript
fetch('https://api.ejemplo.com/usuarios/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
});
```

## Ejercicio
Crea una API local con Express que acepte PUT para reemplazar un producto completo y PATCH para cambiar solo su precio. Valida que PUT no modifique campos no enviados.

## Criterios de revisión
El código debe usar correctamente los encabezados Content-Type, manejar respuestas de estado 200/204, y evitar enviar datos completos innecesarios en PATCH.

## Objetivo
Aprender a usar git bisect para identificar eficientemente el commit exacto que introdujo un bug, reduciendo drásticamente el tiempo de depuración en reposos con historial largo.

## Explicación
git bisect es una herramienta poderosa que asume tu código estaba funcional y luego se rompió. En lugar de revisar commits manualmente, esta herramienta permite realizar una búsqueda binaria automática sobre el historial. Primero marcas el commit actual como 'rotto' y el anterior conocido como 'bueno'. Luego, git bisect ejecuta automáticamente pruebas intermedias en cada paso del proceso. Debes indicar si la versión es buena o rota hasta que el sistema encuentra el punto exacto de ruptura. Es ideal para errores sutiles introducidos hace semanas.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de uso de git bisect con un script de bash que simula una prueba de regresión simple.

```bash
# Marcar el commit actual como roto
git bisect bad
# Marcar el commit anterior conocido como bueno
git bisect good HEAD~10
# Ejecutar la prueba en cada paso intermedio
git bisect run ./test_script.sh
```

## Ejercicio
Marca un commit actual como 'bad' y uno anterior como 'good'. Usa git bisect run con un script de prueba simple que falle solo después del commit problemático.

## Criterios de revisión
El usuario debe identificar correctamente el commit culpable mediante la herramienta, indicando el estado correcto en cada iteración hasta que git bisect termine.

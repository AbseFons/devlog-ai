## Objetivo
Aprender a utilizar ramas protegidas y flujos de trabajo basados en pull requests para mantener la estabilidad del código principal y facilitar la revisión por pares antes de fusionar cambios.

## Explicación
En ingeniería de software moderna, proteger el rama principal (main o master) es crucial. La estrategia recomendada implica crear una rama de funcionalidad desde main, realizar los cambios allí y luego abrir un Pull Request hacia main. Esto permite que otros revisen el código antes de integrarlo. Git no fusiona automáticamente; requiere aprobación explícita. Este proceso reduce errores en producción y mejora la calidad del software mediante revisión colectiva constante.

## Ejemplo (no ejecutado automáticamente)
Crear una rama nueva para desarrollar una función sin afectar el código principal, luego preparar un Pull Request simulado.

```bash
git checkout -b feature/nueva-calculadora
git commit -m 'Añadir calculadora básica'
git push origin feature/nueva-calculadora
```

## Ejercicio
Crea una rama llamada issue/fix-bug-login, haz un commit con un mensaje descriptivo y verifica que la rama existe en tu repositorio remoto.

## Criterios de revisión
El usuario debe crear correctamente una rama desde main, realizar al menos un commit con mensaje claro y confirmar que la rama está lista para ser enviada a revisión.

## Objetivo
Comprender el concepto de atomicidad en bases de datos y cómo garantiza que las operaciones complejas se ejecutan completamente o no se ejecutan en absoluto, manteniendo la integridad del sistema.

## Explicación
La atomicidad es la primera propiedad de las transacciones ACID. Asegura que una transacción compuesta por múltiples operaciones lógicas funcione como una unidad indivisible. Si alguna parte falla, todo el proceso se deshace automáticamente mediante mecanismos como los logs de recuperación. Esto previene estados inconsistentes donde solo algunas partes de una transferencia de dinero o un registro en inventario hayan completado. El motor de la base de datos gestiona esto internamente sin intervención manual.

## Ejemplo (no ejecutado automáticamente)
Simulación conceptual de una transacción bancaria que mueve fondos entre dos cuentas, donde el rollback ocurre si la segunda operación falla.

```sql
BEGIN TRANSACTION;
UPDATE cuentas SET saldo = saldo - 100 WHERE id = 1;
UPDATE cuentas SET saldo = saldo + 100 WHERE id = 2;
COMMIT;
```

## Ejercicio
Analiza el código SQL proporcionado. Identifica qué sucede si la segunda línea UPDATE falla antes de llegar a COMMIT y explica cómo se restaura el estado original de las cuentas involucradas.

## Criterios de revisión
El estudiante debe identificar correctamente que ambas operaciones o ninguna ocurre, describir el rol del log de transacciones en el proceso de deshacer y explicar por qué esto es crucial para la integridad financiera.

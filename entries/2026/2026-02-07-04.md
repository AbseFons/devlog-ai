## Objetivo
Aprender a utilizar ramas protegidas y flujos de trabajo que prevengan la fusión directa de código no revisado al rama principal, asegurando estabilidad en el proyecto.

## Explicación
En ingeniería de software moderna, evitar fusiones directas a main es crucial. Utiliza una rama de desarrollo (ej. feature/login) para trabajar aislado. Una vez terminado, abre un Pull Request o Merge Request hacia la rama destino. Esto activa revisiones por pares automáticas y pruebas CI/CD antes de aceptar el cambio. Nunca empujes directamente a ramas protegidas en reposos colaborativos. Esta disciplina reduce bugs en producción y mantiene un historial claro del progreso.

## Ejemplo (no ejecutado automáticamente)
Crear una rama nueva desde main, realizar cambios simulados y preparar un pull request hacia la rama principal sin fusionar inmediatamente.

```bash
git checkout -b feature/nueva-funcionalidad
git add . && git commit -m 'Añadir lógica de cálculo'
git push origin feature/nueva-funcionalidad
```

## Ejercicio
Crea una rama llamada 'fix/bug-42', realiza un commit con un mensaje descriptivo y abre un pull request en tu plataforma de hosting.

## Criterios de revisión
La rama debe crearse correctamente desde main, el commit debe tener mensaje claro y no debe existir fusión directa a la rama principal.

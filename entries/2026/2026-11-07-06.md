## Objetivo
Aprender las técnicas principales para versionar APIs, asegurando la compatibilidad hacia atrás y facilitando la evolución del servicio sin romper clientes existentes.

## Explicación
El versionado es crucial para gestionar cambios en una API. Existen tres enfoques comunes: versionado por URL (ej. /v1/users), que es explícito pero ensucia la ruta; versionado por encabezados (ej. Accept: application/vnd.api+json;version=2), que mantiene las rutas limpias pero requiere soporte del cliente; y versionado por parámetros de consulta, útil para pruebas rápidas aunque menos semántico. La estrategia recomendada es priorizar la compatibilidad hacia atrás, manteniendo versiones antiguas activas mientras se desarrollan nuevas funcionalidades en versiones superiores.

## Ejemplo (no ejecutado automáticamente)
Definición de rutas y encabezados para una API de usuarios con dos versiones coexistiendo.

```bash
# Versión 1: Ruta estándar
GET /api/v1/users
# Versión 2: Uso de header personalizado
GET /api/users
Accept: application/vnd.mycompany.api+json;version=2
```

## Objetivo
Comprender que las pruebas de regresión verifican que nuevas modificaciones no rompan funcionalidad existente, asegurando estabilidad en el ciclo de vida del software mediante la ejecución selectiva de casos críticos.

## Explicación
Las pruebas de regresión son esenciales tras cada iteración de desarrollo. Su propósito es confirmar que los cambios recientes, como una nueva feature o corrección de bug, no introducen errores en partes del sistema previamente operativas. No se prueban todas las funciones desde cero; se seleccionan casos de uso representativos que cubran el flujo principal y escenarios críticos. Esto optimiza el tiempo de ejecución y reduce la carga sobre los equipos QA. Un conjunto bien diseñado de pruebas de regresión actúa como una red de seguridad, permitiendo a los desarrolladores integrar código con confianza, sabiendo que el núcleo del sistema sigue siendo robusto y funcional ante nuevas alteraciones.

## Ejemplo (no ejecutado automáticamente)
Script en Python que ejecuta un conjunto básico de verificaciones para asegurar que la suma de dos números y la división por cero manejan errores correctamente tras una actualización.

```python
def test_suma():
    assert 2 + 2 == 4

def test_division_error():
    try:
        1 / 0
        assert False, 'Deberia lanzar error'
    except ZeroDivisionError:
        pass
```

## Ejercicio
Crea un script en Python que incluya tres funciones: una para validar el login de un usuario con credenciales correctas, otra para verificar que el login falle con credenciales incorrectas y una tercera para asegurar que la navegación a una página principal redirige correctamente.

## Criterios de revisión
El código debe ejecutar sin errores sintácticos, las tres funciones deben contener al menos una afirmación lógica o manejo de excepciones, y el script debe finalizar indicando 'Todas las pruebas pasaron' si no hay fallos.

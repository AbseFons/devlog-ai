## Objetivo
Comprender el propósito de las pruebas de regresión para asegurar que nuevas modificaciones no rompan funcionalidades existentes, manteniendo la estabilidad del software ante iteraciones continuas.

## Explicación
Las pruebas de regresión son esenciales cuando se introduce un cambio en el código fuente. Su objetivo es verificar que las características previamente funcionales sigan operando correctamente después de la actualización. En lugar de probar todo el sistema desde cero, se selecciona un subconjunto crítico de casos de prueba que cubren los flujos más importantes y aquellos directamente afectados por el cambio. Esto permite detectar errores introducidos accidentalmente (bugs de regresión) sin consumir recursos excesivos. La ejecución automática de estos tests en cada commit o despliegue es una práctica estándar en CI/CD, garantizando calidad continua y reduciendo el riesgo de fallos en producción.

## Ejemplo (no ejecutado automáticamente)
Script que ejecuta un caso de prueba de regresión para verificar la suma de dos números antes y después de una modificación.

```javascript
const resultado = 5 + 3;
console.log('Resultado:', resultado);
if (resultado !== 8) { throw new Error('Fallo en regresión'); }
```

## Criterios de revisión
El script debe ejecutar al menos dos casos: uno con éxito y otro que simule un fallo si la lógica cambia incorrectamente.

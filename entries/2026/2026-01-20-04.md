## Objetivo
Comprender la organización lógica de archivos y directorios dentro de un repositorio Git para facilitar el mantenimiento, la navegación y la colaboración efectiva en proyectos de software.

## Explicación
Un repositorio bien estructurado es fundamental para la salud a largo plazo de cualquier proyecto. La convención estándar separa el código fuente (src/), los recursos estáticos como imágenes o estilos (public/ o assets/), las pruebas (tests/) y la documentación (docs/). Esta segregación permite que los desarrolladores encuentren rápidamente lo que buscan sin perderse en un árbol de directorios plano. Además, mantener una raíz limpia evita commits innecesarios de archivos temporales o de configuración del entorno local. Al seguir estas pautas, se reduce la fricción durante las revisiones de código y se asegura que el historial de versiones refleje únicamente cambios relevantes al producto final.

## Ejemplo (no ejecutado automáticamente)
Creación de una estructura de directorios básica para un proyecto web con separación de código, recursos y pruebas.

```bash
mkdir -p src/components public/images tests/unit docs
mv index.html public/
mv style.css public/
```

## Ejercicio
Crea un nuevo repositorio local llamado 'mi-proyecto'. Dentro, genera las carpetas 'src', 'tests' y 'docs'. Luego, crea un archivo 'README.md' en la raíz y otro 'app.js' dentro de 'src'.

## Criterios de revisión
El directorio raíz debe contener solo el README.md. La carpeta src debe tener al menos un archivo .js. La carpeta tests debe existir aunque esté vacía. No deben haber archivos temporales en la raíz.

## Objetivo
Distinguir claramente el concepto de autenticación (quién eres) del de autorización (qué puedes hacer) en el contexto de las APIs REST, estableciendo la base para diseñar sistemas seguros.

## Explicación
En seguridad de APIs, autenticación y autorización son pasos secuenciales pero distintos. La autenticación verifica la identidad del usuario mediante credenciales como tokens JWT o claves API, respondiendo a '¿Quién eres?'. Una vez validada, la autorización determina los permisos específicos de ese sujeto sobre recursos protegidos, respondiendo a '¿Qué puedes hacer?'. Por ejemplo, un token puede ser válido (autenticado), pero si el rol del usuario no incluye acceso a '/admin', la API rechazará la solicitud con 403. Implementar ambos mecanismos es crucial para prevenir accesos no autorizados incluso ante credenciales robadas.

## Ejemplo (no ejecutado automáticamente)
Solicitud HTTP simulada mostrando un token válido pero sin permisos de escritura en una ruta protegida.

```bash
curl -X POST https://api.ejemplo.com/v1/datos \
  -H 'Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...' \
  -d '{"accion": "crear"}'
```

## Ejercicio
Analiza una respuesta de API que devuelve el estado 403 Forbidden. Investiga en la documentación del proveedor qué roles o scopes faltan para permitir esa acción específica.

## Criterios de revisión
El estudiante debe identificar correctamente si un error es por falta de identidad (401) o por falta de permisos (403), y explicar cómo el token JWT podría contener ambos datos en su carga útil.

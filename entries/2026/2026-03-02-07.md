## Objetivo
Comprender la organización lógica de un repositorio Git, identificando el rol del .git, las ramas principales y la importancia de una estructura de carpetas clara para mantener el código fuente ordenado y escalable en proyectos colaborativos.

## Explicación
Un repositorio Git no es solo una carpeta con código; es un sistema de control de versiones distribuido. La raíz contiene el directorio oculto .git, que almacena el historial completo del proyecto, metadatos y objetos de datos. Las ramas como main o develop permiten trabajar en paralelo sin afectar la estabilidad. Dentro del árbol de archivos, se recomienda separar código fuente, pruebas, documentación y configuración. Esta estructura facilita la navegación, reduce conflictos de merge y permite a nuevos desarrolladores entender rápidamente el propósito de cada archivo. Mantener un repositorio limpio es fundamental para la salud a largo plazo del proyecto.

## Ejemplo (no ejecutado automáticamente)
Estructura inicial de un repositorio Git con archivos clave como README, .gitignore y directorios separados para código y pruebas.

```bash
mkdir -p src tests docs
README.md > README.md
echo 'node_modules/' >> .gitignore
```

## Criterios de revisión
El repositorio debe tener la estructura de directorios solicitada. El archivo .gitignore debe contener al menos una regla válida para ignorar nodulos o compilados. Todos los archivos deben existir en el sistema de archivos local.

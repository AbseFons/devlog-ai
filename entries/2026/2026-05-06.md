## Objetivo
Comprender la importancia del rate limiting para proteger servicios API contra abusos, garantizar estabilidad y distribuir recursos equitativamente entre usuarios concurrentes.

## Explicación
El rate limiting es un mecanismo esencial en el diseño de APIs que restringe el número de solicitudes que un cliente puede realizar dentro de un periodo determinado. Esto previene ataques de denegación de servicio (DoS), evita el agotamiento de recursos del servidor y asegura que los usuarios legítimos mantengan acceso al servicio. Las estrategias comunes incluyen límites basados en tokens, ventanas deslizantes o cuotas fijas por IP o usuario. Implementarlo correctamente desde el inicio es crucial para la escalabilidad y seguridad.

## Ejemplo (no ejecutado automáticamente)
Configuración de un middleware simple en Node.js que aplica un límite de 100 solicitudes por minuto por cliente usando una estructura de mapa para rastrear timestamps.

```javascript
const rateLimitMap = new Map();
function checkRateLimit(clientId) {
  const now = Date.now();
  if (!rateLimitMap.has(clientId)) return true;
  const requests = rateLimitMap.get(clientId);
  if (now - requests.lastRequest < 60000 && requests.count >= 100) return false;
  requests.count++;
  requests.lastRequest = now;
  rateLimitMap.set(clientId, requests);
  return true;
}
```

## Ejercicio
Implementa un middleware de rate limiting en tu servidor API que registre cada solicitud exitosa y rechace aquellas que excedan el límite configurado, devolviendo un estado HTTP 429 con un encabezado X-RateLimit-Limit.

## Criterios de revisión
El código debe manejar correctamente múltiples clientes simultáneos sin colapsar la memoria, usar timestamps precisos para calcular ventanas de tiempo y devolver respuestas consistentes al superar el umbral establecido.

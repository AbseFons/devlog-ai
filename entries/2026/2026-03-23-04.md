## Objetivo
Comprender la importancia de las pruebas de integración para verificar que los módulos individuales interactúan correctamente, asegurando la integridad de los datos y el flujo lógico entre servicios en un entorno distribuido.

## Explicación
Las pruebas de integración evalúan la interacción entre componentes del sistema. A diferencia de las pruebas unitarias, aquí se valida que los datos fluyan sin corrupción entre capas, como desde una API REST hacia una base de datos relacional. Un caso común es probar un proceso de pago: el servicio de autenticación debe comunicar exitosamente con el gateway de pagos y registrar la transacción en la base de datos. Se utilizan herramientas como Postman o Jest para orquestar estas pruebas. El objetivo es detectar fallos de interfaz, problemas de formato de datos o inconsistencias de estado que no son visibles al probar cada módulo aisladamente.

## Ejemplo (no ejecutado automáticamente)
Script de bash que simula una transacción de pago integrando llamadas a servicios ficticios y verifica la persistencia en un archivo JSON local.

```bash
# Simulamos llamada al servicio de autenticacion
response=$(curl -s 'http://localhost:3001/auth/login' -d '{"user":"admin","pass":"secret"}')
echo "Token obtenido: $response"
# Ejecutamos la transaccion de pago con el token
payment_result=$(curl -s 'http://localhost:3002/pay' -H "Authorization: Bearer $response" -d '{"amount":100}')
echo "Resultado pago: $payment_result"
```

## Ejercicio
Crea un script en Python que llame a dos endpoints simulados (uno para crear usuario, otro para verificar saldo) y asegúrate de que el segundo endpoint falle si el primero no se ejecuta correctamente.

## Criterios de revisión
El código debe manejar excepciones de red, validar la respuesta JSON del primer servicio antes de invocar al segundo, y reportar un error claro si la integración falla en cualquier punto.

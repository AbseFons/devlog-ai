## Objetivo
Aprender a estructurar una prueba de integración básica que verifique la comunicación entre un cliente y un servidor, asegurando que los datos se procesan correctamente tras el envío de una solicitud.

## Explicación
Las pruebas de integración evalúan la interacción entre componentes distintos. En este caso, simularemos una petición POST a un endpoint de creación de usuarios. El objetivo es confirmar que el sistema responde con un estado 201 y devuelve los datos del recurso creado. Utilizaremos Postman para enviar la solicitud y validar la respuesta JSON. Este enfoque permite detectar errores de formato o lógica en la capa de servicio antes de llegar a la base de datos.

## Ejemplo (no ejecutado automáticamente)
Solicitud POST a un endpoint ficticio que crea un usuario y verifica la respuesta exitosa con código 201.

```bash
curl -X POST http://localhost:3000/api/users \
  -H "Content-Type: application/json" \
  -d '{"nombre": "Ana", "email": "ana@ejemplo.com"}'
```

## Ejercicio
Configura una colección en Postman con un entorno de prueba local. Crea un request que envíe datos válidos a tu API y añade assertions para verificar el status code y la presencia del campo 'id' en la respuesta.

## Criterios de revisión
1. El request debe tener un status code de 201.
2. La respuesta debe incluir el campo 'id' generado.
3. No deben haber errores de red o timeouts.

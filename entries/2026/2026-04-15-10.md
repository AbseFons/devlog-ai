## Objetivo
Comprender y aplicar el principio de mínimo privilegio (PoLP) para restringir accesos a recursos cloud, reduciendo la superficie de ataque y limitando el daño por credenciales comprometidas.

## Explicación
El principio de mínimo privilegio establece que cada entidad de seguridad debe tener solo los permisos necesarios para realizar su función específica. En entornos cloud modernos, esto implica configurar roles IAM con políticas granulares en lugar de usar cuentas administrativas genéricas. Al asignar permisos específicos por recurso (por ejemplo, lectura de logs pero no borrado), se mitigan riesgos críticos. Este enfoque requiere una evaluación continua de los privilegios activos y la eliminación de accesos obsoletos mediante auditorías periódicas automatizadas.

## Ejemplo (no ejecutado automáticamente)
Política IAM que permite a un servicio solo leer objetos en un bucket específico sin capacidad de escritura o borrado.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject"],
    "Resource": "arn:aws:s3:::mi-bucket-seguro/*"
  }]
}
```

## Ejercicio
Crea un rol IAM en tu cuenta AWS o Azure que otorgue solo permisos de lectura a una base de datos específica, evitando acceso administrativo.

## Criterios de revisión
El rol debe tener exactamente dos acciones permitidas relacionadas con lectura y referirse a un único recurso específico.

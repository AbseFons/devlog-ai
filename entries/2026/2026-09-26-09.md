## Objetivo
Aprender a utilizar el comando git reflog para recuperar commits eliminados accidentalmente mediante reset o revert, entendiendo cómo funciona el historial local de referencias y evitando la pérdida permanente de trabajo.

## Explicación
El reflog registra cada cambio en la referencia HEAD, incluso si se borra un commit con git reset --hard. A diferencia del log normal, que solo muestra commits visibles, el reflog permite navegar por estados intermedios. Para recuperar un estado perdido, busca el hash del commit deseado en la salida de 'git reflog' y usa 'git reset --hard <hash>' para restaurar el branch actual o 'git checkout <hash>' para crear una nueva rama temporal. Este comando es vital cuando se comete un error de borrado masivo antes de que el historial sea sobrescrito por fuerza bruta.

## Ejemplo (no ejecutado automáticamente)
Recuperar un commit eliminado accidentalmente usando git reflog y resetear el branch a ese estado específico sin perder datos locales.

```bash
git reflog
HEAD@{1} -> HEAD (commit 5f3a2b1)
git reset --hard HEAD@{1}
```

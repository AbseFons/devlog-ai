## Objetivo
Eliminar dependencias transitivas en tablas relacionales para garantizar integridad referencial y reducir redundancia de datos, asegurando que cada atributo dependa solo de la clave primaria.

## Explicación
En esta microlección avanzamos desde la Segunda Forma Normal hacia la Tercera. El objetivo es eliminar dependencias transitivas: cuando un atributo no clave depende de otro atributo no clave en lugar de depender directamente de la clave primaria. Por ejemplo, si una tabla 'Empleados' tiene 'Departamento' y 'Jefe', y el nombre del jefe depende del departamento, existe una dependencia transitiva. Esto genera anomalías de actualización. Para corregirlo, creamos una nueva tabla 'Departamentos' con su propia clave y atributos como 'Nombre_Jefe'. La tabla original queda solo con la clave foránea al departamento. Este proceso asegura que los datos sean atómicos y consistentes, optimizando consultas y manteniendo el esquema libre de redundancias evitables.

## Ejemplo (no ejecutado automáticamente)
Transformación de una tabla plana con dependencias transitivas en un esquema normalizado a 3FN separando la información del departamento.

```sql
CREATE TABLE Departamentos (
  id_dept INTEGER PRIMARY KEY,
  nombre_jefe VARCHAR(50)
);

CREATE TABLE Empleados (
  id_empleado INTEGER PRIMARY KEY,
  id_dept INTEGER REFERENCES Departamentos(id_dept),
  salario DECIMAL(10,2)
);
```

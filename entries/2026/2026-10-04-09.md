## Objetivo
Comprender cómo las pruebas unitarias automatizadas actúan como primera línea de defensa en la pirámide, asegurando calidad antes de llegar a integración o E2E.

## Explicación
En esta segunda serie sobre la pirámide de pruebas, nos enfocamos en la base: las pruebas unitarias. Estas son rápidas, aisladas y verifican lógica específica sin dependencias externas complejas. En un pipeline CI/CD moderno, ejecutar estas pruebas en cada commit previene regresiones costosas. Si una prueba falla, el build se detiene inmediatamente, protegiendo al equipo de desplegar código roto. La clave es mantener la cobertura alta aquí para reducir la carga en niveles superiores. Un caso realista implica probar funciones matemáticas o validaciones de entrada en un servicio web.

## Ejemplo (no ejecutado automáticamente)
Script que define una función simple y verifica su comportamiento con casos de éxito y error, simulando una prueba unitaria básica.

```javascript
function sumar(a, b) { return a + b; }
console.log(sumar(2, 3) === 5 ? 'Prueba aprobada' : 'Prueba fallida');
```

## Ejercicio
Crea una función que calcule el área de un círculo y escribe dos pruebas: una con radio válido y otra con radio negativo.

## Criterios de revisión
El código debe ejecutar sin errores, mostrar mensajes claros para cada caso y mantener la lógica aislada de dependencias externas.

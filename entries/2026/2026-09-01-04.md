## Objetivo
Al finalizar esta lección, el desarrollador será capaz de crear etiquetas semánticas (v1.0.0) en una rama principal protegida, entender la diferencia entre tags anotados y ligeros, y utilizar comandos seguros para liberar versiones sin comprometer la integridad del historial compartido.

## Explicación
Las etiquetas (tags) en Git son marcadores de referencia que identifican puntos específicos del historial como releases. A diferencia de las ramas, los tags suelen ser inmutables y se usan para versionar software distribuido. Existen dos tipos: ligeros (lightweight), que son simplemente punteros a un commit, y anotados (annotated), que contienen metadatos como autor, fecha y mensaje. Para entornos profesionales, los tags anotados son preferibles porque permiten auditoría. Es crucial proteger la rama principal (ej. main o master) para evitar que se sobrescriban etiquetas accidentales. El flujo típico implica desarrollar en una rama de funcionalidad, realizar un merge forzado a main tras pruebas exitosas y luego crear el tag con git tag -a.

## Ejemplo (no ejecutado automáticamente)
```python
# Simulación de flujo de trabajo en terminal para liberar versión
# 1. Asegurar que la rama principal esté limpia y actualizada
git checkout main
git pull origin main

# 2. Crear una etiqueta anotada con mensaje descriptivo
# -a: crea tag anotado, -m: añade mensaje, -f: fuerza sobretag si existe
git tag -a v1.0.0 -m "Release inicial: autenticación de usuarios implementada"

# 3. Verificar la etiqueta creada y sus metadatos
git show v1.0.0

# 4. Empaquetar el release (simulado con tar)
tar czf release-v1.0.0.tar.gz main

# 5. Subir la etiqueta al remoto de forma segura
# --push: envía tags, --force no se usa aquí para evitar sobrescritura accidental
git push origin v1.0.0
```

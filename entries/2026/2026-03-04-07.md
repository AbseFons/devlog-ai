## Objetivo
Comprender la estructura jerárquica de las pruebas de software, priorizando casos unitarios sobre integración y E2E para optimizar velocidad, costo y detección temprana de defectos en el ciclo de desarrollo.

## Explicación
La pirámide de pruebas es un modelo arquitectónico que organiza los tipos de pruebas según su alcance y frecuencia. La base amplia está compuesta por pruebas unitarias, rápidas y baratas, que validan componentes individuales. Sobre ellas se sitúan las pruebas de integración, que verifican la interacción entre módulos. En la cúspite, menos frecuentes pero críticas, están las pruebas de aceptación o end-to-end. Este enfoque asegura una cobertura robusta sin depender excesivamente de entornos complejos y lentos en la cima. Ignorar esta proporción puede llevar a fallos costosos detectados tarde.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de estructura de directorio y archivo para organizar pruebas unitarias, de integración y E2E siguiendo el modelo piramidal en un proyecto Node.js.

```javascript
// tests/unit/user.test.js
import { User } from '../src/User';
const user = new User('alice', 'pass123');
expect(user.isValid()).toBe(true);

// tests/integration/auth.test.js
import request from 'supertest';
import app from '../src/app';
describe('Auth Integration', () => {
  it('should login successfully', async () => {
    const res = await request(app).post('/login').send({ user: 'alice', pass: 'pass123' });
    expect(res.statusCode).toBe(200);
  });
});
```

## Ejercicio
Crea un repositorio con tres carpetas: unit, integration y e2e. Implementa una función simple en la raíz y escribe al menos una prueba unitaria, una de integración y una E2E que verifique flujos distintos.

## Criterios de revisión
El proyecto debe tener estructura de carpetas clara, pruebas ejecutables con un runner estándar (como Jest o Mocha), y al menos tres casos de prueba activos en niveles diferentes de la pirámide.

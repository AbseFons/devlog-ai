## Objetivo
Comprender la creación de ramas para desarrollo aislado, el uso de pull requests para integración segura y la importancia de mantener una rama principal estable en equipos colaborativos.

## Explicación
En ingeniería de software moderna, el flujo de trabajo basado en ramas es esencial. Cada nueva funcionalidad debe desarrollarse en una rama separada derivada del main o develop. Esto permite trabajar sin interferir con la estabilidad del código base. Una vez completado el desarrollo local, se realiza un commit detallado y luego se abre una pull request. Esta solicitud invita a revisiones por pares antes de fusionar cambios. La revisión asegura calidad, detecta errores tempranos y fomenta la colaboración. Solo tras aprobarse los cambios mediante pruebas automáticas y validación humana, se fusiona la rama al destino principal. Este proceso minimiza riesgos de regresión y mantiene el historial del proyecto claro y ordenado.

## Ejemplo (no ejecutado automáticamente)
Crear una rama para una nueva funcionalidad de login y preparar una pull request simulada con mensajes de commit claros.

```bash
git checkout -b feature/login-nuevo
git add src/auth/login.js
```

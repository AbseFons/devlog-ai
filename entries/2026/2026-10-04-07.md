## Objetivo
Aprender a identificar y eliminar dependencias transitivas en tablas SQL para evitar redundancia de datos, anomalías de actualización y garantizar la integridad referencial en diseños de bases de datos robustos.

## Explicación
En esta lección avanzamos más allá de la Segunda Forma Normal. Analizaremos cómo las dependencias transitivas ocurren cuando un atributo no clave depende de otro atributo no clave, en lugar de depender directamente de la clave primaria. Por ejemplo, si una tabla 'Pedidos' contiene el nombre del proveedor y la dirección del proveedor, la dirección depende del ID del proveedor, no del ID del pedido. Esto crea redundancia. Para normalizar a la 3FN, extraemos esa información a una nueva tabla 'Proveedores', dejando solo el ID en 'Pedidos'. Este proceso reduce el almacenamiento, previene inconsistencias al actualizar direcciones y simplifica las consultas mediante joins eficientes.

## Ejemplo (no ejecutado automáticamente)
Se muestra la estructura de una tabla desnormalizada con dependencias transitivas y su transformación a dos tablas relacionadas para cumplir la 3FN.

```sql
CREATE TABLE Pedidos (
    id_pedido INT PRIMARY KEY,
    id_proveedor INT,
    nombre_cliente VARCHAR(100),
    direccion_proveedor VARCHAR(255)
);

CREATE TABLE Proveedores (
    id_proveedor INT PRIMARY KEY,
    nombre_proveedor VARCHAR(100),
    direccion_proveedor VARCHAR(255)
);
```

## Ejercicio
Diseña una tabla 'Empleados' que contenga un campo 'departamento_id' y otro 'jefe_nombre'. Identifica la dependencia transitiva si el nombre del jefe depende del departamento en lugar de ser un dato atómico directo o clave, y propone la estructura normalizada resultante.

## Criterios de revisión
El diseño debe eliminar dependencias transitivas, asegurando que todos los atributos no clave dependan únicamente de la clave primaria de su propia tabla. Se evalúa la reducción de redundancia y la claridad en las relaciones entre tablas.

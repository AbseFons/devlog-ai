## Objetivo
Comprender cómo SQL Server decide ejecutar consultas mediante la visualización del plan de ejecución, identificando cuellos de botella como escaneos de índice o tablas grandes para optimizar el rendimiento.

## Explicación
El comando EXPLAIN (o SET STATISTICS IO ON) revela los pasos que el motor de base de datos tomará antes de devolver resultados. Esto permite detectar operaciones costosas como 'Clustered Index Scan' en tablas masivas o 'Table Scan' innecesarios. Al analizar estos planes, puedes ajustar índices faltantes o reescribir consultas para forzar el uso de índices más eficientes, reduciendo significativamente el tiempo de respuesta y mejorando la escalabilidad de la aplicación.

## Ejemplo (no ejecutado automáticamente)
Consulta que busca empleados por departamento con un índice compuesto en las columnas utilizadas.

```sql
SELECT Id, Nombre, Departamento
FROM Empleados
WHERE Departamento = 'Ventas'
ORDER BY Id;

-- Verificar el plan de ejecución
SET STATISTICS IO ON;
EXEC sp_executesql N'SELECT Id, Nombre, Departamento FROM Empleados WHERE Departamento = ''Ventas'' ORDER BY Id';
SET STATISTICS IO OFF;
```

## Ejercicio
Crea una tabla 'Pedidos' con 10.000 filas y un índice en la columna 'Fecha'. Ejecuta una consulta que filtre por fecha sin usar el índice y luego modifica la consulta para aprovecharlo.

## Criterios de revisión
El plan debe mostrar 'Index Seek' en lugar de 'Index Scan' o 'Table Scan'. El tiempo de ejecución debe reducirse notablemente tras la optimización.

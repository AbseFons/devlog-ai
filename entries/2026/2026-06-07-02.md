## Objetivo
Aprender a almacenar credenciales sensibles como claves API en variables de entorno del sistema operativo para evitar exponerlas en el código fuente o repositorios públicos, garantizando la seguridad inicial de la aplicación.

## Explicación
Los secretos, como contraseñas y tokens, nunca deben escribirse directamente en el código. La práctica estándar es utilizar variables de entorno proporcionadas por el sistema operativo. Estas variables existen en la memoria del proceso y no se guardan en los archivos fuente, lo que impide su commit accidental a Git. Herramientas como Docker o Kubernetes también gestionan estos secretos de forma segura. En este caso de uso, leemos una variable llamada 'API_KEY' antes de hacer llamadas a un servicio externo. Si la variable no existe, el programa falla con un mensaje claro en lugar de usar una clave por defecto insegura.

## Ejemplo (no ejecutado automáticamente)
Script que lee una variable de entorno y valida su existencia antes de usarla para autenticarse.

```bash
# Leer la variable de entorno
export API_KEY="${API_KEY:-}" 
if [ -z "$API_KEY" ]; then
  echo "Error: Faltan credenciales en las variables de entorno"
  exit 1
fi
echo "Credenciales cargadas correctamente para la sesión actual.
```

## Ejercicio
Configura una variable de entorno llamada 'DB_PASSWORD' con un valor ficticio y modifica el script anterior para que lea esta nueva variable en lugar de API_KEY.

## Criterios de revisión
El código debe leer la variable sin hardcodear valores, mostrar un mensaje de error si la variable está vacía y no imprimir el valor del secreto en la salida estándar.

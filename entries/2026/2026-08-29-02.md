# Git: cherry-pick para integrar commits específicos

## Objetivo
El desarrollador aplicará cherry-pick para seleccionar un commit individual desde otra rama y fusionarlo en la actual, resolviendo conflictos de manera controlada sin afectar el historial principal del proyecto.

## Explicación
El comando git cherry-pick permite extraer los cambios contenidos en un commit específico de una rama remota o local y aplicarlos a la rama actual. A diferencia de merge o rebase, no mueve el historial, sino que crea nuevos commits con el mismo mensaje pero en el contexto actual. Esto es vital cuando necesitas integrar una corrección crítica o una característica puntual sin traer todo el ruido de otras ramas. El proceso puede generar conflictos si los archivos modificados son idénticos; Git pausará la operación para que edites manualmente las diferencias antes de finalizar con git cherry-pick --continue.

## Ejemplo (no ejecutado automáticamente)
```bash
# Obtener el commit hash desde la rama feature-auth
git log origin/feature-auth --oneline

# Aplicar ese commit específico a main
git cherry-pick <HASH_DEL_COMMIT>

# Si hay conflictos, editar los archivos y continuar
git cherry-pick --continue
```

## Ejercicio
En un repositorio local con dos ramas (main y feature-fix), identifica el último commit de feature-fix que corrige una vulnerabilidad. Ejecuta cherry-pick para aplicar solo ese cambio a main, resuelve los conflictos si existen en archivos de configuración y verifica que la rama resultante tenga el nuevo commit sin incluir otros cambios de la rama original.

## Criterios de revisión
El desarrollador debe haber ejecutado correctamente el comando cherry-pick con un hash válido, documentado los conflictos resueltos en un archivo de registro y confirmado que la rama principal mantiene su integridad histórica tras la operación.

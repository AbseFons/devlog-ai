## Objetivo
Aprender a definir restricciones CHECK para limitar rangos de datos y UNIQUE para garantizar la unicidad, asegurando la integridad referencial y semántica en tablas relacionales.

## Explicación
Las restricciones en SQL son fundamentales para mantener la calidad de los datos. La cláusula CHECK valida que una columna cumpla con una condición lógica específica, como un rango numérico o un formato de fecha válido. Por ejemplo, se puede impedir que el salario sea negativo. Por otro lado, UNIQUE asegura que no existan valores duplicados en una columna o conjunto de columnas, ideal para identificadores secundarios como números de teléfono o correos electrónicos dentro de una tabla. Ambas restricciones se definen en la creación de tablas o mediante ALTER TABLE. Su correcta implementación previene errores de negocio y corrupción de datos antes de que ocurran.

## Ejemplo (no ejecutado automáticamente)
Creación de una tabla 'empleados' donde el salario debe ser mayor a cero y el departamento_id sea único para evitar duplicidad en asignaciones lógicas.

```sql
CREATE TABLE empleados (
  id INT PRIMARY KEY,
  nombre VARCHAR(100),
  salario DECIMAL(10,2) CHECK (salario > 0),
  depto_id INT UNIQUE
);
```

## Ejercicio
Crea una tabla 'clientes' con columnas: id (INT), email (VARCHAR), y fecha_nacimiento (DATE). Aplica una restricción CHECK para que la edad calculada a partir de fecha_nacimiento no sea menor a 18 años, y otra UNIQUE en la columna email.

## Criterios de revisión
El código debe compilar sin errores sintácticos. La restricción CHECK debe usar funciones de fecha válidas del sistema SQL (como TIMESTAMPDIFF o YEAR). La restricción UNIQUE debe aplicarse correctamente a la columna email. No deben existir duplicados al insertar un mismo correo.

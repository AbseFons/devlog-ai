## Objetivo
Aprender a descomponer tablas con datos repetitivos en series temporales para evitar anomalías de actualización y mejorar la integridad referencial mediante la separación de dimensiones.

## Explicación
En la normalización avanzada, identificamos columnas que repiten valores de otras (como fechas o categorías) y las extraemos a tablas independientes. Por ejemplo, si una tabla 'Ventas' contiene repetidamente el nombre del producto y su categoría para cada fecha, esto viola la 3FN. Se debe crear una tabla 'Productos' con sus atributos estáticos y otra 'VentasDiarias' que solo guarde claves foráneas y valores variables como cantidad o precio. Esto reduce el almacenamiento y asegura que al cambiar un nombre de producto, solo se actualice una fila en lugar de cientos. La clave es analizar la dependencia funcional: si una columna depende totalmente de toda la clave primaria compuesta, debe moverse a su propia tabla.

## Ejemplo (no ejecutado automáticamente)
Creación de tablas normalizadas separando datos estáticos de transaccionales para evitar redundancia en registros diarios.

```sql
CREATE TABLE Productos (id INT PRIMARY KEY, nombre VARCHAR(50), categoria VARCHAR(30));
CREATE TABLE VentasDiarias (id INT, fecha DATE, producto_id INT, cantidad INT, precio DECIMAL(10,2), FOREIGN KEY (producto_id) REFERENCES Productos(id));
```

## Ejercicio
Diseña una estructura de tablas para un sistema de biblioteca que elimine la repetición de datos de libros y autores en los registros de préstamos diarios.

## Criterios de revisión
El diseño debe cumplir con la Tercera Forma Normal (3FN), separando claramente las entidades estáticas de las transacciones temporales.

## Objetivo
Distinguir cuándo utilizar merge para preservar historia colaborativa versus rebase para crear una línea de desarrollo lineal y limpia antes de fusionar ramas principales.

## Explicación
Merge preserva cada punto de divergencia como un commit único, creando un gráfico en forma de Y que refleja fielmente la cronología real del trabajo. Es ideal para entornos colaborativos donde el historial debe ser auditado. Rebase, por el contrario, toma los commits de una rama y los aplica uno a uno sobre la punta de otra, reescribiendo la historia para que parezca secuencial. Esto produce una línea recta, útil para preparar ramas antes de un merge final, pero no se debe usar en repositorios compartidos activos porque altera el historial común.

## Ejemplo (no ejecutado automáticamente)
Se muestra cómo rebase mover localmente los commits de la rama feature sobre main antes de fusionar, limpiando el historial visualmente sin crear nodos de merge intermedios.

```bash
git checkout feature
feature_branch=$(git rev-parse HEAD)
git checkout main
git rebase --onto main $feature_branch
```

## Ejercicio
Crea dos ramas llamadas 'main' y 'dev'. Haz un commit en cada una. Luego, usa rebase para mover los commits de 'dev' sobre 'main' y verifica que el historial ahora sea lineal.

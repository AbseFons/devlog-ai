## Objetivo
Al finalizar esta lección, el desarrollador podrá distinguir cuándo usar PUT para reemplazar recursos completos y cuándo aplicar PATCH para modificaciones parciales, evitando sobreescribir datos críticos no deseados en arquitecturas RESTful modernas.

## Explicación
En las APIs REST, la elección entre PUT y PATCH define la estrategia de actualización. El método PUT es idempotente y requiere enviar el estado completo del recurso; si falta un campo, se pierde. Por el contrario, PATCH permite actualizar solo los campos específicos que cambian, ideal para escenarios donde el cliente no conoce toda la estructura del objeto. Esto reduce el volumen de datos transferidos y minimiza riesgos de corrupción accidental. Ambos métodos son fundamentales para mantener la integridad de los datos en sistemas distribuidos complejos.

## Ejemplo (no ejecutado automáticamente)
```javascript
// Caso: Actualizar solo el 'email' de un usuario sin afectar su 'password'
const user = {
  id: 123,
  name: "Ana García",
  email: "ana.antes@empresa.com"
};

// Simulación de solicitud PATCH con JSON Patch (RFC 6902)
const patchOperation = [
  { op: "replace", path: "/email", value: "ana.nueva@empresa.com" }
];

// Envío al endpoint RESTful
fetch('https://api.ejemplo.com/users/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(patchOperation)
});
```

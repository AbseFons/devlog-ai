## Objetivo
Comprender la distinción fundamental entre mocks y stubs para aislar dependencias externas, facilitando pruebas unitarias rápidas y deterministas sin depender de servicios reales.

## Explicación
En ingeniería de software, los mocks y los stubs son herramientas esenciales para el aislamiento de código. Un stub es una implementación simulada que devuelve valores predeterminados cuando se llama a un método, permitiendo continuar la ejecución del flujo principal sin interactuar con bases de datos o APIs externas. Por otro lado, un mock no solo simula la respuesta, sino que también verifica cómo fue utilizado: si se invocaró el método correcto, cuántas veces y con qué argumentos. Mientras los stubs se centran en proporcionar datos para evitar bloqueos, los mocks actúan como vigilantes de comportamiento esperado. Utilizar stubs es ideal cuando solo necesitas datos iniciales, mientras que los mocks son necesarios para validar la interacción correcta entre componentes.

## Ejemplo (no ejecutado automáticamente)
Un stub simple en JavaScript que simula una llamada a una API de usuario devolviendo un objeto fijo sin realizar red.

```javascript
const mockApi = {
  fetchUser: (id) => ({ id, name: 'Juan', role: 'admin' })
};
```

## Ejercicio
Crea una función en JavaScript que reciba un objeto de usuario y valide si su rol es 'admin'. Luego, reemplaza la llamada a una API real por el stub proporcionado para ejecutar la prueba sin internet.

## Criterios de revisión
El código debe usar exclusivamente el objeto mock definido. La función de validación debe retornar true o false según el rol. No se deben incluir llamadas reales a fetch o axios.

## Objetivo
Comprender cómo eliminar dependencias transitivas para asegurar que cada atributo dependa solo de la clave primaria, optimizando integridad y reduciendo redundancia en bases de datos relacionales.

## Explicación
La normalización a la Tercera Forma Normal (3NF) extiende la Segunda Forma Normal eliminando dependencias transitivas. Esto ocurre cuando un atributo no clave depende de otro atributo no clave, en lugar de depender directamente de la clave primaria. Por ejemplo, si una tabla 'Pedidos' contiene 'Ciudad' y 'Pais', y 'Ciudad' determina 'Pais', entonces 'Pais' depende transitivamente de la clave. Para corregirlo, creamos una nueva tabla donde 'Ciudad' sea clave y 'Pais' dependa de ella, dejando solo el ID en la tabla original. Esto previene anomalías de actualización: cambiar un país no requiere modificar múltiples filas. La 3NF garantiza que los datos estén estructurados lógicamente, minimizando almacenamiento duplicado y asegurando consistencia a largo plazo en sistemas empresariales complejos.

## Ejemplo (no ejecutado automáticamente)
Se muestra una tabla 'Empleados' con dependencias transitivas entre departamento y ciudad. Se separa la información de ciudades en una tabla independiente para cumplir con la 3NF.

```sql
CREATE TABLE Departamentos (
  id_departamento INT PRIMARY KEY,
  nombre VARCHAR(50),
  ciudad VARCHAR(50)
);

CREATE TABLE Empleados (
  id_empleado INT PRIMARY KEY,
  nombre VARCHAR(100),
  id_departamento INT,
  FOREIGN KEY (id_departamento) REFERENCES Departamentos(id_departamento)
);
```

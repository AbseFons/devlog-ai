## Objetivo
Comprender que una clase debe tener un solo motivo para cambiar, evitando la complejidad innecesaria y facilitando el mantenimiento del código al separar responsabilidades lógicas.

## Explicación
El principio de Responsabilidad Única establece que cada clase debe encapsular una única responsabilidad. Si una clase realiza múltiples tareas distintas, cualquier cambio en una de ellas podría afectar a la otra, aumentando el riesgo de errores. Por ejemplo, una clase 'Usuario' que maneja tanto la autenticación como el envío de correos electrónicos viola este principio. Es mejor dividir estas funciones en clases separadas: una para validar credenciales y otra para gestionar notificaciones. Esto mejora la legibilidad, permite pruebas unitarias más sencillas y hace que el sistema sea más flexible ante cambios futuros.

## Ejemplo (no ejecutado automáticamente)
Clase 'Usuario' refactorizada donde la autenticación está separada de la gestión de correos electrónicos, demostrando cómo dividir responsabilidades mejora la estructura del código.

```javascript
class Autenticacion {
  validar(usuario) { return usuario.password === '123'; }
}
class Notificaciones {
  enviarCorreo(email) { console.log('Email enviado a:', email); }
}
```

## Ejercicio
Crea una clase 'Factura' que calcule el total y otra clase 'Reporte' que genere un PDF. Evita mezclar la lógica de cálculo con la generación de archivos.

## Criterios de revisión
El código debe tener dos clases separadas, sin funciones duplicadas entre ellas, y cada clase debe realizar exactamente una tarea específica.

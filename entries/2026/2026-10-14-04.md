## Objetivo
Comprender cómo la propiedad de consistencia garantiza que una transacción pase de un estado válido a otro, invirtiendo cambios si ocurren errores lógicos o de negocio.

## Explicación
La consistencia asegura que cada transacción mantenga la base de datos en un estado válido. Si durante el procesamiento se detecta una violación de reglas (como claves foráneas o restricciones de integridad), la transacción debe abortarse completamente. Esto implica revertir todos los cambios parciales realizados previamente, asegurando que no queden residuos de datos inconsistentes. El motor de base de datos utiliza mecanismos internos para detectar estas anomalías y ejecutar las acciones correctivas necesarias antes de confirmar la operación.

## Ejemplo (no ejecutado automáticamente)
Script SQL que intenta insertar un empleado con un ID de departamento inexistente, lo cual debe fallar y revertir la transacción automáticamente.

```sql
BEGIN TRANSACTION;
INSERT INTO empleados (id_empleado, nombre, id_departamento) VALUES (101, 'Ana Lopez', 999);
-- Esta línea causará un error porque el departamento 999 no existe
-- La transacción se abortará y la inserción anterior se revertirá
COMMIT;
```

## Criterios de revisión
El código debe iniciar una transacción explícitamente, intentar una inserción que viole una restricción de integridad definida previamente, y demostrar que no se confirma la transacción al producirse el error.

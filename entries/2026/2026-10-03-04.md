## Objetivo
Diferenciar el uso de PUT para reemplazar recursos completos contra PATCH para actualizaciones parciales, asegurando integridad de datos y eficiencia en transferencias.

## Explicación
En la arquitectura RESTful, los verbos HTTP definen operaciones sobre recursos. PUT es idempotente y requiere enviar el estado completo del recurso; si falta un campo, se pierde. PATCH permite modificar solo atributos específicos sin definir todo el objeto, ideal para actualizaciones frecuentes de perfiles o configuraciones. Ambos métodos son esenciales para mantener consistencia en sistemas distribuidos.

## Ejemplo (no ejecutado automáticamente)
Actualización parcial del usuario usando PATCH con JSON

```javascript
fetch('https://api.ejemplo.com/usuarios/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
});
```

## Ejercicio
Crea una API local con Express que acepte PUT para reemplazar un producto y PATCH para cambiar solo su precio. Valida que el cuerpo de la solicitud contenga los campos necesarios.

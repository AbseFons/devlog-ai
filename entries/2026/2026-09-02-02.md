## Objetivo
El desarrollador aplicará el principio de separación de responsabilidades para aislar la lógica de negocio del renderizado visual, garantizando que cambios en la interfaz no rompan la funcionalidad central y facilitando pruebas unitarias aisladas.

## Explicación
En arquitecturas modernas, dividir el sistema en capas con propósitos únicos es vital. El núcleo (Core) debe contener solo la lógica de negocio pura, sin dependencias visuales. La capa de presentación se encarga exclusivamente de mostrar datos. Si mezclas ambos, un cambio en el diseño obliga a reescribir reglas de negocio o viceversa. Esta barrera permite escalar equipos: diseñadores trabajan en UI mientras ingenieros optimizan algoritmos. Además, simplifica las pruebas; puedes validar la lógica sin montar interfaces gráficas complejas. Mantener esta separación evita acoplamiento innecesario y hace el código más mantenible a largo plazo.

## Ejemplo (no ejecutado automáticamente)
```python
# nucleo.py: Lógica pura de cálculo de impuestos
def calcular_impuesto_base(ingresos, deduccion):
    return max(0, ingresos - deduccion)

# presentacion.py: Renderizado visual del resultado
def renderizar_reporte(cantidad_a_pagar):
    print(f"--- Informe Fiscal ---")
    print(f"Impuesto a pagar: ${cantidad_a_pagar:.2f}")
    print("----------------------")

# app.py: Orquestador que une ambas responsabilidades
def ejecutar_proceso(ingresos, deduccion):
    cantidad = calcular_impuesto_base(ingresos, deduccion)
    renderizar_reporte(cantidad)
```

## Ejercicio
Crea un archivo llamado 'calculadora.py' con una función 'sumar()' que retorne el total de dos números. Luego, crea 'vista.py' con una función 'mostrar_resultado()' que imprima el texto 'El resultado es: ' seguido del valor devuelto por sumar(). Finalmente, en 'main.py', llama a sumar() y pasa su salida a mostrar_resultado().

## Criterios de revisión
1. El archivo calculadora.py no debe importar ni usar funciones de impresión o renderizado.
2. El archivo vista.py no debe realizar cálculos matemáticos, solo formatear texto.
3. main.py debe ser el único punto donde ambas capas interactúan.
4. Si cambias la lógica en calculadora.py, vista.py no debe modificarse.

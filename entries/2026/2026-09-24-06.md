## Objetivo
Aprender a reducir drásticamente el tamaño de las imágenes Docker utilizando builds multi-etapa, separando la instalación de dependencias del tiempo de ejecución para mejorar la eficiencia y seguridad.

## Explicación
Las imágenes Docker por defecto suelen ser voluminosas porque incluyen herramientas de construcción como compiladores o gestores de paquetes. La técnica de 'multi-stage builds' permite definir múltiples etapas en un mismo archivo Dockerfile. En la primera etapa, instalamos todo lo necesario para compilar el código (por ejemplo, Go, Node.js o Python). Luego, en una segunda etapa limpia, copiamos solo el binario compilado y las dependencias finales desde la primera etapa a una imagen base ligera como Alpine Linux. El resultado final es una imagen que contiene únicamente lo esencial para ejecutar la aplicación, eliminando archivos temporales y herramientas de construcción innecesarias.

## Ejemplo (no ejecutado automáticamente)
Creación de una imagen optimizada para una API REST en Go usando un build multi-etapa con Alpine Linux como base final.

```bash
# Etapa 1: Construcción
FROM golang:1.21-alpine AS builder
WORKDIR /app
COPY . .
RUN go build -o main .
# Etapa 2: Imagen final ligera
FROM alpine:latest
RUN apk --no-cache add ca-certificates
WORKDIR /root/
COPY --from=builder /app/main .
EXPOSE 8080
CMD ["./main"]
```

## Ejercicio
Crea un Dockerfile para una aplicación Python que instale las dependencias en una etapa inicial y luego copie solo el entorno virtual activado a una imagen base de Python slim.

## Criterios de revisión
La imagen resultante debe tener menos de 100MB, no incluir archivos de instalación de paquetes del sistema operativo ni herramientas de desarrollo innecesarias en la capa final.

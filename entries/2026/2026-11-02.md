## Objetivo
Aprender a devolver códigos HTTP precisos en lugar de errores genéricos, mejorando la experiencia del desarrollador que consume la API y facilitando el manejo adecuado de fallos por parte del cliente.

## Explicación
Un diseño robusto de errores evita respuestas ambiguas como '500 Internal Server Error' para problemas específicos. En su lugar, utilice códigos HTTP estándar: 400 Bad Request para sintaxis inválida, 401 Unauthorized cuando falta autenticación y 404 Not Found si el recurso no existe. Esto permite que los clientes implementen flujos de recuperación correctos sin necesidad de lógica compleja en el servidor. La consistencia en la estructura del cuerpo del mensaje de error también es vital para mantener la interoperabilidad entre diferentes servicios.

## Ejemplo (no ejecutado automáticamente)
Respuesta JSON correcta para un recurso no encontrado con código 404 y detalles específicos.

```javascript
res.status = 404;
res.json({
  error: 'Recurso no encontrado',
  codigo: 404,
  detalle: 'El ID proporcionado no existe en la base de datos.'
});
```

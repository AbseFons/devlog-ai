## Objetivo
Aprender a utilizar el patrón adaptador para integrar sistemas con interfaces incompatibles, permitiendo que clases existentes trabajen con nuevas dependencias sin modificar su código original.

## Explicación
El patrón adaptador actúa como un puente entre dos interfaces incompatibles. Imagina una API legacy de inventario que solo acepta objetos JSON planos, mientras tu aplicación moderna utiliza entidades ricas con validaciones complejas. En lugar de refacturar la API antigua o crear una capa de mapeo masiva en el controlador, encapsulas la lógica de transformación dentro de un adaptador específico. Este objeto implementa la interfaz que espera tu sistema actual y delega las llamadas a la API externa, traduciendo los datos antes y después del intercambio. Esto mantiene el código legacy intacto y aísla la complejidad de integración en una capa clara y testeable.

## Ejemplo (no ejecutado automáticamente)
Clase adaptador que envuelve una API de inventario antigua para exponer métodos modernos con validación de datos.

```javascript
class LegacyInventoryAdapter {
  constructor(api) { this.api = api; }
  async getStock(product) {
    const raw = await this.api.query({ id: product.id });
    return { ...raw, status: 'active' };
  }
}
```

## Ejercicio
Crea un adaptador para una API de pagos que devuelve solo el ID de transacción. Modifica la interfaz de tu servicio de carrito para que acepte este adaptador y devuelva un objeto con estado, monto y fecha formateada.

## Criterios de revisión
El adaptador debe encapsular completamente la lógica de transformación sin exponer detalles de la API legacy. La integración no debe requerir cambios en el código de la API original ni en los controladores existentes.

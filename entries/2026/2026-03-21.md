## Objetivo
Aprender a prevenir inyecciones SQL y XSS mediante la validación estricta del tipo y longitud de las entradas del usuario antes de procesarlas en la aplicación.

## Explicación
La seguridad comienza rechazando datos no conformes. Antes de usar cualquier entrada externa, verifica su tipo (string), longitud máxima y caracteres permitidos. Por ejemplo, un campo de 'usuario' debe ser alfanumérico y menor a 50 caracteres. Si la entrada falla estas reglas, se rechaza inmediatamente sin mostrar mensajes de error detallados que revelen la estructura interna de la base de datos. Esta capa defensiva reduce drásticamente el riesgo de ataques de inyección. Implementa siempre listas blancas de patrones aceptables en lugar de confiar únicamente en listas negras de prohibiciones.

## Ejemplo (no ejecutado automáticamente)
Función que valida un nombre de usuario rechazando caracteres especiales y limitando la longitud antes de insertarlo en una consulta SQL parametrizada.

```javascript
function validarUsuario(nombre) {
  const regex = /^[a-zA-Z0-9_]{3,50}$/;
  if (!regex.test(nombre)) throw new Error('Formato inválido');
}
```

## Objetivo
Diferenciar claramente entre autenticación (quién eres) y autorización (qué puedes hacer), fundamentales para diseñar APIs seguras que protejan recursos sensibles mediante tokens y roles.

## Explicación
En el desarrollo de APIs, la autenticación verifica la identidad del usuario, usualmente mediante credenciales o tokens como JWT. La autorización determina qué acciones puede realizar esa identidad identificada. Es común confundir ambos conceptos: saber quién es el usuario no implica que pueda acceder a todos los datos. Una API segura implementa primero un mecanismo de autenticación robusto y luego aplica políticas de autorización granulares en cada endpoint, asegurando que incluso si un token es robado, el daño esté limitado por los permisos asociados.

## Ejemplo (no ejecutado automáticamente)
Un script que simula una petición a una API protegida mostrando cómo el encabezado Authorization valida la identidad pero la ruta determina el acceso.

```bash
curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9" https://api.ejemplo.com/v1/usuarios

curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9" https://api.ejemplo.com/v1/admin/config
```

## Objetivo
Aprender a crear etiquetas permanentes en repositorios Git para marcar versiones estables, facilitando la distribución de software y el seguimiento histórico de cambios específicos sin afectar las ramas de desarrollo activas.

## Explicación
Las etiquetas (tags) son marcadores inmóviles que apuntan a un commit específico, ideal para denotar versiones como v1.0 o release-2.3. A diferencia de las ramas, no se mueven con nuevos commits. Para crear una etiqueta, usa 'git tag -a version-nombre -m mensaje' para generar etiquetas anidadas con descripción, o 'git tag nombre' para etiquetas ligeras. Las etiquetas son esenciales en flujos de trabajo CI/CD para desplegar artefactos. Se pueden listar con 'git tag' y eliminar con 'git tag -d'. Es crucial usar nombres que sigan convenciones semánticas (ej: v1.2.0) para que las herramientas de gestión de paquetes los reconozcan automáticamente.

## Ejemplo (no ejecutado automáticamente)
Crear una etiqueta anidada llamada v1.0.0 con un mensaje descriptivo en el repositorio local.

```bash
git tag -a v1.0.0 -m "Versión inicial estable del módulo de autenticación"
git push origin v1.0.0
```

## Ejercicio
Crea una etiqueta ligera llamada 'beta' en tu rama actual y verifica que apunte al commit correcto.

## Criterios de revisión
La etiqueta debe existir, apuntar al commit actual y no tener mensaje asociado.

## Objetivo
Comprender los parámetros estándar para paginar respuestas en APIs RESTful, evitando sobrecargar el servidor y optimizando el rendimiento de la aplicación mediante el uso eficiente de recursos.

## Explicación
La paginación es un mecanismo esencial en las APIs REST para gestionar grandes volúmenes de datos. En lugar de devolver todos los registros en una sola respuesta, que podría saturar la memoria del cliente o el servidor, se divide la información en bloques llamados páginas. Los parámetros más comunes son 'page' o 'offset' para indicar qué conjunto de datos solicitar y 'limit' o 'size' para definir cuántos elementos incluir por página. Además, las respuestas suelen incluir metadatos como 'total', 'pages' y los números de 'first' y 'last' página para facilitar la navegación. Este enfoque no solo mejora la velocidad de carga en aplicaciones web y móviles, sino que también reduce el consumo de ancho de banda y protege contra ataques de denegación de servicio por respuesta excesiva.

## Ejemplo (no ejecutado automáticamente)
Solicitud GET a una API de usuarios con parámetros de paginación para obtener solo los primeros 10 registros de la página 1, incluyendo metadatos de navegación en el cuerpo de la respuesta.

```bash
curl -X GET "https://api.ejemplo.com/usuarios?page=1&limit=10"

{
  "data": [
    {"id": 1, "nombre": "Ana"},
    {"id": 2, "nombre": "Carlos"}
  ],
  "meta": {
    "total": 50,
    "page": 1,
    "limit": 10
  }
}
```

## Ejercicio
Crea una petición HTTP usando curl o fetch que solicite la página 2 con un límite de 5 elementos a una API ficticia llamada 'https://api.tienda.com/productos'.

## Criterios de revisión
La respuesta debe incluir los parámetros 'page=2' y 'limit=5' en la URL. El cuerpo JSON debe mostrar exactamente 5 productos si existen, junto con el campo 'total' indicando el número total de productos disponibles.

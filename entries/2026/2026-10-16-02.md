## Objetivo
Comprender y aplicar el principio de mínimo privilegio configurando roles con permisos estrictos para servicios cloud, reduciendo la superficie de ataque y protegiendo datos sensibles sin comprometer la funcionalidad operativa del sistema.

## Explicación
El principio de mínimo privilegio establece que cada entidad de seguridad, como un servicio o usuario, debe tener solo los permisos necesarios para realizar su función específica. En entornos cloud modernos, esto implica evitar el uso de cuentas con acceso administrativo global. Por ejemplo, en lugar de asignar un rol 'Admin' a una función Lambda, se crea un rol personalizado que permite únicamente leer y escribir en las tablas específicas de la base de datos requeridas. Esta práctica limita el daño potencial ante una vulneración o error de configuración. La implementación requiere auditar los permisos actuales, eliminar privilegios innecesarios y documentar cada excepción. Es fundamental revisar periódicamente estos roles para adaptarlos a cambios en la arquitectura del sistema.

## Ejemplo (no ejecutado automáticamente)
Creación de un rol IAM personalizado en AWS que otorga acceso limitado solo a una base de datos específica, evitando permisos administrativos globales.

```bash
# Crear política JSON con permisos limitados
PolicyDocument = {
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["rds:DescribeDBInstances", "rds:CreateDBInstance"],
    "Resource": "arn:aws:rds:*:123456789012:db:mi-bd-segura"
  }]
}
# Asignar la política a un rol específico
aws iam create-role --role-name LambdaDBAccessRole --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"lambda.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
aws iam attach-role-policy --role-name LambdaDBAccessRole --policy-arn arn:aws:iam::aws:policy/AmazonRDSFullAccess
```

## Ejercicio
Crea un rol en tu cuenta de AWS (o sandbox) que permita a una función Lambda solo listar y describir instancias de RDS en un subgrupo específico, sin capacidad de eliminar o modificar parámetros críticos.

## Criterios de revisión
El rol debe tener menos de 5 acciones permitidas; no debe incluir permisos de 'Delete' ni 'Modify'; el recurso debe estar restringido a una ARN específica; la política debe ser válida según el validador de políticas IAM.

## Objetivo
Aprender a sincronizar actualizaciones del DOM con el ciclo de renderizado del navegador para evitar bloqueos en el hilo principal y garantizar animaciones fluidas.

## Explicación
Manipular el DOM frecuentemente dentro de bucles `while` o `setInterval` puede causar saltos visuales porque el navegador no tiene tiempo de pintar la pantalla. La solución es usar `requestAnimationFrame`. Esta función programa una llamada a la siguiente animación antes de que el navegador pinte la página, sincronizándose con la tasa de refresco del monitor (usualmente 60Hz). Al mover la lógica de actualización dentro de este callback, aseguramos que los cambios en el DOM ocurran justo antes de cada repaint, mejorando significativamente el rendimiento y la experiencia del usuario.

## Ejemplo (no ejecutado automáticamente)
Un script que mueve un elemento div a través de una ventana usando requestAnimationFrame para mantener 60 FPS estables.

```javascript
const elem = document.getElementById('miElemento');
let posicion = 0;
function animar() {
  if (posicion < window.innerWidth) {
    elem.style.left = posicion + 'px';
    posicion += 2;
    requestAnimationFrame(animar);
  }
}
```

## Ejercicio
Crea un elemento div con id 'target' en el HTML. Escribe un script JS que haga que este div se deslice suavemente de izquierda a derecha usando requestAnimationFrame. Asegúrate de detener la animación cuando el elemento alcance el borde derecho.

## Criterios de revisión
El código debe usar exclusivamente requestAnimationFrame para la lógica de movimiento, no setInterval o setTimeout. La animación debe ser fluida sin saltos visuales y detenerse automáticamente al llegar al límite del contenedor.

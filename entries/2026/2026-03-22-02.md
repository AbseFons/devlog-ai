## Objetivo
Aprender a utilizar el comando git cherry-pick para aplicar manualmente un commit específico de otra rama al repositorio actual, permitiendo integrar funcionalidades aisladas sin fusionar toda la historia de commits.

## Explicación
El comando git cherry-pick extrae los cambios contenidos en un commit específico y los aplica como nuevos commits en tu rama actual. Es ideal para portar arreglos críticos o características puntuales desde una rama remota o de desarrollo sin realizar un merge completo que podría traer código no deseado. El sintaxis básica es 'git cherry-pick <hash-del-commit>'. Si el commit tiene conflictos, Git los marcará y deberás resolverlos manualmente antes de finalizar la operación con ':'. Es fundamental verificar la integridad del historial después de usarlo para mantener un log limpio.

## Ejemplo (no ejecutado automáticamente)
Aplicar un parche de seguridad específico extraído de una rama remota al desarrollo principal.

```bash
# Obtener el hash del commit en la rama remota
REMOTE_COMMIT="a1b2c3d4"
# Aplicar el commit a la rama actual
git cherry-pick $REMOTE_COMMIT
```

## Ejercicio
En un repositorio local con dos ramas, 'main' y 'feature-fix', identifica el hash del último commit en 'feature-fix'. Ejecuta git cherry-pick con ese hash en tu rama 'main' y verifica que la historia de commits refleje la nueva entrada.

## Criterios de revisión
El usuario debe ejecutar correctamente el comando sin errores de sintaxis, resolver conflictos si los hubiera (simulados o reales) y confirmar visualmente en el historial que el commit seleccionado se ha añadido como nuevo.

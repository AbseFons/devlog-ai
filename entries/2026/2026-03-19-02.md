## Objetivo
Aprender a almacenar credenciales sensibles fuera del código fuente utilizando variables de entorno, evitando exponer claves en repositorios públicos y comprendiendo los riesgos básicos de la seguridad de secretos.

## Explicación
Los secretos como contraseñas o tokens nunca deben hardcodearse en el software. La práctica estándar es utilizar variables de entorno para inyectar estos valores dinámicamente durante la ejecución. Esto permite que el mismo código funcione en diferentes entornos (desarrollo, pruebas, producción) sin modificar su fuente. En este caso de uso, simularemos un servicio web simple que lee una clave de API desde el sistema operativo antes de conectarse a un servicio externo. Es crucial recordar que las variables de entorno son visibles en los procesos y pueden ser filtradas si no se configuran correctamente los permisos del servidor o la terminal.

## Ejemplo (no ejecutado automáticamente)
Script de inicialización que define una variable de entorno segura para una API Key antes de ejecutar la aplicación.

```bash
export MI_API_KEY="sk_live_9f8e7d6c5b4a3z2y1x"
node app.js
```

## Criterios de revisión
El código debe leer la variable de entorno sin hardcodear valores sensibles, no debe contener credenciales reales y debe manejar el caso donde la variable no esté definida lanzando un error claro.

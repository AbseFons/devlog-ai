## Objetivo
Aprender a usar el comando git bisect para identificar eficientemente el commit exacto que introdujo una regresión en el código, ahorrando tiempo frente al uso manual de bisectación binaria.

## Explicación
El comando git bisect automatiza la búsqueda lineal de cambios. Es ideal cuando un bug aparece repentinamente y no sabes qué commit lo causó. El proceso implica marcar una versión conocida como buena (antes del error) y otra como mala (con el error). Git luego seleccionará commits intermedios para que los pruebes, alternando entre versiones buenas y malas hasta aislar la causa raíz. Este método es crucial en mantenimiento de software legacy o cuando las pruebas son costosas.

## Ejemplo (no ejecutado automáticamente)
Se marca un commit antiguo como bueno y el actual con error como malo para iniciar la bisectación automática.

```bash
git bisect start
HEAD~100:good
HEAD:bad
```

## Ejercicio
Marca tu último commit como 'malo' y el commit anterior como 'bueno'. Ejecuta git bisect y reporta el primer commit que Git sugiere probar.

## Criterios de revisión
El usuario debe ejecutar correctamente los comandos de inicio, identificar el commit sugerido por Git y comprender la lógica de reducción del espacio de búsqueda.

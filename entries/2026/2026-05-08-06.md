## Objetivo
Aprender a utilizar git bisect para identificar eficientemente el commit exacto que introdujo un bug, reduciendo drásticamente el tiempo de depuración en reposos con historia lineal.

## Explicación
El comando git bisect es una herramienta poderosa que transforma la búsqueda de errores en un proceso binario. En lugar de revisar commits uno por uno, permite marcar dos puntos: uno conocido como 'bueno' (sin el error) y otro como 'malo' (con el error). Git luego ejecuta automáticamente comandos intermedios para comparar estados. El usuario solo debe validar si la versión actual es buena o mala. Este método divide el espacio de búsqueda a la mitad en cada iteración, garantizando encontrar el commit culpable en muy pocos pasos, incluso en repositorios con miles de cambios.

## Ejemplo (no ejecutado automáticamente)
Script bash que automatiza la validación de un bug al ejecutar una prueba específica y marcar el estado actual para git bisect.

```bash
# Verifica si la aplicación falla
if ! ./run_tests.sh; then
  echo "Estado: MALO"
  git bisect bad
else
  echo "Estado: BUENO"
  git bisect good
fi
```

## Ejercicio
1. Crea una rama con un commit que rompa la funcionalidad principal.
2. Regresa al último commit estable conocido.
3. Ejecuta 'git bisect start' marcando el actual como malo y el anterior como bueno.
4. Deja que git avance automáticamente o valida manualmente cada paso hasta encontrar el commit exacto.

## Criterios de revisión
El usuario debe demostrar la capacidad de iniciar una sesión de bisect, validar correctamente los estados intermedios y finalizar con 'git bisect reset' para limpiar el historial.

## Objetivo
Aprender a configurar datos de prueba reutilizables mediante fixtures en la clase TestCase, optimizando el tiempo de ejecución y asegurando un entorno limpio para cada caso de prueba sin necesidad de repetir código de inicialización.

## Explicación
En esta segunda parte de la serie sobre pruebas unitarias con unittest, exploraremos los fixtures. Estos son métodos especiales como setUp y tearDown que se ejecutan automáticamente antes y después de cada método de prueba. Su utilidad radica en preparar el estado del sistema (como instanciar objetos o crear bases de datos temporales) justo antes de ejecutar la lógica a probar y limpiarlo inmediatamente después. Esto garantiza que cada prueba sea aislada e independiente, evitando efectos secundarios entre ellas. Al usar fixtures, el código se vuelve más legible y mantenible, ya que la configuración se centraliza en la clase TestCase en lugar de repetirse en cada método.

## Ejemplo (no ejecutado automáticamente)
Un fixture que inicializa una lista vacía antes de cada prueba para simular un carrito de compras.

```python
class TestCarrito(unittest.TestCase):
    def setUp(self):
        self.carrito = []

    def test_agregar_item(self):
        self.carrito.append('manzana')
        self.assertEqual(len(self.carrito), 1)
```

## Ejercicio

Luego, escribe dos pruebas: una que agrega un usuario y verifica su existencia, y otra que intenta agregar un usuario duplicado verificando que no se sobrescriba.

## Criterios de revisión
El código debe heredar de unittest.TestCase, incluir métodos setUp y tearDown correctamente definidos, y las pruebas deben usar assertEqual o assertTrue para validar la lógica del diccionario sin dejar datos residuales entre ejecuciones.

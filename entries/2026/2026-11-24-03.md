## Objetivo
Aprender a controlar el aislamiento de transacciones y evitar condiciones de carrera al modificar datos concurrentemente en una base de datos local, asegurando la integridad referencial.

## Explicación
En esta segunda parte de sqlite3, exploramos cómo gestionar explícitamente las transacciones para garantizar la consistencia de los datos. SQLite utiliza niveles de aislamiento por defecto (READ COMMITTED), pero en escenarios de alta concurrencia es vital entender el comportamiento de bloqueos y lecturas sucias. Utilizaremos context managers o llamadas directas a commit/rollback para simular operaciones atómicas. Este enfoque es crucial cuando se implementan sistemas de inventario o reservas donde dos procesos no deben sobrescribirse mutuamente sin un control estricto del estado transaccional.

## Ejemplo (no ejecutado automáticamente)
Script que inicia una transacción, actualiza un contador y la confirma, demostrando el bloqueado implícito en SQLite.

```python
import sqlite3
conn = sqlite3.connect('db.sqlite')
with conn:
    conn.execute("UPDATE usuarios SET saldo = saldo + 1 WHERE id = 1")
```

## Objetivo
Aprender a identificar y resolver conflictos de merge mediante la inspección directa de archivos, preservando cambios intencionales de ambos desarrolladores sin sobrescribir datos críticos.

## Explicación
Cuando Git detecta un conflicto durante una fusión o actualización remota, marca las líneas afectadas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. El objetivo es editar el archivo manualmente para integrar la lógica deseada. Primero, elimina los marcadores de Git. Luego, compara ambas versiones: ¿qué cambio era prioritario? Si ambos modificaron la misma línea, decide cuál prevalece o combina las lógicas. Guarda el resultado limpio y ejecuta 'git add' seguido de 'git commit'. Esta práctica manual es esencial para mantener la integridad del código compartido.

```bash
  function login() { return true; }

>>>>>>> branch-feature

```

## Ejercicio
Crea un archivo local con una función 'procesarDatos' que sume dos números. Actualiza el repositorio remoto donde la misma función ha sido modificada para restar los números. Resuelve el conflicto manualmente en tu editor, asegurando que la nueva versión realice la suma y la resta según un flujo condicional simple.

## Criterios de revisión
El archivo debe estar libre de marcadores de Git (<<<<, =====, >>>>>). La lógica final debe reflejar una combinación válida de ambas versiones. El comando 'git status' debe mostrar el archivo como resuelto sin conflictos pendientes.

## Objetivo
Comprender y aplicar el principio de mínimo privilegio al definir roles IAM específicos para servicios en la nube, evitando permisos administrativos generales.

## Explicación
El principio de mínimo privilegio establece que cada entidad (usuario, servicio o proceso) debe tener solo los permisos estrictamente necesarios para su función. En entornos cloud modernos, asignar el rol 'Administrador' a un contenedor es una práctica riesgosa. En su lugar, se deben crear políticas granulares. Por ejemplo, si un servicio necesita leer logs, se le otorga permiso de lectura específica sobre ese bucket o carpeta, sin capacidad de escritura ni borrado. Esto limita el impacto en caso de compromiso. La implementación requiere auditar las necesidades reales del sistema y definir roles personalizados que reflejen estas limitaciones, asegurando una postura de seguridad defensiva robusta desde el diseño.

## Ejemplo (no ejecutado automáticamente)
Definición de una política IAM en JSON que otorga solo lectura a un bucket específico para un servicio de análisis.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:GetObject", "s3:ListBucket"],
    "Resource": ["arn:aws:s3:::logs-prod-app", "arn:aws:s3:::logs-prod-app/*"]
  }]
}
```

## Ejercicio
Crea un archivo de política IAM llamado 'policy-minimal.json' que otorgue a un usuario solo el permiso de listar objetos en una carpeta compartida, sin permitir la descarga ni modificación.

## Criterios de revisión
La política debe especificar correctamente los recursos ARN y las acciones permitidas. Debe excluir explícitamente acciones como 's3:PutObject' o 's3:DeleteObject'. El formato JSON debe ser válido.

## Objetivo
Aprender a prevenir inyecciones SQL y XSS mediante la validación estricta de patrones en las entradas del usuario, asegurando que solo se acepten caracteres alfanuméricos permitidos antes de procesar datos sensibles.

## Explicación
La validación de entradas es la primera línea de defensa contra ataques como inyección SQL o XSS. En lugar de confiar únicamente en la limpieza posterior (sanitización), debemos validar que la entrada cumpla con un patrón estricto esperado. Por ejemplo, si un campo solo acepta correos electrónicos, rechazamos cualquier texto que no coincida con el formato RFC 5322. Esto reduce la superficie de ataque y evita errores de lógica en la base de datos. Implementar expresiones regulares o librerías de validación para cada tipo de dato es crucial. Nunca confíes en la entrada del usuario sin verificar su integridad estructural antes de usarla en consultas o renderizado.

## Ejemplo (no ejecutado automáticamente)
Función que valida un correo electrónico usando una expresión regular estricta y devuelve el objeto limpio si es válido, o null si falla.

```javascript
function validarCorreo(email) {
  const patron = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!patron.test(email)) return null;
  return email.trim();
}
```

## Ejercicio
Crea una función que valide un campo de 'nombre completo' permitiendo solo letras, espacios y guiones medios. Devuelve el nombre limpio si cumple, o lanza un error personalizado indicando qué caracteres son inválidos.

## Criterios de revisión
El código debe incluir una expresión regular válida para nombres, manejar casos con espacios múltiples eliminándolos, y lanzar un Error con mensaje claro si la entrada contiene números o símbolos prohibidos.

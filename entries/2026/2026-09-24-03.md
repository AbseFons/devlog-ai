## Objetivo
Aprender a usar el comando git reflog para recuperar commits eliminados accidentalmente mediante reset o revert, comprendiendo cómo Git registra la historia de puntaje de HEAD incluso cuando no está en el historial visible.

## Explicación
El comando git reflog muestra un registro privado de todas las posiciones que ha ocupado tu referencia local HEAD. A diferencia del historial normal (git log), el reflog incluye movimientos causados por reset --hard, revert o checkout que eliminan commits del grafo visible pero mantienen su rastro interno. Para recuperar un estado perdido, ejecuta git reflog para listar los hashes de commit recientes con sus marcas temporales. Identifica la entrada correspondiente al estado deseado y usa git reset --hard <hash> para restaurar el directorio de trabajo y el historial a ese punto exacto. Este mecanismo es vital en entornos de desarrollo donde se realizan correcciones rápidas o experimentos que luego deben deshacerse sin perder datos.

## Ejemplo (no ejecutado automáticamente)
Recuperar un commit eliminado accidentalmente usando git reflog y reset --hard

```bash
git reflog
HEAD@{1} -> HEAD (commit abc1234)
git reset --hard HEAD@{1}
```

## Criterios de revisión
El usuario debe identificar correctamente la entrada del reflog correspondiente al estado deseado, ejecutar el comando de recuperación sin errores y verificar que el archivo eliminado reaparezca en el directorio de trabajo.

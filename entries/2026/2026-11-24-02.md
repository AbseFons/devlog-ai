## Objetivo
Distinguir funcionalmente entre mocks y stubs mediante un caso de uso realista, evitando confusiones comunes al diseñar pruebas de integración que validan interacciones específicas con dependencias externas simuladas.

## Explicación
En esta lección exploramos la distinción crítica: los stubs son respuestas predefinidas que simulan el comportamiento básico de una dependencia para permitir la ejecución del código bajo prueba, sin importar cómo se llame a ella. Por otro lado, los mocks no solo devuelven datos, sino que verifican si las interacciones ocurrieron exactamente como se esperaba (ej: 'se llamó al método X con parámetro Y'). Un ejemplo clásico es simular una base de datos: un stub devuelve el usuario encontrado siempre; un mock verifica que la consulta SQL fue ejecutada correctamente antes de devolver el resultado.

## Ejemplo (no ejecutado automáticamente)
Simulación de llamada a API externa donde el stub devuelve datos fijos y el mock valida la estructura de la petición realizada.

```javascript
const stub = () => ({ id: 1, nombre: 'Ana' });
const mock = (req) => { if(req.method === 'GET') return true; throw new Error('Método no permitido'); };
```

## Objetivo
Diferenciar el uso de PUT para reemplazar recursos completos y PATCH para actualizaciones parciales, asegurando integridad de datos en arquitecturas RESTful modernas sin sobrecargar la red.

## Explicación
En APIs REST, los métodos HTTP definen operaciones sobre recursos. PUT es idempotente y requiere enviar el estado completo del recurso; si no se envían todos los campos, el servidor reemplaza lo existente con datos nulos o vacíos. PATCH, en cambio, permite modificar solo los atributos específicos que cambian, ideal para actualizaciones frecuentes de perfiles o configuraciones. Ambos usan verbos HTTP estándar y códigos 200/204 para éxito. Es crucial elegir el correcto según la necesidad: integridad total (PUT) o eficiencia parcial (PATCH).

## Ejemplo (no ejecutado automáticamente)
Actualización parcial de un usuario enviando solo el campo 'email' con PATCH.

```javascript
fetch('/api/users/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
});
```

## Ejercicio
Crea una API local con Express que acepte PUT para actualizar todo un producto y PATCH para cambiar solo su precio. Usa dos rutas distintas.

## Criterios de revisión
El código debe implementar ambas rutas, manejar errores de sintaxis JSON en el cuerpo y devolver códigos HTTP correctos (200 o 400). Debe incluir validación básica antes de persistir cambios.

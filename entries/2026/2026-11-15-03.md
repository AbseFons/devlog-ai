## Objetivo
Comprender cómo las claves foráneas garantizan la consistencia de datos al vincular tablas, analizando el impacto de las acciones CASCADE y RESTRICT en operaciones de borrado o actualización masiva dentro de una base de datos relacional.

## Explicación
Las claves foráneas no solo establecen relaciones entre tablas, sino que definen reglas estrictas para mantener la integridad referencial. Cuando se elimina un registro en la tabla padre (por ejemplo, un cliente), la acción definida en la clave foránea determina el comportamiento: CASCADE borra automáticamente los hijos (pedidos), mientras que RESTRICT impide la operación si existen dependencias. Este control es vital para evitar datos huérfanos o inconsistencias lógicas. En sistemas de producción, elegir la estrategia correcta depende del dominio del negocio; por ejemplo, no se pueden borrar clientes con pedidos pendientes sin una transacción explícita o un proceso de limpieza previo.

## Ejemplo (no ejecutado automáticamente)
Definición de una clave foránea con cascada y consulta para verificar la integridad tras una eliminación.

```sql
CREATE TABLE pedidos (
  id INT PRIMARY KEY,
  cliente_id INT,
  FOREIGN KEY (cliente_id) REFERENCES clientes(id) ON DELETE CASCADE
);
DELETE FROM clientes WHERE nombre = 'Empresa X';
```

## Ejercicio
Crea dos tablas, 'autores' y 'libros', donde 'libros' tenga una clave foránea a 'autores'. Inserta datos de prueba. Luego, intenta borrar un autor que tenga libros asociados usando ON DELETE CASCADE y verifica que los libros desaparezcan automáticamente.

## Criterios de revisión
El código debe definir correctamente la sintaxis de FOREIGN KEY con ON DELETE CASCADE. La consulta de eliminación debe ejecutarse sin errores y el resultado final debe mostrar que las filas en la tabla hijos han sido eliminadas junto con la fila padre.

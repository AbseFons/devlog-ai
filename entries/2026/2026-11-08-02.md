## Objetivo
Aprender a identificar y resolver manualmente conflictos de merge utilizando herramientas de línea de comandos, asegurando la integridad del código sin perder cambios locales ni remotos.

## Explicación
Cuando Git detecta un conflicto durante un merge o una actualización, detiene el proceso marcando los archivos afectados con bloques '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, debes abrir el archivo en tu editor de texto preferido. Analiza ambas versiones: la tuya (local) y la del repositorio remoto. Decide qué lógica es correcta o si necesitas combinar ambas. Una vez editado el archivo manualmente eliminando los marcadores de conflicto, guarda los cambios. Finalmente, ejecuta 'git add <archivo>' para marcarlo como resuelto y 'git commit' para finalizar la operación.

Se muestra un fragmento de código en JavaScript donde se debe decidir entre mantener una variable global o hacerla local tras un conflicto.

```javascript
function calcularTotal() {
  const precio = 10;
  //<<<<<<< HEAD
  let descuento = 5;
  //=======
  let descuento = 0;
  //>>>>>>> branch-remoto
}
```

## Ejercicio
Crea un repositorio local con una rama 'feature' que contenga un archivo 'app.js'. Haz un commit. En el repositorio remoto, modifica el mismo archivo y haz otro commit. Intenta hacer merge de la rama remota en tu local y observa el conflicto. Resuelve el conflicto manualmente eliminando los marcadores y guardando el archivo.

## Criterios de revisión
El archivo debe estar libre de marcadores de conflicto (<<<<, =>>>) y Git debe reportar que no hay conflictos pendientes al ejecutar 'git status'. El código final debe ser funcional y lógico.

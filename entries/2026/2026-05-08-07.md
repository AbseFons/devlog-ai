## Objetivo
Aprender a configurar límites de tasa en APIs para proteger recursos y evitar abusos mediante la inspección de cabeceras de respuesta estándar.

## Explicación
El rate limiting es esencial para garantizar la estabilidad de una API. Cuando un cliente excede su cuota, el servidor responde con un estado 429 Too Many Requests. Este código muestra cómo implementar un middleware simple en Node.js que calcula las solicitudes por ventana de tiempo. Si se supera el límite, se envían cabeceras como X-RateLimit-Limit y Retry-After para informar al cliente sobre su estado actual y cuándo puede reintentar. Esta práctica permite a los desarrolladores construir aplicaciones más robustas y respetuosas con los recursos del servidor.

## Ejemplo (no ejecutado automáticamente)
Middleware de Node.js que aplica un límite de 100 solicitudes por minuto usando un mapa de tokens.

```javascript
const rateLimitMap = new Map();
function checkRateLimit(req, res) {
  const ip = req.ip;
  if (!rateLimitMap.has(ip)) rateLimitMap.set(ip, { count: 0, resetTime: Date.now() + 60000 });
  const limitData = rateLimitMap.get(ip);
  if (limitData.count >= 100) {
    res.setHeader('X-RateLimit-Limit', '100');
    res.setHeader('Retry-After', Math.ceil((limitData.resetTime - Date.now()) / 1000));
    return res.status(429).send('Too Many Requests');
  }
  limitData.count++;
}
```

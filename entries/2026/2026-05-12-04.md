## Objetivo
Aprender a almacenar credenciales sensibles fuera del código fuente utilizando variables de entorno, evitando exponer contraseñas en repositorios públicos y comprendiendo los fundamentos básicos de la seguridad de secretos.

## Explicación
Los secretos, como contraseñas o claves API, nunca deben hardcodearse en el software. La práctica estándar es utilizar variables de entorno para inyectar estos valores dinámicamente durante la ejecución. Esto asegura que el código fuente sea seguro al no contener credenciales visibles. En este caso de uso, simularemos un servicio web que necesita una clave de conexión a base de datos. El desarrollador define la variable DATABASE_PASSWORD en su sistema operativo antes de iniciar la aplicación. La aplicación lee esta variable y utiliza el valor para autenticarse sin escribir la contraseña en ningún archivo de texto plano dentro del proyecto. Esta separación entre configuración sensible y lógica de negocio es esencial para proteger la integridad de los datos y cumplir con normativas de seguridad.

## Ejemplo (no ejecutado automáticamente)
Definición de una variable de entorno con una clave ficticia y lectura desde un script simulado en Bash.

```bash
export DB_PASSWORD='SuperSecretKey123'
read -s -p 'Introduce la contraseña (simulado): ' PASS
```

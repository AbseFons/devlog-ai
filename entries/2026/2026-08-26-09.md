## Objetivo
Al finalizar esta lección, el desarrollador será capaz de implementar validación de entrada para prevenir inyecciones SQL mediante la restricción de caracteres permitidos y el uso de consultas parametrizadas, asegurando que los datos procedentes del usuario nunca se ejecuten como código SQL.

## Explicación
La inyección SQL ocurre cuando datos no filtrados se insertan directamente en una consulta. La defensa más robusta combina dos capas: primero, validar estrictamente el formato de la entrada (ej. permitir solo dígitos para un ID) antes de procesarla; segundo, utilizar siempre consultas parametrizadas o prepared statements. Esto asegura que el motor de base de datos interprete los valores como datos y no como instrucciones lógicas. Nunca confíes en la limpieza del lado del servidor si puedes evitarlo; la validación en el cliente es una barrera adicional útil pero no suficiente por sí sola.

## Ejemplo (no ejecutado automáticamente)
```python
import re

def obtener_usuario(id_str):
    # Validacion estricta: solo numeros permitidos para IDs de usuario
    if not re.fullmatch(r'\d+', id_str):
        raise ValueError('El ID debe ser un numero entero.')
    
    conn = obtener_conexion_db()
    cursor = conn.cursor()
    # Uso de parametrizacion para evitar inyeccion, incluso con datos validados
    sql = 'SELECT * FROM usuarios WHERE id = %s'
    cursor.execute(sql, (id_str,))
    return cursor.fetchone()
```

## Objetivo
Aprender a integrar código en el rama principal mediante Pull Requests, garantizando que las pruebas automatizadas pasen antes de la fusión para mantener la estabilidad del proyecto y fomentar la revisión por pares.

## Explicación
En esta lección exploramos la estrategia estándar de integración continua. El flujo consiste en crear una rama de funcionalidad desde el desarrollo principal, implementar cambios y ejecutar pruebas locales. Antes de solicitar la integración, se debe configurar un Pull Request que active los tests automátizados en el servidor CI/CD. Solo si todos los indicadores verdes aparecen, el equipo revisa el código manualmente para asegurar calidad antes de fusionar. Este proceso evita conflictos masivos y mantiene el historial del proyecto claro.

## Ejemplo (no ejecutado automáticamente)
Comandos Git para crear rama, hacer commit y abrir Pull Request con mensaje estructurado

```bash
git checkout -b feature/nueva-funcionalidad
git add .
git commit -m 'feat: implementar validacion de entrada'
# Abrir PR en la interfaz del repositorio
```

## Ejercicio
Crea una rama llamada 'fix/error-login', realiza un cambio pequeño en el archivo de autenticación, haz un commit con mensaje descriptivo y simula la apertura de un Pull Request documentando los cambios.

## Criterios de revisión
El estudiante debe crear correctamente la rama, realizar al menos un commit válido con mensaje que siga convención de commits, y describir en el ejercicio cómo verificaría las pruebas antes de fusionar.

## Objetivo
Distinguir conceptualmente entre merge y rebase en Git, entendiendo cómo cada comando afecta la línea de tiempo del historial y cuándo es preferible usar uno u otro para mantener un proyecto limpio.

## Explicación
Merge crea una nueva rama fusionando dos líneas de historia, preservando el contexto real de los desarrollos paralelos. Rebase reescribe el historial moviendo commits para que parezcan haber ocurrido secuencialmente en la rama principal. Merge es seguro y transparente; rebase puede ser peligroso si se aplica a ramas compartidas públicamente porque altera hashes existentes. Usa merge para integraciones de equipo y rebase localmente antes de push.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un merge desde una rama feature hacia main, mostrando la creación de un commit de fusión.

```bash
git checkout main
git merge feature-branch
```

## Ejercicio
Crea dos ramas en tu repositorio local: 'main' y 'feature-login'. Realiza un cambio en 'feature-login', haz commit, luego fusiona esa rama a 'main' usando el comando merge.

## Criterios de revisión
El historial debe mostrar un nodo de fusión único. No deben existir commits duplicados ni reescritos de historia local antes del push.

## Objetivo
Aprender a aislar la lógica de negocio bajo prueba simulando dependencias externas como bases de datos o APIs, evitando efectos secundarios no deseados durante las pruebas unitarias.

## Explicación
En esta lección avanzamos en unittest introduciendo el mocking. A diferencia de la serie anterior donde probábamos funciones puras, aquí enfrentamos dependencias reales. Usaremos mock.patch para reemplazar dinámicamente métodos o atributos de una clase durante la ejecución de la prueba. Esto permite verificar que nuestra función llama al servicio correcto sin ejecutar consultas SQL lentas ni depender de redes inestables. La sintaxis @patch('modulo.clase.metodo') intercepta la llamada y devuelve un objeto mock configurado con return_value. Es crucial entender que el patching debe aplicarse antes de importar o instanciar la clase afectada si no se usa decorador, aunque unittest lo maneja automáticamente en pruebas unitarias estándar.

## Ejemplo (no ejecutado automáticamente)
Se define una clase ServicioUsuario que llama a una API externa. La prueba reemplaza esa llamada con un valor fijo para verificar el comportamiento sin red.

```python
from unittest.mock import patch

class ServicioUsuario:
    def obtener_datos(self):
        # Simula llamada a API
        return {'id': 1, 'nombre': 'Ana'}

@patch('modulo.ServicioUsuario.obtener_datos')
def test_obtener_datos_mockado(mock_metodo):
    mock_metodo.return_value = {'id': 99, 'nombre': 'Carlos'}
    servicio = ServicioUsuario()
    resultado = servicio.obtener_datos()
    assert resultado['nombre'] == 'Carlos'
```

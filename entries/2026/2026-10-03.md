## Objetivo
Diferenciar claramente entre autenticación (quién eres) y autorización (qué puedes hacer) en el contexto de APIs REST, estableciendo la base para diseñar sistemas seguros.

## Explicación
En las arquitecturas de API, la autenticación verifica la identidad del usuario mediante credenciales como tokens JWT o sesiones. La autorización, por otro lado, determina los permisos específicos de esa identidad identificada. Un error común es confundir ambos conceptos; un sistema puede saber quién eres (autenticado) pero negarte el acceso a una ruta específica si no tienes el rol adecuado (no autorizado). Para implementar esto correctamente, se deben usar encabezados HTTP distintos: 'Authorization' para la autenticación y roles o scopes en los metadatos del token para la autorización. Esto asegura que incluso si un atacante obtiene un token válido, solo podrá acceder a los recursos permitidos por ese token específico.

## Ejercicio
Crea un endpoint '/api/data' que requiera autenticación. Luego, modifica la lógica para que solo usuarios con el rol 'admin' puedan acceder a él, devolviendo un error de autorización si el rol no coincide.

## Criterios de revisión
El código debe distinguir entre errores 401 (no autenticado) y 403 (no autorizado). La explicación debe mencionar tokens o sesiones. El ejemplo JSON debe mostrar claramente la diferencia en el mensaje de error.

## Objetivo
Comprender por qué nunca se deben almacenar credenciales en código fuente y aprender el principio básico de utilizar variables de entorno para inyectar secretos de forma segura en aplicaciones.

## Explicación
Los secretos, como contraseñas o claves API, son activos críticos que no deben residir en repositorios públicos. Guardarlos directamente en el código expone la aplicación a filtraciones masivas si el repositorio se hace público accidentalmente. La práctica estándar es separar la lógica de la aplicación de los datos sensibles. Utilizamos variables de entorno para pasar estos valores al momento de ejecutar el programa. El sistema operativo gestiona estas variables, y la aplicación las lee mediante funciones específicas sin tocar archivos de configuración estáticos o texto plano en el disco. Este enfoque minimiza la superficie de ataque y asegura que los secretos no viajen a través del control de versiones.

## Ejemplo (no ejecutado automáticamente)
Script que demuestra cómo leer una variable de entorno para obtener un secreto, evitando escribirlo en el código.

```bash
# Leer el secreto desde la variable de entorno
SECRET_KEY="${MY_APP_SECRET:-}"
```

## Objetivo
Comprender el uso de códigos de estado 3xx para redirigir clientes a recursos actualizados, gestionando versiones de API y cambios de ubicación sin devolver errores.

## Explicación
Los códigos 3xx indican que la solicitud fue recibida pero el cliente debe realizar otra acción. El más común es 301 Moved Permanently, usado cuando una URL cambia definitivamente. En APIs modernas, también se usa 302 Found para redirecciones temporales o 307 Temporary Redirect para mantener el método HTTP original. Esto es vital en versionado de endpoints: al cambiar /v1/resource por /v2/resource, devolver 301 evita que los clientes fallen. Sin embargo, algunos frameworks requieren 302 para evitar problemas de caché agresiva. Es crucial configurar cabeceras Location correctamente. Las APIs deben documentar estas redirecciones en su changelog para que los desarrolladores actualicen sus URLs base.

## Ejemplo (no ejecutado automáticamente)
Endpoint que redirige a la nueva versión de la API con código 301 y cabecera Location

```javascript
app.get('/old-endpoint', (req, res) => {
  res.redirect(301, '/new-endpoint');
});
```

## Ejercicio
Crea un endpoint que devuelva 302 cuando el parámetro version sea 'temp' y 301 si es 'permanente'.

## Criterios de revisión
El código debe usar res.redirect con el estado correcto, incluir la cabecera Location en la respuesta y manejar ambos casos de uso sin errores.

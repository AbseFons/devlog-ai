## Objetivo
Comprender la definición de idempotencia en el contexto de las APIs REST y reconocer su importancia para garantizar la consistencia de datos ante llamadas repetidas o fallos de red.

## Explicación
La idempotencia es una propiedad crítica en las APIs REST que asegura que múltiples solicitudes idénticas produzcan el mismo efecto que una sola solicitud. Esto es vital cuando ocurren reintentos automáticos por errores de red. Las operaciones GET, HEAD y OPTIONS son naturalmente idempotentes. POST, PUT y DELETE pueden serlo si se implementan correctamente (por ejemplo, usando encabezados como 'Idempotency-Key'). Sin embargo, crear una API idempotente requiere un diseño cuidadoso del backend para evitar duplicidad de registros o cobros múltiples.

## Ejercicio
Diseña un endpoint POST que registre una transacción financiera. Implementa una lógica en el backend que, al recibir una solicitud con un ID único de transacción repetido, devuelva el estado exitoso sin crear un registro duplicado en la base de datos.

## Criterios de revisión
El código debe manejar correctamente la retransmisión de solicitudes idénticas. La respuesta a una segunda llamada con los mismos datos debe ser exactamente igual a la primera (mismo cuerpo y estado HTTP). No deben generarse registros duplicados en la persistencia.

## Objetivo
Comprender la inmutabilidad como principio central en el modelado de eventos de dominio para garantizar trazabilidad y consistencia en sistemas distribuidos.

## Explicación
En el diseño de eventos de dominio, un evento representa un hecho ocurrido que no puede ser alterado. A diferencia de las entidades agregables, los eventos son inmutables; una vez registrados, su estado es definitivo. Esto permite reconstruir el historial del sistema sin ambigüedades. Al modelar un evento, capturamos solo lo que sucedió, eliminando la lógica de 'por qué' o 'cómo', dejando eso para las entidades y agregados. Esta separación asegura que el registro sea una fuente única de verdad histórica.

## Ejemplo (no ejecutado automáticamente)
Definición de una clase Event en C# que encapsula datos inmutables con un constructor privado y propiedades auto-propiedades.

```csharp
public class OrderCreatedEvent
{
    public Guid Id { get; }
    public string CustomerName { get; }
    public decimal TotalAmount { get; }
    public DateTime OccurredAt { get; }

    private OrderCreatedEvent(Guid id, string name, decimal amount, DateTime date)
    {
        Id = id;
        CustomerName = name;
        TotalAmount = amount;
        OccurredAt = date;
    }

    public static OrderCreatedEvent Create(Guid id, string name, decimal amount, DateTime date)
    {
        return new OrderCreatedEvent(id, name, amount, date);
    }
}
```

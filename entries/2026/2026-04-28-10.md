## Objetivo
Comprender la diferencia fundamental entre las operaciones de lectura (GET) y creación (POST) en una API RESTful, identificando sus verbos, códigos de estado asociados y patrones de diseño estándar para construir endpoints seguros y predecibles.

## Explicación
En el diseño de APIs REST, los métodos HTTP definen la acción sobre un recurso. El método GET se utiliza exclusivamente para recuperar datos sin efectos secundarios; debe ser idempotente y seguro. Por otro lado, POST inicia una acción que cambia el estado del servidor, como crear un nuevo recurso. Al enviar una solicitud POST a un endpoint de recursos (ej. /usuarios), el servidor responde típicamente con 201 Created y la ubicación del nuevo recurso en el encabezado Location. GET nunca debe modificar datos ni devolver códigos 201. Esta distinción es crucial para mantener la integridad de los datos y permitir que clientes y cachés funcionen correctamente.

## Ejemplo (no ejecutado automáticamente)
Solicitud POST para crear un usuario con respuesta 201 y ubicación del recurso

```bash
curl -X POST https://api.ejemplo.com/usuarios \
  -H "Content-Type: application/json" \
  -d '{"nombre": "Ana", "email": "ana@ejemplo.com"}'
```

## Ejercicio
Crea un endpoint GET que retorne una lista de productos y otro POST que reciba JSON para agregar uno nuevo.

## Criterios de revisión
El endpoint GET debe devolver código 200 con un array de objetos. El endpoint POST debe devolver código 201 con el objeto creado y el encabezado Location.

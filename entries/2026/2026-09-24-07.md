## Objetivo
Comprender cómo las claves foráneas mantienen la consistencia de datos al definir comportamientos específicos para la eliminación de registros en tablas relacionadas, evitando referencias huérfanas.

## Explicación
Las claves foráneas no solo vinculan datos, sino que protegen la integridad cuando se eliminan o actualizan registros. SQL permite definir restricciones ON DELETE: CASCADE elimina automáticamente los hijos al borrar el padre; SET NULL deja el campo vacío si es permitida la nulosidad; RESTRICT impide la eliminación si existen dependencias. Esta elección depende del dominio de negocio. Por ejemplo, en un sistema de pedidos, eliminar un producto podría no deber borrar los pedidos históricos (SET NULL o mantener datos), mientras que en una sesión temporal, CASCADE sería ideal. La definición se realiza en el enunciado de CREATE TABLE o ALTER TABLE.

## Ejemplo (no ejecutado automáticamente)
Definición de tabla 'pedidos' con clave foránea a 'productos' y restricción ON DELETE SET NULL para no perder historial de pedidos al eliminar un producto.

```sql
CREATE TABLE productos (
  id INT PRIMARY KEY
);

CREATE TABLE pedidos (
  id INT PRIMARY KEY,
  producto_id INT,
  FOREIGN KEY (producto_id) REFERENCES productos(id)
    ON DELETE SET NULL
);
```

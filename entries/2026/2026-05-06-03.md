## Objetivo
Distinguir conceptualmente entre merge y rebase en Git, entendiendo cómo cada uno afecta la historia del repositorio y cuándo aplicar cada estrategia para mantener un historial limpio o preservar relaciones complejas.

## Explicación
Merge crea un nuevo commit que fusiona dos ramas, preservando la historia lineal original con una rama de fusión. Rebase reescribe la historia moviendo los commits de una rama sobre la punta de otra, creando una línea temporal lineal. Usa merge para preservar contextos complejos o conflictos inevitables; usa rebase para mantener un historial limpio en ramas de desarrollo antes de fusionar al main.

## Ejemplo (no ejecutado automáticamente)
Comandos básicos para realizar un merge y un rebase entre dos ramas locales

```bash
git checkout feature
git merge main

# Alternativa con rebase
# git checkout main
# git pull --rebase origin main
```

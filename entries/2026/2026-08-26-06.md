## Objetivo
Al finalizar esta lección, podrás redactar mensajes de commit que sigan el formato convencional (type(scope): description), identificando correctamente el tipo de cambio realizado y evitando ambigüedades en el historial del proyecto.

## Explicación
Los commits convencionales estandarizan la comunicación entre desarrolladores. Un buen mensaje debe comenzar con un tipo como feat, fix o docs, seguido de un scope opcional y una descripción en presente, sin mayúscula inicial ni punto final. Esto permite generar changelogs automáticos y entender rápidamente el impacto del cambio.

## Ejemplo (no ejecutado automáticamente)
```python
# Archivo: src/utils.py

def calcular_promedio(lista):
    """Calcula el promedio de una lista de números."""
    if not lista:
        return 0
    return sum(lista) / len(lista)

# Cambio realizado en este commit:
# Tipo: feat(scope): añadir validacion vacia
# Descripción: Retorna 0 si la lista esta vacia para evitar division por cero.
```

## Ejercicio
Crea un archivo llamado 'utils.py' con una función que sume dos números. Luego, haz un commit con el mensaje 'fix(utils): manejar entrada no numerica lanzando error'. Asegúrate de que el mensaje siga la convención.

## Criterios de revisión
El commit debe incluir exactamente el prefijo 'fix(utils):', seguido de una descripción en presente y sin puntos finales. El archivo debe contener la lógica básica de suma y manejo de errores.

## Objetivo
Al finalizar esta lección, el desarrollador podrá identificar la causa raíz de un conflicto de fusión, decidir si editar manualmente o usar herramientas automáticas, y aplicar una estrategia segura para integrar cambios sin perder datos locales ni remotos.

## Explicación
Un conflicto en Git surge cuando dos ramas modifican las mismas líneas de un archivo de forma incompatible. El sistema detiene la operación y marca los bloques conflictivos con marcadores '<<<<<<<', '=======', y '>>>>>>>'. Para resolverlo, primero lee el contexto del cambio: ¿es una corrección de bug o una refactorización? Si ambos cambios son válidos, edita el archivo manualmente eliminando los marcadores y fusionando la lógica. Evita usar comandos como 'git checkout --ours' sin entender las implicaciones, ya que pueden borrar trabajo local. Una vez resuelto, guarda el archivo y ejecuta 'git add' seguido de 'git commit'. Esta práctica garantiza un historial limpio y evita la pérdida de funcionalidad crítica en el proyecto.

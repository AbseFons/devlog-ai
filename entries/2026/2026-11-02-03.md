## Objetivo
Comprender la relación entre imágenes inmutables y contenedores efímeros, aprendiendo a construir una imagen personalizada con Dockerfile para ejecutar un servicio web simple.

## Explicación
Las imágenes de Docker son plantillas inmutables que contienen todo lo necesario para ejecutar una aplicación. Los contenedores son instancias ligerias y efímeras creadas a partir de esas imágenes. En esta lección, construiremos una imagen personalizada partiendo de una base oficial como 'python:3.12-slim'. El proceso implica definir instrucciones en un archivo Dockerfile: establecer la imagen base, copiar el código fuente al contenedor, instalar dependencias y exponer el puerto necesario. Al ejecutar 'docker build', se genera una nueva capa de imagen que incluye nuestro código específico. Posteriormente, con 'docker run', creamos un contenedor aislado basado en esa imagen. Esta separación permite escalar servicios fácilmente, ya que cada instancia del contenedor comparte la misma base pero mantiene su propio estado de ejecución.

## Ejemplo (no ejecutado automáticamente)
Creación de una imagen Docker personalizada para ejecutar una aplicación Flask simple con un archivo de código fuente y un Dockerfile básico.

```bash
FROM python:3.12-slim
COPY app.py /app/app.py
RUN pip install flask
EXPOSE 5000
```

## Criterios de revisión
El Dockerfile debe tener exactamente cuatro instrucciones: FROM, COPY, RUN y EXPOSE. La imagen base debe ser una versión ligera de Node.js. El comando RUN debe instalar dependencias sin usar credenciales ni paquetes destructivos.

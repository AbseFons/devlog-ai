## Objetivo
Aprender a automatizar la búsqueda del commit que introdujo un bug utilizando 'git bisect run' en combinación con un script de prueba, ahorrando tiempo y esfuerzo manual al iterar entre versiones estables e inestables.

## Explicación
El comando 'git bisect' permite navegar linealmente por el historial de commits para aislar la introducción de un error. Sin embargo, hacerlo manualmente comparando cada commit es tedioso. La solución eficiente es 'git bisect run', que ejecuta automáticamente un script de prueba (por ejemplo, un shell script) en cada paso del proceso de bisección. El script debe devolver '0' si el estado es correcto y un valor distinto si hay fallo. Git usará estos resultados para descartar commits seguros y centrarse en los sospechosos, hasta encontrar exactamente dónde rompió la funcionalidad.

## Ejemplo (no ejecutado automáticamente)
Un script de bash que verifica si una aplicación específica se ejecuta correctamente en el entorno actual, retornando exito o error segun el estado del proceso.

```bash
#!/bin/bash
if ./app --version > /dev/null 2>&1; then
  echo "ok"
else
  echo "bug"
fi
```

## Ejercicio
Crea un repositorio con una versión inicial estable y luego introduce un cambio que rompa la funcionalidad. Usa 'git bisect start', marca el commit actual como bug, busca el último commit conocido bueno, y ejecuta 'git bisect run ./test_bug.sh'.

## Criterios de revisión
El script debe retornar correctamente 'ok' o 'bug'. El comando 'bisect run' debe terminar indicando el commit exacto que introdujo el error sin intervención manual.

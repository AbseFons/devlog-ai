## Objetivo
Diferenciar el uso de PUT para reemplazar recursos completos contra PATCH para actualizaciones parciales, asegurando integridad de datos y eficiencia en transferencias.

## Explicación
En la arquitectura RESTful, los verbos HTTP definen operaciones sobre recursos. PUT es idempotente y requiere enviar el estado completo del recurso; si faltan campos, se pierden. PATCH permite modificaciones selectivas enviando solo los cambios, ideal para actualizaciones frecuentes de perfiles o configuraciones. Ambos métodos retornan códigos 200 (éxito) o 400/404 según la validación. La elección depende de si el cliente conoce toda la estructura del recurso o solo necesita alterar atributos específicos.

## Ejemplo (no ejecutado automáticamente)
Actualización parcial de un usuario enviando solo el campo 'email' con PATCH en JavaScript usando fetch API.

```javascript
const response = await fetch('/api/users/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
});
```

## Ejercicio
Crea una API local con Express que acepte PUT para reemplazar un objeto completo y PATCH para actualizar solo el campo 'estado'.

El código debe manejar correctamente los encabezados Content-Type, validar la estructura JSON entrante y devolver códigos de estado HTTP apropiados (200, 400, 404).

## Objetivo
Comprender la distinción fundamental entre las operaciones de lectura (GET) y creación (POST) en arquitecturas REST, aplicando los verbos HTTP correctos para diseñar endpoints seguros y semánticamente precisos que reflejen fielmente la intención del cliente.

## Explicación
En el diseño de APIs RESTful, los métodos HTTP definen la acción sobre los recursos. GET se utiliza exclusivamente para recuperar datos sin efectos secundarios, ideal para listar usuarios o obtener detalles de un producto. Por otro lado, POST inicia una transferencia de datos hacia el servidor, típicamente para crear nuevos recursos como un registro en una base de datos. Es crucial no usar GET para acciones que modifican estado, ya que esto viola la idempotencia esperada y puede exponer lógica sensible. Al elegir correctamente entre estos verbos, garantizamos que la API sea predecible, fácil de depurar y alineada con los estándares de la industria.

## Ejemplo (no ejecutado automáticamente)
Definición de un endpoint GET para listar usuarios activos y un POST para registrar uno nuevo en una API ficticia.

```javascript
const fetchUsers = async () => {
  const response = await fetch('https://api.ejemplo.com/usuarios', { method: 'GET' });
  return response.json();
};

const crearUsuario = async (datos) => {
  const response = await fetch('https://api.ejemplo.com/usuarios', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(datos)
  });
  return response.json();
};
```

## Objetivo
Comprender cómo la propiedad de consistencia garantiza que una transacción deje el sistema en un estado válido, utilizando bloques TRY-CATCH para revertir cambios ante fallos lógicos.

## Explicación
La consistencia asegura que una transacción transforme el estado de la base de datos desde un estado válido a otro válido. Si durante la ejecución ocurre un error lógico, como una división por cero o una violación de restricción, el sistema debe abortar toda la operación para no dejar datos corruptos. En SQL Server, esto se logra con bloques TRY-CATCH dentro de procedimientos almacenados. Al detectar una excepción, el bloque CATCH ejecuta comandos ROLLBACK para deshacer todos los cambios realizados en la transacción actual, asegurando que ninguna parte de la operación quede comprometida.

## Ejemplo (no ejecutado automáticamente)
Procedimiento almacenado que intenta transferir fondos y revierte la operación si el saldo es insuficiente o ocurre un error.

```sql
CREATE PROCEDURE TransferirFondos @Origen INT, @Destino INT, @Monto DECIMAL(10,2)
AS
BEGIN TRY
    UPDATE Cuentas SET Saldo = Saldo - @Monto WHERE IdCuenta = @Origen
    UPDATE Cuentas SET Saldo = Saldo + @Monto WHERE IdCuenta = @Destino
END TRY
BEGIN CATCH
    ROLLBACK TRANSACTION
    PRINT 'La transacción fue abortada por inconsistencia.'
END CATCH
```

## Ejercicio
Crea un procedimiento almacenado que intente actualizar dos tablas relacionadas. Si la segunda actualización falla, el sistema debe revertir automáticamente la primera y registrar el error en una tabla de auditoría.

## Criterios de revisión
El código debe incluir bloques TRY-CATCH válidos, comandos ROLLBACK tras un error, y mensajes claros indicando el estado de la transacción. No deben existir datos residuales tras un fallo.

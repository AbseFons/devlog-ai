## Objetivo
Aprender a implementar mecanismos de versionado en endpoints REST para garantizar la compatibilidad hacia atrás y gestionar cambios en la estructura de datos sin interrumpir clientes existentes.

## Explicación
El versionado es crucial para mantener la estabilidad de las aplicaciones que consumen APIs. Existen dos enfoques principales: versionado por URL (ej. /api/v1/usuarios) y versionado por encabezados (ej. Accept: application/vnd.api+json;version=2). El primero es explícito pero ensucia la ruta, mientras que el segundo mantiene las URLs limpias pero requiere soporte en el cliente. Para 2026, se recomienda priorizar el versionado por URL para mayor claridad en los logs y herramientas de desarrollo, reservando los encabezados para casos específicos como actualizaciones de formato de respuesta. Siempre define una política clara de ciclo de vida para cada versión.

Definición de rutas versionadas para un endpoint de usuarios con comentarios en la documentación.

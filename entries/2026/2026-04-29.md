## Objetivo
Comprender el concepto fundamental de inyección de dependencias y cómo la inversión de control desacopla las clases, facilitando pruebas unitarias y un mantenimiento más sencillo en aplicaciones modernas.

## Explicación
La inyección de dependencias (IoC) es un patrón de diseño que permite a una clase recibir sus dependencias desde el exterior en lugar de crearlas internamente. Este enfoque promueve la inversión de control, donde el flujo de control se invierte: en lugar de que tu código controle las instancias, el framework o contenedor lo hace. Al declarar qué necesita una clase (sus dependencias), logras un acoplamiento débil entre componentes. Esto significa que puedes cambiar fácilmente la implementación de una dependencia, como reemplazar un servicio real con un mock para pruebas unitarias, sin modificar la lógica del negocio. En esta serie, exploraremos cómo estructurar aplicaciones escalables y mantenibles aplicando estos principios desde el inicio.

## Ejemplo (no ejecutado automáticamente)
Clase Cliente que recibe una dependencia de ServicioPago mediante su constructor en lugar de instanciarla internamente.

```java
public class Cliente {
    private final ServicioPago servicioPago;

    public Cliente(ServicioPago servicioPago) {
        this.servicioPago = servicioPago;
    }

    public void procesar() {
        servicioPago.realizarPago(100);
    }
}
```

## Ejercicio

Luego, escribe un método en tu clase principal que instancie un 'GeneradorPDFFalso' y lo inyecte en un nuevo objeto 'Reporte' para generar un reporte sin usar PDF real.

## Criterios de revisión
El código debe mostrar una clase con constructor dependiente, la eliminación de 'new GeneradorPDF()' dentro de la clase dependiente, y la creación de una instancia externa que inyecta el objeto en la otra.

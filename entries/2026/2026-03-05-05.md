## Objetivo
Distinguir claramente los conceptos de autenticación (quién eres) y autorización (qué puedes hacer) en el contexto de las APIs REST, identificando cuándo aplicar cada mecanismo para proteger recursos sensibles.

## Explicación
En el desarrollo de APIs, es fundamental no confundir autenticación con autorización. La autenticación verifica la identidad del usuario o servicio mediante credenciales como tokens JWT o claves API, respondiendo a '¿Quién eres?'. Una vez validada esta identidad, entra en juego la autorización, que determina los permisos específicos del sujeto sobre recursos protegidos, respondiendo a '¿Qué puedes hacer?'. Mientras la autenticación suele ser un paso único por sesión, la autorización se evalúa dinámicamente para cada solicitud. Implementar ambos correctamente previene accesos no autorizados y asegura que usuarios legítimos solo accedan a datos relevantes a su rol.

## Ejemplo (no ejecutado automáticamente)
Solicitud HTTP con token de autenticación y encabezado de permisos para acceder a un recurso protegido.

```bash
curl -X GET 'https://api.ejemplo.com/v1/usuarios' \
  -H 'Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...' \
  -H 'X-Permisos: read,profile'
```

## Ejercicio
Crea un endpoint en tu API local que requiera un token válido para autenticar y verifique si el usuario tiene permiso de 'admin' antes de devolver datos sensibles.

## Criterios de revisión
El código debe validar la presencia del token, decodificarlo o verificar su firma, y luego consultar una lista de roles o permisos asociados al sujeto. Si falta el permiso específico, la API debe retornar un error 403 Forbidden.

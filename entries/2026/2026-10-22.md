## Objetivo
Comprender cómo la base de datos optimiza consultas complejas mediante el análisis del plan de ejecución, identificando cuellos de botella como escaneos de tablas completas o uniones ineficientes para mejorar el rendimiento.

## Explicación
El comando EXPLAIN permite inspeccionar el plan de ejecución generado por el optimizador de consultas antes de ejecutar la operación real. Esto es crucial en bases de datos grandes donde una mala elección de índices puede ralentizar aplicaciones significativamente. Al analizar el plan, identificamos si se utilizan índices adecuados o si se realizan escaneos secuenciales costosos. En este caso, observaremos una consulta con JOIN que podría beneficiarse de un índice específico en la columna de clave foránea.

## Ejemplo (no ejecutado automáticamente)
Consulta SQL con JOIN y uso de EXPLAIN para verificar el plan de ejecución y detectar si se usa un índice.

```sql
EXPLAIN ANALYZE SELECT u.nombre, o.fecha
FROM usuarios u
INNER JOIN pedidos o ON u.id = o.usuario_id
WHERE o.total > 100;
-- Verificar que 'usuario_id' tenga un índice.
```

## Criterios de revisión
El plan debe mostrar 'Index Scan' o 'Index Seek' en lugar de 'Seq Scan' para las tablas principales. Debe existir al menos un índice creado explícitamente en el código SQL previo a la consulta.

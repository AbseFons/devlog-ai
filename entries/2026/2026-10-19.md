## Objetivo
El desarrollador identificará vulnerabilidades críticas en su stack mediante escaneo automatizado y aplicará parches sin interrumpir el flujo de trabajo, reduciendo la superficie de ataque antes de que un exploit sea explotado en producción.

## Explicación
Las Vulnerabilities Common Exploits (CVE) representan fallos conocidos en software. La estrategia defensiva no es esperar a ser atacados, sino mantener un inventario actualizado. Utiliza herramientas como Snyk o Dependabot para escanear tu repositorio. Al detectar una CVE de alto riesgo, evalúa el impacto: ¿afecta a la lógica de negocio? ¿Existe un parche estable? Prioriza las actualizaciones que cierran brechas críticas sin romper compatibilidad. Documenta cada cambio en el changelog del proyecto para auditoría futura. La seguridad es responsabilidad continua, no un evento puntual.

## Ejemplo (no ejecutado automáticamente)
```javascript
// Escaneo de dependencias con npm audit
const { execSync } = require('child_process');

try {
  const report = execSync('npm audit --json', { encoding: 'utf8' });
  const vulnerabilities = JSON.parse(report);
  
  if (vulnerabilities.vulnerable.length > 0) {
    console.log(`Se encontraron ${vulnerabilities.vulnerable.length} vulnerabilidades.`);
    vulnerabilities.vulnerable.forEach(pkg => {
      console.log(`Paquete: ${pkg.package}`);
      console.log(`Vulnerabilidad: ${pkg.title}`);
      console.log(`Solución recomendada: Ejecutar 'npm install ${pkg.package}@latest'`);
    });
  } else {
    console.log('No se detectaron vulnerabilidades críticas.');
  }
} catch (error) {
  console.error('Error al ejecutar el escaneo:', error.message);
}
```

## Ejercicio
En un repositorio de prueba, instala una dependencia vulnerable intencionalmente. Ejecuta el script de auditoría proporcionado para generar un reporte JSON. Crea un archivo 'remediation_plan.md' donde documentes los pasos exactos para actualizar cada paquete afectado y validas que la aplicación sigue funcionando tras la actualización.

## Criterios de revisión
El reporte debe listar al menos tres paquetes vulnerables con sus versiones actuales y recomendadas. El plan de remediación debe incluir comandos específicos de instalación sin usar credenciales ni eliminar archivos del sistema. La validación final debe demostrar que la aplicación responde correctamente a una solicitud HTTP tras aplicar los parches.

## Objetivo
Aprender a utilizar el comando git reflog para recuperar estados de trabajo eliminados accidentalmente, evitando la pérdida permanente de código sin necesidad de repositorios remotos complejos.

## Explicación
El historial de comandos (git log) muestra solo los commits públicos, pero el reflog registra cada cambio en el HEAD, incluyendo borrados accidentales. Cuando un commit se elimina con 'reset --hard' o 'rebase -i', el objeto sigue existiendo temporalmente en el reflog hasta que se expira. Este comando permite navegar por estos estados ocultos para restaurar versiones específicas. Es vital usarlo cuando la limpieza del historial accidental provoca la pérdida de trabajo local. El reflog actúa como una red de seguridad interna, permitiendo deshacer operaciones destructivas locales sin depender de un backup externo inmediato.

## Ejemplo (no ejecutado automáticamente)
Se ejecuta git reflog para listar el historial oculto y luego se restaura el estado anterior a un reset accidental utilizando la referencia correspondiente.

```bash
git reflog
HEAD@{1}~1: revertir commit borrado
```

## Ejercicio
Simula un error donde borras un commit importante con 'git reset --hard HEAD~1'. Usa git reflog para encontrar la referencia del estado anterior y restaura el archivo perdido.

## Criterios de revisión
El usuario debe listar correctamente el historial oculto, identificar la referencia adecuada (ej. HEAD@{2}) y ejecutar el comando de restauración sin perder datos adicionales.

## Objetivo
Aprender a interpretar los planes de ejecución reales generados por EXPLAIN ANALYZE para identificar cuellos de botella en bases de datos SQL y mejorar el rendimiento de las aplicaciones mediante ajustes precisos en índices o reescritura de consultas.

## Explicación
La sentencia EXPLAIN ANALYZE ejecuta la consulta real y registra el tiempo transcurrido, ofreciendo un plan de ejecución tangible. A diferencia de EXPLAIN estándar que solo simula, esta versión revela si una tabla fue escaneada completa o utilizada mediante índices eficientes. Al analizar los tiempos de lectura de filas y las operaciones de unión, puedes detectar consultas lentas causadas por falta de índices adecuados o estadísticas desactualizadas. Este análisis permite tomar decisiones informadas sobre la arquitectura de la base de datos sin necesidad de monitoreo externo complejo.

## Ejemplo (no ejecutado automáticamente)
Consulta que busca empleados activos con ordenamiento por departamento, mostrando el plan de ejecución real y los tiempos involucrados para identificar ineficiencias potenciales en el acceso a las tablas.

```sql
EXPLAIN ANALYZE SELECT e.nombre, d.departamento
FROM empleados e
JOIN departamentos d ON e.id_departamento = d.id
WHERE e.estado = 'activo'
ORDER BY d.departamento;
```

## Ejercicio
Crea una tabla de productos con al menos 10.000 registros y un índice en el campo precio. Ejecuta una consulta que filtre por precio mayor a 50 y ordena por nombre, luego usa EXPLAIN ANALYZE para verificar si utiliza el índice correctamente.

## Criterios de revisión
El plan debe mostrar 'Index Scan' o 'Index Only Scan' en lugar de 'Seq Scan' para la tabla de productos. El tiempo total de ejecución debe ser menor a 100 milisegundos. La consulta debe incluir al menos una cláusula JOIN y un filtro WHERE.

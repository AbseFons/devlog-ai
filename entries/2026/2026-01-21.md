## Objetivo
Comprender la distinción fundamental entre mocks y stubs para escribir pruebas unitarias más limpias, predecibles y enfocadas en la lógica del sistema bajo prueba.

## Explicación
En ingeniería de software, los mocks y los stubs son herramientas esenciales para aislar unidades de código. Un stub es una implementación simplificada que devuelve valores predeterminados sin verificar cómo se llama a él; su propósito es simular el comportamiento básico de un servicio externo o base de datos para evitar dependencias lentas. Por otro lado, un mock no solo responde, sino que también verifica las interacciones: comprueba qué métodos fueron invocados, con qué argumentos y cuántas veces. Esto permite detectar fallos de integración sutiles donde la lógica del sistema no llama a los servicios externos como se espera. Usar stubs es ideal para probar flujos rápidos, mientras que los mocks son necesarios cuando la correcta interacción con dependencias es parte crítica de la funcionalidad.

## Ejemplo (no ejecutado automáticamente)
Un stub en JavaScript que simula una llamada a API devolviendo datos estáticos sin verificar la invocación.

```javascript
const apiStub = {
  fetchUser: () => ({ id: 1, name: 'Ana' })
};
```

## Ejercicio
Crea una función en Python que utilice un stub para simular una llamada a base de datos y luego modifica el stub para verificar que la función principal lo invoque exactamente una vez con el parámetro correcto.

## Criterios de revisión
El código debe diferenciar claramente entre stub y mock, usar al menos un caso de uso realista sin credenciales, y evitar comandos destructivos.

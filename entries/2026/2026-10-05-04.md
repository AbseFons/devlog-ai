## Objetivo
Aprender a utilizar flujos de trabajo modernos en Git mediante Merge Requests para integrar cambios de manera controlada, asegurando la calidad del código antes de fusionar ramas principales.

## Explicación
En entornos profesionales, el merge directo a la rama principal suele evitarse. Se prefiere crear una rama de funcionalidad, desarrollar y luego abrir un Merge Request (MR) o Pull Request. Este proceso obliga a realizar revisiones por pares antes de la fusión automática. Git ofrece herramientas como 'git pull --rebase' para mantener el historial limpio, pero la integración final siempre debe pasar por validaciones manuales o automáticas. Esto reduce errores en producción y mejora la colaboración del equipo al hacer visible cada cambio.

## Ejemplo (no ejecutado automáticamente)
Comandos para crear una rama, realizar cambios y preparar un merge request simulado con revisión de código.

```bash
git checkout -b feature/nueva-login
npm test
git add .
git commit -m 'Añadir validación de email'
```

## Ejercicio
Crea una rama llamada 'fix/boton-rojo', realiza un cambio en el archivo README.md y ejecuta 'git push origin fix/boton-rojo'. Simula la creación de un MR describiendo el propósito del cambio.

## Criterios de revisión
El usuario debe crear correctamente la rama, empujarla al remoto y redactar una descripción clara para el merge request que explique qué se modificó y por qué.

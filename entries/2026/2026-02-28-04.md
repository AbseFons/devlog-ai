## Objetivo
Aplicar el principio de separación de responsabilidades dividiendo la lógica de negocio de la persistencia para mejorar la mantenibilidad y facilitar las pruebas unitarias del sistema.

## Explicación
En este diseño, la clase principal se encarga exclusivamente de orquestar la lógica de negocio, mientras que una interfaz abstracta define el contrato para acceder a datos. Una implementación concreta, como un repositorio en memoria o una conexión a base de datos, satisface ese contrato. Esta estructura evita acoplar dependencias externas directamente en la lógica principal, permitiendo sustituir fácilmente la fuente de datos durante las pruebas sin modificar el código de negocio. Al mantener estas preocupaciones separadas, el sistema se vuelve más modular, escalable y fácil de depurar cuando surgen problemas específicos de persistencia.

## Ejemplo (no ejecutado automáticamente)
Un servicio que calcula un total de pedido delegando la carga de productos a un repositorio genérico.

```java
public class PedidoService {
    private RepositorioProducto repositorio;

    public double calcularTotal() {
        return repositorio.obtenerPrecios().stream().mapToDouble(Double::doubleValue).sum();
    }
}
```

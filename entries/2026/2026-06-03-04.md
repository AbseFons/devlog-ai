## Objetivo
Aprender a utilizar el comando git bisect para identificar eficientemente el commit exacto que introdujo una regresión en el código, ahorrando tiempo frente a búsquedas manuales.

## Explicación
El comando git bisect es una herramienta poderosa de Git diseñada para encontrar rápidamente el cambio específico que causó un error. Funciona bajo el principio de la búsqueda binaria: comparas versiones antiguas y nuevas del repositorio hasta aislar el commit problemático. Primero, marcas el estado actual como 'bad' (conocido defectuoso) y seleccionas un commit anterior conocido como 'good' (funcionaba correctamente). Git luego intercala automáticamente una serie de commits intermedios para su revisión. Tú solo debes ejecutar la prueba correspondiente en cada punto intermedio que Git te presente, marcándolo como 'bad' o 'good'. Al finalizar el proceso, Git mostrará el commit exacto donde se introdujo el fallo, facilitando la corrección precisa.

## Ejemplo (no ejecutado automáticamente)
Se ejecuta un script de bash para marcar commits como buenos y malos, iniciando la bisect. El usuario debe probar cada commit intermedio manualmente.

```bash
# Marcar el commit actual como malo
git bisect bad
# Marcar un commit antiguo conocido como bueno
git bisect good <hash-commit-bueno>
# Git seleccionará el siguiente commit para probar
```

## Ejercicio
En un repositorio de ejemplo, marca el HEAD como 'bad' y el commit inicial del proyecto como 'good'. Ejecuta git bisect y prueba los commits intermedios hasta que Git identifique el culpable.

## Criterios de revisión
El usuario debe completar correctamente al menos tres iteraciones de bisect, marcando cada estado con precisión y ejecutando el comando final para mostrar el commit problemático.

## Objetivo
Aprender a usar el reflog para recuperar commits eliminados accidentalmente mediante reset o revert, entendiendo que este registro local protege contra la pérdida de historia en repositorios compartidos.

## Explicación
El comando git reflog muestra un historial cronológico de las referencias locales del HEAD. A diferencia del log normal, registra cada cambio de posición del puntero principal, incluso si se eliminó el commit resultante con 'git reset' o 'git revert'. Esto es vital para recuperar estados perdidos sin afectar la historia pública. Al ejecutar git reflog, verás entradas como 'HEAD@{1}' que indican posiciones anteriores. Puedes restaurar un estado específico usando 'git reset --hard HEAD@{n}'. Este mecanismo actúa como una red de seguridad local, permitiendo deshacer errores graves antes de empujar cambios a servidores remotos. Es fundamental revisar el reflog antes de ejecutar operaciones destructivas para evitar pérdidas de datos irreversibles.

## Ejemplo (no ejecutado automáticamente)
Se muestra cómo recuperar un commit borrado accidentalmente usando la referencia relativa del reflog.

```bash
git reflog
HEAD@{1}~2: revert commit error
HEAD@{1}: reset --hard HEAD^
```

## Criterios de revisión
El usuario debe identificar correctamente al menos tres entradas en el reflog y ejecutar un comando de recuperación exitoso sin perder datos adicionales.

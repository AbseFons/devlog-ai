## Objetivo
Comprender cómo configurar roles básicos y asignar permisos específicos a usuarios mediante listas de control de acceso para proteger recursos críticos en una aplicación web.

## Explicación
El Control de Acceso Basado en Roles (RBAC) es un modelo fundamental para gestionar quién puede hacer qué dentro de un sistema. En esta microlección, exploraremos la implementación práctica utilizando listas de control de acceso (ACL). Estas listas permiten definir reglas explícitas que restringen el acceso a recursos sensibles como archivos de configuración o bases de datos. Al asignar roles predefinidos como 'lector' o 'editor', simplificamos la administración y reducimos errores humanos. Es crucial evitar permisos excesivos; aplicar el principio de menor privilegio garantiza que, incluso si una credencial es comprometida, el daño potencial sea limitado. Este enfoque estructurado mejora la postura de seguridad general sin complicar innecesariamente el flujo de trabajo diario del equipo de desarrollo.

## Ejemplo (no ejecutado automáticamente)
Definición de roles y asignación de permisos de lectura/escritura a un archivo de configuración usando ACLs en Linux.

```bash
# Definir el grupo 'admin' y añadir al usuario 'dev1'
groupadd admin && usermod -aG admin dev1
# Asignar permisos de lectura para todos y escritura solo al grupo admin
chmod 750 /etc/app/config.yml
chown root:admin /etc/app/config.yml
```

## Ejercicio
Crea un script que defina un nuevo grupo 'analistas', añada dos usuarios existentes a este grupo y asigne permisos de solo lectura (444) a un archivo de reporte en la carpeta '/reports/2026/'.

## Criterios de revisión
El script debe ejecutar correctamente los comandos groupadd, usermod y chmod/chown sin errores. Los permisos finales del archivo deben ser exactamente 444 y el propietario/root grupo debe ser 'analistas'. No se permiten credenciales hardcoded ni comandos que modifiquen archivos de sistema críticos.

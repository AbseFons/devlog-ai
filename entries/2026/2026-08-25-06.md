## Objetivo
Al finalizar esta lección, el desarrollador será capaz de diseñar un sistema donde las cuentas de servicio tengan solo los permisos estrictamente necesarios para una tarea específica, reduciendo la superficie de ataque y cumpliendo con políticas de seguridad modernas sin comprometer la funcionalidad operativa.

## Explicación
El principio de mínimo privilegio exige que cada entidad de software o usuario posea únicamente las autorizaciones mínimas requeridas para su función. En entornos de producción, esto significa evitar cuentas administrativas globales para procesos automatizados. Al otorgar permisos excesivos, un compromiso de credenciales permite al atacante controlar todo el sistema. La implementación correcta implica definir roles granulares y auditar periódicamente las asignaciones. Este enfoque limita el daño potencial en caso de brecha, ya que la entidad comprometida no podrá escalar privilegios ni acceder a datos sensibles fuera de su ámbito operativo definido.

## Ejemplo (no ejecutado automáticamente)
```python
import os
from pathlib import Path

def crear_usuario_servicio():
    """Crea un usuario con permisos limitados solo al directorio de logs."""
    # Evita usar 'sudo' o grupos administrativos para procesos de lectura.
    # El usuario solo puede leer archivos dentro de /var/log/app/
    
    ruta_logs = Path('/var/log/app')
    usuario_servicio = 'app_reader'
    
    # Simulación de asignación de permisos en un sistema real
    # En Linux, esto se haría con chmod/chown o scripts de IAM
    permisos_lectura = 0o444  # Solo lectura para todos
    
    if ruta_logs.exists():
        os.chmod(ruta_logs, permisos_lectura)
        print(f'Usuario {usuario_servicio} tiene acceso de solo lectura a {ruta_logs}')
    else:
        raise FileNotFoundError(f'Directorio no encontrado: {ruta_logs}')

if __name__ == '__main__':
    crear_usuario_servicio()
```

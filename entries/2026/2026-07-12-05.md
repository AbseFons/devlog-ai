## Objetivo
Aprender a identificar y resolver conflictos de merge mediante la inspección directa de archivos, preservando cambios locales y remotos sin sobrescribir datos críticos.

## Explicación
Cuando Git detecta un conflicto durante una fusión o actualización, marca las líneas afectadas con marcadores '<<<<<<<', '=======', y '>>>>>>>'. El objetivo es editar el archivo para mantener la lógica de ambas versiones. Primero, analiza qué cambio aporta cada rama: ¿es una corrección de bug local o una nueva funcionalidad remota? Elimina los marcadores y escribe manualmente el código resultante que integre ambas intenciones. Guarda el archivo y ejecuta 'git add' para marcarlo como resuelto. Finalmente, completa la fusión con 'git commit'. Esta práctica manual es esencial cuando las herramientas automáticas no pueden determinar la intención del desarrollador.

1. Crea dos ramas en tu repositorio local: 'feature-a' y 'feature-b'.

3. En 'feature-b', cambia el nombre de la variable 'total' a 'montoFinal' sin alterar la lógica.
4. Haz merge de ambas ramas y resuelve el conflicto manualmente siguiendo los pasos explicados.

## Criterios de revisión
El archivo debe contener la función con el parámetro de impuesto y la variable renombrada a 'montoFinal', sin marcadores de conflicto visibles, y el comando git add debe haber sido ejecutado exitosamente.

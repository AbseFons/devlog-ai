## Objetivo
Aprender a identificar vulnerabilidades conocidas (CVE) en las librerías de un proyecto utilizando herramientas automatizadas para mitigar riesgos de seguridad antes del despliegue.

## Explicación
Las dependencias de terceros son una fuente común de vulnerabilidades. Herramientas como OWASP Dependency-Check analizan el árbol de dependencias de tu aplicación comparando las versiones instaladas con bases de datos de CVE públicas. Este proceso genera un informe detallado que clasifica los hallazgos por severidad. Es crucial integrar estas escaneos en la pipeline de CI/CD para bloquear despliegues que contengan vulnerabilidades críticas o altas. No se deben ignorar las advertencias; cada CVE representa una puerta trasera potencial para atacantes. La gestión proactiva del ciclo de vida de las dependencias es fundamental para mantener la integridad del software.

## Ejemplo (no ejecutado automáticamente)
Ejecución de Dependency-Check en un proyecto Java para generar un informe XML con vulnerabilidades detectadas.

```bash
dependency-check.sh --scan ./src/main/java --format XML
mv dependency-check-report.xml report_vulnerabilidades.xml
```

## Ejercicio
Ejecuta el comando de escaneo en un proyecto real o de prueba. Revisa el archivo generado y documenta al menos dos vulnerabilidades encontradas, describiendo su impacto potencial y la acción correctiva sugerida (actualización de versión o parche).

## Criterios de revisión
El informe debe estar generado correctamente en formato XML. Se identifican explícitamente dos CVEs con su número de referencia. Se propone una solución técnica viable para cada hallazgo sin comprometer la funcionalidad del sistema.

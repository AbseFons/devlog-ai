## Objetivo
Aprender a utilizar códigos HTTP apropiados para comunicar estados de error específicos, mejorando la legibilidad y facilitando el manejo de excepciones por parte del cliente.

## Explicación
El diseño robusto de una API comienza definiendo correctamente los códigos de estado. No basta con devolver un 500 genérico; es crucial distinguir entre errores de validación (400), no autorizados (401/403) o recursos inexistentes (404). Una respuesta bien estructurada debe incluir un cuerpo JSON que detalle el motivo del fallo y, si es posible, una pista sobre cómo corregirlo. Esto permite a los desarrolladores frontend construir interfaces de usuario más inteligentes que informen al usuario final con claridad en lugar de mostrar mensajes crípticos.

## Ejemplo (no ejecutado automáticamente)
Respuesta JSON detallada para un error de validación de campo requerido ausente.

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "El campo 'email' es obligatorio y debe ser válido."
  }
}
```

## Ejercicio
Crea un endpoint que intente guardar un usuario sin email y devuelva un objeto JSON con el código de error específico y un mensaje descriptivo en español.

## Criterios de revisión
La respuesta debe tener un estado HTTP 400, incluir una clave 'error' con subclaves 'code' y 'message', y evitar mensajes genéricos como 'Algo salió mal'.

## Objetivo
Comprender el propósito de los códigos de respuesta HTTP en la serie 1xx, conocidos como indicadores de procesamiento, y su rol en la comunicación asíncrona entre clientes y servidores.

## Explicación
Los códigos de respuesta HTTP comienzan con '1' para indicar que la solicitud ha sido recibida y está siendo procesada, pero aún no se ha completado. Estos códigos son temporales y rara vez llegan al cliente final en peticiones estándar sincrónicas, ya que el servidor suele esperar a enviar un código 2xx o 3xx antes de finalizar la conexión. Sin embargo, son fundamentales en escenarios asíncronos como WebSockets o peticiones largas donde el servidor necesita informar al cliente del estado intermedio sin cerrar la comunicación prematuramente. Conocerlos ayuda a diseñar sistemas más robustos que manejen correctamente las pausas en el procesamiento.

## Ejemplo (no ejecutado automáticamente)
Un script de Python que simula una solicitud asíncrona y muestra cómo un servidor podría devolver un código 102 (Procesando) antes de finalizar la operación, ilustrando el uso real de estos códigos en monitoreo interno.

```python
import time
from http.server import BaseHTTPRequestHandler, HTTPServer
class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(102)
        self.end_headers()
        self.wfile.write(b'Procesando solicitud...')
HTTPServer(('localhost', 8000), Handler).serve_forever()
```

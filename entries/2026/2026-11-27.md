## Objetivo
Implementar una estrategia segura para la rotación continua de credenciales en entornos Kubernetes, minimizando la exposición de datos sensibles y automatizando el proceso sin intervención manual.

## Explicación
En lugar de almacenar secretos estáticos en archivos o variables de entorno, esta lección propone integrar Vault Agent Sidecar. Este componente se ejecuta junto a la aplicación objetivo dentro del contenedor. Su función es solicitar tokens cortos (TTL) directamente al servidor Vault, descifrarlos y entregarlos a la aplicación mediante sockets seguros o volúmenes temporales. Al expirar el token, Vault Agent lo renueva automáticamente antes de que caduque, garantizando que la aplicación siempre opere con credenciales vigentes. Este enfoque elimina la necesidad de actualizar manualmente los secrets en el clúster y reduce drásticamente la ventana de riesgo si una clave es comprometida.

## Ejemplo (no ejecutado automáticamente)
Configuración de un sidecar Vault Agent en un Deployment de Kubernetes que rota credenciales cada hora usando tokens cortos.

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: secure-app
spec:
  template:
    spec:
      containers:
      - name: vault-agent
        image: hashicorp/vault-agent:latest
```

## Ejercicio
Crea un archivo de manifest YAML para un Deployment que incluya un contenedor Vault Agent Sidecar configurado para inyectar secretos en un volumen mount específico.

## Criterios de revisión
El manifest debe definir correctamente el lado del agente, especificar la dirección del servidor Vault y configurar el TTL del token corto. Verifica que no haya credenciales hardcoded y que el mecanismo de renovación esté habilitado.

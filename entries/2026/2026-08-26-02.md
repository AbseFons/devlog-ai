## Objetivo
Al finalizar esta lección, el desarrollador implementará un script que inyecta credenciales efímeras desde un almacén seguro directamente al entorno de ejecución del pipeline, eliminando la persistencia de claves estáticas en los registros y garantizando que cada compilación utilice un token único con tiempo de vida limitado.

## Explicación
La gestión manual de secretos en pipelines CI/CD es una fuente crítica de vulnerabilidad. Las credenciales almacenadas como variables de entorno globales o en archivos de configuración son accesibles para cualquier proceso que lea los registros del servidor, comprometiendo la integridad del despliegue. La solución reside en la rotación automática: solicitar un token nuevo al inicio de cada ejecución y asegurarse de que expire antes de finalizar el pipeline. Esto minimiza la ventana de oportunidad para un atacante que haya filtrado logs. En esta microlección aprenderás a estructurar una función que interactúe con un servicio de gestión de secretos, obtenga credenciales temporales y las utilice para autenticar en un repositorio remoto o iniciar un contenedor, asegurando que no queden rastros en el sistema de archivos ni en la memoria persistente tras la terminación del proceso.

## Ejemplo (no ejecutado automáticamente)
```python
import os
import subprocess

def obtener_secreto_temporal():
    # Simulación de llamada a API de gestión de secretos (ej. Vault o AWS Secrets Manager)
    # En producción, esto se reemplaza con la llamada real al proveedor.
    response = subprocess.run(['curl', '-s', 'https://vault.internal/api/v1/secret/data/prod/db-creds'], capture_output=True, text=True)
    if response.returncode != 0:
        raise Exception("Fallo al obtener secretos")
    
    # Extraer credenciales del JSON de respuesta
    import json
    data = json.loads(response.stdout)
    username = data['data']['username']
    password = data['data']['password']
    token_expiration = data['data']['ttl_seconds']
    
    return username, password, token_expiration

def ejecutar_pipeline_con_secretos():
    # Obtener credenciales efímeras
    user, pwd, ttl = obtener_secreto_temporal()
    print(f"Credenciales obtenidas. Válido por {ttl} segundos.")
    
    try:
        # Ejecutar el comando del pipeline usando las credenciales en memoria
        # Nota: No guardar estas variables en un archivo ni imprimir la contraseña completa
        env = os.environ.copy()
        env['DB_USER'] = user
        env['DB_PASS'] = pwd  # Solo se usa para inyectar, no persiste fuera de este scope
        
        # Ejemplo de comando seguro: clonar repo o ejecutar deploy
        subprocess.run(['git', 'clone', '--depth=1', 'https://${env["DB_USER"]}:${env["DB_PASS"]}@github.com/org/proyecto.git'], check=True)
        print("Pipeline completado con éxito.")
    finally:
        # Limpieza implícita al salir del scope, pero en producción se recomienda revocar explícitamente
        pass

if __name__ == "__main__":
    ejecutar_pipeline_con_secretos()
```

## Criterios de revisión
1. El código debe leer las variables de entorno sin hardcodear valores sensibles.
2. Debe imprimir un mensaje de advertencia si el token se mantiene más allá del tiempo simulado.
3. No debe haber ninguna instancia del token visible en la salida después de los 5 segundos.
4. El script debe fallar con un código de error distinto a cero si falta alguna variable de entorno requerida.

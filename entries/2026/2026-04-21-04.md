## Objetivo
Aprender a cancelar peticiones asíncronas en JavaScript utilizando AbortController para evitar bloqueos de UI y ahorrar recursos cuando el usuario abandona una página o cambia de tarea antes de que la respuesta llegue.

## Explicación
En aplicaciones modernas, las peticiones asíncronas pueden colgar si el usuario navega lejos. La solución nativa es AbortController. Al crear una instancia y pasar su señal al segundo argumento de fetch, cualquier llamada a controller.abort() detendrá inmediatamente la petición. Esto lanza un error específico que debe atraparse con try/catch para limpiar estados de carga o mostrar mensajes amigables. Es fundamental verificar si el error tiene la propiedad name igual a 'AbortError' antes de tratarlo como fallo de red. Este patrón mejora la experiencia del usuario al responder rápidamente a sus acciones, evitando esperas innecesarias y liberando memoria del navegador.

## Ejemplo (no ejecutado automáticamente)
Se muestra cómo iniciar una petición a una API pública de usuarios y cancelarla tras un segundo simulado para demostrar el control manual del flujo.

```javascript
const controller = new AbortController();
fetch('https://jsonplaceholder.typicode.com/users/1', { signal: controller.signal })
```

## Ejercicio
Crea una función que llame a una API de clima. Dentro, establece un temporizador que llame a controller.abort() después de 3 segundos. En el bloque catch, verifica si el error es un AbortError y muestra 'Cancelado por usuario', o maneja otros errores como fallos de red.

## Criterios de revisión
El código debe importar o instanciar correctamente AbortController, pasar la señal a fetch, lanzar abort() desde un setTimeout y diferenciar en el catch entre AbortError y otros errores.

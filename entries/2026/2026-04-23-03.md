## Objetivo
Establecer una convención clara para organizar el árbol de archivos en un nuevo repositorio, separando código fuente, configuración y documentación para facilitar la navegación y el mantenimiento del proyecto a largo plazo.

## Explicación
Un diseño de repositorio sólido comienza definiendo carpetas lógicas desde el primer commit. Se recomienda crear una raiz con subdirectorios como 'src' o 'lib' para el código fuente, 'config' para archivos de entorno y 'docs' para la documentación. Es crucial mantener un archivo '.gitignore' en la raiz inmediatamente para excluir nodulos de dependencias, logs y archivos temporales del historial. Esta estructura inicial previene la proliferación de archivos sueltos en la raiz, lo que dificulta el trabajo en equipo. Al normalizar esta arquitectura desde el inicio, se reduce la fricción al integrar nuevos desarrolladores y se asegura que el historial de commits refleje cambios semánticos claros sin ruido de archivos irrelevantes.

## Ejemplo (no ejecutado automáticamente)
Inicialización de un repositorio con estructura de carpetas estandarizada y archivo .gitignore configurado para excluir dependencias.

```bash
mkdir -p my-project/{src,config,docs}
cd my-project
git init
echo 'node_modules/' > .gitignore
```

## Ejercicio
Crea un repositorio local llamado 'api-gateway'. Dentro de la raiz, genera las carpetas 'controllers', 'models' y 'tests'. Luego, crea un archivo '.env.example' en la raiz y añade una regla a '.gitignore' que ignore todos los archivos que comiencen con '.'.

## Criterios de revisión
El repositorio debe tener al menos tres subdirectorios funcionales en la raiz. El archivo .gitignore debe existir y contener al menos dos patrones de exclusión válidos, incluyendo uno para archivos ocultos.

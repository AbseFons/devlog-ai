## Objetivo
Aprender a configurar contenedores de dependencias para manejar versiones múltiples y evitar conflictos en aplicaciones complejas, mejorando la mantenibilidad del código.

## Explicación
En esta lección avanzamos más allá de la inyección básica. Exploraremos cómo definir contenedores de dependencias con configuraciones específicas para diferentes entornos. Esto permite aislar versiones de librerías críticas sin afectar al resto del sistema. La clave reside en declarar las dependencias explícitamente en el archivo de configuración, especificando su versión exacta y el tipo de inyección requerida. Al hacerlo, garantizamos que cada módulo reciba exactamente lo que necesita, reduciendo drásticamente los errores de 'dependencia rota'. Este enfoque es esencial para arquitecturas modulares donde distintos servicios requieren versiones distintas de la misma librería base.

## Ejemplo (no ejecutado automáticamente)
Definición de un contenedor de dependencias con múltiples versiones aisladas para un servicio de autenticación y otro de reportes.

```typescript
import { Container } from 'dependency-injection';

const container = new Container();
container.register('auth', () => require('jsonwebtoken').v5);
container.register('reports', () => require('chart.js').v4);
```

## Ejercicio
Crea un contenedor que registre dos versiones diferentes de la librería 'axios' (una para llamadas internas y otra para externas) y verifica que se inyecten correctamente en sus respectivos servicios.

## Criterios de revisión
El código debe registrar al menos dos versiones distintas de una misma dependencia, usar el registro dinámico del contenedor y demostrar la inyección correcta en dos servicios diferentes.

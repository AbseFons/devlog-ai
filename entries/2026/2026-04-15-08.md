## Objetivo
Comprender la distinción fundamental entre autenticación (quién eres) y autorización (qué puedes hacer) al diseñar endpoints seguros, evitando confusiones comunes en el desarrollo de microservicios modernos.

## Explicación
En las arquitecturas de API, la autenticación verifica la identidad del usuario mediante tokens como JWT o sesiones, respondiendo a '¿Quién eres?'. La autorización, por otro lado, utiliza esa identidad para consultar políticas de acceso (RBAC) y determinar permisos específicos, respondiendo a '¿Qué puedes hacer?'. Un error frecuente es confundir ambos conceptos: autenticarse no implica tener acceso total. Por ejemplo, un usuario logueado puede autenticarse correctamente pero ser denegado al intentar acceder a una ruta administrativa si carece del rol adecuado. Implementar middleware que separe estas lógicas asegura que la validación de identidad ocurra primero, seguida de la evaluación de permisos antes de procesar la solicitud.

## Ejemplo (no ejecutado automáticamente)
Middleware en Node.js que separa la lógica de verificación del token (autenticación) de la consulta a la base de datos de roles (autorización).

```javascript
const verificarToken = async (req, res, next) => {
  const usuario = await validarJWT(req.headers.authorization);
  if (!usuario) return res.status(401).json({ msg: 'No autenticado' });
  req.usuario = usuario;
};

const verificarRol = async (req, res, next) => {
  const { rolRequerido } = req.params;
  if (req.usuario.rol !== rolRequerido) return res.status(403).json({ msg: 'No autorizado' });
  next();
};
```

## Ejercicio
Crea un endpoint '/api/datos-publicos' que solo requiera autenticación y otro '/api/admin/configuracion' que exija tanto autenticación como autorización con rol 'admin'.

## Criterios de revisión
El código debe implementar dos funciones middleware distintas. La primera valida el token sin consultar roles. La segunda verifica explícitamente el rol del usuario antes de delegar a la siguiente función. Ambos deben devolver códigos HTTP 401 y 403 respectivamente en caso de fallo.

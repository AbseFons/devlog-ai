## Objetivo
Comprender la diferencia entre cobertura de código y límites funcionales, aprendiendo a diseñar casos de prueba que validen no solo el flujo normal sino también los bordes críticos del sistema para prevenir fallos en producción.

## Explicación
La cobertura de código mide qué porcentaje del código fuente se ejecuta durante las pruebas, pero una alta cobertura no garantiza la calidad si no se prueban los límites. Los límites son valores extremos o condiciones borde que a menudo rompen el sistema. Por ejemplo, enviar un array vacío cuando se espera uno con elementos, o ingresar caracteres especiales en un campo de texto. Un buen plan de testing incluye casos para entradas vacías, máximas y mínimas aceptadas, así como tipos de datos inesperados. Esto asegura robustez frente a errores de usuario o integraciones externas fallidas.

## Ejemplo (no ejecutado automáticamente)
Función que valida un número de teléfono verificando límites de longitud y formato básico.

```javascript
function validarTelefono(numero) {
  const regex = /^\d{10}$/;
  return numero.length === 10 && regex.test(numero);
}
console.log(validarTelefono('1234567890')); // true
console.log(validarTelefono('123456789')); // false
```

## Ejercicio
Crea una función que acepte un string de email y devuelva true si tiene exactamente un '@' y al menos tres caracteres antes y después de él.

## Criterios de revisión
La función debe devolver false para emails con múltiples '@', sin '@', o con menos de tres caracteres en las secciones local y dominio.

## Objetivo
Comprender la organización lógica de un repositorio Git, diferenciando entre el directorio raíz, las carpetas de trabajo, .git y los archivos de configuración esenciales para iniciar un proyecto.

## Explicación
Un repositorio Git no es solo una carpeta con código; es una estructura jerárquica específica. Al inicializar un repositorio con 'git init', se crea instantáneamente el directorio oculto '.git', que actúa como base de datos interna conteniendo todos los objetos, referencias y metadatos necesarios para la historia del proyecto. Este directorio debe permanecer intacto y nunca ser modificado manualmente por el usuario. El resto del árbol de directorios representa el área de trabajo, donde se desarrollan las versiones actuales del código. Es fundamental distinguir entre archivos rastreados (en el repositorio) y no rastreados (como 'node_modules' o '.env'). La comprensión de esta separación es vital para evitar fugas de información sensible y mantener la integridad del historial de commits.

## Ejemplo (no ejecutado automáticamente)
Inicialización de un repositorio Git con estructura básica y creación de archivos de configuración estándar.

```bash
# Crear directorio del proyecto
mkdir mi-proyecto
cd mi-proyecto
# Inicializar el repositorio (crea .git)
git init
# Crear archivo README.md en la raíz
echo '# Mi Proyecto' > README.md
# Crear carpeta de trabajo
dir src
# Crear archivo de configuración .gitignore
echo 'node_modules/' > .gitignore
```

## Ejercicio
Crea un repositorio Git llamado 'backend-api'. Dentro, genera una carpeta llamada 'controllers' y otro archivo llamado '.env.example'. Asegúrate de que el directorio oculto '.git' exista sin abrirlo manualmente.

## Criterios de revisión
El directorio raíz debe contener al menos dos archivos visibles (ej. README.md) y un archivo .gitignore. El directorio oculto '.git' debe estar presente. No deben existir carpetas con nombres que comiencen por puntos excepto '.git'. El comando 'ls -la' debe mostrar la estructura correcta.

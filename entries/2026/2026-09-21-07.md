## Objetivo
Comprender cómo utilizar consultas parametrizadas para evitar que entradas de usuario maliciosas alteren la lógica de la base de datos y comprometan la integridad de los datos almacenados.

## Explicación
La inyección SQL ocurre cuando se concatenan directamente las entradas del usuario en una consulta, permitiendo a un atacante modificar el comportamiento del motor de base de datos. La solución robusta consiste en usar consultas parametrizadas o prepared statements. Estas técnicas separan la estructura de la consulta de los datos, obligando al motor de base de datos a tratar cualquier entrada como literal y no como código ejecutable. Por ejemplo, en Python con SQLAlchemy, el método execute() acepta un diccionario de parámetros que se vinculan automáticamente a los marcadores de posición en la consulta SQL, bloqueando intentos de inyección incluso si el usuario intenta cerrar comillas o insertar comentarios maliciosos.

## Ejemplo (no ejecutado automáticamente)
Consulta parametrizada segura para autenticación de usuarios utilizando Python y SQLAlchemy.

```python
from sqlalchemy import create_engine, text

engine = create_engine('sqlite:///users.db')
with engine.connect() as conn:
    stmt = text("SELECT * FROM users WHERE username = :username AND password_hash = :password")
    result = conn.execute(stmt, {'username': 'admin', 'password_hash': 'secure_hash'})
```

## Ejercicio
Crea una función en Python que acepte un nombre de usuario y una contraseña. Utiliza una consulta parametrizada para verificar si el usuario existe en la base de datos. Asegúrate de que, si el usuario intenta inyectar código SQL mediante comillas o comentarios, la consulta falle sin revelar información del esquema.

## Criterios de revisión
El código debe utilizar explícitamente marcadores de posición (:param) y no concatenar cadenas con inputs del usuario. Debe manejar excepciones de conexión y evitar errores de sintaxis que expongan detalles internos de la base de datos.

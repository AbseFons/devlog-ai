## Objetivo
Comprender que una clase debe tener un solo motivo para cambiar, evitando la complejidad innecesaria y facilitando el mantenimiento del código al separar responsabilidades lógicas.

## Explicación
El principio de Responsabilidad Única establece que cada clase debe encargar exactamente una tarea. Cuando mezclamos lógica de negocio con persistencia o validación en un solo módulo, cualquier cambio afecta todo el sistema. Por ejemplo, si una clase maneja tanto la creación de usuarios como el envío de correos, un fallo en el servidor de correo podría romper la funcionalidad principal. Separar estas responsabilidades permite que cada parte evolucione independientemente. Esto reduce los efectos secundarios no deseados y hace que las pruebas unitarias sean más sencillas y precisas.

## Ejemplo (no ejecutado automáticamente)
Clase separada para validar usuarios y otra para persistir datos, demostrando la división de responsabilidades en un sistema de registro.

```javascript
class ValidadorUsuario {
  validar(email) { return email.includes('@'); }
}
class RepositorioUsuarios {
  guardar(usuario) { console.log('Guardado: ' + usuario); }
```

## Ejercicio
Crea una clase 'Calculadora' que sume dos números y otra clase 'Logger' que registre la operación realizada. Luego, modifica el código para que la calculadora no contenga lógica de registro.

## Criterios de revisión
El código debe tener al menos dos clases distintas sin dependencias entre ellas. Debe existir una función de validación o separación clara de responsabilidades en cada clase.

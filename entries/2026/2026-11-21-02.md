## Objetivo
Aprender a dividir la lógica de negocio de validación de entrada de usuario en una clase separada, mejorando la mantenibilidad y permitiendo reutilizar reglas de validación sin contaminar la lógica principal del controlador.

## Explicación
En esta microlección exploramos cómo aplicar el principio de separación de responsabilidades al validar datos de entrada. En lugar de mezclar reglas de negocio con la lógica del controlador, creamos una clase dedicada a la validación. Esto permite que cada regla sea testeable por separado y fácil de actualizar. Al encapsular la lógica en un objeto específico, evitamos errores comunes como duplicar código o romper funcionalidades existentes al modificar una sola condición. Este enfoque promueve arquitecturas limpias donde cada componente tiene un propósito claro y único.

## Ejemplo (no ejecutado automáticamente)
Clase de validación que verifica si un correo electrónico tiene formato correcto antes de procesarlo en el controlador principal.

```javascript
class EmailValidator {
  static isValid(email) {
    const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
    return pattern.test(email);
  }
}
```

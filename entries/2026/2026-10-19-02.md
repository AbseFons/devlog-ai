## Objetivo
Al finalizar, el desarrollador podrá diferenciar el uso de restricciones CHECK para rangos numéricos o lógicos y UNIQUE para claves naturales, aplicándolas correctamente en tablas de negocio sin violar la integridad referencial.

## Explicación
Las restricciones SQL aseguran la calidad de los datos. La cláusula UNIQUE garantiza que ninguna columna o conjunto de columnas contenga valores duplicados, ideal para identificadores como códigos de producto o correos electrónicos. Por otro lado, CHECK valida que los datos cumplan una condición específica, como asegurar que un precio sea positivo o que un estado esté en una lista permitida. Ambas se definen al crear la tabla o mediante ALTER TABLE. Es crucial entender que UNIQUE permite un solo valor NULL, mientras que CHECK puede combinarse con otras restricciones para crear modelos de datos robustos y libres de errores lógicos antes de que lleguen a la capa de aplicación.

## Ejemplo (no ejecutado automáticamente)
```sql
CREATE TABLE productos (
    id INT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL UNIQUE,
    precio DECIMAL(10, 2) CHECK (precio > 0),
    stock INT CHECK (stock >= 0)
);

INSERT INTO productos (id, nombre, precio, stock)
VALUES (1, 'Laptop', 999.99, 50);

-- Esto fallará: duplica el nombre 'Laptop'
-- INSERT INTO productos VALUES (2, 'Laptop', 800.00, 30);

-- Esto fallará: precio negativo
-- INSERT INTO productos VALUES (3, 'Mouse', -10.00, 100);
```

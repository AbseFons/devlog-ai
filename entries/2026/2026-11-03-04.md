## Objetivo
Comprender cómo diseñar endpoints idempotentes para garantizar que múltiples solicitudes idénticas produzcan el mismo efecto, incluso ante fallos de red o reintentos automáticos, evitando duplicidad de datos.

## Explicación
La idempotencia asegura que una operación no se repita accidentalmente. En APIs REST, los métodos POST y PUT pueden ser idempotentes si implementan lógica específica. Un patrón común es usar un encabezado 'Idempotency-Key'. El servidor almacena esta clave con el resultado de la última ejecución exitosa. Si recibe otra solicitud con la misma clave, devuelve inmediatamente el resultado guardado sin procesar la operación nuevamente. Esto protege contra duplicación de pagos o creación múltiple de registros por fallos de red.

## Ejemplo (no ejecutado automáticamente)
Implementación en Node.js que valida una clave idempotente antes de procesar una transacción de pago simulada, devolviendo el estado anterior si la clave ya existe.

```javascript
const key = req.headers['idempotency-key'];
if (key && idempotencyStore.has(key)) return res.json({ status: 'completed', data: idempotencyStore.get(key) });
```

## Ejercicio
Crea un endpoint POST /transferir que acepte un encabezado X-Idempotency-Key. Implementa una memoria (Map o base de datos simple) para guardar la clave con el resultado tras un éxito. Si llega otra petición con la misma clave, responde con el mismo JSON sin ejecutar la lógica de transferencia nuevamente.

## Criterios de revisión
El endpoint debe devolver el mismo estado HTTP y cuerpo JSON para solicitudes repetidas con la misma clave. No debe generar errores ni duplicar registros en la base de datos simulada.

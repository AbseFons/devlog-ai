## Objetivo
Comprender el significado de los códigos de estado HTTP que comienzan con 2, esenciales para confirmar la recepción correcta de solicitudes y el éxito del procesamiento de datos en aplicaciones web modernas.

## Explicación
Los códigos 2xx indican que la solicitud fue recibida, entendida y procesada exitosamente. El más común es el 200 OK, que confirma una respuesta estándar tras una petición válida. El 201 Created se utiliza cuando un recurso nuevo ha sido generado como resultado de una acción del cliente, típico en POSTs exitosos. Por otro lado, el 202 Accepted significa que la solicitud fue aceptada para procesamiento, pero no necesariamente completada aún, útil en tareas asíncronas. Finalmente, el 204 No Content confirma que la acción se realizó sin necesidad de devolver un cuerpo de respuesta, común en operaciones de borrado o actualización silenciosa. Dominar estos códigos permite depurar flujos de datos y construir interfaces más robustas.

## Ejemplo (no ejecutado automáticamente)
Solicitud POST a una API que crea un usuario y devuelve el código 201 con los detalles del recurso creado.

```javascript
fetch('https://api.ejemplo.com/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana' })
}).then(res => {
  if (res.status === 201) return res.json();
})
```

## Ejercicio
Crea una petición GET a una API pública de clima y verifica que la respuesta tenga el código 200. Luego, intenta enviar un POST con datos inválidos y confirma que recibas un error 400.

## Criterios de revisión
Identificar correctamente qué significa cada código 2xx. Diferenciar entre creación inmediata (201) y aceptación asíncrona (202). Reconocer cuándo una respuesta vacía es válida (204).

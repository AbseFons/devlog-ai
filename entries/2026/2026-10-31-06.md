## Objetivo
Comprender cómo estructurar una aplicación separando la lógica de negocio de la persistencia de datos para mejorar el mantenimiento, la escalabilidad y la seguridad del sistema.

## Explicación
En esta microlección exploramos la arquitectura por capas, enfocándonos en la separación estricta entre el modelo de datos y la lógica de aplicación. Al encapsular las operaciones de acceso a base de datos dentro de una capa dedicada (Data Access Layer), evitamos que las consultas SQL contaminen el código de negocio. Esto permite cambiar el motor de persistencia sin alterar la lógica principal. Además, facilita las pruebas unitarias al poder inyectar repositorios falsos. La clave reside en definir interfaces claras entre capas, asegurando que cada una tenga responsabilidades únicas y bien delimitadas.

## Ejemplo (no ejecutado automáticamente)
Implementación de un servicio de usuario que utiliza un repositorio para guardar datos sin exponer la lógica de base de datos al controlador.

```javascript
class UserRepository {
  async save(user) { await db.users.insertOne(user); }
}
class UserService {
  constructor(repo) { this.repo = repo; }
  async register(userData) { return this.repo.save(userData); }
}
```

## Ejercicio
Crea una clase 'OrderService' que reciba un objeto 'OrderRepository' en su constructor. Implementa el método 'createOrder' para guardar un pedido, asegurando que no haya referencias directas a la base de datos dentro del servicio.

## Criterios de revisión
El código debe mostrar inyección de dependencias clara, encapsulamiento de consultas SQL y ausencia de lógica de persistencia fuera de su capa correspondiente.

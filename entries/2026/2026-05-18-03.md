## Objetivo
Comprender que una clase debe tener un solo motivo para cambiar, evitando la complejidad innecesaria y facilitando el mantenimiento del código al separar responsabilidades lógicas.

## Explicación
El principio de Responsabilidad Única establece que cada clase debe encargar exactamente una tarea. Cuando una clase realiza múltiples funciones distintas, como procesar datos y enviar notificaciones, se vuelve frágil ante cambios en cualquiera de esas áreas. Al dividir estas responsabilidades en clases separadas, mejoramos la modularidad y la reutilización del código. Este enfoque permite que los desarrolladores modifiquen un aspecto del sistema sin afectar otros, reduciendo errores y simplificando las pruebas unitarias.

## Ejemplo (no ejecutado automáticamente)
Clase 'Reporte' que genera contenido y envía correos en lugar de hacerlo todo junto.

```javascript
class Reporte {
  generarContenido() { return 'Datos del reporte'; }
}
class Notificador {
  enviarCorreo(mensaje) { console.log('Email enviado:', mensaje); }
}
```

## Ejercicio
Refactoriza una clase existente que maneja pagos y envía confirmaciones en dos clases separadas.

## Criterios de revisión
El código debe tener dos clases distintas, cada una con un método público específico sin dependencias entre ellas.

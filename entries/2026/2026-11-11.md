## Objetivo
Diferenciar el uso de PUT para reemplazar recursos completos y PATCH para actualizaciones parciales, asegurando integridad de datos sin sobreescribir información irrelevante.

## Explicación
En la arquitectura RESTful, los métodos HTTP definen operaciones sobre recursos. PUT es idempotente y requiere enviar el estado completo del recurso; si faltan campos, se pierden. PATCH permite modificaciones selectivas enviando solo los cambios, ideal para actualizaciones frecuentes de perfiles o configuraciones. Ambos usan JSON en el cuerpo de la solicitud. Es crucial elegir el correcto según la necesidad: PUT para crear o reemplazar totalmente, PATCH para editar partes específicas. Esto optimiza el ancho de banda y reduce errores al no forzar la transmisión de datos innecesarios.

## Ejemplo (no ejecutado automáticamente)
Actualización parcial del perfil de un usuario enviando solo el campo 'email' con PATCH.

```javascript
fetch('https://api.ejemplo.com/usuarios/123', {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email: 'nuevo@email.com' })
});
```

## Ejercicio
Crea una API local con Express que tenga un endpoint /users/{id} que acepte PUT para reemplazar el objeto completo y PATCH para actualizar solo el campo 'nombre'.

El código debe manejar correctamente la diferencia entre ambos métodos, validar que PUT envíe todos los campos necesarios y que PATCH solo modifique los especificados en el cuerpo de la solicitud.

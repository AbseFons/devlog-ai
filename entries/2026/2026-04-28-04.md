## Objetivo
Aprender a utilizar ramas protegidas y flujos de trabajo basados en pull requests para mantener la estabilidad del código principal mientras se desarrollan nuevas funcionalidades de forma aislada y controlada.

## Explicación
En ingeniería de software, la integridad del repositorio principal es vital. La estrategia estándar implica crear una rama de desarrollo desde el branch principal antes de iniciar cualquier trabajo significativo. Esto aísla los cambios experimentales o en progreso. Una vez que la funcionalidad está lista, se solicita un pull request hacia el branch protegido. Este proceso obliga a revisar los cambios mediante código y pruebas automatizadas antes de su fusión. Nunca debe realizarse un commit directo al branch principal para evitar romper la línea de tiempo establecida. Esta disciplina reduce drásticamente los errores en producción y facilita la colaboración entre múltiples desarrolladores sin conflictos innecesarios.

## Ejemplo (no ejecutado automáticamente)
Crear una rama de desarrollo llamada feature-login desde el main, realizar un commit simulado y luego preparar un pull request hacia el branch principal.

```bash
git checkout -b feature-login
git add .
git commit -m 'Añadir lógica de autenticación'
git push origin feature-login
```

## Ejercicio
Crea una rama llamada 'fix-bug-calculadora', realiza un commit con un mensaje descriptivo y simula la creación de un pull request hacia el branch principal.

## Criterios de revisión
El usuario debe haber creado correctamente la rama, realizado al menos un commit con mensaje válido y entender que los cambios no se fusionan directamente sin revisión.

## Objetivo
Aprender a documentar cambios que mejoran la estructura interna del código sin alterar su comportamiento externo, utilizando el tipo 'refactor' en los commits convencionales para mantener un historial limpio y legible.

## Explicación
En esta microlección exploramos el uso del prefijo 'refactor:' dentro de los commits convencionales. Este tipo es crucial cuando reescribimos código para hacerlo más claro, eficiente o mantenible, sin cambiar las funcionalidades visibles. Por ejemplo, podrías renombrar variables confusas, extraer funciones largas o simplificar expresiones complejas. Al usar este prefijo, comunicas a tus compañeros que el cambio es puramente estructural. Esto evita alarmas innecesarias en los sistemas de integración continua y permite una revisión más rápida del historial de cambios, facilitando la colaboración en equipos grandes donde la claridad del mensaje es tan importante como el código mismo.

## Ejemplo (no ejecutado automáticamente)
Refactorización de una función que calcula impuestos separando la lógica de cálculo base de las reglas específicas por región.

```javascript
function calcularImpuestoBase(monto) {
  return monto * 0.15;
}

function aplicarRegiones(monto, region) {
  if (region === 'zonaA') {
    return calcularImpuestoBase(monto) + 5;
  }
  return calcularImpuestoBase(monto);
}
```

## Ejercicio
Crea una función llamada 'optimizarBucle' que tome un array de números y devuelva el mismo array pero con la lógica interna optimizada para evitar iteraciones redundantes, documentando el cambio en el mensaje del commit.

## Criterios de revisión
El commit debe incluir el prefijo 'refactor:', el mensaje debe ser conciso (menos de 50 caracteres) y el código debe demostrar una mejora clara en la eficiencia o legibilidad sin alterar la salida original.

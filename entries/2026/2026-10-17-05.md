## Objetivo
Aprender a construir consultas seguras utilizando parámetros para evitar que los datos del usuario alteren la lógica de la consulta y provoquen vulnerabilidades.

## Explicación
La inyección SQL ocurre cuando se concatenan directamente las entradas del usuario en una consulta. Para mitigarlo, debemos usar sentencias parametrizadas. El motor de base de datos trata el valor del parámetro como un dato literal, no como código ejecutable. Esto asegura que caracteres especiales como comillas o puntos y coma no rompan la sintaxis. En aplicaciones web modernas, frameworks como Hibernate o Entity Framework gestionan esto automáticamente, pero en consultas nativas o lenguajes como Python con sqlite3, es obligatorio pasar los argumentos explícitamente. Este enfoque elimina la necesidad de escapar manualmente cada carácter, reduciendo errores humanos y garantizando una defensa robusta contra ataques maliciosos que intenten manipular la base de datos.

## Ejemplo (no ejecutado automáticamente)
Consulta segura en Python usando placeholders para evitar inyección SQL.

```python
import sqlite3
conn = sqlite3.connect('db.sqlite')
cursor = conn.cursor()
usuario = input('Usuario: ')
password = input('Password: ')
query = "SELECT * FROM usuarios WHERE usuario = ? AND password = ?"
cursor.execute(query, (usuario, password))
```

El código debe utilizar explícitamente sintaxis de parametrización (como ? o :id). No debe contener ninguna concatenación de strings con variables de entrada. La estructura de la consulta debe ser válida incluso si el usuario introduce caracteres SQL inyectados.

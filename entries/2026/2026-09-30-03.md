## Objetivo
Comprender la importancia de separar el código fuente de la configuración del proyecto para garantizar portabilidad, reproducibilidad y un control de versiones limpio en cualquier entorno de desarrollo.

## Explicación
En el diseño de repositorios modernos, es fundamental distinguir entre archivos que contienen lógica de negocio (código) y aquellos que definen el entorno de ejecución (configuración). Los archivos de configuración, como package.json, requirements.txt o Dockerfile, deben ser versionados junto con el código fuente. Esto asegura que cualquier desarrollador pueda clonar el repositorio y ejecutar la aplicación exactamente igual que el autor original sin necesidad de instalaciones manuales. Una estructura de directorio clara evita mezclar dependencias globales con las del proyecto, facilitando la limpieza y el mantenimiento a largo plazo.

## Ejemplo (no ejecutado automáticamente)
Estructura de directorio mostrando la separación entre código fuente en src/ y archivos de configuración en la raíz.

```bash
# Estructura base del repositorio
mkdir -p src/config
# Archivo de configuración principal
npm init -y
```

## Ejercicio
Crea un nuevo directorio llamado 'proyecto-demo' y dentro de él, establece una carpeta 'src' para el código y una carpeta 'config' para los archivos de entorno.

## Criterios de revisión
El repositorio debe tener al menos dos niveles de profundidad (raíz y subcarpeta) y no contener archivos binarios ni credenciales en la raíz.

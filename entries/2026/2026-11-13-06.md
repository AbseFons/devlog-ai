## Objetivo
Aprender a aplicar el principio de mínimo privilegio asignando permisos específicos por servicio en lugar de usar cuentas administrativas genéricas, reduciendo la superficie de ataque y limitando el daño potencial ante una violación de credenciales.

## Explicación
El principio de mínimo privilegio exige que cada entidad, ya sea un usuario o un servicio automatizado, posea únicamente los permisos estrictamente necesarios para su función. En entornos de nube modernos, esto implica evitar la asignación de roles como 'Administrador' a procesos de backend. Por ejemplo, un servicio de procesamiento de imágenes no necesita acceso al sistema de archivos raíz ni capacidad de reiniciar otros nodos. Se deben definir políticas que otorguen solo las acciones requeridas, como leer una carpeta específica o escribir en un bucket de almacenamiento temporal. Esta segmentación permite detectar anomalías más fácilmente y contiene los efectos de una brecha. La implementación requiere revisar constantemente los roles activos y eliminar aquellos que ya no son necesarios, asegurando que la configuración inicial sea segura desde el diseño.

## Ejemplo (no ejecutado automáticamente)
Asignación de un rol personalizado en AWS IAM para un servicio Lambda que solo puede leer archivos de una carpeta específica y escribir logs en un bucket designado.

```bash
# Crear política JSON con permisos limitados
POLICY='{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["s3:GetObject","s3:PutObject"],"Resource":["arn:aws:s3:::mi-bucket-procesamiento/*"]}]}'
# Asignar la política al rol del servicio
aws iam create-role --role-name LambdaMinimoPrivilegio --assume-role-policy-document '{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"lambda.amazonaws.com"},"Action":"sts:AssumeRole"}]}'
# Vincular la política al rol creado
aws iam attach-role-policy --role-name LambdaMinimoPrivilegio --policy-arn arn:aws:iam::123456789012:policy/PolicaLimitada
```

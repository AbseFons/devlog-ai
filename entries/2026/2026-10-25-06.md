## Objetivo
Aprender a crear etiquetas semánticas (v1.0, v2.1) en Git para marcar hitos de versión estables, diferenciando entre commits locales y releases globales listas para distribución.

## Explicación
Las etiquetas en Git son puntos fijos en el historial que representan versiones específicas del proyecto. A diferencia de los commits, las etiquetas no se mueven automáticamente con nuevos cambios. Para una gestión profesional, se recomienda usar 'git tag' con la convención semántica (ej: v1.2.3). Esto permite a los usuarios saber exactamente qué funcionalidades incluye cada versión. El comando 'git push --tags' es crucial para compartir estas versiones con otros desarrolladores o repositorios remotos como GitHub. Es vital distinguir entre etiquetas ligeras y anotadas; las anotadas permiten mensajes de liberación detallados. Nunca etiquetes un estado inestable sin consenso del equipo.

## Ejemplo (no ejecutado automáticamente)
Crear una etiqueta anotaada para la versión 1.5.0 con mensaje de cambios y empujarla al remoto.

```bash
git tag -a v1.5.0 -m "Release: Corrección de bug en autenticación"
git push origin v1.5.0
```

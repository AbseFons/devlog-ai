## Objetivo
Comprender cómo los índices aceleran las búsquedas en bases de datos relacionales y aprender a estructurar consultas para evitar escaneos completos de tablas grandes, mejorando el rendimiento general de la aplicación.

## Explicación
Los índices actúan como un índice del libro, permitiendo saltar directamente a la información deseada sin leer cada página. En SQL, los índices B-Tree son ideales para columnas con valores únicos o rangos. Cuando una consulta usa WHERE, JOIN o ORDER BY en columnas indexadas, el motor de base de datos evita el 'Full Table Scan', reduciendo drásticamente el tiempo de respuesta. Sin embargo, añadir índices indiscriminadamente puede ralentizar las inserciones y actualizaciones debido a la necesidad de mantener la estructura del índice. El equilibrio clave reside en identificar las consultas más lentas y crear índices solo en las columnas frecuentemente consultadas, asegurando que el plan de ejecución aproveche estas estructuras para acceder a los datos de manera eficiente.

## Ejemplo (no ejecutado automáticamente)
Creación de un índice en la columna 'email' de una tabla de usuarios para acelerar búsquedas por correo electrónico y consultas de autenticación.

```sql
CREATE INDEX idx_users_email ON users(email);
SELECT * FROM users WHERE email = 'usuario@ejemplo.com';
```

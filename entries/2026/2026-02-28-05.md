## Objetivo
Comprender la diferencia entre cobertura de código y pruebas de límites, asegurando que las aplicaciones manejen correctamente valores extremos sin depender únicamente del porcentaje de líneas cubiertas.

## Explicación
La cobertura de código mide qué porcentaje del código fuente se ejecutó durante las pruebas, pero no garantiza que el sistema funcione en todos los escenarios. Un alto porcentaje de cobertura puede ocultar fallos en casos límite. Las pruebas de límites verifican explícitamente valores al borde de la capacidad, como el tamaño máximo permitido o el valor cero. Es crucial combinar ambas estrategias: usar cobertura para detectar código no tocado y pruebas de límites para validar la robustez ante entradas extremas que podrían causar desbordamientos o errores de lógica.

## Ejemplo (no ejecutado automáticamente)
Función que valida un límite de caracteres en una cadena de texto, probando el valor exacto del límite, uno por debajo y uno por encima.

```javascript
function validarLongitud(texto, maximo) {
  if (texto.length > maximo) {
    return false;
  }
  return true;
}

console.log(validarLongitud("Hola", 4)); // true
console.log(validarLongitud("HOLA", 4)); // false
```

## Ejercicio
Crea una función en Python que acepte un número entero y devuelva 'OK' si está entre -100 y 100, e incluya casos de prueba para los valores exactos -100, 100, -101 y 101.

## Criterios de revisión
El código debe ejecutar sin errores en los límites definidos. Debe fallar o retornar un mensaje específico si el valor excede el rango permitido.

## Objetivo
Comprender los fundamentos del Control de Acceso Basado en Roles (RBAC) y cómo aplicar listas de control de acceso para restringir operaciones de lectura y escritura en recursos críticos, garantizando el principio de mínimo privilegio desde el inicio del desarrollo.

## Explicación
El Control de Acceso Basado en Roles asigna permisos a roles funcionales en lugar de usuarios individuales. En esta microlección, analizaremos cómo definir una estructura de ACLs para proteger un archivo de configuración sensible. El objetivo es permitir que los administradores lean y escriban, mientras que los desarrolladores solo pueden leer. Esto se logra mapeando roles a políticas específicas dentro del sistema operativo o middleware. La implementación correcta previene fugas de información accidental y mitiga riesgos ante compromisos de cuentas de bajo privilegio. Es fundamental auditar periódicamente estos roles para asegurar que coincidan con las necesidades actuales del negocio.

## Ejemplo (no ejecutado automáticamente)
Definición de reglas ACL en un archivo de configuración de servidor web para separar permisos entre administradores y desarrolladores sobre una carpeta de logs.

```bash
chmod 750 /var/log/app
chown admin:devops /var/log/app
setfacl -m u:developer:r-x /var/log/app
```

## Ejercicio
Crea un script que defina tres roles (admin, auditor, desarrollador) y aplique permisos de lectura/escritura a una carpeta de datos compartida usando ACLs.

## Criterios de revisión
El script debe asignar correctamente los permisos sin usar comandos root innecesarios y documentar cada cambio de permiso aplicado.

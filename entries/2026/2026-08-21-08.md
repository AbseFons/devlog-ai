## Objetivo
Comprender que las subclases deben respetar el comportamiento esperado de sus superclases sin introducir restricciones más estrictas, asegurando que cualquier código que funcione con la clase base siga funcionando correctamente con sus derivados.

## Explicación
El principio de Sustitución de Liskov establece que los objetos de una clase derivada deben poder sustituir a sus objetos de clase base sin alterar el correcto funcionamiento del programa. En la práctica, esto significa que si un método en la clase padre asume ciertas condiciones sobre sus datos o comportamiento, la subclase no debe violar esas suposiciones. Por ejemplo, si una clase 'Ave' tiene un método 'volar', una subclase como 'Pingüino' no debería implementar ese método de forma que rompa el flujo esperado por el código que lo llama. Esto previene errores sutiles donde la herencia se usa para cambiar la semántica en lugar de extenderla, manteniendo la coherencia del diseño y facilitando la prueba y reutilización del código.

## Ejemplo (no ejecutado automáticamente)
```python
class Ave:
    def volar(self):
        return "El ave vuela."

class Pingüino(Ave):
    # Violación de Liskov: no debe sobrescribir el comportamiento fundamental
    # si la clase base asume que todos los objetos pueden volar.
    def volar(self):
        return "El pingüino no puede volar."

class Parque:
    def mostrar_aves(self, ave):
        print(ave.volar())

# Uso incorrecto: el código asume que todas las aves vuelan
pinguino = Pingüino()
parque = Parque()
print(parque.mostrar_aves(pinguino))  # Resultado inesperado o error lógico
```

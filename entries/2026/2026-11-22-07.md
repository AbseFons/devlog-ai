## Objetivo
Comprender cómo invertir las dependencias para que las entidades de alto nivel no dependan de implementaciones concretas, sino de abstracciones, facilitando pruebas y flexibilidad en el diseño del sistema.

## Explicación
El principio L (Inversión de Dependencias) establece que los módulos de alto nivel no deben depender de módulos de bajo nivel; ambos deben depender de abstracciones. Esto se logra mediante interfaces o clases abstractas. Al hacerlo, desacoplamos la lógica de negocio de las implementaciones específicas, como bases de datos o servicios externos. Por ejemplo, en lugar de que un servicio de pagos dependa directamente de una clase concreta de base de datos, depende de una interfaz genérica. Esto permite cambiar la implementación subyacente sin alterar el código del cliente. Además, promueve la creación de pruebas unitarias más sencillas mediante mocks o stubs que implementan las abstracciones necesarias.

## Ejemplo (no ejecutado automáticamente)
Implementación de un servicio de notificaciones que depende de una interfaz abstracta en lugar de una implementación concreta de correo electrónico.

```javascript
interface Notificador {
  enviar(mensaje: string): Promise<void>;
}
class CorreoElectronico implements Notificador {
  async enviar(mensaje: string) { console.log('Enviado por email:', mensaje); }
}
```

## Ejercicio
Crea una interfaz 'Pagador' con un método 'procesarPago'. Implementa dos clases concretas, 'Tarjeta' y 'PayPal', que implementen esta interfaz. Luego, crea una clase 'ServicioDeCompras' que dependa de la interfaz 'Pagador' en su constructor.

## Criterios de revisión
El código debe compilar sin errores. El ServicioDeCompras no debe referenciar directamente las clases Tarjeta o PayPal, solo la interfaz Pagador. Debe ser posible inyectar cualquier implementación que cumpla con la interfaz.

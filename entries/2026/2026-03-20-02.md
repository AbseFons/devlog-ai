## Objetivo
Comprender la diferencia entre imágenes inmutables y contenedores efímeros, analizando cómo Docker utiliza capas para construir entornos aislados y reproducibles sin modificar el sistema anfitrión.

## Explicación
En Docker, una imagen es un archivo de plantilla inmutable que contiene todo lo necesario para ejecutar una aplicación: código, librerías y dependencias. Funciona como una plantilla estática. Por otro lado, un contenedor es una instancia en ejecución derivada de una imagen. Cuando se ejecuta un contenedor, Docker crea un espacio aislado con su propio sistema de archivos, red y procesos. Aunque comparten las mismas capas base, cada contenedor mantiene sus cambios específicos. Esta arquitectura permite escalar aplicaciones fácilmente: puedes crear múltiples instancias del mismo contenedor desde la misma imagen, garantizando consistencia entre desarrolladores y servidores de producción.

## Ejemplo (no ejecutado automáticamente)
Creación de una imagen personalizada basada en Alpine Linux para ejecutar un servidor web simple con Nginx, demostrando cómo se construye una imagen ligera y luego se inicia su contenedor correspondiente.

```bash
echo 'hello from docker' > /usr/share/nginx/html/index.html
docker build -t mi-web-app .
docker run -d --name mi-contenedor -p 8080:80 mi-web-app
```

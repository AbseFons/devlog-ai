## Objetivo
Comprender cómo las pruebas unitarias forman la base de la pirámide, asegurando que cada componente funcione aisladamente antes de integrarlo con dependencias externas o interfaces complejas.

## Explicación
En esta segunda serie sobre la pirámide de pruebas, nos enfocamos en el nivel inferior: las pruebas unitarias. Estas son rápidas, baratas y ejecutables sin infraestructura externa. Su propósito es validar la lógica interna de funciones o clases específicas. Al construir una base sólida con estas pruebas, se reduce drásticamente el riesgo de fallos al subir a niveles superiores como integración o E2E. Un caso común es probar un servicio de cálculo de impuestos que ignore temporalmente la conexión a una API fiscal externa, simulando respuestas para verificar que la lógica de negocio maneje correctamente los valores esperados.

## Ejemplo (no ejecutado automáticamente)
Prueba unitaria en JavaScript que verifica el cálculo de un total con descuento aplicado a un carrito de compras, sin depender de una base de datos real.

```javascript
function calcularTotal(carrito) {
  const subtotal = carrito.items.reduce((acc, item) => acc + (item.precio * item.cantidad), 0);
  return subtotal * 0.9;
}

const resultado = calcularTotal({ items: [{ precio: 100, cantidad: 2 }] });
console.assert(resultado === 180, 'El cálculo del total con descuento falló');
```

## Ejercicio
Crea una función que valide si un usuario puede acceder a un recurso basado en su rol y los permisos definidos. Luego, escribe dos pruebas unitarias: una donde el acceso es permitido y otra donde es denegado.

## Criterios de revisión
El código debe incluir al menos dos casos de prueba distintos (acceso concedido y denegado). Las funciones deben ser puras y no depender de variables globales. Los mensajes de error en las pruebas deben ser claros.

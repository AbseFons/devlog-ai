## Objetivo
Comprender y aplicar el principio de mínimo privilegio al definir roles de usuario, limitando el acceso a recursos solo estrictamente necesarios para la función operativa del sistema.

## Explicación
El principio de mínimo privilegio establece que cada entidad (usuario, proceso o servicio) debe poseer únicamente los permisos mínimos requeridos para realizar su tarea específica. En ingeniería de software, esto reduce la superficie de ataque y limita el daño potencial en caso de compromiso. Por ejemplo, un servicio de base de datos no necesita acceso a archivos del sistema operativo ni capacidad de ejecutar comandos externos. Implementar este principio implica auditar permisos existentes, eliminar privilegios innecesarios y asignar roles granulares. Esto se logra mediante configuraciones de seguridad en el sistema operativo o en la aplicación, asegurando que incluso si una cuenta es robada, el atacante no pueda escalar sus privilegios ni acceder a datos críticos fuera del alcance funcional.

## Ejemplo (no ejecutado automáticamente)
Definición de un usuario de servicio con acceso restringido solo a lectura y escritura en una carpeta específica de la base de datos.

```bash
sudo usermod -aG db_readers app_service
chmod 750 /var/data/db_logs
chown app_service:db_readers /var/data/db_logs
```

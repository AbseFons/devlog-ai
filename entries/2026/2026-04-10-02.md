## Objetivo
Aprender a utilizar el comando git bisect para identificar eficientemente en qué commit exacto se introdujo un error de regresión, ahorrando tiempo frente al uso manual de bisectación binaria.

## Explicación
El comando git bisect automatiza la búsqueda lineal de cambios. Primero, marcas el estado actual como 'bad' (conocido que tiene el bug) y seleccionas un commit anterior conocido como 'good' (sin errores). Git luego ejecuta automáticamente comandos intermedios entre ambos puntos. Debes probar cada estado generado y marcarlo como 'bad' si presenta el error o 'good' si funciona correctamente. Este proceso se repite hasta que Git encuentra el commit específico donde la lógica cambió, revelando la causa raíz del problema sin necesidad de revisar manualmente cientos de commits.

## Ejemplo (no ejecutado automáticamente)
Se marca el commit actual como defectuoso y un commit anterior (HEAD~10) como correcto. Luego se ejecuta bisect start y se indican los puntos de referencia para iniciar la búsqueda automática.

```bash
git bisect start
GIT_BISECT_BAD=HEAD
GIT_BISECT_GOOD=HEAD~10
```

## Ejercicio
En un repositorio con un bug introducido hace dos semanas, ejecuta 'git bisect start', marca el commit actual como 'bad' y el primer commit de la semana pasada como 'good'. Observa cómo Git selecciona commits intermedios para probar.

## Criterios de revisión
El usuario debe ejecutar correctamente los comandos iniciales de git bisect sin errores, identificar al menos dos commits intermedios propuestos por Git y saber marcarlos adecuadamente según el estado del bug.

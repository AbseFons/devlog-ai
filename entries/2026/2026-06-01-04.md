## Objetivo
Comprender la diferencia entre cobertura de código y límites funcionales, aprendiendo a diseñar casos de prueba que validen no solo el flujo normal sino también los bordes críticos del sistema para prevenir fallos en producción.

## Explicación
La cobertura de código mide qué porcentaje del código fuente se ejecuta durante las pruebas, pero un alto porcentaje no garantiza la calidad. Los límites son valores de entrada o estado que marcan el inicio y fin del comportamiento esperado. Un error común es probar solo el valor medio (ej. 50) y olvidar los bordes (0, 1, max). Para una cobertura robusta, debes incluir casos de borde: el primer elemento válido, el último, valores nulos y negativos si aplica. Esto revela vulnerabilidades en la lógica de validación que la cobertura simple pasaría por alto.

## Ejemplo (no ejecutado automáticamente)
Función que calcula un descuento basado en cantidad, probando límites de rango y valores extremos.

```javascript
function calcularDescuento(cantidad) {
  if (cantidad < 0 || cantidad > 1000) return 'Error: Rango inválido';
  if (cantidad === 0) return 0;
  return cantidad * 0.95;
}
calcularDescuento(0);
calcularDescuento(1000);
calcularDescuento(-1);
```

## Ejercicio
Crea una función en Python que valide si un usuario tiene acceso a un recurso basado en su nivel de seguridad (de 1 a 5). Debes probar los límites exactos (1 y 5), un valor intermedio (3) y dos casos fuera de rango (0 y 6).

## Criterios de revisión
El código debe incluir al menos tres llamadas a la función: una para el límite inferior, una para el límite superior y una para un valor dentro del rango. Cada llamada debe tener un comentario explicando qué caso de borde o normal está probando.

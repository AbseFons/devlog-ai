## Objetivo
Comprender la distinción fundamental entre autenticación (quién eres) y autorización (qué puedes hacer), esencial para diseñar APIs seguras que protejan recursos sensibles mediante roles y permisos granulares.

## Explicación
En el desarrollo de APIs, confundir autenticación con autorización es un error crítico. La autenticación verifica la identidad del usuario mediante credenciales como tokens JWT o sesiones, respondiendo a '¿Quién eres?'. Una vez validada esta identidad, entra en juego la autorización, que determina los permisos específicos de ese usuario sobre recursos concretos, respondiendo a '¿Qué puedes hacer?'. Mientras la autenticación suele ser binaria (validado/no validado), la autorización es granular y depende del rol o atributos del sujeto. Una API segura implementa ambos: primero valida el token para confirmar identidad, luego consulta una política de acceso (como RBAC) para decidir si permite la operación solicitada. Sin autorización adecuada, un usuario autenticado podría acceder a datos que no le corresponden.

## Ejemplo (no ejecutado automáticamente)
Un endpoint de API en Node.js que valida un token JWT y verifica si el usuario tiene permiso para eliminar un recurso específico basado en su rol.

```javascript
const user = jwt.verify(token, SECRET);
if (user.role !== 'admin') throw new Error('Acceso denegado');
```

## Ejercicio
Crea una función que reciba un objeto de usuario y una ruta de recurso. Devuelve true si el rol del usuario coincide con los permisos requeridos para esa ruta, simulando una matriz de permisos simple.

## Criterios de revisión
El código debe separar claramente la validación del token (autenticación) de la lógica de verificación de roles (autorización). Debe manejar casos donde el rol no existe o es insuficiente sin exponer detalles internos.

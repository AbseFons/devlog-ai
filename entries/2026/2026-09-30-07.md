## Objetivo
Comprender cómo diseñar casos de prueba que cubran no solo el camino feliz, sino también los límites exactos de los datos de entrada. Aprender a validar comportamientos en bordes críticos para evitar fallos sutiles en la producción.

## Explicación
La cobertura de pruebas va más allá de ejecutar código; implica verificar explícitamente los límites definidos por las especificaciones del sistema. Un error común es asumir que probar valores cercanos al límite es suficiente, cuando la validación debe incluir el valor exacto del umbral y uno inmediatamente superior o inferior. Por ejemplo, si un campo acepta hasta 100 elementos, las pruebas deben cubrir 99, 100 y 101. Esto asegura que la lógica de validación maneje correctamente los casos extremos sin colapsar. Ignorar estos puntos puede resultar en vulnerabilidades de seguridad o corrupción de datos.

## Ejemplo (no ejecutado automáticamente)
Script de Python que valida si una lista cumple con un límite máximo de elementos, probando valores justo en el borde y excediendo el umbral.

```python
def validar_limite(lista, maximo):
    if len(lista) > maximo:
        return False
    return True

test_caso = [1, 2, 3]
print(validar_limite(test_caso, 3))  # Debe ser True
```

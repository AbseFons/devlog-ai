## Objetivo
Comprender cómo la propiedad de atomicidad garantiza que una transacción se ejecute completamente o no se ejecute en absoluto, utilizando rollback ante errores.

## Explicación
La atomicidad asegura que las operaciones dentro de una transacción sean indivisibles. Si falla una instrucción, el sistema deshace todos los cambios previos mediante un rollback automático. En este ejemplo, intentamos transferir fondos entre cuentas. Si la segunda operación (deducción) falla por saldo insuficiente, la primera (crédito) se revierte inmediatamente, manteniendo la consistencia de los datos sin dejar huellas parciales.

## Ejemplo (no ejecutado automáticamente)
Script SQL que simula una transferencia fallida y demuestra el rollback automático al lanzar un error en la segunda sentencia.

```sql
BEGIN TRANSACTION;
UPDATE cuentas SET saldo = saldo + 100 WHERE id = 1;
UPDATE cuentas SET saldo = saldo - 100 WHERE id = 2;
ROLLBACK;
```

## Criterios de revisión
El código debe iniciar con BEGIN TRANSACTION, contener al menos tres sentencias UPDATE o INSERT, incluir una sentencia ROLLBACK explícita tras el error simulado y asegurar que el estado final de las tablas sea idéntico al inicial.

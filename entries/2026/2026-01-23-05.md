## Objetivo
Comprender la diferencia fundamental entre las operaciones de lectura (GET) y creación (POST) en una API RESTful, identificando sus verbos, códigos de estado asociados y el flujo correcto de datos para construir endpoints robustos y semánticamente correctos.

## Explicación
En el diseño de APIs REST, los métodos HTTP definen la naturaleza de la operación. El método GET se utiliza exclusivamente para recuperar recursos existentes sin efectos secundarios; debe devolver un código 200 OK o 404 Not Found. Por otro lado, POST inicia una acción que cambia el estado del servidor, típicamente creando un nuevo recurso. Al enviar datos a través de POST, el cliente suele incluir el cuerpo de la petición con los detalles del objeto a crear. El servidor responde con un código 201 Created y, crucialmente, en el encabezado Location, proporciona la URI única del recurso recién generado. Esta distinción semántica garantiza que las aplicaciones clientes puedan manejar errores y flujos de datos de manera predecible y segura.

## Ejemplo (no ejecutado automáticamente)
Solicitud POST para crear un nuevo usuario en una API ficticia, mostrando el cuerpo JSON con los datos del usuario y la respuesta esperada con el ID generado.

```javascript
fetch('https://api.ejemplo.com/usuarios', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ nombre: 'Ana', rol: 'admin' })
}).then(res => res.json());
```

## Ejercicio
Crea un endpoint GET que devuelva una lista de productos y otro POST que acepte un objeto con precio y nombre para registrar un nuevo producto, asegurando que el POST retorne el ID del recurso creado.

## Criterios de revisión
El código debe usar correctamente los verbos HTTP, incluir encabezados de tipo de contenido JSON en las peticiones POST y manejar adecuadamente las respuestas con códigos de estado 201 o 404.

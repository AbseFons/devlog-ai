## Objetivo
Aprender a utilizar ramas protegidas y flujos de trabajo que prevengan la fusión directa de código no revisado al rama principal, asegurando estabilidad en el proyecto.

## Explicación
En ingeniería de software moderna, evitar fusiones directas a main es crucial. Utiliza una rama de desarrollo (ej. feature/login) para trabajar aislado. Una vez listo, crea un Pull Request o Merge Request hacia la rama destino. Esto permite revisión por pares, discusión y pruebas automatizadas antes de integrar cambios. Nunca empujes directamente a ramas protegidas como main o develop sin aprobación explícita del equipo. Esta disciplina reduce bugs en producción y mantiene el historial limpio.

## Ejemplo (no ejecutado automáticamente)
Crear una rama para un nuevo módulo de autenticación y preparar su integración mediante un Pull Request.

```bash
git checkout -b feature/login
# Realizar cambios en el archivo auth.js
git add auth.js
git commit -m 'Añadir lógica de login'
git push origin feature/login
```

## Ejercicio
Crea una rama llamada issue/fix-bug-123, realiza un cambio mínimo en un archivo de texto y prepara el push para revisión.

## Criterios de revisión
Debe existir la rama creada con el nombre correcto, el commit debe tener mensaje descriptivo y no debe haber errores de sintaxis en los comandos.

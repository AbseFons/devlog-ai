## Objetivo
Comprender la estructura básica de una aplicación monolítica dividida en capas lógicas para facilitar el mantenimiento, escalabilidad y pruebas unitarias.

## Explicación
El diseño por capas organiza el sistema en niveles con responsabilidades distintas. La capa de presentación maneja la interacción del usuario, mientras que la capa de negocio encapsula la lógica crítica y las reglas de operación. Finalmente, la capa de acceso a datos se encarga exclusivamente de la persistencia. Esta separación permite modificar una parte sin afectar a las demás, promueve la reutilización de código y simplifica la implementación de pruebas automatizadas al aislar dependencias.

## Ejemplo (no ejecutado automáticamente)
Implementación básica en Python donde la capa de negocio valida un usuario antes de que la capa de datos lo guarde.

```python
class Negocio:
    def validar(self, usuario):
        return len(usuario) > 3

class Datos:
    def guardar(self, usuario):
        print(f"Guardando {usuario}")
```

## Ejercicio
Crea una clase 'CapaPresentacion' que reciba un nombre de usuario desde el input del usuario y llame a las clases 'Negocio' y 'Datos' definidas anteriormente para procesar la solicitud.

## Criterios de revisión
El código debe importar correctamente las clases, no debe haber errores de sintaxis y la lógica de validación debe ejecutarse antes de intentar guardar los datos.

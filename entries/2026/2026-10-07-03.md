## Objetivo
Comprender la importancia de utilizar códigos HTTP específicos para representar estados de error, mejorando la legibilidad y facilitando el manejo adecuado de excepciones por parte del cliente.

## Explicación
En el diseño de APIs RESTful, cada código de estado HTTP debe reflejar con precisión la naturaleza de la respuesta. Utilizar un código genérico como '500' para todos los errores oculta detalles cruciales. Por ejemplo, si una solicitud falla porque falta un campo obligatorio en el cuerpo del mensaje, la API debe devolver '400 Bad Request'. Si el recurso solicitado no existe, corresponde '404 Not Found'. Esta distinción permite a los clientes de la API (como aplicaciones móviles o dashboards) mostrar mensajes de usuario apropiados y ejecutar lógica de recuperación específica. Un buen diseño de errores evita la exposición de información sensible en el cuerpo del mensaje al usar códigos que indican fallos internos del servidor ('5xx') para problemas de validación.

## Ejemplo (no ejecutado automáticamente)
Respuesta JSON correcta ante un error de validación de usuario, indicando claramente qué campo falló y por qué.

```javascript
const response = {
  status: 400,
  message: "Validación fallida",
  errors: { email: ["El formato del correo electrónico es inválido"] }
};
```

## Ejercicio

## Objetivo
Comprender cómo la concatenación directa de cadenas en consultas SQL permite a los atacantes alterar la lógica del sistema y extraer datos sensibles sin autorización.

## Explicación
La inyección SQL ocurre cuando una aplicación toma datos no confiables del usuario y los inserta directamente en una consulta SQL. Si un atacante envía una entrada como "admin' OR '1'='1", el backend puede construir una consulta maliciosa que autentique a cualquier usuario. Para prevenir esto, es imperativo utilizar parámetros parametrizados o prepared statements. Estos mecanismos separan la estructura de la consulta del valor de los datos, asegurando que el motor de base de datos interprete siempre las entradas del usuario como valores literales y nunca como parte de la lógica SQL.

## Ejemplo (no ejecutado automáticamente)
Consulta vulnerable usando concatenación directa versus la versión segura con parámetros en Python.

```python
import sqlite3
conn = sqlite3.connect('db.sqlite')
cursor = conn.cursor()
usuario = "admin"
password = "1234"
# Vulnerable: cursor.execute(f"SELECT * FROM users WHERE user='{usuario}' AND pass='{password}'")
# Seguro:
cursor.execute("SELECT * FROM users WHERE user=? AND pass=?", (usuario, password))
```

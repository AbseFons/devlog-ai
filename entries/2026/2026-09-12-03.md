## Objetivo
Aprender a diseñar pruebas que verifiquen la comunicación correcta entre módulos internos y servicios externos, asegurando la robustez del sistema ante fallos en dependencias.

## Explicación
Las pruebas de integración evalúan cómo los componentes individuales interactúan. En este caso, simularemos una llamada a una API de pasarela de pagos ficticia. El objetivo es validar que el sistema maneje respuestas exitosas y errores gracefully sin depender de infraestructura real inestable. Utilizaremos un cliente HTTP ligero para enviar peticiones POST con datos de prueba anónimos. Es crucial incluir lógica de espera (retry) y manejo de timeouts en el código de prueba para evitar bloqueos. Esta práctica refuerza la resiliencia del software al aislar fallos externos.

## Ejemplo (no ejecutado automáticamente)
Script que simula una transacción de pago enviando datos a un endpoint mock, verificando el estado de respuesta y manejando errores de conexión.

```javascript
const axios = require('axios');
async function testPaymentIntegration() {
  try {
    const response = await axios.post('/api/payments', { amount: 10.5, currency: 'USD' });
    console.log('Pago exitoso:', response.status);
  } catch (error) {
    console.error('Error en integración:', error.message);
  }
}
```

## Ejercicio
Crea un script que envíe una solicitud GET a un servicio de clima mock. Si la respuesta tiene estado 200, imprime 'Datos recibidos'. Si es 404 o 500, captura el error y registra un log con el mensaje 'Servicio no disponible' antes de finalizar.

## Criterios de revisión
El código debe usar una librería HTTP estándar o popular. Debe incluir manejo explícito de excepciones para errores de red. No debe contener credenciales reales ni datos sensibles. La salida en consola debe ser clara y diferenciar entre éxito y fallo.

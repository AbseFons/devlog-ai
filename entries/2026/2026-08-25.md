## Objetivo
Al finalizar esta lección, el desarrollador será capaz de crear una rama de feature desde main, realizar commits locales y ejecutar un comando de merge no destructivo hacia la rama principal, entendiendo el flujo estándar de integración en equipos pequeños.

## Explicación
La gestión de ramas es fundamental para mantener el código estable. La estrategia más común inicia en la rama 'main' o 'master'. Para desarrollar una nueva funcionalidad sin afectar al resto del equipo, se crea una rama específica (feature). Los cambios se realizan allí y se validan localmente antes de integrar. El comando 'git merge' permite unir el trabajo de forma segura, mientras que 'git rebase' ofrece una línea de tiempo lineal alternativa. Es vital evitar comandos destructivos como 'git reset --hard' en ramas compartidas. Esta disciplina previene la pérdida de código y facilita la revisión por pares antes de desplegar cambios críticos en producción.

## Ejemplo (no ejecutado automáticamente)
```python
# Crear rama desde main
git checkout -b feature-nueva-funcionalidad

# Simular desarrollo con un archivo de prueba
echo 'Nueva logica de negocio' > src/nuevo_modulo.py

# Realizar commits locales
git add src/nuevo_modulo.py
git commit -m 'Añadir modulo de calculo avanzado'

# Integrar cambios en main sin borrar historial
git checkout main
git merge feature-nueva-funcionalidad

# Limpiar rama temporalmente tras integracion exitosa
git branch -d feature-nueva-funcionalidad
```

## Ejercicio
Crea una rama llamada 'fix-bug-calculadora', añade un archivo llamado 'bug_fix.txt' con el texto 'Corregido error de division por cero', haz un commit y luego ejecuta el merge hacia la rama principal.

## Criterios de revisión
El merge debe completarse sin errores, el historial del main debe mostrar la entrada de la rama feature y la rama temporal debe eliminarse tras la integración exitosa.

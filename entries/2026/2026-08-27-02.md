## Objetivo
Al finalizar esta lección, el desarrollador podrá distinguir entre imagen y contenedor, entender cómo Dockerfile crea imágenes inmutables y ejecutar un contenedor efímero desde una imagen base oficial sin modificar el sistema anfitrión.

## Explicación
En Docker, la imagen es una plantilla de solo lectura que contiene todo lo necesario para ejecutar una aplicación: código, librerías y dependencias. Es inmutable y se almacena en registros como Docker Hub. El contenedor es una instancia ejecutable y mutable de esa imagen. Cuando lanzas un contenedor, el motor de Docker crea un espacio de archivos aislado basado en la capa de la imagen. Esta separación permite escalabilidad y consistencia entre entornos. Las imágenes se construyen mediante instrucciones en un archivo Dockerfile, mientras que los contenedores se gestionan con comandos como run o exec. Comprender esta distinción es vital para diseñar arquitecturas de despliegue robustas.

## Ejemplo (no ejecutado automáticamente)
```python
import subprocess

# Construir imagen localmente desde Dockerfile
subprocess.run(['docker', 'build', '-t', 'mi-app:v1', '.'])

# Ejecutar contenedor efímero con puerto mapeado
subprocess.run([
    'docker', 'run', '-d', '--name', 'mi-contenedor-prueba',
    '-p', '8080:80',
    'mi-app:v1'
])

# Verificar estado del contenedor
result = subprocess.run(['docker', 'ps'], capture_output=True, text=True)
print(result.stdout)
```

## Criterios de revisión
El Dockerfile debe incluir instrucciones FROM, COPY y CMD. La construcción de la imagen debe finalizar sin errores. El contenedor debe iniciarse en segundo plano (-d) y mostrar el estado 'Up' en la lista de procesos activos.

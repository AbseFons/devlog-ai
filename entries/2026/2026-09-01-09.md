## Objetivo
Al finalizar esta microlección, el desarrollador será capaz de implementar un sistema de registro en Python que capture secuencias lógicas de eventos (series) utilizando identificadores únicos por sesión, permitiendo rastrear flujos complejos sin depender del orden cronológico estricto.

## Explicación
En aplicaciones distribuidas o con alta concurrencia, los registros simples a menudo fallan al explicar el contexto completo de un error. La técnica de 'series' implica agrupar eventos relacionados mediante un ID único (como una solicitud HTTP o una transacción). En lugar de solo imprimir mensajes, estructuramos los datos como diccionarios dentro del objeto de registro. Esto permite que las herramientas de análisis agreguen automáticamente todos los registros que comparten el mismo ID, reconstruyendo la narrativa del flujo incluso si los eventos llegan desordenados o con retraso. Este enfoque transforma un log plano en una base de datos temporal de eventos, facilitando la depuración de flujos asíncronos y la auditoría de procesos largos.

## Ejemplo (no ejecutado automáticamente)
```python
import logging
from datetime import datetime

# Configuración básica del logger
logging.basicConfig(
    format='%(asctime)s - %(message)s',
    level=logging.INFO
)
logger = logging.getLogger('mi_app')

# Simulación de una transacción con ID único
transaccion_id = 'TXN-99821'

try:
    logger.info(f"Inicio de serie: {transaccion_id}")
    # Simular paso 1
    logger.info(f"Paso 1 completado para {transaccion_id}")
    # Simular paso 2 con un pequeño retraso
    import time
    time.sleep(0.5)
    logger.info(f"Paso 2 completado para {transaccion_id}")
except Exception as e:
    logger.error(f"Error en serie {transaccion_id}: {str(e)}")
else:
    logger.info(f"Serie {transaccion_id} finalizada exitosamente.")
```

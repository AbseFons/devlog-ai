## Objetivo
Comprender la importancia de dividir una aplicación en capas lógicas (presentación, lógica y datos) para mejorar el mantenimiento, la escalabilidad y la seguridad del software.

## Explicación
El diseño por capas organiza el sistema en niveles funcionales independientes. La capa de presentación maneja la interacción con el usuario, mientras que la capa de negocio encapsula la lógica crítica y las reglas de operación. Finalmente, la capa de acceso a datos se encarga exclusivamente de la persistencia de información. Esta separación permite modificar una parte del sistema sin afectar a las demás, facilita las pruebas unitarias y promueve un código más limpio y legible. Al evitar que el código de interfaz mezcle lógica compleja o consultas directas a bases de datos, se reduce la deuda técnica y se prepara el proyecto para evolucionar con mayor agilidad en entornos modernos.

## Ejemplo (no ejecutado automáticamente)
Estructura básica en Python mostrando cómo una clase de servicio (capa de negocio) recibe datos limpios desde un controlador y delega la persistencia a un repositório, sin exponer detalles internos.

```python
class ServicioUsuario:
    def procesar(self, nombre):
        return self.repositorio.guardar(nombre)
```

## Ejercicio
Crea una clase 'Controlador' que reciba un string de entrada y llame al método 'procesar' de la clase 'ServicioUsuario', devolviendo el resultado final.

## Criterios de revisión
El código debe mostrar claramente tres bloques distintos: entrada, procesamiento lógico y salida. No debe haber lógica de negocio mezclada con manejo de strings de interfaz.

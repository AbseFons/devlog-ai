## Objetivo
Aprender a implementar restricciones CHECK para limitar rangos de datos y UNIQUE para garantizar la unicidad, asegurando la integridad referencial y lógica en tablas relacionales mediante sintaxis estándar.

## Explicación
Las restricciones CHECK y UNIQUE son fundamentales para mantener la calidad de los datos. La cláusula UNIQUE asegura que ninguna columna o conjunto de columnas contenga valores duplicados, ideal para identificadores como correos electrónicos. Por otro lado, CHECK valida que los datos cumplan una condición específica, como un salario mayor a cero o una fecha futura. Ambas se definen al crear la tabla o mediante ALTER TABLE. Es crucial escribir las condiciones con precisión sintáctica para evitar errores de compilación y asegurar que la base de datos rechace automáticamente entradas inválidas antes de persistirlos.

## Ejemplo (no ejecutado automáticamente)
Creación de una tabla de empleados con restricción CHECK para salario positivo y UNIQUE para el correo electrónico.

```sql
CREATE TABLE empleados (
  id INT PRIMARY KEY,
  nombre VARCHAR(50),
  salario DECIMAL(10,2) CHECK (salario > 0),
  email VARCHAR(100) UNIQUE
);
```

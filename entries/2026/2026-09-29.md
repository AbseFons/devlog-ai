## Objetivo
Comprender y aplicar el concepto fundamental de Listas de Control de Acceso (ACL) para restringir operaciones en recursos críticos, asegurando que solo usuarios autorizados puedan modificar datos sensibles dentro de una arquitectura de seguridad estándar.

## Explicación
El control de acceso es la primera línea de defensa en la seguridad informática. Una Lista de Control de Acceso (ACL) define explícitamente qué identidades pueden realizar acciones específicas sobre un recurso. En este caso, utilizaremos un archivo de configuración simulado donde solo el rol 'admin' puede escribir, mientras que los roles 'usuario' y 'invitado' tienen permisos de lectura o ninguno. Este enfoque minimiza la superficie de ataque al principio del diseño del sistema. La implementación correcta requiere definir reglas claras antes de desplegar cualquier servicio, evitando configuraciones por defecto permissivas que exponen datos a actores maliciosos.

## Ejemplo (no ejecutado automáticamente)
Script en Bash que simula una verificación de permisos para un archivo de configuración sensible, permitiendo escritura solo si el usuario es 'admin'.

```bash
# Simulación de control de acceso
if [ "$USUARIO" == "admin" ]; then
  echo "Acceso concedido: Modificación permitida"
else
  echo "Denegado: Solo lectura para este usuario"
fi
```

## Ejercicio
Crea un script que simule una API REST simple. Define tres endpoints: /datos (lectura pública), /configurar (escritura solo para admin) y /borrar (escritura solo para superadmin). Implementa la lógica de validación en el middleware antes de procesar la solicitud.

## Criterios de revisión
El código debe validar explícitamente el rol del usuario contra las reglas definidas. Debe denegar acceso con un mensaje claro si no se cumple la condición. No debe permitir operaciones de escritura en endpoints restringidos por parte de usuarios no autorizados.

## Objetivo
El desarrollador aplicará inyección de dependencias avanzada para manejar contextos dinámicos, diferenciando claramente entre configuraciones fijas y comportamientos transitorios en arquitecturas modulares sin acoplar lógica de negocio a infraestructura.

## Explicación
En esta lección exploramos cómo la inyección de dependencias evoluciona más allá de la simple sustitución de implementaciones. Analizamos el uso de contenedores condicionales y proveedores reactivos que permiten cambiar comportamientos en tiempo de ejecución sin recompilar. Esto es crucial para sistemas que requieren pruebas A/B, características por suscripción o entornos de desarrollo distintos a producción. La clave reside en desacoplar la creación del objeto de su configuración específica, utilizando interfaces estables mientras se inyectan implementaciones variables. Aprenderás a estructurar tu código para que las decisiones de infraestructura no contaminen la lógica pura, facilitando mantenibilidad y escalabilidad en aplicaciones complejas donde la rigidez inicial es una deuda técnica.

## Ejemplo (no ejecutado automáticamente)
```java
public class Notificador {
    private final MensajeStrategy estrategia;
    
    public Notificador(MensajeStrategy estrategia) {
        this.estrategia = estrategia;
    }
    
    public void enviar(String mensaje) {
        estrategia.procesar(mensaje);
    }
}

enum TipoNotificacion { EMAIL, SMS, PUSH }

class ConfiguracionContexto {
    private static MensajeStrategy estrategiaActual;
    
    public static void establecerEstrategia(TipoNotificacion tipo) {
        switch (tipo) {
            case EMAIL: estrategiaActual = new EmailHandler(); break;
            case SMS: estrategiaActual = new SmsHandler(); break;
            default: estrategiaActual = new PushHandler(); break;
        }
    }
}

public class AppPrincipal {
    public static void main(String[] args) {
        ConfiguracionContexto.establecerEstrategia(TipoNotificacion.EMAIL);
        Notificador notificador = new Notificador(ConfiguracionContexto.estrategiaActual);
        notificador.enviar("Bienvenido al sistema");
    }
}
```

## Ejercicio
Crea una clase 'ServicioReporte' que acepte un 'FormatoSalida' (CSV, JSON, XML) mediante inyección. Implementa tres clases concretas para cada formato y haz que el constructor principal reciba la implementación específica. Luego, escribe un método de prueba que cambie dinámicamente la estrategia de salida sin modificar el objeto ServicioReporte.

## Criterios de revisión
El código debe compilar sin errores, las interfaces deben estar claramente definidas antes de sus implementaciones, y el cambio de estrategia de formato no debe alterar la lógica interna del servicio principal.

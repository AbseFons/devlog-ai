## Objetivo
Comprender la diferencia fundamental entre las operaciones de lectura (GET) y creación (POST) en el diseño de APIs RESTful, aplicando los verbos HTTP correctos para construir endpoints seguros y semánticamente claros.

## Explicación
En las APIs REST, cada método HTTP define una acción específica sobre un recurso. El verbo GET se utiliza exclusivamente para recuperar datos sin efectos secundarios, ideal para listar usuarios o obtener detalles de un producto. Por otro lado, POST inicia una nueva transferencia de datos o crea un recurso en el servidor, como registrar un nuevo usuario. Es crucial mantener esta separación: usar GET nunca debe modificar estado ni crear recursos, mientras que POST es la puerta de entrada para operaciones de creación. Esta distinción permite a los clientes y servidores entender claramente qué esperar de cada solicitud, facilitando el mantenimiento y la escalabilidad del sistema.

## Ejemplo (no ejecutado automáticamente)
Solicitud GET para obtener una lista de usuarios activos desde un endpoint público.

```javascript
fetch('https://api.ejemplo.com/usuarios?activo=true')
  .then(response => response.json())
```

## Criterios de revisión
El endpoint debe responder con estado 201 Created, incluir el cuerpo del nuevo recurso y no permitir la creación si faltan campos obligatorios.

## Objetivo
Aprender la estructura básica del commit convencional para mejorar la legibilidad del historial de cambios, facilitando la generación automática de changelogs y el seguimiento eficiente del desarrollo en equipos colaborativos.

## Explicación
El formato de commits convencionales requiere que cada mensaje empiece con un tipo seguido de un punto y espacio. Los tipos principales son feat para nuevas funcionalidades, fix para correcciones de errores, docs para documentación, style para cambios de formato sin afectar lógica, refactor para reestructuración de código y test para pruebas. Después del tipo, se añade una descripción breve en mayúsculas si corresponde. Este estándar permite a los desarrolladores entender rápidamente el propósito de cada cambio sin necesidad de revisar el código detalladamente.

## Ejemplo (no ejecutado automáticamente)
Ejemplo de mensaje de commit siguiendo la convención para añadir una nueva funcionalidad de búsqueda en tiempo real.

```bash
git commit -m "feat: implementar busqueda en tiempo real en el input principal"

# Verificando el historial
git log --oneline -1
```

Crea un commit que documente una actualización de la guía de estilo del proyecto usando el tipo 'docs' y añade una línea de código de ejemplo dentro del mensaje.

## Criterios de revisión
El mensaje debe comenzar con 'docs:', incluir una descripción clara en inglés o español, evitar caracteres especiales prohibidos y mantener la longitud por debajo de 72 caracteres.

## Objetivo
Comprender y aplicar el principio de mínimo privilegio al definir roles de usuario en un servidor web, limitando el acceso solo a los recursos necesarios para cada tarea específica.

## Explicación
El principio de mínimo privilegio establece que cada entidad (usuario, proceso o servicio) debe tener únicamente los permisos estrictamente necesarios para realizar su función. En entornos de producción, esto es crítico para contener daños ante brechas de seguridad. Por ejemplo, un servicio de backup no necesita acceso a la base de datos completa, solo lectura en tablas específicas. Al asignar roles granulares en lugar de cuentas con permisos administrativos totales, reducimos la superficie de ataque. Si una cuenta comprometida se utiliza para ejecutar código malicioso, el daño estará limitado al alcance de sus privilegios. Implementar este principio requiere un análisis detallado de flujos de trabajo y revisión periódica de asignaciones de acceso.

## Ejemplo (no ejecutado automáticamente)
Definición de roles en Nginx para separar acceso administrativo del servicio de backup.

```bash
user nginx;
add_user backup_user --group www-data --permissions read-only;
```

## Ejercicio
Identifica tres servicios comunes en tu infraestructura y define qué permisos mínimos son necesarios para cada uno.

## Criterios de revisión
El estudiante debe listar los servicios, justificar por qué ciertos permisos no son necesarios y proponer una asignación de roles que cumpla con el principio de mínimo privilegio.
